## 1. Finding: the q-Young idempotents are *oblique* projectors

The H₃(q) primitive idempotents `e_a` (a = μ_n ⊢ 3) satisfy `e_a² = e_a`
but are **not self-adjoint** (`e_aᵀ ≠ e_a`). Consequences that bit the
first kernel attempt (failed 7/18 partitions, errors up to 4.07):

- `e_a ≠ Q_a Q_aᵀ` for an orthonormal column basis `Q_a`. The
  orthogonal projector onto `im(e_a)` is *not* `e_a`.
- The cross-sector image bases `Q_a`, `Q_b` (a ≠ b) are **not mutually
  orthogonal**, so `Q_aᵀ X Q_b` is not the (a,b) block of `X` in the
  decomposition `V = ⊕_a im(e_a)`.

**Correct reduction.** Use the *adapted basis* `P = [Q_(3) | Q_(2,1) |
Q_(1,1,1)]` (columns span each `im e_a`; `P` is invertible because the
`e_a` are a complete orthogonal system of idempotents so the images
direct-sum to the block) together with its **true inverse** `P⁻¹` —
never `Pᵀ`. Every operator becomes `X̂ = P⁻¹ X P` with sector blocks
`X̂_{a,b}`. Then, using that the left word `B_p` commutes with every
`e_a` (so `B̂_p` is block-**diagonal**):

```
χ_block = Tr[B̂_p · M̂ · B̂_n] = Σ_{a,b} Tr[ bp_a · m_{a,b} · bn_{b,a} ]
   bp_a    = B̂_p[a,a]   (r_a × r_a)
   m_{a,b} = M̂[a,b]     (r_a × r_b)   — bridge, cross-sector
   bn_{b,a}= B̂_n[b,a]   (r_b × r_a)   — right word, cross-sector
```

`r_a = rank(e_a) = Tr(e_a) ≤ c_LR · dim(V_{μ_p}) · dim(V_{μ_n}) ≤ ~40`,
bounded independent of `dim V_λ` (the A=8,9 enabler).

**Verified** (`chi_via_reduced_blocks_mpfr`, pure mpmath, no wheel):
`reduced == dense == one-level χ`, 18/18 partitions of D/T/³He/⁴He, to
the 50-dps floor. Third assertion in
`derived-chi-catalogue-matrix-m-mu-n-mpfr.witness.json`.

## 2. Finding: single-level reduction does NOT save flops

At single level the `X̂ = P⁻¹ X P` transforms are full `size × size`
(forming `B_p`, `B_n`, `M` densely, then changing basis). So Phase 1.4
**validates the block structure but does not beat the dense path on
flops**. The wall-clock win requires never forming the full matrices —
i.e. building the generators *directly* in the reduced representation.
That is the recursion (§3), not a post-hoc projection.

This is the load-bearing correction to the optimistic framing in
`2026-06-08-matrix-m-optimization-A-8-9-path.md` §2 Tier 1: the bounded
sub-block dimension is necessary but the *projection* must be folded
into the generator construction, not applied after.

## 3. Tier-3 recursion (the actual A=8,9 path) — design

The braid `β` for ³A strands has the nested bridge structure (audit
2026-06-08 §3 Tier 3):

```
β = β_0 · σ_{k₁} · ( β_1 · σ_{k₂} · ( β_2 · σ_{k₃} · … ) )
```

Each level peels off 3 strands (one nucleon worth) on the right. At
level ℓ the right factor `V_skew^{(ℓ)}` decomposes under its own H₃
(generated by `σ_{k_ℓ+1}, σ_{k_ℓ+2}`) into `μ^{(ℓ)} ⊢ 3` isotypics via
the same q-Young idempotents. The recursion:

1. Build the level-0 μ_p blocks (existing `precompute_block_tables_mpfr`).
2. Within each, build the adapted basis `P⁽⁰⁾` for the first right-H₃
   split → sector blocks of size `r_a⁽⁰⁾`.
3. The right word `B_n` factors as `β_1 · σ_{k₂} · (…)`; recurse on the
   `β_1 · (…)` part *inside each sector block* — its generators are
   already the level-1 reduced operators, never the full matrix.
4. Terminate when the remaining right factor is a single H₃ (deuteron-
   complete), where the reduced kernel of §1 is exact and small.

**Per-(μ_0,…,μ_{A−1}) tuple block size** `≤ c_LR · ∏_ℓ dim(V_{μ_ℓ}) ≤
~2^A`; most tuples have `c_LR = 0` and are skipped (see §4a). For ⁹Be
the largest multi-LR table is ~52k entries (audit 2026-06-08 §5),
one-time precompute < 1 s.

**Key implementation rule (from §2):** at each level store operators
as their **sector-block matrices in the adapted basis**, and build the
next level's generators by `P⁻¹ σ P` *restricted to the active sector*
— so the dimension carried forward is `r_a^{(ℓ)}`, never `dim V_λ`.

**Verifiability in-sandbox:** the recursion's *correctness* (recursive
χ == dense χ) is checkable on D/T/³He/⁴He with pure mpmath. The
*wall-clock payoff* only manifests at A ≥ 6 and needs the real sweep.

## 4. Orthogonal optimizations

### 4a. Skip zero-LR tuples
Many `(μ_p, μ_n)` (and multi-level `(μ_0,…)`) pairs have `c_LR = 0` —
the sector is empty (`r_a = 0`) and contributes nothing. The reduced
kernel already drops `r = 0` sectors automatically (the adapted basis
only includes non-empty images). For the recursion, prune tuples with
`c_LR = 0` *before* descending. LR coefficients are pure combinatorics;
a Python `lr_coefficient` fallback (independent of the wheel) is a small
add (Littlewood–Richardson rule on skew tableaux). **Saves 30–60% of
block count** (audit §3a).

### 4b. Precompute the abstract H₃ symmetrizer once
The *coefficients* of `e_(3), e_(2,1), e_(1,1,1)` as words in the two
generators are fixed (`_S3_ELEMENTS_MPFR` + the `q`-powers). Only the
*embedding* (the block-restricted `σ_{k+1}, σ_{k+2}`) varies per λ.
Marginal but free: hoist the `q`-power scalars out of the per-block
loop. (Current code recomputes `q**length` per block; caching them per
`dps`/`q` is a micro-opt.)

### 4c. Parallel batch
`pyhecke_native.chi_lambdas_via_gp` batches all partitions in one Rust
call; orthogonal to the per-partition reduction. Modest (~5–20%),
not a path to A=9 on its own (audit §3c).

### 4d. Bar symmetry (already wired)
Conjugate pairs `λ, λᵀ` derive one from the other (PR #1952), ~50%
across the sweep, stacks multiplicatively with everything above.

## 5. Tier-2 Rust port — spec (needs Rust toolchain)

Port the reduced/recursive path into `tools/hecke-engine`:

- **Types:** reuse the existing `mpfr`-backed `Float` (PR #2017 matrix-M
  port) for sector-block matrices; `Vec<partition>` keys as in the
  Python adapted basis.
- **Entry:** `chi_via_reduced_blocks(shape, word, k_split) -> Float`
  mirroring `chi_via_reduced_blocks_mpfr`, then `chi_via_recursive_blocks`
  for the §3 nesting.
- **Adapted basis:** Gauss–Jordan inverse of `P` over `mpfr` (or solve
  `P X = σ P` per generator to avoid an explicit inverse).
- **PyO3:** expose both via `pyhecke-native`, cross-check against the
  Python kernel on D/T/³He/⁴He (the existing determinism test pattern,
  PR #2023).
- **Expected:** ~100–1000× per-multiply over mpmath (audit §2 Tier-2);
  combined with §3, ⁹Be sweep in seconds.
