# hadron-knot-table — stale witness + binding regression (findings)

**Date:** 2026-06-16
**Branch:** `claude/youthful-faraday-5snwms` (PR #2355)
**Trigger:** While moving the appendix `hadron-knot-table` to the true
substrate q₀ (off the legacy 111/100 rational), regenerating its witness
exposed two pre-existing problems unrelated to the q₀ change.

## Finding 1 — the committed witness is self-stale

`hadron-knot-table.witness.json` records `scriptHash = bb86bfa94159`, but
the current `hadron_knot_table.py` hashes to `e09e2e0eb3ed`. The witness
was generated by an **older producer** and never refreshed. No CI check
flagged it (self-staleness was unchecked until the validator enhancement
on this PR — see
[`docs/design/2026-06-16-witness-staleness-propagation.md`](../design/2026-06-16-witness-staleness-propagation.md)).
It is one of **694 self-stale witnesses (42%)** the enhanced validator
now surfaces.

## Finding 2 — regeneration reveals a likely binding regression

Re-running the current producer changes values far beyond any q effect:

| ⁴He field | committed witness | current-code regen | note |
|-----------|-------------------|--------------------|------|
| `tr_M` | 1.427904 | 1.496291 | from `build_atom_nf`/`nf_tr` — **not** touched by the q₀ work |
| `B_MeV` | 28.1915 | 0.7183 | ⁴He binds at ~28 MeV; **0.72 MeV is physically wrong** |

`tr_M` and `B_MeV` come from `build_atom_nf`/`binding_energy`, which the
q₀ volume change does not touch — so this is a **pre-existing regression**
in the current producer (or its upstream `binding_energy` in
`hecke_core_legacy.py`), independent of q₀. Because the committed witness
predates it, the regression has been masked.

## Action taken

- **Did NOT ship the regenerated witness** — it would have laundered the
  binding regression into a "refreshed" witness. The committed (stale)
  witness and the producer were restored to their prior state.
- **Parked the validated q₀ work.** The mpmath q₀ port of the nucleon-
  level `V_full` (mirrors `HeckeRational.V_full` at q₀, tractable where
  the exact-Fraction engine blows up) was cross-checked against the
  rational 1.11 engine to the expected q-gap (4He 2.8e-4, 6Li 1.1e-3,
  12C 2.0e-3, 16O 1.6e-4). It is correct but **blocked** on first
  resolving Finding 2 (otherwise its regeneration bundles the
  regression).

## Why this is the motivating case for the staleness infra

This is exactly the failure the staleness-propagation design targets:

1. **Self-staleness** (Finding 1) sat undetected — *no CI gate on
   `scriptHash` drift*. → fixed by the validator's new self-check.
2. **Refresh-laundering** (Finding 2) — a blind "regenerate the stale
   witness" would have committed a physically-wrong value. → motivates
   **assertion-gating on refresh** (block when `allPassed` flips false;
   an assertion `B(⁴He) ≈ 28 MeV` would have caught it).
