# Narrative-proof presence audit (2026-06-24)

**Question (author, 2026-06-24):** *Does each lemma/prop/thm in the paper
have a narrative proof in the paper? Is this a QA-sidecar dimension?*

> **Correction (2026-06-24, same day).** The first cut of this audit used
> a prose heuristic on the parent block's `.md` and reported "~331 gaps."
> That was **wrong**: it ignored the platform's existing `proof` **block
> kind** (`<name>-proof.ts` + `<name>-proof.md`, linked via the parent's
> `proofs: [...]`), where the narrative proof actually lives. Re-run
> against the real mechanism, the numbers below are authoritative:
> **167 covered / 492 gaps.** Two blocks the first cut flagged
> (`electron-period-base`, `bar-parity-split`) already had complete proof
> blocks and were never gaps.

## Answers

**1. No — about a quarter of provable blocks have a narrative proof
block.** Of **659** provable blocks (`theorem` / `lemma` / `proposition`
/ `corollary`), **167** have a linked, non-trivial `proof` block; **492**
do not. For those 492 the proof, if it exists, lives only in Lean or in
inline parent prose, and is not separately tracked. (Some of the 492 are
deliberately external/axiomatic — e.g. `thm:jones-markov-trace`, "the
proof occupies §3–5 of Jones (1987)" — and should be marked exempt rather
than given a proof block; see the convention doc.)

**2. No — narrative-proof *presence* is not currently a QA-sidecar
dimension.** The `qa-criteria-registry.ts §PROOF` axis (~15 criteria) is
entirely **Lean-side**: `proof-no-bare-sorries`, `proof-lean-compiles`,
`proof-build-green`, `proof-no-axiom-growth`, the vacuity family, the
rater scores. The single narrative-touching criterion,
`proof-narrative-lean-equiv`, is **gated on a `.lean` existing** and
checks *equivalence* between prose and Lean — it never asserts the
positive requirement "a provable block must carry a narrative proof
block." So a block with a perfect Lean proof and no proof block passes
every existing proof criterion while having no separately-tracked paper
proof.

## Mechanism (already exists — no schema change needed)

The author's ask — "narrative proof as a separate `.md`, part of the
content block, to track easier" — is **already** the platform's `proof`
block kind. ~170 already exist. Convention + authoring guide:
[`docs/conventions/narrative-proof-sidecar.md`](https://github.com/litlfred/qou/blob/claude/wonderful-newton-bh1fxt/docs/conventions/narrative-proof-sidecar.md).
The only genuinely-new platform work is a `proof-narrative-present` QA
criterion; spec:
[`docs/conventions/narrative-proof-sidecar-folio-assistant-requirements.md`](https://github.com/litlfred/qou/blob/claude/wonderful-newton-bh1fxt/docs/conventions/narrative-proof-sidecar-folio-assistant-requirements.md).

## Method

Audit
[`content/pipeline/audit-narrative-proof-presence.ts`](https://github.com/litlfred/qou/blob/claude/wonderful-newton-bh1fxt/content/pipeline/audit-narrative-proof-presence.ts)
(`bun run …`). A provable block is **covered** iff it has a linked,
non-trivial `proof` block — from the parent's `proofs: [...]` or from a
`proof` block whose `uses: [...]` names the parent. Otherwise it is a
**gap**. Margins still need a human pass (a definitional proposition needs
no proof; an external result should be marked exempt, not proven).
