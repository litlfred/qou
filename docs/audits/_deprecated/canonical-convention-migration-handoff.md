The two underlying **math blockers** preventing further migration:

### Blocker A — Crystal limit of averaged crossings

`term7_alpha5_crystal_derivation.crystal_chi_lambda(shape, word)`
takes `word: list[int]` and computes χ_λ(β) at q → 0 via the
sign-of-axial-distance permutation rule on SYTs.  This rule is
defined on σ_g (signed) and σ_g⁻¹ (involutive at q = 0).  For an
averaged crossing `I_g = σ_g − (h/2)·1` with `h = q − q⁻¹`, the
q → 0 limit diverges (h → −∞) and the standard signed-permutation
formula `T ↦ sign(ρ_T(g)) · T` does not extend.

**To resolve** (research-scale; pick one path):

1. Take the q → 0 limit of the symmetric eigenspace projection
   (the +q-eigenvalue half of σ — gives `I` the same crystal action
   as σ, minus the trivial trace).  Conjecturally equivalent to
   `[2]_q I = q⁻¹·1 + q·σ` route → q → 0 limit only well-defined
   on the ideal generated by `(σ + q⁻¹)`.
2. Define a separate functor (the "averaged crystal limit") that
   carries the projection-to-symmetric-channel structurally.
3. Extract from `conj:crystal-graph-realization` the explicit
   crystal-graph action of `I_g`; if the conjecture is closed
   structurally, the action descends.

Each path is research; the right answer is not obvious and may
require new theory tied to `conj:crystal-graph-realization`.
Recommend: investigate (1) first as the most direct algebraic
route.

### Blocker B — GS filtration on averaged crossings

`gb_filtration_jet_tracker.reduce_braid(name, n, word, expected)`
walks the GS reduction system on a list-of-int word.  Its inner
loop applies σ_i / σ_i⁻¹ commutation/braid moves; `I_i` does not
have its own GS rewrite rule.

**To resolve** (~3-5 days focused work):

1. Add `I_i` as a third generator class in `HeckeElement.terms`
   (currently keyed by perm; needs extension to include averaged
   markers).
2. Encode the `I_i · I_j` commutation rule for `|i − j| ≥ 2`
   (follows from σ_i / σ_j commutation + linearity).
3. Encode the `I_i · I_{i+1} · I_i` braid-like relation (follows
   from σ relations + the averaged definition; explicit formula
   is a sum of 8 terms involving σ, σ⁻¹, and `1`).
4. Verify the tracker reduces canonical 4He / D / ³He words to
   the same GS filtration grade as the legacy disjoint words
   give for these atoms.  If grades match, the canonical
   convention is filtration-equivalent to legacy and the
   `atomic-braid-gb-filtration-extension` witness can be
   regenerated in canonical convention with no loss.  If grades
   differ, the difference IS new physics — needs human review.

## Recommended next-steps for the new agent

In priority order:

### Step 1 — Investigate Blocker B (engineering, ~3-5 days)

This is the more tractable blocker.  Read
`computations/gb_filtration_jet_tracker.py`,
specifically the `reduce_braid` function and the
`HeckeElement.apply_generator` method.  Add an averaged-crossing
generator class.  Verify on the 4 canonical atom words (p, n, d,
4He) — the canonical 4He word has 47 crossings (9 averaged + 23 σ
+ 15 σ⁻¹) while the legacy version has 12 (all σ/σ⁻¹) ; if both
reduce to the same GS grade, the migration is safe.

If Blocker B closes, regenerate
`atomic-braid-gb-filtration-extension.witness.json` in canonical
convention and migrate the
`build_atomic_braid_recipe_4he_chain.py` to read from canonical.
Drop the legacy 4He chain.

### Step 2 — Research Blocker A (math research)

Investigate path 1 first (symmetric-eigenspace q → 0 limit of I).
Recommend collaboration with someone familiar with the categorical
crystal-limit functor; this is genuine research, not engineering.
A failed spike is acceptable output (documents that path 1 is not
viable, narrows the search).

If Blocker A closes, regenerate
`term7-alpha5-crystal-derivation.witness.json` in canonical
convention.  Cross-check that `S_crystal(A)` numerics agree with
the legacy values to within tolerance — they should, since the
crystal-limit is the same categorical object viewed in two
conventions.  If they differ, the difference is new physics.

### Step 3 — Wire downstream consumers

Once steps 1 and 2 close, update PR #605's
`markov-trace-assembly-{neutron, deuteron}` SCRIPT_CITED
"atomic-braid-recipe-{n, d}" steps to consume
`atomic-braid-recipe-{n,d}-canonical.derivation.json` directly
(promote to DERIVED).  This makes those mass-trace chains
fully-trusted modulo the remaining Wedderburn-weight frontier.

### Step 4 — Delete legacy artifacts

After steps 1–3, `atomic_braid_gb_filtration_extension.py` and
`build_atomic_braid_recipe_4he_chain.py` and their witnesses can
be deleted.  This finally completes the directive ("use I averaged
crossing everywhere").

## Anti-goals (do NOT do)

- **Do not** silently rewrite `crystal_chi_lambda` to handle
  averaged crossings without resolving Blocker A first.  Doing so
  produces wrong math (the q → 0 limit of `I` is genuinely not
  defined by the signed-permutation rule).
- **Do not** delete `atomic_braid_gb_filtration_extension.py` or
  `term7_alpha5_crystal_derivation.py` before their consumers
  migrate.  They are the **only** scripts that produce certain
  witnesses (`atomic-braid-gb-filtration-extension.witness.json`,
  `term7-alpha5-crystal-derivation.witness.json`); deletion
  breaks the audit trail.
- **Do not** force the canonical 4He word into the SDP solver's
  scope without verifying the solver scales to A = 4 first
  (currently A ≤ 3).  Premature SDP claims for ⁴He propagate
  through chain descriptions and are review-flagged.
