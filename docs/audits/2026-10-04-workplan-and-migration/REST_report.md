## Skill gaps in folio-assistant

1. **No skill or check for archival bytes held in git.** `materialize-remote` assumes archival bytes arrive from outside. Nothing tells a folio that already commits 639 MB of originals how to move them to an archival store with fixity, and no audit flags a PDF under `library/`.
2. **The `repository-size` health check is cat-harness-local.** Its action text names largest blobs but not the library/archival route, and it does not run against dependents. qou would trip `major` today, unseen.
3. **There is no graph kind for working notes** (derivation notes, ledgers, scoping docs). The choices are `folio` (rendered content) or nothing, so 512 files sit undeclared. A `notes` (context) kind with a promote-to-block process would let them be declared without editing.
4. **`repo-conversion` does not classify `docs/**/*.md` by math density**, so outside-tree math is invisible to it (ORPH made the same point).
5. **Nothing checks that a generated library `INDEX.md` matches the entry count** (693 vs 715).
6. **No skill covers retiring legacy derived indexes** (proof-objects, glossary, mapping) with a label-parity gate.
