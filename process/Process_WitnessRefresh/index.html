summaryBring qou's computation witnesses back in line with the producers that write them, without a witness ever being rewritten that the owner did not approve.
descriptionBring qou's computation witnesses back in line with the producers that write them, without a witness ever being rewritten that the owner did not approve. Owner, 2026-10-04: "all witnesses tools will need to go into the KG"; this is the process those Tools run in. A WITNESS IS CONTENT HERE. Its numbers are what the paper quotes, so the owner's rule that a migration changes no mathematics applies to it, and so does the ask-first rule for refreshing one. That is why the decision sits in the owner's lane between the measurement and the re-run, and why nothing before it writes a file: the dry run and the parity check both work on the committed tree or a scratch copy of it. THE PLAN IS run_pipeline.py --dry-run --content-only, UNCHANGED. The process does not re-derive staleness; it calls the pipeline's own answer through the witness-refresh-plan Tool, so the list a person approves is exactly the list the pipeline would act on.
