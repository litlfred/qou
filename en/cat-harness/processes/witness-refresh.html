Refresh computation witnesses

Process_WitnessRefresh · strict (defaulted) · 6 step(s)

Bring qou’s computation witnesses back in line with the producers that write them, without a witness ever being rewritten that the owner did not approve. Owner, 2026-10-04: “all witnesses tools will need to go into the KG”; this is the process those Tools run in.

A WITNESS IS CONTENT HERE. Its numbers are what the paper quotes, so the owner’s rule that a migration changes no mathematics applies to it, and so does the ask-first rule for refreshing one. That is why the decision sits in the owner’s lane between the measurement and the re-run, and why nothing before it writes a file: the dry run and the parity check both work on the committed tree or a scratch copy of it.

THE PLAN IS run_pipeline.py --dry-run --content-only, UNCHANGED. The process does not re-derive staleness; it calls the pipeline’s own answer through the witness-refresh-plan Tool, so the list a person approves is exactly the list the pipeline would act on.

Steps

Every one of the 6 step(s) is documented.

step lane skill / sub-process what it does
List stale producers (pipeline dry run)
Task_Plan		 Compute agent — Run python3 computations/run_pipeline.py --dry-run --content-only (the witness-refresh-plan Tool). It lists every content-linked producer whose witness is stale (script changed, a dependency changed, or a stale q0) in dependency order, and writes nothing.
Classify each: does a re-run reproduce it?
Task_Parity		 Compute agent — Run the platform’s witness-parity Tool on the listed witnesses. It re-runs each committed producer in a scratch git worktree and reports pass, fail (with the differing paths) or unknown (environment mismatch, stale script, error, timeout). The owner sees, for each candidate, whether a refresh would change numbers or only provenance.
Approve which producers to re-run
Task_Approve		 Owner (the paper’s author) — The owner picks the producers whose witnesses may be rewritten, from the classified list. Saying nothing approves none. A witness whose re-run changes numbers needs a decision about which result is right before it is approved.
Re-run the approved producers
Task_Run		 Compute agent — Re-run exactly the approved Python (computations/) or Rust (crates/qou-values, crates/hecke-engine) producers at the active proton pin (q0Anchor = "proton"; muon pin on hold until rederivation per 2026-11-28 owner ruling), in dependency order. A producer that writes sibling witnesses outside the approved set is reported, and those files are restored to their committed state rather than committed.
Precision gates; keep audit output out
Task_Gates		 Compute agent — Run scripts/precision-gates.sh --changed. A red that names one of the refreshed witnesses stops the process at the producer. A red that predates the change does not, but it is reported. The gate scripts rewrite their own audit-report witnesses as a side effect; those are restored, never committed.
Commit the refreshed witnesses
Task_Commit		 Compute agent — Commit only the approved witnesses, naming the producers, the fields that changed and the gate result, and re-run witness-parity on them, expecting pass.
