`content/quantum-observable-universe/lean/QOU/IwahoriHecke/Quotient.lean`.

**Header (lines ~24-46) claims:**
- the ideal is "generated by Hecke **+ braid** relations", listing the alternating-product
  braid generator explicitly with `m_{st}` factors;
- `T : S → IwahoriHeckeQuot` "satisfies the Hecke **+ braid** relations definitionally".

**The code says otherwise:**

    def heckeQuadraticGenerators : Set (FreeAlgebra R S) :=
      { heckeQuadraticRelation R q S s | s : S }

    def heckeIdeal : Ideal (FreeAlgebra R S) :=
      Ideal.span (heckeQuadraticGenerators R q S)

No braid generator appears. The **per-def docstring on `heckeIdeal` is honest** and states the
restriction ("Sprint 2 scope: we include only the Hecke quadratic relations here"), and
`Defn.lean`'s caveat agrees. So the defect is confined to the module header contradicting the
body of its own file.

**Why it matters beyond tidiness.** A reader who takes the header at face value concludes the
corpus has H_n(q). It does not — the quadratic-only quotient is a strictly larger algebra, and
anything asserting the braid relations hold in it would be false. This is what sent this
session checking; a reader with less reason to be suspicious would not have.

Fix: correct the header to match `heckeIdeal`'s own docstring, or land the braid generators
(that is `qou-phir`, not this bean). **The doc fix should not wait on the code fix** — an
inaccurate header is worse than an acknowledged gap.

## Fixed 2026-08-29 (PR #6055) — and there were FOUR errors, not one

This bean reported the braid-relation claim. Reading the whole header found
three more, one of them structural:

1. the display presents the ideal as quadratic **+ braid**;
2. "`heckeIdeal` … generated by Hecke **+ braid** relations";
3. "`T` … satisfies the Hecke **+ braid** relations definitionally";
4. `IwahoriHeckeQuot := (FreeAlgebra R S) ⧸ heckeIdeal` — **the wrong
   construction.** The live definition is `RingQuot (heckeRel …)`, and the
   `Ring` instance's own docstring in the same file calls the `Ideal.Quotient`
   form *a bug that was fixed*. So the header does not merely overstate the
   ideal's contents; it describes the superseded, buggy design.

Error 4 matters more than 1–3: a reader who trusts the header reasons about a
quotient the file does not build.

Also found: **`heckeIdeal` is dead code.** Defined once, referenced only from
docstrings, used by no construction in the tree. Labelled vestigial rather than
deleted — removing it is a behaviour-neutral cleanup but belongs with whoever
reworks the quotient (`qou-phir`), not as a drive-by here.

Header rewritten to match the body, with the scope stated as a blockquote so it
cannot be skimmed past. `Quotient.lean` re-verified `lean`-direct: compiles with
only the two pre-existing `unusedSectionVars` warnings on `[DecidableEq W]`.

**Not done here:** adding the braid relations to `heckeRel`. Ten files consume
`IwahoriHeckeQuot`, so changing that quotient is `qou-phir`'s scope.
