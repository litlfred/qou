## The hole

`witness_raw_float64_audit.py` scans **committed** `*.witness.json`. A producer
whose witness is never committed therefore cannot be flagged by it, no matter
how dirty its output is — the ratchet's coverage is the tracked tree, not the
set of producers.

Measured on `main` 2026-08-26, over the 1554 producers that declare
`WitnessBuilder("<literal>")`:

    1554   declare a witness name
      14   whose <name>.witness.json is NOT tracked in git
       0   of those 14 are gitignored

The name mapping is exact and not a guess — `witness.py:1117`: *"Computation
name (becomes the filename: `<name>.witness.json`)"* — and it was confirmed
end-to-end by running one of the 14 and watching it write exactly that file.

Since none of the 14 is gitignored, none of them is uncommitted **by design**.
(`.gitignore` does deliberately exclude several large witnesses under "Large
computation witnesses (regenerated by running the script)" — those are a
legitimate, separate class, and none of the 14 is in it.)

## At least one of the 14 is genuinely dirty — verified by running it

`qbeta_c3_barodd_determined_solve_probe` (71.7 s) emits
`qbeta-c3-barodd-determined-solve.witness.json` carrying **9 raw float64
fields**, all in `.assertions[*].{computed,expected,tolerance}`. With that file
present, `witness_raw_float64_audit.py --strict` **exits 1** and reports 3 NEW
dirty fields against the baseline. It has presumably been emitting them for as
long as it has existed, and nothing could report it.

The producer's own output says so at the point of writing:

    raw-float64: 9 raw float64 field(s) would enter the witness ...
    Carry mpmath.mpf from the source and serialize with _precision.fmt

So the builder-side warning fires correctly. What is missing is the *durable*
signal: a warning on stdout of an uncommitted run reaches nobody.

**The other 13 are candidates, not confirmed dirty.** Deciding each needs its
producer run.

## 14 is a LOWER BOUND on one shape, not the size of the hole

This counts only `WitnessBuilder("<string-literal>")`. Not counted:

* **hand-rolled writers.** Producers that `write_text` a JSON witness without
  `WitnessBuilder` at all. Three were found incidentally in the `qou-aj91`
  no-witness batch, and **two of them have committed witnesses carrying
  `scriptFile: null`** (`qbeta-argu-phase-branch-selection`,
  `qbeta-meridian-holonomy-anchor-swing`) — the "bare producers" class
  AGENTS.md describes. Those are the inverse problem: committed, so the
  ratchet CAN see them, but with no provenance link back to the producer, so
  no provenance-keyed audit can.
* **stdout-only probes.** Seven of the same batch of eleven write nothing at
  all. Nothing to be dirty, but also nothing to audit — see `qou-aj91`.
* a name built dynamically rather than passed as a literal.

## What NOT to do

Do not commit the 14 witnesses to make them visible. For
`qbeta-c3-barodd-determined-solve` that is *forbidden* — the audit says it
directly: *"Do NOT add the file to the baseline to silence this"*, and
committing a witness with 9 raw float64 fields grows a ratchet that is
supposed to only drain. Fix at the producer first (`mpmath.mpf` end to end,
serialize with `_precision.fmt`), then the witness can be committed clean.

## Found by

Trying to execute the `qou-aj91` no-witness batch. The batch's plan was
"re-run and commit the witness first, to get a muon baseline"; this producer
was the only one of eleven able to do that, and the ratchet blocked it. That
is the ratchet working — the point of this bean is that it only worked because
someone happened to run the producer.
