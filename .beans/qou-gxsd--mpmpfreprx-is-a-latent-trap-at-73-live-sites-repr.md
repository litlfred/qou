Found while regenerating witnesses after the 435-commit main merge (bean qou-uiut's branch).

`computations/probe_option_e_phase2_crystal_vertex_candidates.py:141` died with
`ValueError` from mpmath's `MPZ`:

    chi_w0 = mp.mpf(repr(h6_block["chi_lambda_w0_direct"]))

The field WAS a float. Under NO-FLOAT64 its producer converted it to a 50-digit
`fmt` string, and `repr` of a str keeps the QUOTES — mpmath is handed
"'4.783...'" and rejects it. The probe has been dead at that line since the
upstream conversion. Fixed there with `str`.

## The general fact, measured

`str` and `repr` are IDENTICAL for float and int in Python 3 (both give the
shortest round-tripping form), and `repr` is WRONG for three types this corpus
actually passes:

    str        repr('1.23')            -> "'1.23'"          quotes -> MPZ error
    Decimal    repr(Decimal('1.5'))    -> "Decimal('1.5')"  unparseable
    numpy      repr(np.float64(0.1))   -> 'np.float64(0.1)' unparseable (numpy 2.x)

So `mp.mpf(str(x))` strictly dominates `mp.mpf(repr(x))`: identical output
wherever repr is correct, correct in three cases where it is not.

## Scope

**73 live sites** (excluding `_deprecated/`), concentrated in
`computations/deltalambda/`. Enumerate with:

    grep -rn 'mp\\.mpf(repr(' --include=*.py computations/ qou-mass/ tools/ | grep -v _deprecated

## Why this is safe to sweep, and how to prove it

The change is NUMERICALLY INERT wherever the value is a float, because the
string produced is byte-identical. So a sweep should move no witness digit.
That is the gate: regenerate a sample and require byte-identity apart from
timestamps. Anywhere a number DOES move, the site was reading a non-float and
was already broken or already wrong — which is a finding, not a regression.

## Do NOT

Do not "fix" this by switching to `float(x)` — that caps a 50-digit witness
string at 53 bits, which is the defect NO-FLOAT64 exists to prevent, and it
would be invisible because the value still parses.

## Note on the counter-argument

`codata_constants._ame_binding_mev` deliberately documents `repr` (not `str`)
on a parsed float as "the shortest round-tripping form". That reasoning is
correct and unaffected: for a float the two are the same, so switching to
`str` keeps that property and adds the three cases above.

## 2026-09-07 — swept, 73 of 74, and the safety argument is static

Done. What changed the plan is that the inertness gate written into this bean
("regenerate a sample and require byte-identity") turned out to be unnecessary:
the same conclusion follows from the types, with no producer run at all.

**If `mp.mpf(repr(x))` SUCCEEDS today, `x` is a float or an int.** `mp.mpf`
accepts only a string that parses as a number; a `str`'s repr carries quotes,
a `Decimal`'s and a numpy scalar's carry a constructor, and none of those
parse. So every currently-working site holds a float or int — and for those
`str(x) == repr(x)` exactly, since Python 3.2. The substitution therefore
cannot move a value that works; it can only fix one that raises.

That is stronger than the sampling gate: sampling would have covered the sites
it happened to touch, and this covers all 73.

### Three exclusions, each for a different reason

* **`tools/pyhecke/python/pyhecke/atom.py`** — a **checkpoint-key file**.
  `hadron_knot_table._ckpt_key()` hashes it, so editing it while the nuclide

* **`qou-mass/src/qou_mass/_internal/codata_constants.py`** — generated by

* **`computations/substrate/codata_constants.py`** — `_ame_binding_mev`
  documents its `repr` choice deliberately, and its input is a float, so `str`
  is byte-identical. Overriding a stated decision for zero functional gain is
  not this sweep's business.

  Worth recording though: that docstring's reason does not hold as written.
  It says "`repr` (not `str`) on the parsed float is the shortest
  round-tripping form" — but `str` and `repr` have been identical for floats
  since Python 3.2, so the parenthetical distinguishes nothing. The
  **conclusion is right and the reasoning is not**, which is the sort of note
  that quietly teaches the next reader the wrong rule.

## 2026-09-13 — closed. Zero live instances, and main converged on the same fix

Re-measured on the merged tree after main's 702 commits. `mp.mpf(repr(` now
matches **5 places, none of which is the defect**:

| site | what it is |
|---|---|
| `computations/substrate/codata_constants.py:281` | the documented exclusion — `repr` on a parsed **float**, where `str` is byte-identical |
| `qou-mass/.../codata_constants.py:280` | its vendored copy, generated from the above |
| `computations/_h4_substrate.py:32` | a COMMENT main wrote about the trap |
| `computations/probes/tau_amphichiral_sdp_probe.py:91` | likewise a comment |
| `tools/pyhecke/python/pyhecke/atom.py:452` | **correct use** — see below |

That last one is worth naming, because a sweep would have "fixed" it and broken
a guard. It reads

    if isinstance(q, _mp.mpf) and _mp.mpf(repr(float(q))) == q:
        raise TypeError(... "q is an mpf holding only float64 information" ...)

which is a **representability test**: it round-trips through `float` ON PURPOSE
to detect an mpf carrying no more than 53 bits, and rejects it. Same idiom as
`qou_substrate.precision.str_at_true_precision`. Replacing `repr` with `str`
there leaves it working by accident rather than by construction.

### The 73-site sweep held, and main reached the same conclusion independently

The two sites that were open when this bean was last touched are both resolved
by main, and **better than the sweep did it**. `_h4_substrate` and
`tau_amphichiral_sdp_probe` both read a constant that is *already* an mpf
pinned at `_CONST_DPS`, so main deleted the conversion entirely —
`ALPHA_EM = mp.mpf(1) / _ec.ALPHA_EM_INV`, `cal_tau_e = TAU_OVER_E` — rather
than swapping `repr` for `str`. A string round-trip that was never needed is
better removed than corrected, and main's comments record the same failure this
bean opened on: "`mp.mpf(repr(...))` was the float64 -> mpf idiom and raises
ValueError on an mpf's repr."

`tools/pyhecke/python/pyhecke/atom.py` was the one site this bean deferred, on
the grounds that it is a CHECKPOINT-KEY file and editing it would discard the
running table's atoms. That deferral turns out to have been the right call for
the wrong reason: the site needed no edit at all.

**Closed.** Nothing outstanding.
