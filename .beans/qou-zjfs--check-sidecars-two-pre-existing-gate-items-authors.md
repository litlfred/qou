## 1. `authors-note.qa.json` is stale and `qa-sweep` cannot target the block

`introduction/authors-note.md` is regenerated by
`scripts/refresh-authors-note.ts` (the Lean-coverage stats sentence), so its
sidecar drifts every time coverage moves. Measured on `origin/main`:

    recorded source_hashes.md = 04a05568db03
    actual  md hash           = ba294bd5327f

i.e. **already stale before PR #5538 branched.**

`qa-sweep` will not refresh it. Targeting the block directly — by bare path or
by `.ts` path — reports `blocks: 0`; sweeping the *directory* processes
`intro` (556 lines of cached-entry churn) and skips `authors-note` entirely.
The likely cause: `authors-note.ts` is `prose()` with **no label**, and the
sweep's block enumeration appears to key on labelled blocks. `introduction.ts`
does reference it (`sec:authors-note` → `"authors-note"`), so the manifest is
not the problem.

Do **not** hand-edit the sidecar — it is generated. The fix is one of:
* give the block a label so the sweep enumerates it; or
* teach `qa-sweep` to enumerate label-less prose; or
* exempt regenerated blocks from the staleness check.

Owner call which. Until then `check-sidecars` will keep flagging it on any
branch that touches the note.

## 2. canonical-mass status guard: false positive

    computations/binding_hbarq_rung_forward_test.py:30
    mass: m_p/(m_e·Vol(𝓑₃)) = ρ_p/ℏ_q² ≈ 258  (ρ_p = linking_weight ≈ 2.53, O(1))

The guard looks for a **deprecated absolute-mass status figure** (966 / 406 /
2.89 % / −57 %). This line cites none of them: it is a *ratio* inside an
explicit ℏ_q→0 **scaling** argument ("the mass multiplier is O(1/ℏ_q²) while
the binding multiplier is O(1)"), not a claim about `m_p`'s live accuracy. The
guard is matching the `m_p/(m_e·Vol(𝓑₃))` shape.

Per the guard's own message this wants an `ALLOWLIST_SUBSTR` entry. Left alone
on #5538: unrelated domain (mass/binding vs Specht/RSK), someone else's file,
and a one-line allowlist edit belongs with whoever owns that guard's tuning.
