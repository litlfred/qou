`content/quantum-observable-universe/lean/QOU/IwahoriHecke/Quotient.lean`.

**Header (lines ~24-46) claims:**
- the ideal is "generated by Hecke **+ braid** relations", listing the alternating-product
  braid generator explicitly with `m_{st}` factors;
- `T : S → IwahoriHeckeQuot` "satisfies the Hecke **+ braid** relations definitionally".

**The code says otherwise:**

    def heckeQuadraticGenerators : Set (FreeAlgebra R S) :=
      { heckeQuadraticRelation R q S s | s : S }

    def heckeIdeal : Ideal (FreeAlgebra R S) :=
      Ideal.span (heckeQuadraticGenerators R q S)

No braid generator appears. The **per-def docstring on `heckeIdeal` is honest** and states the
restriction ("Sprint 2 scope: we include only the Hecke quadratic relations here"), and
`Defn.lean`'s caveat agrees. So the defect is confined to the module header contradicting the
body of its own file.

**Why it matters beyond tidiness.** A reader who takes the header at face value concludes the
corpus has H_n(q). It does not — the quadratic-only quotient is a strictly larger algebra, and
anything asserting the braid relations hold in it would be false. This is what sent this
session checking; a reader with less reason to be suspicious would not have.

Fix: correct the header to match `heckeIdeal`'s own docstring, or land the braid generators
(that is `qou-phir`, not this bean). **The doc fix should not wait on the code fix** — an
inaccurate header is worse than an acknowledged gap.
