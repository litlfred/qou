## 2026-08-30 (later) — spanning + independence both land; the wall is Matsumoto

Added on the same branch, all sorry-free, `lean`-direct exit 0, axioms clean:

* `TwRep.lean` — `toEnd : H_n(q) →ₐ[K] Module.End K (S_{n+1} →₀ K)`, and
  `orbitMap_surjective`: the module is **cyclic**, generated by `T_1`.
* `TwSpanning.lean` — `single_mem_of_closed`, `eq_top_of_singles`. No type-A
  specialisation needed; Mathlib's right descents are exactly the induction.
* `TwIndependent.lean` — `linearIndependent_Tw`: **the `T_w` are linearly
  independent**, so `dim_K H_n(q) ≥ (n+1)!`. Plus `basisTw`, conditional.

### The move that got independence without Matsumoto

`T_w` is built from *some* reduced word (`Classical.choose`). That is a priori
not well-defined — ruling it out **is** Matsumoto. But `applyWord_single` shows
that along **any** reduced word the operators merely walk the basis, so
whichever word was chosen, `orbitMap (T_w) = single w 1`. Distinct basis
vectors ⇒ independent. Well-definedness is never used.

### The remaining gap, stated exactly

`orbitMap` is surjective. So the full basis theorem is **exactly** injectivity
of `orbitMap`, equivalently `dim_K H_n(q) ≤ (n+1)!`, equivalently that the
`T_w` also span. That is where Matsumoto is genuinely needed: two reduced words
for the same `w` give the same element of `H` **iff** they are connected by
braid moves (invariance under a braid move is immediate from `σ_braid` /
`σ_commute`; the combinatorial statement that reduced words are braid-connected
is Matsumoto). `basisTw` carries that hypothesis explicitly and its docstring
says it is not established.

### Two routes to close it, neither started

1. **Prove Matsumoto** (Mathlib TODO, `Coxeter/Basic.lean:78`). Needs the
   strong exchange property first; Mathlib's `Coxeter/Inversion.lean` has the
   ingredients (`wordProd_mul_getD_rightInvSeq`, `IsReduced.nodup_rightInvSeq`)
   but not the property. Upstreamable; a multi-session piece.
2. **Type-A tower spanning.** Span `H_{n+1}` over `H_n` by the `n+1` staircase
   elements `1, σ_n, σ_n σ_{n-1}, …` and induct — the Hecke analogue of the
   `InCosets` / `card_An_le` argument already in `SymmetricCoxeter.lean`.
   Avoids Matsumoto entirely, but is type-A only and not upstreamable as such.


## 2026-08-30 (route 2 started) — the tower's algebraic ingredients

Proceeding with the type-A tower spanning route (the Matsumoto-free one), since
it was the recommendation and is reversible. Landed, all sorry-free:

* `HeckeTower.lean` — `incl : H_n(q) →ₐ[K] H_{n+1}(q)`, `incl_σ`.
* `HeckeStaircase.lean` — an ℕ-indexed generator layer `gen` (so every side
  condition is `omega`-shaped, not `Fin`-shaped) with `gen_sq` / `gen_braid` /
  `gen_comm`; the runs `stair k = σ_n σ_{n-1} ⋯ σ_{n-k+1}`; and the three
  relations the closure argument needs:
  - `stair_comm` — a generator strictly below the run commutes past it;
  - `stair_fold` — `c_{k+1} σ_{n-k} = (q−1)·c_{k+1} + q·c_k`, the **only**
    place a coefficient appears in the whole argument;
  - `stair_push` — `c_k σ_i = σ_{i−1} c_k` above the foot;
  plus `stair_push_full` and `gen_mem_inclRange`.

With `c_k σ_{n-k} = c_{k+1}` (definitional) those are the four closure cases.

### One defect found and fixed before it cost anything

`stair_push` first shipped with hypothesis `n − k + 1 < i`. The foot of `c_k` is
`σ_{n+1−k}`, and the two agree for `k ≤ n` but differ at the **full run**
`k = n+1`, where truncated subtraction turns `n − (n+1) + 1` into `1` while the
real foot is `σ_0`. So it silently excluded `i = 1` at `k = n+1` — a case the
closure needs and which is true (`n = 1`: `c₂σ₁ = σ₁σ₀σ₁ = σ₀σ₁σ₀ = σ₀c₂`).
Hypothesis weakened to `n + 1 − k < i` with `hk : k ≤ n + 1` added so the
induction step gets `k ≤ n` and truncation cannot bite again.

### Still to build

1. The submodule `M = Σ_{k≤n+1} (incl range) · c_k`, and `M · σ_i ⊆ M` from the
   four cases above.
2. `M = ⊤`, via `1 ∈ M` plus the span of generator-products being everything
   (`RingQuot.mkAlgHom` surjective + `FreeAlgebra.adjoin_range_ι` +
   `Algebra.adjoin_eq_span`).
3. The induction on `n`: `dim_K H_{n+1} ≤ (n+2)·dim_K H_n ≤ (n+2)!`.
4. Over a **field**: with `linearIndependent_Tw` giving `≥`, conclude `orbitMap`
   injective and make `basisTw` unconditional. Note this last step wants
   `[Field K]`; `basisTw` as stated is over any `CommRing`.


## 2026-08-30 — CLOSED over a field: the `T_w` ARE a basis, and Matsumoto is never used

`QOU/Hecke/TwBasisField.lean`:

```lean
theorem finrank_eq_factorial : Module.finrank K (IwahoriHecke K q n) = (n+1)!
theorem orbitMap_injective   : Function.Injective (orbitMap K q n)
noncomputable def basisTwOfField :
    Module.Basis (Equiv.Perm (Fin (n+1))) K (IwahoriHecke K q n)
@[simp] theorem coe_basisTwOfField : ⇑(basisTwOfField K q n) = Tw K q n
```

The two halves meet: `exists_spanning_finset` gives `≤ (n+1)!`,
`orbitMap_surjective` gives `≥ (n+1)!`, and a surjection between spaces of equal
finite dimension is injective — exactly the hypothesis `basisTw` was carrying.

**Matsumoto is never used.** `T_w` is the product along *some* reduced word;
well-definedness is never needed, because along any reduced word the operators
merely walk the basis, so `orbitMap (T_w) = single w 1` whichever word was
chosen. Mathlib lists Matsumoto as an open TODO (`Coxeter/Basic.lean:78`).

**The field is used in exactly one file.** Everything upstream — the Coxeter
bridge, the `Rs` relations, the representation, the spanning bound, the
independence — holds over an arbitrary commutative ring. If the basis is wanted
over `ℤ[q,q⁻¹]`, `TwBasisField.lean` is the only file to redo.

Whole 14-file arc: `lean`-direct exit 0, no warnings, `#print axioms` clean on
every declaration, and greps clean for `sorry` / `native_decide` / `axiom` /
`: True` / `:= trivial`.
