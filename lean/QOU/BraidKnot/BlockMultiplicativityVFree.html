          class QOU.BraidKnot.BlockMultiplicativityVFree (R : Type u_1) [CommSemiring R] :
          Type u_1

          The block-multiplicativity conjecture as a Lean class.

          Class fields:

          • v_p, v_n: the block factors (proton, neutron) at the operative q.
          • q_schur_duality_holds_at: predicate naming the q values where the conjectural q-Schur duality identity is established.
          • q_schur_duality_classical: discharges the q = 1 case (provable from Plancherel duality + symmetric-group Specht-module branching).

          Downstream theorems consume the class via [Instance] per AGENTS.md §3b-cond.

          • v_p : R
          • v_n : R
          • q_schur_duality_holds_at : R → Prop
          • q_schur_duality_classical : q_schur_duality_holds_at 1

            def QOU.BraidKnot.blockMultiplicativityVFree_unitFactors (R : Type u_1) [CommSemiring R] :
            BlockMultiplicativityVFree R

            Unit-factor model with the predicate read as its own witness. The block factors are both 1, and — the part worth reading carefully — q_schur_duality_holds_at is defined to be fun q => q = 1. So the conjectural field q_schur_duality_classical : q_schur_duality_holds_at 1 unfolds to 1 = 1 and closes by rfl. Nothing about q-Schur duality or Plancherel duality is encoded; the class field is satisfied by choosing the predicate to be the equation the field asserts.

            That the reduction at q = 1 is Plancherel duality for symmetric groups, provable via Specht-module branching once Mathlib's API lands, remains true and remains unformalised.

            A def, not an instance, since 2026-08-24, and given a name: it was anonymous, so resolution supplied it for every CommSemiring under the generated name instBlockMultiplicativityVFree, and t1_free_eq_block_product below — the module's one conditional result — took [h : BlockMultiplicativityVFree R] that no caller had to satisfy.

            Callers name it: letI := blockMultiplicativityVFree_unitFactors R.
