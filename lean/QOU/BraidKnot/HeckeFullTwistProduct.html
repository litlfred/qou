    ∏Lᵢ = Δ² for every n #

    HeckeJucysMurphyElements proved the twist identity at n = 2 and n = 3 by writing both sides out and applying one braid move. That does not generalise: at n = 4 the word has 12 letters and the number of braid moves grows. This file proves it for all n.

    What is being proved, and what commutativity does not give #

    jmRaw_comm makes the product L₀L₁⋯Lₙ order-independent. That is a different statement from identifying it with the full twist, and it is not used here — this file is pure braid-group combinatorics and touches the Hecke relation nowhere. (Contrast sigma_comm_transp_pair, where the Hecke relation was essential.)

    The shape of the argument #

    Two words, both built only from the generators:

    • delta k = σ₀σ₁⋯σ_{k−1} — the ascending run. Δ² = (delta n)^{n+1} is the full twist of B_{n+1}.
    • run b k = σ_{b+k−1}⋯σ_b — a descending run with bottom b.

    The JM element factors as Lₖ = run 0 k · delta k (jmRaw_eq_run_mul_delta), which is just its own recursion read as a word. Everything then rests on one identity:

    (delta (b+k) · σ_{b+k})^{k+1} = (delta (b+k))^{k+1} · run b (k+1)          `delta_pow_run`

    At b = 0 this reads (delta (n+1))^{n+1} = (delta n)^{n+1} · run 0 (n+1), and multiplying on the right by delta (n+1) turns the right-hand side into (delta n)^{n+1} · L_{n+1} and the left into (delta (n+1))^{n+2} — which is the induction step for the twist identity.

    The free bottom index b is what makes the induction go through: the step consumes the inductive hypothesis at b+1, not at b, so a version stated only at b = 0 would not close.

    The one place a braid move happens #

    run_push — the statement that a descending run can be pushed through delta, at the cost of turning the trailing σ_{b+j} into a σ_b. Its inductive step reduces to

    σ_{m+1} σ_m σ_{m+1} = σ_m σ_{m+1} σ_m

    with everything else moved aside by far-commutation. Every other lemma here is bookkeeping.

        For any r commuting with σ_{m+1}, and any b < m:

        m = b + j → run H (b + 1) j * delta H m * HeckeGenerators.σ q m = delta H m * run H (b + 1) j * HeckeGenerators.σ q b

        The push law — the only place a braid move happens in this file.

        run (b+1) j · delta m · σ_m  =  delta m · run (b+1) j · σ_b        (m = b + j)

        A descending run can be carried through delta; the price is that the trailing generator drops from σ_m all the way to σ_b. That drop is exactly what turns the ascending-run power into a JM element in delta_pow_run.

        The index m is carried as a variable with m = b + j as a hypothesis rather than written as b + j inline: the induction re-associates the sum at every step, and a syntactic b + j would force a rewrite before each use.
