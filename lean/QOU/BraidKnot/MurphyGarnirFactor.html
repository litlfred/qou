    3.13's factorisation, lifted to the Hecke algebra #

    Mathas' Lemma 3.13 says a row-standard non-standard tableau t factors as t = g · w through a Garnir tableau g with ℓ(d(t)) = ℓ(d(g)) + ℓ(w). That is a statement about permutations; 3.14's induction consumes a statement about Murphy elements:

    m_{s t}  =  m_{s g} · T_w

    This file is that lift, and it is exactly what length-additivity buys. T is not a homomorphism from S_n — T_u · T_v is a q-combination in general — but on a length-additive factorisation it is, which is TwBasis.Tw_mul_Tw.

    The handedness, for the fourth time on this arc #

    Tw_mul_Tw reads T_v · T_w = T_{w·v} — the flipped order forced by orbitMap, not a typo (see QOU/Hecke/TwMul.lean). So the permutation factorisation d(t) = w · d(g) lifts to the algebra factorisation

    T_{d(t)}  =  T_{d(g)} · T_w

    with T_w on the right. That is the side Mathas needs — m_{st} = T*_{d(s)} · x_λ · T_{d(t)} has T_{d(t)} rightmost, so the Garnir factor T_{d(g)} ends up adjacent to x_λ and T_w is peeled off outside. Had the convention been the unflipped one the same lemma would have produced T_w · T_{d(g)} and stranded T_w in the middle, where it is useless. Worth stating because the three earlier instances of this trap (sortPerm's orientation, IsDistinguishedL, and T_w⁻¹'s triangularity against w⁻¹) were each found only after something had been built the wrong way round.

    Two reference tableaux, and the gap that leaves — read this before using §4 #

    d(t) is "the permutation carrying the reference tableau to t", and this corpus has two reference tableaux, in two different files, both called dOf:

    reference file
    TableauPerm.dOf row-superstandard t^λ — Mathas' QOU/BraidKnot/TableauPerm.lean
    HeckeMurphyYoung.dOf column-superstandard QOU/BraidKnot/HeckeMurphyYoung.lean

    The whole Garnir chain (GarnirTableau, GarnirDescentAdditive, DescentNodeExists, length_dOf_smul_eq_add_iff) is built on the row one; murphyM is built on the column one. They differ by a fixed permutation on the right — writing c for colSuperstandard ≫ (t^λ)⁻¹,

    HeckeMurphyYoung.dOf t  =  TableauPerm.dOf t * c

    so the factorisation dOf (w • g) = w * dOf g holds for both (it is insensitive to the reference — §1 proves it for the column one, TableauPerm.dOf_smul for the row one), while length additivity does not transfer: ℓ(x) and ℓ(x · c) are unrelated, and length_mul_eq_add_iff turns the hypothesis into an inversion-set containment that right-multiplication by c does not preserve.

    Consequence, stated plainly: §3's Garnir corollary is proved for the row-referenced T_{d(t)}, which is Mathas'; §4's murphyM_smul is proved for murphyM as it is currently defined, i.e. column-referenced, and takes its length hypothesis as given. The two are not composed here, and composing them is not a rewrite. Do not write a corollary chaining §3 into §4; it would be false as an inference even though both halves are true.

    RESOLVED next door — QOU/BraidKnot/MurphyRefTab.lean. At the row instance the length hypothesis of §4 is what a Garnir descent node supplies, so §3 and §4 meet: MurphyRefTab.exists_garnir_murphyMRow_factor, sorry-free.

    The prohibition in this paragraph still stands for murphyM itself — it is about the column-referenced element, and that inference is still invalid.

    And the cheap way out is REFUTED — measured, not assumed #

    There were two ways to close it: restate murphyM over refTab (a definitional change to merged code), or re-prove the Garnir length additivity against the column reference. The second is the cheap one if it is true, and it is a factual question about small symmetric groups, so it was measured before either was attempted (murphy_reference_tableau_additivity_probe.py, exact integer arithmetic, four self-checks before any verdict):

    n row-standard non-standard t row reference column reference
    3 6 6/6 6/6
    4 37 37/37 30/37
    5 220 220/220 138/220
    6 1526 1526/1526 797/1526

    Smallest counterexample: λ = (2,1,1), t = ((1,3),(4),(2)) — its one descent node gives ℓ(d_col(t)) = 2 against ℓ(d_col(g)) + ℓ(w) = 3 + 1. The failure rate grows with n (0 %, 19 %, 37 %, 48 %), so this is not a small-n artifact.

    So option 2 is false and option 1 is forced — and option 1 is now taken, in MurphyRefTab.lean (see the note above). Length additivity at a Garnir descent node is a property of the row-superstandard reference, not a fact about Garnir tableaux that happens to be recorded there.

    This also corrects murphyM's own docstring, which calls the reference "a red herring: colSuperstandard is as good as Murphy's row-superstandard t^λ — both are full rank". That was a rank measurement and remains true as one. It does not generalise: here is a property where the reference is decisive.

    What this does NOT prove #

    3.14 itself. This supplies one rewriting step of its induction — the step that turns a non-standard t into a Garnir g plus a T_w factor. What remains is that the resulting terms drop in MurphyInductionMeasure.murphyLex, which needs 3.12's algebra half, which needs 3.9. MurphyInductionMeasure supplies the well-founded measure; nothing here touches the mathematics of the descent.

    2. The lift: a length-additive tableau factorisation becomes a T-basis one #

    3. The Garnir corollary, in Mathas' reference #

    DescentNodeExists.exists_garnir_length_additive gives the inversion-set containment; length_dOf_smul_eq_add_iff turns it into length additivity; §2 turns that into the T-basis factorisation. The w is recovered from d being a bijection.

    Note the shape of the conclusion: T_{d(t)} factors through the Garnir tableau, with the residual T_w on the right. That is the rewriting step 3.14's induction performs.

    4. The Murphy element itself #

    With murphyM as currently defined — column-superstandard reference — the factorisation of T_{d(t)} passes straight through to m_{st}, because T_{d(t)} is the rightmost factor.

    Read the scope note in the module docstring before chaining this to §3: the length hypothesis here is about the column-referenced d, and the Garnir result of §3 supplies it for the row-referenced one. They are different hypotheses.

    source
    theorem QOU.BraidKnot.MurphyGarnirFactor.murphyM_smul {μ : YoungDiagram} {n : ℕ} (K : Type u_1) [Field K] (q : K) (hn : Specht.nOf μ = n + 1) (s g : Specht.Tableau μ) (w : Equiv.Perm (Fin (Specht.nOf μ))) [DecidablePred fun (x : Equiv.Perm (Fin (n + 1))) => x ∈ HeckeMurphyYoung.youngSubgroup n hn (ColSuperstandardTableau.colSuperstandard μ)] (hlen : (Hecke.SymmetricCoxeter.permCoxeterSystem n).length (HeckeMurphyYoung.dAt n hn (w • g)) = (Hecke.SymmetricCoxeter.permCoxeterSystem n).length ((finCongr hn).permCongrHom w) + (Hecke.SymmetricCoxeter.permCoxeterSystem n).length (HeckeMurphyYoung.dAt n hn g)) :
    HeckeMurphyYoung.murphyM K q n hn s (w • g) = HeckeMurphyYoung.murphyM K q n hn s g * Hecke.TwBasis.Tw K q n ((finCongr hn).permCongrHom w)

    m_{s, w • g} = m_{s, g} · T_w on a length-additive factorisation.

    This is the Murphy-element form of Tw_dAt_smul, and the step 3.14's induction rewrites with. Nothing is assumed about g being Garnir — the lemma is exactly as strong as its length hypothesis.
