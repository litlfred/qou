    QOU.BraidKnot.SpechtStandardBasisCore — brick-4 definitions + the order-agnostic core #

    Definitions-and-lower-machinery half of brick 4's standard-basis theorem for Specht modules (dim_k S^μ = #SYT(μ), Sagan, The Symmetric Group, Thm 2.5.2).

    This module holds all the brick-4 objects and every lemma that does not itself depend on the dominance/triangular core — the SYT→tableau conversion, the standard polytabloids, the abstract Triangular lever, the corestriction reduction, and the spanning half (with its single honest straightening stub).

    It sits below the two independence cores (SpechtDominanceCore, SpechtTriangularCore), which import it read-only. The triangular-dependent capstone declarations (standardPolytabloid_triangular — now proved by consuming SpechtTriangularCore.standardPolytabloid_triangular' — plus standardPolytabloid_linearIndependent, standardBasis, specht_finrank_eq_numSYT) live above those cores, in QOU.BraidKnot.SpechtStandardBasis.

    Everything here is declared in the QOU.BraidKnot.SpechtStandardBasis namespace (unchanged), so downstream references (SpechtStandardBasis.sytToTableau, .cellLabel, .standardPolytabloid, .leadTab, .Triangular, .linearIndependent_corestrict_iff, .standardPolytabloid_span, …) resolve exactly as before — SpechtStandardBasis re-exports this file by importing it.

    So the opaque dimension identity dim = numSYT becomes a clean map: "it is a basis question — linear independence + spanning, both classically cited, everything else machine-checked."

    1. SYT → general tableau conversion (sorry-free) #

    A standard Young tableau T assigns to each cell (i, j) ∈ μ a label T.entry i j < μ.card, injectively (T.inj_on). Reading this off as a map μ.cells → Fin (μ.card) gives an injection between two finite types of equal cardinality (Fintype.card μ.cells = μ.cells.card = μ.card), hence a bijection. Inverting it yields the general (bijective) tableau Fin (nOf μ) ≃ μ.cells that brick 2 consumes.

            2a. Row/column-descent existence (SYT recognition, sorry-free) #

            The first layer of the Garnir core straightening_step_colMax: a polytabloid that is not a standard polytabloid comes from a tableau with a descent — either a row descent (a right-neighbour label ≤ its left) or a column descent (a lower-neighbour label ≤ its upper).                 3. The two genuine content obligations #

                The linear-independence half (§3a) is reduced, sorry-free, to a single combinatorial core (standardPolytabloid_triangular) via a locally-proved triangular-independence lever; the spanning half (§3b) remains one honest stub.

                3a. Linear independence — reduced to Sagan's dominance lemma #

                The classical independence argument is unitriangularity in the dominance order: e_T = ±{T} + (dominated terms), so the standard polytabloids form a triangular family over the tabloid basis and are therefore independent. The "triangular ⇒ independent" lever is absent from the pinned Mathlib (its only such machinery is Gram–Schmidt-specific, requiring an inner-product space), so we supply it locally, sorry-free, and reduce the obligation to exactly Sagan's dominance lemma.
