    QOU.BraidKnot.ColSuperstandardTableau — the column-superstandard tableau #

    Constructs the column-superstandard tableau of a Young diagram: the labelling that fills cells column by column, top to bottom, left to right. This is the tableau whose polytabloid is the Okounkov–Vershik base seminormal vector (JucysMurphy.seminormalVector_base_exists, bean sv8b).

    Before this file the tableau did not exist anywhere in the corpus. Note the row- superstandard tableau that does exist (SytRowSuperstandard) is not the right object: its polytabloid is not a JM eigenvector, so building toward it would be proving a false statement (audit 2026-07-19-ov-base-vector-column-superstandard-verification.md).

    The construction #

    Specht.Tableau μ is definitionally Fin (nOf μ) ≃ μ.cells, and nOf μ = μ.cells.card by rfl. So the column-superstandard tableau is not a hand-rolled enumeration — it is the order isomorphism Finset.orderIsoOfFin for the column-then-row lexicographic order on cells.

    Why the order lives on ℕ ×ₗ ℕ and not on ℕ × ℕ #

    The obvious route — declare LinearOrder (ℕ × ℕ) by column-then-row and apply orderIsoOfFin to μ.cells directly — does not work, and fails in a way that looks like it should. ℕ × ℕ already carries Mathlib's componentwise order Prod.instLE_mathlib, so a competing LinearOrder instance forms a diamond: the bare definition elaborates, but every declaration that annotates the type resolves LE to the ambient componentwise instance and mismatches —

    has type      @OrderIso … (@Subtype.instLE _ instDistribLatticeOfLinearOrder.…toLE _)
but expected  @OrderIso … (@Subtype.instLE _ Prod.instLE_mathlib _)

    — and every order lemma below states the order, so all of them would hit it. It is an instance-level mismatch, not a syntactic one; show/unfold do not fix it.

    Instead we map the cells into Mathlib's existing lex synonym ℕ ×ₗ ℕ (whose LinearOrder is the intended instance, no diamond) via swapLex, take the order isomorphism there, and transport back. ℕ × ℕ's Mathlib order is left untouched, so nothing else in the tree that reasons about cells is disturbed.

    -- Ref: [vershik-kerov1977] Vershik–Kerov, Young's seminormal form -- Ref: [sagan2001] Sagan, The Symmetric Group §2.5–§3.1

              The same-column count — the first half of the eigen-equation #

              OVBaseSeminormalVector.jm_polytabloid_split writes the JM action on e_t as

              X_s · e_t = (same-column count) · (−e_t) + (off-column Garnir sum),

              where the same-column count is #{j < s : (j s) ∈ colStab t}. For the column-superstandard tableau that count is exactly the row index of s's cell, which is where the −i of content (i,j) = j − i comes from.

              theorem QOU.BraidKnot.ColSuperstandardTableau.sameColumn_count (μ : YoungDiagram) (s : Fin (Specht.nOf μ)) :
              {j : Fin (Specht.nOf μ) | ↑j < ↑s ∧ Equiv.swap j s ∈ Specht.colStab (colSuperstandard μ)}.card = (↑((colSuperstandard μ) s)).1

              The same-column count is the row index. For the column-superstandard tableau, #{j < s : (j s) ∈ colStab} equals the row of s's cell.

              The bijection sends j to its row. It lands in range (row s) by sameColumn_filter_eq; it is injective because a label is determined by its cell and the column is pinned; and it is surjective because a Young diagram is down-closed in columns (YoungDiagram.up_left_mem), so every row below s's in the same column is occupied.
