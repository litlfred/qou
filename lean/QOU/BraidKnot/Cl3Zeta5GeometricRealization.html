    QOU.BraidKnot.Cl3Zeta5GeometricRealization — dependent conjectural class (§3b), witness-anchored #

    §3b class axiomatisation for content block conj:cl3-zeta5-geometric-realization: Geometric realisation of the depth-3 Bring trilog $\mathrm{Cl}_3(2\pi/5) = \mathrm{Re}\,\mathrm{Li}_3(\zeta_5)$.

    Dependent conjecture (§3b-tax). The class takes [W : BringTrilogDepth3Witness] — the geometric-realisation conjecture presupposes the depth-3 witness identification (which archimedean values are to be realised), so the dependency is threaded through the TYPE (the derived conjecture_graph edge), not restated as prose. The two candidate invariants must realise the witnessed values W.cl3_2pi5 / W.cl3_4pi5 — not merely an unconstrained pair with the right sum. The pair identity $\mathrm{Cl}_3(2\pi/5) + \mathrm{Cl}_3(4\pi/5) = -(12/25)\,\zeta(3)$ (half the full 4-term orbit sum — each Clausen value appears twice in the $k = 1..4$ orbit, Cl₃ even and $2\pi$-periodic) is DERIVED sorry-free (realize_pair_sum) from the witness's pair_sum_eq.

    History (bean 5e79 / T1, incl. the factor-2 anchor fix): full record in docs/coordination/s5-so3-keystone.md.

    Residual Mathlib gap (flagged, not faked). No Clausen Cl₃ evaluation exists in Mathlib or Infra.Polylogarithm (only the parametric predicted closed form cl3OrbitSumPredicted), so the witnessed components live as class fields of BringTrilogDepth3Witness, not closed numbers. The candidate-2 (torus-knot CS) sub-case was numerically refuted (PSLQ — CS of Bring-natural torus knots is rational), so the conjecture is the existence of some geometric invariant pair realising the witnessed values.
