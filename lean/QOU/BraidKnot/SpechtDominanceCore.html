    QOU.BraidKnot.SpechtDominanceCore — an independent reduction of brick-4's dominance core #

    QOU.BraidKnot.SpechtTriangularCore.standardPolytabloid_dominance_order is the single remaining sorry of brick 4 (the standard-basis theorem for Specht modules). It packages Sagan, The Symmetric Group, Thm 2.5.2's dominance content as:

    ∃ _ : LinearOrder (Tabloid μ),
  ∀ T : StandardYoungTableau μ, ∀ a ∈ (standardPolytabloid T).support, a ≤ leadTab T

    This module is an independent reduction of that same statement (it imports SpechtStandardBasis read-only and does not import or modify SpechtTriangularCore). Where SpechtTriangularCore reduced the triangular bundle to this LinearOrder-and-support existential, this file peels the LinearOrder construction and the Finsupp/support plumbing off it too, constructs the dominance partial order concretely, and isolates the irreducible combinatorial heart as a single, LinearOrder-free, support-free, relation-level core:

    dominance_colStab_lemma — under the concrete dominance order domRel (a proved partial order on Tabloid μ), for a standard tableau T every column permutation weakly decreases the tabloid (π ∈ C_t, T standard ⟹ domRel {π•t} {t}). This is Sagan's §2.4 dominance lemma. (Restricted to standard T: over all tableaux it contradicts antisymmetry — see the lemma's doc.)

    The dominance order itself is no longer opaque: dominance_relation_exists is now sorry-free, built from the explicit partial-sum order domRel whose three order axioms + decidability are all discharged. Everything else is sorry-free:

    • Layer 1 (support_subset_colStab_image) — supp(e_T) ⊆ {{π•t} : π ∈ C_t}, pure Finsupp plumbing.
    • The Szpilrajn-for-Fintypes lever (exists_linearOrder_of_partialOrder) — the pinned Mathlib has no linear-extension-of-a-partial-order lemma (Szpilrajn/LinearExtension are absent, verified against the cached oleans), so we supply it locally via the down-set-cardinality + Fintype-index lexicographic trick. A natural Mathlib-upstream candidate. From a finite partial order it produces a LinearOrder whose ≤ dominates the partial relation.
    • The tabloid↔row-pattern bridge (tabloidRowPattern, tabloidRowPattern_injective) — a tabloid is its row pattern (rowEquiv_iff), so Tabloid μ ↪ (Fin n → ℕ). Pins down what the dominance order's antisymmetry concretely asserts.
    • The concrete dominance order (domCount, domRel, domRel_refl, domRel_trans, domRel_antisymm, domRel_decidable) — the dominance count domCount f i m = #{l : l<m ∧ f l ≤ i}; the order domRel a b ≡ ∀ i m, domCount(a) ≤ domCount(b); reflexivity/transitivity are pointwise, antisymmetry is domCount_inj (the marginal domCount f i (l+1) − domCount f i l = [f l ≤ i] recovers the row pattern) composed with tabloidRowPattern_injective, and decidability is the clamp domCount_clamp (saturation past n, via the cell row-index bound rowPattern t l < n) reducing ∀ i m : ℕ to a bounded quantifier. All sorry-free.
    • The assembly (dominance_relation_exists) — packages domRel + the four sorry-free order/decidability proofs + the one cited dom_colStab field into DominanceData. sorry-free (its only conjectural ingredient is the core lemma below, passed as the dom_colStab field).
    • Layers 2–3 wiring (exists_order_colStab_decreasing, standardPolytabloid_dominance_order') — the lever turns domRel into the required LinearOrder; Layer 1 + the colStab-decrease field supply the support bound. The verbatim brick-4 target standardPolytabloid_dominance_order' follows sorry-free modulo the one core.

    The Szpilrajn-for-Fintypes lever (sorry-free) #

    The pinned Mathlib has no linear-extension-of-a-partial-order lemma. We supply it for Fintypes: from a reflexive/transitive/antisymmetric relation r, the lexicographic key a ↦ (#{b | r b a}, idx a) into ℕ ×ₗ ℕ (down-set cardinality, tie-broken by the Fintype index) is injective and turns r into a LinearOrder whose ≤ dominates r: if r a b then #{·|r · a} ≤ #{·|r · b}, strictly unless r b a too (whence a = b by antisymmetry).

      The dominance order on tabloids via partial-sum counts (sorry-free) #

      The dominance partial order is built concretely from the dominance count domCount f i m = #{l : (l:ℕ) < m ∧ f l ≤ i} of a row pattern f — "among the m smallest labels, how many lie in rows ≤ i". The relation domRel a b :≡ ∀ i m, domCount (rowPat a) i m ≤ domCount (rowPat b) i m is then a genuine partial order, all three order axioms discharged sorry-free:

      • reflexivity / transitivity are pointwise le_refl / le_trans.
      • antisymmetry is the substantive sorry-free fact: equal counts everywhere force equal row patterns (domCount_inj, via the marginal domCount f i (l+1) − domCount f i l = [f l ≤ i]), whence equal tabloids (tabloidRowPattern_injective).
      • decidability comes from clamping both indices into [0, n] (the counts saturate past n, using the row-index bound rowPattern t l < n), reducing the ∀ i m : ℕ to a decidable bounded quantifier.

      All of this is ℕ-valued (§7c-clean: no ℝ, no ordering on q).

            Standardness core: within a column, the row is strictly monotone in the label #

            The single place where standardness (col_strict) enters. For a standard tableau T with filling t = sytToTableau T, two labels in the same column have their rows ordered the same way as the labels: smaller label ⟹ higher up. This makes the "row ≤ i" set within any column a down-set of that column (under the label order), which is the combinatorial fact the dominance lemma rests on.

Summed over columns this is the whole inequality.

            Proof. Reindex the π-twisted count by π (card_filter_perm), then decompose column-by-column (Finset.card_eq_sum_card_fiberwise keyed by colPattern t).             Why standard T (not all tableaux). The statement is true precisely because T is standard: columns increase downward (col_strict), so each column already holds its smallest label at the top — {t} is the dominance-maximum of its column orbit, and any π ∈ C_t weakly decreases it. Over arbitrary t the claim is false and is even inconsistent with dom_antisymm: applying it at both t and t' = π•t (note colStab t' = colStab t ∋ π⁻¹) forces {π•t} = {t}, i.e. colStab t ⊆ rowStab t; with colStab t ∩ rowStab t = {1} that gives colStab t = {1}, false once μ has a column of length ≥ 2. (n=2 single column: with standard t = id, the swap π moves label 0 down from row 0 to row 1, dropping domCount at (i=0,m=1) from 1 to 0 — {π•t} strictly below {t}, consistent.)
