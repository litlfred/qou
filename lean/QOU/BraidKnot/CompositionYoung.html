    Young subgroups of a composition, and the conjugacy Mathas' Lemma 3.9 opens with #

    Mathas' Lemma 3.9 is the foundation of the Murphy-basis spanning argument (3.9 → 3.12 → 3.13 → 3.14 → 3.20; see 2026-09-04-mathas-murphy-chain-status.md). It is stated for a composition μ — parts not weakly decreasing — and its proof opens:

    "Choose an element d ∈ S_n such that S_ν = d S_μ d⁻¹ and such that t^μ d and t^ν d⁻¹ are both row standard."

    The corpus's Young subgroup (Specht.rowStab) is indexed by a YoungDiagram, so it cannot express S_μ for a composition. This file supplies that, and reduces the conjugacy to two facts neither of which needed writing.

    The two free facts #

    • Mathlib's Composition.index : Fin n → Fin c.length already is the block function — "which part does this label fall in" — so a composition's Young subgroup is the stabiliser of it, with nothing to construct.
    • Mathlib's MulAction.stabilizer_smul_eq_stabilizer_map_conj already is the conjugacy: stabilizer (g • a) = map (conj g) (stabilizer a).

    What is left is the interface between them, which is youngOfComp_conj below: the conjugating d has to carry one block function onto the other up to relabelling the blocks, and relabelling is invisible to a stabiliser (stabilizer_comp_left).

    Note on the action instance #

    QOU.BraidKnot.Specht.instArrowMulAction declares the same σ • f = f ∘ σ⁻¹ action, but specialised to Fin (nOf μ) → ℕ and indexed by a YoungDiagram, so it does not apply here. The instance below is the general one. They should eventually be unified — the specialised one is the odd case — but that is a refactor of Specht.lean and is deliberately not done here; this file does not import Specht.lean, so the two never meet and no instance diamond arises.

      theorem QOU.BraidKnot.CompositionYoung.youngOfComp_conj {n : ℕ} {c c' : Composition n} (d : Equiv.Perm (Fin n)) {π : Fin c'.length → Fin c.length} (hπ : Function.Injective π) (h : d • c.index = π ∘ c'.index) :
      youngOfComp c' = Subgroup.map (MulEquiv.toMonoidHom (MulAut.conj d)) (youngOfComp c)

      The conjugacy criterion of Lemma 3.9.

      If d carries c's block function onto c''s, up to an injective renaming of the blocks, then the two Young subgroups are conjugate by d.

      This is the whole of "choose d such that S_ν = d S_μ d⁻¹" — given the d. Producing the d (the permutation that sorts the parts into decreasing order) is a separate step and is not done here.

      The conjugating d, constructed #

      youngOfComp_conj takes d on trust. Mathas produces it as "the permutation permuting the rows", and Mathlib supplies exactly the decomposition that needs: Composition.blocksFinEquiv : ((i : Fin c.length) × Fin (c.blocksFun i)) ≃ Fin n, whose forward map is c.embedding i j and which therefore satisfies c.index (blocksFinEquiv ⟨i, j⟩) = i.

      So d is a composite of three equivalences — read Fin n in c''s block coordinates, rename the blocks and match their sizes, write it back in c's — and the block-matching property falls out of index_embedding with no combinatorics.

      structure QOU.BraidKnot.CompositionYoung.BlockMatch {n : ℕ} (c c' : Composition n) :
      Type

      A block matching between two compositions of n: a bijection of block indices that preserves part sizes.

      This is the data Mathas' d is built from. It is not automatic — two compositions of the same n need not have the same multiset of parts — so it is a hypothesis, and a reordering of parts is exactly the case that supplies it.

        def QOU.BraidKnot.CompositionYoung.sortPerm {n : ℕ} {c c' : Composition n} (m : BlockMatch c c') :
        Equiv.Perm (Fin n)

        The permutation carrying c''s blocks onto c's, order-preservingly inside each block: read a position in c''s block coordinates, rename the block along the matching, write it back in c's.

        🛑 The direction here is load-bearing, and it is not the one to guess. Either d or d⁻¹ transports the blocks, so the subgroup conjugacy is indifferent to which is named sortPerm; the Hecke side is not. Mathas' d must be minimal-length in its coset — ℓ(v·d) = ℓ(v) + ℓ(d) for v in the Young subgroup, i.e. d ∈ D_μ — because that is what makes T_v T_d = T_{vd} and hence what the intertwining T_d · x_μ = x_ν · T_d runs on.

        Measured exhaustively over every (composition, composition, size-preserving matching) triple for n = 2..6 — 1955 triples, exact integer arithmetic — in sortperm_length_additive_probe.py:

        this orientation           1955 / 1955
its inverse                1433 / 1955   — 522 failures

        The smallest failure needs no machine: c = (1,2), c' = (2,1), π = (1,0) gives the inverse (2,0,1) of length 2, and v = swap(1,2) of length 1 has v·(2,0,1) = (1,0,2) of length 1, against 1 + 2. An earlier version of this file defined sortPerm as that inverse; the probe caught it before anything was built on it.

          Non-vacuity #

          youngOfComp_conj has three hypotheses; a criterion nothing satisfies proves nothing. The identity instance below shows they are simultaneously satisfiable and that the conclusion is the expected one — a genuine two-block worked case would be stronger, and needs the sorting d that the next step supplies.

            A non-identity matching, and a non-identity conjugator #

            BlockMatch.refl and youngOfComp_conj_one only show the hypotheses are satisfiable; both are identity instances, and a criterion that fired only at the identity would be worthless. The composition (2,2) settles it: its two equal parts admit the swap as a block matching, and the conjugator that swap produces is not the identity permutation.

            sortPerm_swap22_ne_one is the load-bearing one — it evaluates the whole blocksFinEquiv composite that sortPerm is built from, so it checks the construction computes to something real rather than merely typechecking.

            decide here is a closed finite computation on Composition 4 and Perm (Fin 4) — the sanctioned case in AGENTS.md, and it is proving a falsifiable inequality rather than masking a goal.
