    The transposition expansion on the bounded presentation #

    Tranche 2 of porting jmRaw_comm (bean qou-t1kv). This is the bound-heavy half: the sum-of-transpositions expansion of the additive Jucys–Murphy family, and the three commutation lemmas that make σ_j commute with A_i.

    The bounds, derived per lemma #

    transpB H l i is a word in σ_l … σ_{i−1}, so it is well-formed for i < n.

    lemma relation used bound
    transpB_self / transpB_succ none —
    addJMB_eq_transpB_sum none —
    sigma_comm_transpB_pair braid j, hecke (j+1), far j m i < n
    sigma_comm_transpB_far far · m m + 1 < n
    sigma_comm_transpB_base braid j, and far via the previous j + 2 < n
    sigma_comm_transpB_disjoint far j m, and the base case i < n
    sigma_comm_transpB_below far j m, far j l i < n

    The expansion A_k = d · Σ_{i<k} T_(i,k) needs no bound at all — it is the two recursions and Finset algebra, with no Hecke, braid or far relation anywhere. That is the same phenomenon as runB_peel_bot in the full-twist port, and it is worth stating: the sum expansion, which is the conceptual heart of the argument, is relation-free. What costs bounds is only the commutation.

    sigma_comm_transpB_far is the one lemma whose bound is on a different index than the statement's i: it commutes σ_m past T_(l,i) for m > i, so it is m, not i, that has to be a generator.

      j + 1 < i → i < n → HeckeGeneratorsBelow.σ q n j * (transpB H j i + transpB H (j + 1) i) = (transpB H j i + transpB H (j + 1) i) * HeckeGeneratorsBelow.σ q n j

      Pair-swap law: for i > j+1, σ_j commutes with T_(j,i) + T_(j+1,i).

      The base case needs the Hecke relation at j+1 as well as the braid relation at j; both are covered by i < n, since the base sits at i = j + 2.
