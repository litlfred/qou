    1. Objects of the framed-oriented-tangle category #

    An object is a finite sequence of oriented framed points on the line. A point carries an orientation Sign (true = +, an outgoing/up strand; false = −, its reverse). Orientation reversal is Boolean negation. The framing is recorded elsewhere (the twist generator); the object records only the boundary sign word, as in Turaev's presentation.

              2. Generating morphisms — the free tangle-diagram datatype #

              TangleMor X Y is the free collection of tangle diagrams from boundary X to boundary Y, generated by the elementary tangles (cup, cap, positive/negative crossing, framing twist) closed under formal identity, vertical composition (comp, stacking) and horizontal composition (tensor, juxtaposition). It is free: no Reidemeister/Turaev relation is imposed, so this is a quiver of generators, not the tangle category (which is this quotiented by those relations — open, §Open).

              source
              inductive QOU.BraidKnot.FramedTangle.TangleMor :
              TangleObject → TangleObject → Type

              The free datatype of tangle diagrams on the oriented-framed generators. Constructors are the generating morphisms plus formal id/comp/tensor; the geometric relations are not imposed (see the file docstring, obligation 2).

              • id (X : TangleObject) : TangleMor X X

                The empty/identity tangle on a boundary X.

              • comp {X Y Z : TangleObject} : TangleMor X Y → TangleMor Y Z → TangleMor X Z

                Vertical composition (stacking one tangle atop another).

              • tensor {X Y X' Y' : TangleObject} : TangleMor X Y → TangleMor X' Y' → TangleMor (X ++ X') (Y ++ Y')

                Horizontal composition (side-by-side juxtaposition); boundaries concatenate.

              • cup (s : Sign) : TangleMor [] [s, s.bar]

                Cup (creation / coevaluation): a ∪ of a strand and its reverse, [] ⟶ [s, s̄].

              • cap (s : Sign) : TangleMor [s, s.bar] []

                Cap (annihilation / evaluation): a ∩, [s, s̄] ⟶ [].

              • braidPos (s t : Sign) : TangleMor [s, t] [t, s]

                Positive crossing (over-braid) of two adjacent strands, [s, t] ⟶ [t, s].

              • braidNeg (s t : Sign) : TangleMor [s, t] [t, s]

                Negative crossing (under-braid), [s, t] ⟶ [t, s]. Inverse of braidPos after the Reidemeister-II relation, which is not imposed on this free datatype.

              • twist (s : Sign) : TangleMor [s] [s]

                Framing twist θ (a +1 curl) on a single strand, [s] ⟶ [s].

              • twistInv (s : Sign) : TangleMor [s] [s]

                Inverse framing twist θ⁻¹ (a −1 curl), [s] ⟶ [s].

                3. The Reshetikhin–Turaev ribbon-functor signature #

                RibbonFunctorData 𝒞 packages the data of the RT functor into a Mathlib braided right-rigid category 𝒞: a coloring object V and a ribbon/balancing twist, carried as data because Mathlib has no ribbon (balanced) typeclass. From this data the canonical images of the generators are defined (below) via the target's coevaluation η_, evaluation ε_, and braiding β_.

                Only the per-generator images are given here. Assembling them into a total, relation-respecting functor TangleMor X Y → (mapObj X ⟶ mapObj Y) is the open work (file docstring, obligations 1–2).
