    Certifying a concave maximum, and what a capped enumeration does not tell you #

    SearchCoercivity made the e_inf search finite. This file is about the two steps that make it decided, and about the one step of the argument that is not a step at all.

    The objective F is concave, so it obeys the supergradient inequality at every point. That alone bounds nothing — the linear term grad F(w) . (u - w) is unbounded above on an unbounded domain — so the search region is confined first, by an independent per-row bound, and the linear term is then maximised over the resulting box. sup_le_of_supergradient is that argument, stated for an arbitrary F, w, gradient g and box: nothing here knows what the REV_n objective is.

    The step that is easy to get wrong, and was #

    Maximising g i * (u i - w i) over u i ∈ [lo i, hi i] is a case split on the sign of g i — at hi i when g i ≥ 0 and at lo i when g i < 0. Charging every coordinate |g i| * (hi i - w i) regardless looks conservative and is not: it is a different quantity, and in the measured case it is larger by a factor of 2.25e11, which turns a certificate with slack 6.4e-12 into one with slack 1.447 — still true, and useless.

    boundary_charge_eq_zero and abs_charge_pos isolate why. At the optimum the constrained coordinates sit ON the lower boundary with strictly negative gradients (correct KKT behaviour, not a convergence failure). For such a coordinate the correct charge g * (lo - w) is exactly zero when w = lo, while |g| * (hi - lo) is strictly positive. The whole factor lives in that one case.

    What a capped enumeration is evidence for #

    Xbot — the bottom edge of the e_inf staircase — is tabulated by enumerating profiles with a cap on their length. A capped maximum is a lower bound on the true one, so observing capped < other says nothing whatever about true ≤ other. capped_lt_not_sufficient is that non-implication, with an explicit witness: cap = 0 ≤ true = 2, cap = 0 < other = 1, and 2 ≤ 1 is false.

    The corpus recorded one observation in favour of Xbot(s) <= Xblock(s) — "the top is higher by 0.01982 at s = 13" — and it is precisely of that shape, with the bottom table's row cap saturated at the point of measurement. Lifting the cap makes the two tables exactly equal there (rev_e_infinity_g1_bottom_edge_cap_probe.py, 5/5). The inequality is neither proved nor refuted by any of it; what the probe removes is the appearance of support.

    Bounding every block length with one certificate #

    The top edge's blocks have every entry ≥ 1, so a row whose tangent slope falls below ln q₀ / 2 contributes a strictly negative cap, the cumulative cap eventually drops below the certified bound, and no longer block can reach it. The bottom edge's class permits zero entries, so its relaxation has u ≥ 0, every row cap is ≥ 0, the cumulative cap is non-decreasing — and that argument has no analogue. Reusing it there would be a false transfer, and the shape of the two classes is the whole of the difference.

    What replaces it is a different move. The bottom edge's per-row slope turns out to be independent of the block length (the block rows above a given row and the undisplaced tail above the block are one sum split at an arbitrary place), so a length-T program is the restriction of a single program to its first T coordinates, and a certificate taken at an ascent point padded with zeros bounds them all — at the cost of whatever the padded coordinates are charged.

    They are not charged zero, and expecting that was the error here. box_charge_eq_zero_of_nonpos says when a padded coordinate costs nothing, and the measurement says the hypothesis fails: in the bottom frame every slope is strictly positive, being ∑_{i odd} gx(b₀ⱼ + i) — the odd gaps the one-body term reaches and the gap-2 ladder does not. So the operative lemma is sum_charge_extend_le, which bounds the padded block rather than deleting it; the charges decay geometrically and the probe carries rows until the marginal one is negligible, then bounds the remainder by its geometric tail instead of dropping it. The zero version is kept because it is the statement one reaches for first, and because its hypothesis — g ≤ 0, not g < 0, since a padded coordinate may have gradient exactly zero and there the if takes the opposite branch — is the part that is easy to get wrong when the situation does permit it.
    box_mul_sub_le the linear term over [lo, hi] is maximised at an endpoint chosen by sign g
    boundary_charge_eq_zero on the lower boundary with g < 0 the correct charge vanishes
    abs_charge_pos the absolute-value charge there does not
    sup_le_of_supergradient confinement + supergradient ⇒ an explicit bound on F
    box_charge_eq_zero_of_nonpos a padded coordinate (g ≤ 0, w = lo) is charged zero in both branches
    sum_charge_extend if every padded coordinate is charged zero the bound is unchanged
    sum_charge_extend_le and when they are not — the bottom edge's case — the bound grows by at most their total
    capped_lt_not_sufficient a capped maximum falling short of a bound proves nothing about the true one

    theorem QOU.BraidKnot.SupergradientCertificate.box_mul_sub_le (g w lo hi x : ℝ) (h1 : lo ≤ x) (h2 : x ≤ hi) :
    g * (x - w) ≤ if 0 ≤ g then g * (hi - w) else g * (lo - w)

    The box maximisation. Over x ∈ [lo, hi], the linear term g * (x - w) is largest at hi when g is non-negative and at lo when it is negative.

    This is the load-bearing case split of the certificate. Both branches are needed: replacing the g < 0 branch by anything that does not evaluate at lo gives a valid but far weaker bound.

    theorem QOU.BraidKnot.SupergradientCertificate.boundary_charge_eq_zero (g lo hi : ℝ) (hg : g < 0) :
    (if 0 ≤ g then g * (hi - lo) else g * (lo - lo)) = 0

    Why the case split is worth 2.25e11. A coordinate pinned to the lower boundary (w = lo) with a strictly negative gradient contributes exactly nothing to the slack.

    theorem QOU.BraidKnot.SupergradientCertificate.abs_charge_pos (g lo hi : ℝ) (hg : g < 0) (h : lo < hi) :
    0 < |g| * (hi - lo)

    The absolute-value charge at the same point is strictly positive — so the two differ by the whole of it, not by a refinement.

    theorem QOU.BraidKnot.SupergradientCertificate.sup_le_of_supergradient {ι : Type u_1} [Fintype ι] (F : (ι → ℝ) → ℝ) (w g lo hi : ι → ℝ) (V : ℝ) (hconc : ∀ (u : ι → ℝ), F u ≤ F w + ∑ i : ι, g i * (u i - w i)) (hbox : ∀ (u : ι → ℝ), V ≤ F u → ∀ (i : ι), lo i ≤ u i ∧ u i ≤ hi i) (u : ι → ℝ) :
    F u ≤ max V (F w + ∑ i : ι, if 0 ≤ g i then g i * (hi i - w i) else g i * (lo i - w i))

    The certificate. If F obeys a supergradient inequality at w, and every u that reaches the incumbent V is confined to the box ∏ [lo i, hi i], then F is bounded above everywhere by an explicit number: the incumbent, or F w plus the box-maximised linear term.

    Neither hypothesis mentions concavity by name — hconc is what concavity supplies, and hbox is what an independent coercivity bound supplies. The conclusion holds at every u, including those outside the box, which is the point: outside it, F u < V.

    theorem QOU.BraidKnot.SupergradientCertificate.box_charge_eq_zero_of_nonpos (g lo hi w : ℝ) (hg : g ≤ 0) (hw : w = lo) :
    (if 0 ≤ g then g * (hi - w) else g * (lo - w)) = 0

    Padding a certificate is free. A coordinate whose gradient is non-positive and whose reference point sits ON the lower box endpoint is charged exactly nothing — in either branch of the sign split, which is why the hypothesis is g ≤ 0 and not g < 0.

    boundary_charge_eq_zero above is the strict case seen at a KKT-active coordinate. This is the one the length argument needs, because a padded coordinate may have gradient exactly 0, and there the if takes the other branch (0 ≤ g) and lands on g * (hi - w) — zero for a different reason.

    theorem QOU.BraidKnot.SupergradientCertificate.sum_charge_extend {ι : Type u_1} {κ : Type u_2} [Fintype ι] [Fintype κ] (g lo hi w : ι ⊕ κ → ℝ) (hz : ∀ (b : κ), (if 0 ≤ g (Sum.inr b) then g (Sum.inr b) * (hi (Sum.inr b) - w (Sum.inr b)) else g (Sum.inr b) * (lo (Sum.inr b) - w (Sum.inr b))) = 0) :
    (∑ x : ι ⊕ κ, if 0 ≤ g x then g x * (hi x - w x) else g x * (lo x - w x)) = ∑ a : ι, if 0 ≤ g (Sum.inl a) then g (Sum.inl a) * (hi (Sum.inl a) - w (Sum.inl a)) else g (Sum.inl a) * (lo (Sum.inl a) - w (Sum.inl a))

    The same bound over a larger index set. Split the coordinates into the ones the ascent point actually uses and the ones it was padded with; if every padded coordinate is charged zero, the certificate's linear term is exactly the one computed over the used coordinates alone.

    This is what turns a certificate at one block length into a certificate at every block length. It is a statement about the sum, and it carries no analytic content — which is the point: the analytic content is that the padded coordinates satisfy box_charge_eq_zero_of_nonpos, and that is checked, not assumed.

    source
    theorem QOU.BraidKnot.SupergradientCertificate.sum_charge_extend_le {ι : Type u_1} {κ : Type u_2} [Fintype ι] [Fintype κ] (g lo hi w : ι ⊕ κ → ℝ) (B : ℝ) (hB : (∑ b : κ, if 0 ≤ g (Sum.inr b) then g (Sum.inr b) * (hi (Sum.inr b) - w (Sum.inr b)) else g (Sum.inr b) * (lo (Sum.inr b) - w (Sum.inr b))) ≤ B) :
    (∑ x : ι ⊕ κ, if 0 ≤ g x then g x * (hi x - w x) else g x * (lo x - w x)) ≤ (∑ a : ι, if 0 ≤ g (Sum.inl a) then g (Sum.inl a) * (hi (Sum.inl a) - w (Sum.inl a)) else g (Sum.inl a) * (lo (Sum.inl a) - w (Sum.inl a))) + B

    The version the measurement actually needs. The padded coordinates are not free, so they are bounded rather than deleted: whatever they are charged in total, the certificate over the larger index set exceeds the one over ι by at most that.

    This is the honest form of sum_charge_extend, and the two differ in exactly the way a geometric tail differs from a vanishing one — which is the whole content of the bottom-edge case, where every slope is strictly positive and only the decay is available.

    theorem QOU.BraidKnot.SupergradientCertificate.capped_lt_not_sufficient :
    ∃ (cap : ℝ) (true_ : ℝ) (other : ℝ), cap ≤ true_ ∧ cap < other ∧ ¬true_ ≤ other

    A capped maximum falling short proves nothing about the true one. cap ≤ true and cap < other are jointly satisfiable with ¬ (true ≤ other), so the inference is invalid.

    This is the shape of the corpus's sole recorded evidence for Xbot(s) ≤ Xblock(s): a bottom table whose enumeration cap was saturated at the measured point.

    theorem QOU.BraidKnot.SupergradientCertificate.gradient_nonpos_of_antitone_tail {J : ℕ} (Γ c : ℕ → ℝ) (lam : ℝ) (hmono : ∀ (i j : ℕ), i ≤ j → Γ j ≤ Γ i) (hc : ∀ (j : ℕ), 0 ≤ c j) (hJ : Γ J ≤ lam) (j : ℕ) :
    J ≤ j → Γ j - c j - lam ≤ 0

    The hypothesis sum_charge_extend assumes, discharged from monotonicity.

    sum_charge_extend is stated over "if every padded coordinate is charged zero", and says in its own docstring that the analytic content is elsewhere: "the padded coordinates satisfy box_charge_eq_zero_of_nonpos, and that is checked, not assumed." This is the lemma that stops it being assumed, for the one reason the bottom-edge frame actually supplies.

    The per-row gradient is Γ j - c j - lam, with Γ the row's tangent slope, c j ≥ 0 the linear wall cost, and lam ≥ 0 the integrality-gap multiplier. Γ is antitone in the row index, so a single row J with Γ J ≤ lam forces the whole tail beyond it non-positive — one inequality covers infinitely many coordinates, which is exactly what a certificate at every block length needs.

    Note c enters only through 0 ≤ c j: subtracting a non-negative cost can only help, so the bound does not depend on the wall's shape.

    theorem QOU.BraidKnot.SupergradientCertificate.padded_tail_charge_eq_zero {J : ℕ} (Γ c lo hi w : ℕ → ℝ) (lam : ℝ) (hmono : ∀ (i j : ℕ), i ≤ j → Γ j ≤ Γ i) (hc : ∀ (j : ℕ), 0 ≤ c j) (hJ : Γ J ≤ lam) (hw : ∀ (j : ℕ), J ≤ j → w j = lo j) (j : ℕ) :
    J ≤ j → (if 0 ≤ Γ j - c j - lam then (Γ j - c j - lam) * (hi j - w j) else (Γ j - c j - lam) * (lo j - w j)) = 0

    The composition: an antitone tail is charged exactly nothing. gradient_nonpos_of_antitone_tail feeds box_charge_eq_zero_of_nonpos directly, so every padded row past J contributes zero to the certificate's linear term — not a bounded amount, zero.

    This is the fact the bottom-edge measurement reports (padded charge 0.0, tail 0.0 [exactly zero (g ≤ 0, lo = w = 0, Γ monotone)]), and it is why sum_charge_extend rather than sum_charge_extend_le is the operative form there.

    theorem QOU.BraidKnot.SupergradientCertificate.antitone_hypothesis_is_necessary :
    ¬∀ (Γ : ℕ → ℝ) (lam : ℝ), Γ 0 ≤ lam → ∀ (j : ℕ), 0 ≤ j → Γ j - lam ≤ 0

    Antitonicity is load-bearing, not decoration. Without it a single row below lam says nothing about the tail: take Γ = (1, 2, 2, …) and lam = 1. Then Γ 0 ≤ lam holds and the row-1 gradient is +1, so the tail is charged a positive amount and the certificate over the padded index set is strictly larger than the one over the used coordinates.

    Stated as a refutation rather than a remark because a hypothesis nobody has shown to bite is indistinguishable from one that does not.
