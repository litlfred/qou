    The left quantum dimension. The mirror of qDimObj: the same coevaluation and evaluation, but crossing the strand with the inverse braiding (β_ Xᘁ X).inv instead of the forward (β_ X Xᘁ).hom. In a general braided rigid category the two traces differ; a category in which they agree for every object is spherical.

      The pivotal structure #

      PivotalStructure used to be declared here, pointwise: a ∀ X, X ≅ Xᘁᘁ plus a naturality field. It has moved to QOU/MathlibExt/PivotalCategory.lean as PivotalCategory, stated the way Mathlib's own "Future work" list asks for it — a natural isomorphism 𝟭 C ≅ ᘁᘁ — with PivotalCategory.ofPointwise and PivotalCategory.pivotor_naturality showing the two presentations carry the same data. That file also supplies the rightDualFunctor / doubleDualFunctor the functorial statement needs, which Mathlib does not have either.

      The pivotal structure now exists — under a ribbon hypothesis. QOU.MathlibExt.pivotalOfRibbon makes every ribbon right-rigid category pivotal, sorry-free: the pivotor is θ ≫ drinfeldIso, its naturality combines BalancedCategory.twist_naturality with drinfeldIso_naturality, and its monoidality is twist_drinfeld_monoidal_tensorDoubleDualIso.

      An earlier revision of this paragraph claimed the stronger thing — that pivotalOfBraided makes every braided right-rigid category pivotal, unconditionally. That is false and the instance has been removed. drinfeldIso is natural but not monoidal, missing by exactly the inverse monodromy (QOU.MathlibExt.rightDualIso_swap_tensor); braiding alone does not give a pivotal structure in the literature's sense, which is the sense Barrett–Westbury needs.

      In practice the hypothesis costs this file nothing: Ribbon.lean makes every symmetric category balanced, so the datum is still supplied for the whole class of categories the keystone cares about rather than for one example.

      That does not discharge hTransport below. The transport identity qDimObj (Xᘁ) = leftQDim X is a statement about the two traces; having the pivotor is a prerequisite for it, not a proof of it. The hypothesis is still carried.

      class QOU.BraidKnot.PivotalSpherical.SphericalStructure (C : Type u_2) [CategoryTheory.Category.{u_3, u_2} C] [CategoryTheory.MonoidalCategory C] [CategoryTheory.BraidedCategory C] [CategoryTheory.RightRigidCategory C] :
      Prop

      Sphericality, in the standard form: the left and right quantum dimensions agree on every object. (Equivalently, the left and right traces agree — here specialised to the identity, which is the case the keystone consumes.)

      Why this is a hypothesis and not a theorem, and when you do not need it.

      leftQDim and qDimObj are the two twistless closures, and they differ by the monodromy (β_ Xᘁ X).inv against (β_ X Xᘁ).hom. No axiom of a braided rigid category forces the monodromy to vanish, so this class cannot be derived here — it is a genuine condition, which is what spherical_of_symmetric below witnesses from the other side (symmetric ⇒ monodromy trivial ⇒ spherical).

      The classical ribbon ⇒ spherical is a theorem about the twisted traces, and it does not reach these two. If a BalancedCategory is in scope, do not carry this hypothesis: use QOU.MathlibExt.qDimTwistedLeftWith_eq, which proves left = right for qDimTwistedLeftWith / qDimTwistedWith in any RibbonCategory. Its companion qDimTwistedLeftWith_eq_of_cap shows the balancing axiom does all the geometric work and the ribbon axiom is used exactly once, on the cap.

      So the division of labour is: this class is the right object precisely where there is no twist available — as here, where the variable block is braided right-rigid and no θ exists. Where a twist does exist, sphericality is a theorem and this class is the wrong thing to assume. Nothing in this file needs migrating on that account: the results below are true at braided right-rigid generality, and requiring a ribbon structure to obtain them would be a loss, not a gain.

        The consequence is worth stating plainly. Transport is not unconditionally provable, because sphericality is not — the left and right traces genuinely differ in a general braided rigid category, and a category where they agree is what spherical names. So the residual recorded against this file was never two inputs of which one might fall; it is one condition, wearing two names.

        Why the twist does not close it — the exact obstruction #

        The natural next thought, once a ribbon structure is available, is the classical ribbon ⇒ spherical. It does not apply to qDimObj and leftQDim as defined here, and the theorem below says precisely why.

        source
        theorem QOU.BraidKnot.PivotalSpherical.qDim_twist_eq_leftQDim {C : Type u_2} [CategoryTheory.Category.{u_3, u_2} C] [CategoryTheory.MonoidalCategory C] [CategoryTheory.BraidedCategory C] [CategoryTheory.RightRigidCategory C] [MathlibExt.BalancedCategory C] (X : C) :
        CategoryTheory.CategoryStruct.comp (η_ X Xᘁ) (CategoryTheory.CategoryStruct.comp (β_ X Xᘁ).hom (CategoryTheory.CategoryStruct.comp (CategoryTheory.MonoidalCategoryStruct.tensorHom (MathlibExt.BalancedCategory.twist Xᘁ) (MathlibExt.BalancedCategory.twist X)) (ε_ X Xᘁ))) = leftQDim X

        The two traces differ by exactly the twist factor θ_{Xᘁ} ⊗ θ_X.

        Inserting that factor into the right trace produces the left trace on the nose. The proof is the Joyal–Street balancing axiom, which turns the double braiding into θ_{Xᘁ ⊗ X} dressed by the two component twists, followed by naturality of θ against η ≫ β⁻¹ : 𝟙_C ⟶ Xᘁ ⊗ X — which absorbs the whole θ_{Xᘁ ⊗ X}, since θ_{𝟙} = 𝟙.

        This is why ribbon ⇒ spherical does not apply here. The classical theorem concerns the twisted trace, in which θ is already inserted; qDimObj and leftQDim are the twistless traces, and between those two the twist is not a normalisation but the entire difference. A ribbon structure supplies θ_{Xᘁ} = (θ_X)ᘁ, which relates the factor's two halves — it does not make the factor disappear. So sphericality is not a consequence of the ribbon axiom for these definitions, and by transport_iff_spherical neither is transport. Scope (a): this is a statement about these two definitions, not a claim that no twisted formulation closes.
