    The Murphy element with its reference tableau made explicit — and 3.13 composed onto it #

    MurphyGarnirFactor proves two halves and refuses to compose them, because d(t) means two different things in the corpus:

    • the Garnir chain (GarnirTableau, DescentNodeExists, exists_garnir_Tw_factor) uses TableauPerm.dOf, whose reference is the row-superstandard t^λ — Mathas';
    • murphyM uses HeckeMurphyYoung.dOf, whose reference is column-superstandard.

    murphy_reference_tableau_additivity_probe.py then measured that the difference is not cosmetic: 3.13's length additivity holds at every one of 1789 row-standard non-standard tableaux under the row reference and fails for 48 % of them at n = 6 under the column one, with the smallest counterexample at λ = (2,1,1). So the composition cannot be obtained by re-proving the Garnir side; the Murphy element has to be stated over t^λ.

    What this file does, and what it deliberately does not #

    It does not edit HeckeMurphyYoung. Instead it makes the reference an explicit parameter — the thing whose absence caused the collision — and recovers the existing definitions as instances:

    dOfRef r t        d(t) relative to an arbitrary reference `r`
dAtRef n h r t    the same at the Hecke algebra's index
murphyMRef r s t  T*_{d_r(s)} · x_r · T_{d_r(t)}

murphyMRef (colSuperstandard μ) = murphyM      (`murphyMRef_colSuperstandard`, `rfl`)
murphyMRow := murphyMRef (refTab μ)            Mathas' element

    Nothing downstream of murphyM changes: murphyM is definitionally one instance of murphyMRef, so murphyFamily, basisOfSpanning and murphyBasisOfSpanning are untouched and keep proving exactly what they proved.

    The rank axis is clear for the row instance, and this was checked rather than assumed. murphy_supp_rsk_probe.py's rank guard reports row 6/6, 24/24, 120/120 — FULL at n = 3,4,5, the same as the column reference. (That guard sat below its file's if __name__ block and had never run; it is wired in now. What its result licenses is narrow: the reference does not change the rank. It does change 3.13's length additivity, which is the whole reason this file exists — so do not restate it as "the reference does not matter".)

    The composition #

    exists_garnir_murphyMRow_factor is the point: for a row-standard non-standard t,

    m^row_{s t}  =  m^row_{s g} · T_w

    with g a Garnir tableau. This is the rewriting step Mathas' Lemma 3.14 performs, on the element 3.14 is actually about. In MurphyGarnirFactor the two halves could only be stated separately; here they meet.

    Still not 3.14 #

    The step is proved; the induction is not run. What remains is that the terms this rewriting produces descend in MurphyInductionMeasure.murphyLex, which needs 3.12's algebra half and hence 3.9 at basis level. murphyLex_wellFounded says such an induction terminates; it does not say the terms descend.

            4. The composition MurphyGarnirFactor could not make #

            At r = refTab μ the length hypothesis of §3 is the conclusion of TableauPerm.length_dOf_smul_eq_add_iff, which is what the Garnir descent node supplies. So the two halves meet, and they meet only here — under the column reference the hypothesis is false for 48 % of n = 6 tableaux.

            A row-standard non-standard t gives a Garnir tableau g and a w with

            m^row_{s t}  =  m^row_{s g} · T_w

            This is 3.14's rewriting step, on the object 3.14 is about. It does not hold for the column-superstandard murphyM — see the module docstring; that is why the reference had to become a parameter first.
