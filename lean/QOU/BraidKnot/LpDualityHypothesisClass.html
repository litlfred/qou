    QOU.BraidKnot.LpDualityHypothesisClass — finite LP strong-duality + complementary slackness as a §3b-cond class #

    Class-axiomatises the two routine LP-theory inputs to the operator-selection-LP machinery:

    1. Strong duality (Schrijver §7.2): for a bounded + feasible finite LP, the primal and dual optima coincide, giving duality_gap = 0.
    2. Complementary slackness (Schrijver §7.4): at the optimum, a partition λ lies in the LP active set iff its primal constraint is tight.

    These are the two sorrys in content/.../braids-and-knots/confinement-nf-partial-proof.lean (theorems strong_duality + complementary_slackness). Per AGENTS.md §3b-cond, axiomatising them as a class lets the two theorems be derived as class.field references rather than free-standing sorrys — the proper conditional-class locale for LP-theory inputs that aren't yet wired in Mathlib.

    The class is purely a hypothesis carrier; the trivial model fills both fields via the LP-theory citations (single sorry per field, with explicit -- Ref: [schrijver1986theory] per AGENTS.md §1). When Mathlib gets a finite-dim LP-duality library (Mathlib.Analysis.Convex.LinearProgramming or similar), the trivial-model sorrys can be discharged unconditionally without touching the consumer side of the class.

    Bridge to prop:confinement-nf-partial-proof: a future refactor can add [lpDuality : HasFiniteLPDuality lp] to the hypotheses of theorem_3_strong_duality and theorem_1_maximizer_in_active_set, deriving them from lpDuality.dualityGapZero and lpDuality.complementarySlackness respectively — no sorrys in the consumer file, only in the trivial model.

    References:

    • Schrijver, A. (1986). Theory of Linear and Integer Programming, Wiley. §7.2 (strong duality), §7.4 (complementary slackness).

          No global instance — and why the two that were here proved False #

          This namespace used to carry

          axiom schrijver_strong_duality :
    ∀ (lp : OperatorSelectionLP), lp.duality_gap = 0
axiom schrijver_complementary_slackness :
    ∀ (lp : OperatorSelectionLP) (lam : lp.Λ),
      lam ∈ lp.active_set ↔ lp.tight lam

          plus a schrijverModel building a HasFiniteLPDuality lp from them for any lp. Each axiom independently made the library inconsistent.

          OperatorSelectionLP carries primal_obj and dual_obj as arbitrary, independent reals — it has no feasibility, boundedness or optimality data at all — and duality_gap is defined as |primal_obj − dual_obj|. So the first axiom asserts that any two reals are equal:

          def badLP : OperatorSelectionLP where
  Λ := Empty; finite := by infer_instance
  primal_obj := 0; dual_obj := 1
  active_set := ∅; tight := fun _ => True

theorem strong_duality_axiom_is_inconsistent : False := by
  have h : badLP.duality_gap = 0 := schrijver_strong_duality badLP
  simp [OperatorSelectionLP.duality_gap, badLP] at h

          The second is separately inconsistent for the same reason: active_set and tight are independent fields, so an LP with an empty active set and a universally-true tightness predicate refutes the iff. Both proofs compiled, with #print axioms naming one axiom each.

          The mathematics is not at fault — the transcription is. Schrijver §7.2 holds for a bounded and feasible LP at its optimum. Those hypotheses were dropped, and OperatorSelectionLP does not even carry the fields needed to state them, so the axioms quantified over structures for which the theorem is simply false. Same shape as the JSJ/Thurston case (PR #4774): a correct citation attached to a statement broader than the cited result.

          The class itself was always right, and the module docstring above says so — "The class is purely a hypothesis carrier." Taking HasFiniteLPDuality lp as an instance hypothesis for a specific lp is the correct §3b-cond pattern, and theorem_3_via_class / theorem_1_via_class below consume it correctly. What was wrong was manufacturing that hypothesis for free, for every lp, via two false axioms. Removed, not completed: a caller must now supply the instance for their own LP, which is where the real LP-theory obligation belongs.

          Follow-up (bean qou-7t1n): to state Schrijver honestly, OperatorSelectionLP needs its constraint data plus feasibility/boundedness/optimality predicates, and the duality result should be conditional on those. That is a genuine modelling task, not a transcription fix, and is deliberately not attempted inside an unsoundness repair.
