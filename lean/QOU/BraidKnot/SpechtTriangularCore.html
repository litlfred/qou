    QOU.BraidKnot.SpechtTriangularCore — further reduction of brick-4's Triangular stub #

    QOU.BraidKnot.SpechtStandardBasis.standardPolytabloid_triangular packages the linear-independence half of the standard-basis theorem into a single Triangular bundle (three fields: lead_inj, diag_unit, supp_le) modulo one sorry. Two of those three fields are order-independent; only the third (supp_le, the dominance bound) needs the dominance order on tabloids and is the genuine deep core.

    This module REDUCES the bundle further: it proves both order-independent fields sorry-free (diag_unit and lead_inj — the latter via the leading-tabloid-determines-SYT argument, fully formalised here). The remaining field (supp_le) is supplied by standardPolytabloid_dominance_order, itself discharged sorry-free here by consuming the deeper relation-level core SpechtDominanceCore.standardPolytabloid_dominance_order' (which peels off the LinearOrder construction + Finsupp/support plumbing via a Szpilrajn-for-Fintypes lever, leaving only Sagan's dominance lemma as SpechtDominanceCore.dominance_relation_exists). It then reassembles standardPolytabloid_triangular' — a verbatim restatement of the brick-4 bundle — sorry-free modulo that one relation-level core.

    It imports SpechtStandardBasis and SpechtDominanceCore read-only (mirroring how SpechtIrreducible reproduces brick 2 reduced to fewer cores); it does not modify them.

    1. The key lemma: C_t ∩ R_t = {1} (sorry-free) #

    A permutation lying in both the column stabilizer and the row stabilizer of a (bijective) tableau t fixes both coordinate-projections of every cell, hence fixes every cell, hence — t being an Equiv — is the identity. This is the one fact that makes the diagonal coefficient ±1: only π = 1 contributes both a nonzero sign and the leading tabloid {t}.

    π = 1

    C_t ∩ R_t = {1}. If π : Perm (Fin (nOf μ)) stabilizes both the column pattern and the row pattern of a bijective tableau t, then π = 1.

    3. FACT 2 — leadTab injective (fully sorry-free) #

    leadTab T = {sytToTableau T} and tabloid equality is row-pattern equality, so leadTab T₁ = leadTab T₂ decodes to: for every label l, the T₁-cell with entry l and the T₂-cell with entry l lie in the same row. The conclusion T₁ = T₂ then follows because within a row the entries appear in strictly increasing column order (row_strict), so within row i the entry function is the unique strict-monotone enumeration of the row's value-set — and since the row's value-set is the same for both tableaux (the decoded hypothesis), the two enumerations coincide (Finset.orderEmbOfFin_unique). This whole argument is formalised here, so leadTab_injective carries no sorry.
