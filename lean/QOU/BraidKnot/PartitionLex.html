    The lexicographic order on shapes — the order Mathas' Garnir lemma actually uses #

    Mathas' Lemma 3.12 (Hecke algebras and Schur algebras of the symmetric group) is the Garnir relation the Murphy-basis spanning argument runs on. It concludes with a shape moving up an order, and the order is lexicographic, not dominance.

    He says so in the sentence immediately before it, introduced for exactly these lemmas:

    "For the next few Lemmas we need another ordering on the set of partitions. Given partitions λ and μ we write λ > μ if λ is greater than μ in the lexicographic ordering. That is, there exists an integer j ≥ 1 such that λᵢ = μᵢ for 1 ≤ i < j and λⱼ > μⱼ. … Note that if λ ⊵ μ then λ > μ."

    Why this file exists, rather than reusing partitionDom #

    The corpus already carries the dominance order (SpechtClassification.partitionDom), and it is the natural thing to reach for. It is the wrong order here, and measurably so. garnir_shape_dominance_probe.py checks both orders against Mathas' Garnir composition, exhaustively over every partition and every Garnir node for n = 2..11 — 910 nodes, exact integer arithmetic:

    sorted(ν) >_lex λ    910 / 910
sorted(ν) ⊳ λ        824 / 910    — 86 failures

    The smallest counterexample needs no machine, and it is dom_fails_lex_holds below: λ = (3,3) with Garnir node (0,1) gives ν = (4,1,1), and 4 ≥ 3 but 4 + 1 < 3 + 3.

    lexGt_of_partitionDom_of_ne is Mathas' own "note", and it is what lets an existing dominance result feed a lex induction: dominance is strictly stronger, so every partitionDom fact in the corpus is still usable here — the implication just does not run the other way.

    Why the weaker order is the better one to induct on #

    Lex is total on the partitions of a fixed n, where dominance is only partial. So a straightening induction that decreases in lex is comparing every pair, which is what makes the well-founded recursion routine rather than delicate. This is the reason Mathas switches orders for these lemmas at all.

        The column-length criterion — the engine for the Garnir step #

        The Garnir composition moves one shape to another by changing the multiset of parts, so the natural thing to reach for is a sorting argument: sort the new composition, compare the two descending lists entrywise. That is avoidable.

        A YoungDiagram is determined by either its row lengths or its column lengths, and the two are exchanged by the single characterisation

        (s, j) ∈ μ   ↔   j < μ.rowLen s   ↔   s < μ.colLen j

        so a statement about how many parts exceed a threshold — which is exactly what the Garnir count says — is a statement about colLen, and it converts to a statement about rowLen with no list, no sort, and no permutation reasoning.

        lexGt_of_colLen is that conversion. Its hypotheses are what the Garnir counting argument delivers verbatim: the number of parts above k goes up by at least one, and the count above every larger threshold is unchanged.

        theorem QOU.BraidKnot.PartitionLex.lexGt_of_colLen {μ ν : YoungDiagram} {k : ℕ} (hgt : ∀ (m : ℕ), k < m → μ.colLen m = ν.colLen m) (hk : μ.colLen k < ν.colLen k) :
        ν >ₗ μ

        The column-length criterion for a lex step.

        If ν has strictly more parts exceeding k than μ does, and exactly as many parts exceeding every larger threshold, then ν >ₗ μ — with the witness named: μ.colLen k, the number of parts of μ above k.

        This is the shape of every Garnir step. Naming the witness rather than leaving it existential is what the probe measured: it is not the Garnir row i. At λ = (2,2,2) with node (i,j) = (1,0) the new shape is (3,2,1), which first differs from λ at row 0, because the merged part overtakes the rows above i that tie with λᵢ. μ.colLen k gets that right; i does not.

        The proof needs no sorting. Below the witness both diagrams contain every column j ≤ k (their column lengths there are at least μ.colLen k, which exceeds the row index) and agree above k by hypothesis, so the rows match. At the witness the hypothesis at k separates them: ν still has column k, μ does not.

        The two orders are genuinely different #

        Everything above would be consistent with lex and dominance agreeing, in which case this file would be redundant and partitionDom could have been used directly. They do not agree, and the witness is the smallest Garnir counterexample the probe found.

            theorem QOU.BraidKnot.PartitionLex.dom_fails_lex_holds :
            nu411 >ₗ lam33 ∧ ¬SpechtClassification.partitionDom nu411 lam33

            The separating example: lex holds where dominance fails.

            (4,1,1) >ₗ (3,3) because 4 > 3 in the first row, but (4,1,1) does not dominate (3,3) because 4 + 1 = 5 < 6 = 3 + 3.

            This is exactly the pair Mathas' Garnir composition produces at λ = (3,3), node (0,1), so the failure is not a curiosity about the two orders — it is the induction step of Lemma 3.12 refusing to be a dominance step.

            Only rows 0 and 1 are ever inspected: the lex witness is row 0, and dominance already fails at the partial sum over {0, 1}.

            The engine is not vacuous — it derives the instance above #

            lexGt_of_colLen would be useless if its hypotheses were hard to meet. They are met by the very pair that separates the two orders, and re-deriving dom_fails_lex_holds.1 through the engine rather than by hand is the check that the criterion is usable on a real Garnir step.

            At the threshold k = 3: (3,3) has no part exceeding 3, while (4,1,1) has one. Above 3 neither has any. So the criterion fires with witness lam33.colLen 3 = 0 — which is indeed where the two shapes first differ.
