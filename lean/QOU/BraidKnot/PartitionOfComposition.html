    A composition as a Young diagram, and its column lengths as a part count #

    Mathas' Garnir lemma replaces two parts of a partition by three, producing a composition — the parts are no longer weakly decreasing. Turning that back into a shape means sorting, and reasoning about the sorted list is the expensive part of the argument.

    This file makes it cheap, by never looking at the sorted list again after building the diagram:

    colLen_ofComposition :  (ofComposition l).colLen m  =  l.countP (m < ·)

    countP is permutation-invariant, so the right-hand side is a statement about the composition as given — no sortedness, no indices, no reasoning about where the new parts landed. Everything the Garnir step needs is then countP arithmetic on a list that differs from μ.rowLens in three entries.

    Together with PartitionLex.lexGt_of_colLen, whose hypotheses are exactly two column-length facts, this reduces "the Garnir shape is lex-greater" to counting.

      Zero parts are harmless — they sort to the end and contribute no cells — so a composition with a zero part, which the Garnir splitting produces whenever j = 0, needs no special handling.

        theorem QOU.BraidKnot.PartitionOfComposition.lt_countP_iff_of_sorted {w : List ℕ} :
        List.Sorted (fun (x1 x2 : ℕ) => x1 ≥ x2) w → ∀ (m i : ℕ), i < List.countP (fun (x : ℕ) => decide (m < x)) w ↔ ∃ (h : i < w.length), m < w[i]

        On a weakly-decreasing list the entries exceeding m form an initial segment, so "index i has an entry exceeding m" and "i is below the count of such entries" are the same condition.

        This is the only place sortedness is used; everything downstream is countP.

        source
        theorem QOU.BraidKnot.PartitionOfComposition.colLen_ofComposition (l : List ℕ) (m : ℕ) :
        (ofComposition l).colLen m = List.countP (fun (x : ℕ) => decide (m < x)) l

        The bridge. A composition's diagram has, in column m, exactly as many cells as the composition has parts exceeding m.

        The right-hand side does not mention the sort, and countP is permutation-invariant, so this is a fact about the composition as written.

        The round trip, so the bridge applies to any diagram #

        colLen_ofComposition speaks about a diagram built from a list. A Garnir step starts from an existing μ, so it needs the same statement about μ itself — which follows once sorting an already-sorted list is seen to do nothing.

        Non-vacuity #

        The bridge would compile just as well if ofComposition produced something unrelated to the parts it was handed, so it is checked against the Garnir composition that made the whole order question concrete: λ = (3,3) at node (0,1) gives the composition (1, 4, 1), whose diagram is (4,1,1).
