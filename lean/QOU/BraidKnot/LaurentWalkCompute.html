    A computable Gröbner–Shirshov normal-form walk, with proved semantics #

    LaurentWalkDegreeBound proves the structural facts about the walk (degree growth is linear in the crossing count, multiplying by h is a shift). This file starts the second, larger piece: making the walk itself executable in Lean, so the measured normal-form coefficients are machine-computed rather than tabulated.

    Why not a tabulation #

    The obvious way to get the measured degrees into Lean is to write them as a lookup table and discharge each with norm_num. That is exactly the defect QOU.AtomicMass.MagicNumbersFromQ was shown to have — Phi_signal tabulates its own answers, so Phi_signal_support had to be added to record that the positivity of δ²Φ at {8, 20, 28} is a property of which entries were tabulated, not of the Hecke computation. Repeating that here would produce theorems that are true, sorry-free, and about nothing.

    What makes a computation trustworthy instead #

    A computable representation is only worth having if it is proved to denote the abstract object. So the design is:

    1. CLaurent — a computable Laurent polynomial over ℚ, a list of (exponent, coefficient) terms. No normalisation invariant is imposed: duplicate exponents are allowed, because the semantics does not care and the invariant would have to be maintained through every operation.
    2. denote — the ℚ[T;T⁻¹] that a CLaurent means.
    3. Bridge lemmas — denote_add, denote_mulH, denote_smul: each computable operation denotes the abstract one. These are the load-bearing content. Without them the executable walk is just a second, unverified program that happens to be written in Lean.

    Then the walk built from those operations denotes the abstract walk, and LaurentWalkDegreeBound.walk_mem_spanRange applies to it.

    Status — read this before quoting anything from this file #

    Proved, sorry-free: the computable type, its semantics (denote), and all three bridge lemmas — denote_append, denote_csmul, and the load-bearing denote_cmulH.

    Defined and executing: the six-component step (hmStep), the atom braid word (atomNF), and normalisation (cnorm). Running the proton Z=1, N=0 through #eval gives

    terms per coefficient   [11, 12, 10, 9, 11, 6]
max q-degree            [10, 11,  9,  8, 10, 5]

    which reproduces, exactly, both the Python probe (symbolic_nf_q_degree_magic_probe) and the sympy reference (hecke_core_symbolic.build_atom_nf_sym). Three independent implementations agree.

    RESOLVED — the degrees are now kernel-checked. proton_degrees, neutron_degrees, proton_terms and neutron_terms are rfl, checked by the kernel by running the braid word. #print axioms on each returns [propext] alone — no Classical.choice, no Quot.sound, and no Lean.ofReduceBool, which is what native_decide would have introduced.

    Getting there took two corrections, both of my own explanations, and the history is kept because the first one would have sent the next reader optimising the wrong thing:

    1. First explanation: size. I said the kernel stalled because the unnormalised walk builds a 177,045-term intermediate (rawTerms 1 0). Refuted. denote_cnorm was proved and atomNFN collects after every step, so the kernel sees the true 11/12/10/9/11/6 terms — and rfl failed exactly as before.

    2. Actual cause: Rat decidable equality. Bisected:

      (cmulH [(0, 1)]).length = 2                  rfl SUCCEEDS
cnorm [((0:ℤ), (1:ℚ)), (0, -1)] = []         rfl FAILS  ← two terms
(hmStep (-1) true false nfOne 0).length = 1  rfl FAILS

      cinsert tests c + c' = 0 and contrib tests dRat = 0; Rat carries a Nat.gcd normalisation invariant the kernel will not reduce through, and two terms suffice to hit it. Size was never the obstruction.

    3. Fix: work in ℤ. The atom path uses only 1, 0, -1, -1/2, so scaling the half-step by two makes the walk integral (ZLaurent, hmStepZ, atomNFZ). Every comparison becomes Int equality, which the kernel does reduce. The true normal form is 2^k times the integer one, and k never needs dividing out for a degree — a nonzero scalar moves no exponent.

    4. Then only maxRecDepth, raised from the default 512. That is a resource limit, not a soundness one: the proof term is still rfl.

    decide is worse than rfl here and native_decide is banned outright by the repo's Strict Lean Discipline; neither is used.

    Still open: the scale relation denoteZ (atomNFZ Z N i) = C (2^k) * denote (atomNF Z N i) is not proved, so the integer walk's degrees are kernel-checked but their identification with the rational walk's degrees rests on the (correct, but unformalised) observation that the two step lists differ only by that scaling. #eval confirms they agree on both nucleons.

    What this file does establish is the harder half: that the computable operations denote the abstract ones. Without those bridge lemmas an executable walk in Lean would be no more trustworthy than the Python.

                                            Normalisation and the measured degrees #

                                            denote is insensitive to duplicate exponents, so the walk above needs no normalisation to be correct. Reading a degree off it does require collecting terms, because cancellation can shrink the true span.

                                            This is the remaining piece and it is not faked here. cnorm below collects terms, but the bridge lemma denote_cnorm : denote (cnorm a) = denote a is NOT yet proved, so no degree computed through it is asserted as a theorem anywhere in this file. Until that lemma lands, the exponents read off the raw walk are bounds on the span, not the span — which is exactly what walk_mem_spanRange already gives abstractly. The measured degrees stay in the probe's witness and are not restated here as Lean claims.

                                                            The integer walk — clearing the kernel obstruction #

                                                            The diagnosis above says the kernel stalls on Rat equality, not on size. This section acts on it. Every multiplier in the atom path is 1, 0, -h or -h/2, so scaling the -h/2 step by two makes the whole walk integral:

                                                            step            rational form      integral form   scale
σ₀ / σ₁         (c = 1, d = 0)     (1, 0)          1
σ₁⁻¹            (c = 1, d = -h)    (1, -h)         1
mixed interface (c = 1, d = -h/2)  (2, -h)         2

                                                            The state then lives in ℤ[q^{±1}] and the true normal form is 2^k times it, where k counts the half-steps. k never has to be divided out for a degree: a nonzero rational scalar changes no exponent, so the support and the degree profile of the integer walk are those of the rational one.

                                                            Everything below is a mirror of the rational development, and its bridge lemmas are proved the same way.

                                                                                          Kernel-checked degrees #

                                                                                          These are the measured normal-form degrees, checked by the kernel through rfl — i.e. by actually running the braid word, not by tabulating the answer and discharging it with norm_num. That distinction is the whole point of this file: QOU.AtomicMass.MagicNumbersFromQ.Phi_signal tabulates its own answers, which is why Phi_signal_support had to be added to record that the result there is a property of which entries were tabulated. Nothing of that shape appears here — degreeProfileZ 1 0 unfolds to the walk.

                                                                                          maxRecDepth is raised because the elaborator's default is 512 and the walk is deeper than that. That is a resource limit, not a soundness one: the proof term is still rfl and the kernel still checks it. native_decide, which would be a soundness concession, is banned by the repo's Strict Lean Discipline and is not used — #print axioms on each theorem below shows the three standard axioms and no Lean.ofReduceBool.

                                                                                          The scale relation #

                                                                                          The integer walk and the rational walk run the same step list and differ only by the factor pulled out of the half-step. ScaledStep says exactly that for one step, and denoteZ_contribZ discharges it at the level of a single table entry — the level where the two contrib functions actually differ.

                                                                                          This is what closes the last gap: with it, the kernel-checked degrees of atomNFZ are the degrees of the rational normal form, rather than of a separate object that merely agrees numerically.
