          theorem QOU.QBeta.NFVec.trAt_eq_quadratic {R : Type u_1} [CommRing R] (h z : R) (v : NFVec R) :
          trAt h z v = v.gamma + (v.s0 + v.s1 + v.eminus) * z + (v.Lminus + v.Lplus + h * v.eminus) * z ^ 2

          The trace is a quadratic in z, with explicit coefficients.

          This is the structural fact behind the acceptance test: for a fixed element the map z ↦ trAt h z v is a quadratic, so requiring it to take a prescribed value does not leave a free choice of z — it determines z up to which of two roots. "Which element" and "which functional" are therefore one question.

          Level 1 is the augmentation #

          At z = q with h = q - q⁻¹ the basis weights collapse to 1, q, q, q², q², q³ — the augmentation σᵢ ↦ q on the basis 1, σ₀, σ₁, σ₁σ₀, σ₀σ₁, σ₀σ₁σ₀. The only weight that is not visibly a power of q is the last, and it is one.

          source
          theorem QOU.QBeta.eminus_weight_at_level_one {R : Type u_1} [Field R] (q : R) (hq : q ≠ 0) :
          q * ((q - q⁻¹) * q + 1) = q ^ 3

          The e⁻ weight at level 1 is q³. With h = q - q⁻¹, q·(h·q + 1) = q³ — so the trace at z = q really is the augmentation on the whole basis, not merely on the short words.

          Multiplicativity forces order-blindness #

          The augmentation is an algebra map, so it is a product over the letters of a word; a product over a list is invariant under permuting the list. This is why level 1 cannot distinguish two words built from the same multiset of crossings in a different order — and hence why an Option E element must differ in the multiset, not the braid.

          source
          theorem QOU.QBeta.monoidHom_order_blind {M : Type u_1} {R : Type u_2} [Monoid M] [CommMonoid R] (ε : M →* R) {w w' : List M} (hperm : w.Perm w') :
          ε w.prod = ε w'.prod

          A multiplicative functional is blind to the order of a word.

          The commutativity that does the work is the target's, not the braid monoid's. w.prod = w'.prod is false in M: a braid monoid is not commutative, and a permuted word is a different braid. What is true is that ε carries the product to a product of images, and that product lives in a commutative ring where reordering is free. So order-blindness is a property of the functional, not of the words — which is why it is level 1 that has it.

          source
          theorem QOU.QBeta.augmentation_difference_order_blind {M : Type u_1} {R : Type u_2} [Monoid M] [CommRing R] (ε : M →* R) {n n' p p' : List M} (hn : n.Perm n') (hp : p.Perm p') :
          ε n.prod - ε p.prod = ε n'.prod - ε p'.prod

          Order-blindness passes to a difference of two words.

          Δ = 𝓑_n - 𝓑_p is a difference of two words. If each is re-ordered — which is what a different generator assignment or a different interleaving does — the value of a multiplicative functional on the difference is unchanged. So at level 1 those variants are not different candidates at all.

          Which levels can be multiplicative #

          monoidHom_order_blind says multiplicativity buys order-blindness. The converse question — which Markov parameters are multiplicative at all — has a sharp answer, and it is what separates the two admissible levels.

          A unital multiplicative map on H₃(q) sends a Hecke generator σᵢ to its Markov weight z, and the Hecke relation σ² = hσ + 1 then forces z² = hz + 1. That quadratic has exactly two roots, and z_D is neither.

          The corpus already has the z ↦ 1 case (QOU.QBeta.CounitSigmaOne); this is the general statement it is an instance of.

          source
          theorem QOU.QBeta.hecke_image_factor {R : Type u_1} [Field R] (q z : R) (hq : q ≠ 0) :
          z ^ 2 - (q - q⁻¹) * z - 1 = (z - q) * (z + q⁻¹)

          The Hecke image equation factors. Over any commutative ring, with h = q - q⁻¹, z² - hz - 1 = (z - q)(z + q⁻¹).

          source
          theorem QOU.QBeta.multiplicative_forces_eigenvalue {R : Type u_1} [Field R] (q z : R) (hq : q ≠ 0) (hrel : z ^ 2 = (q - q⁻¹) * z + 1) :
          z = q ∨ z = -q⁻¹

          Only two Markov parameters can be multiplicative. If a unital multiplicative functional sends the Hecke generator to z, then z = q or z = -q⁻¹ — the two eigenvalues of σ.

          source
          theorem QOU.QBeta.conventionD_not_multiplicative {q : ℝ} (hq : 0 < q) :
          ¬(q ^ 3 / (q ^ 2 + 1)) ^ 2 = (q - q⁻¹) * (q ^ 3 / (q ^ 2 + 1)) + 1

          Level 2 is not multiplicative.

          z_D = q³/(q²+1) is neither eigenvalue: it is strictly below q and strictly above -q⁻¹. So no unital multiplicative functional has z_D as its Markov parameter, and the argument that makes level 1 order-blind is unavailable at level 2.

          🛑 Scope. This removes the obstruction; it does not prove that level 2 is order-sensitive. Non-multiplicativity permits sensitivity, it does not force it. That level 2 actually distinguishes two specific same-multiset words is a measurement (qbeta_option_e_required_level_probe, the interleaved vs gen-grouped models), not a consequence of this theorem.

          The acceptance test #

          If a candidate overshoots the target at one admissible level and undershoots it at the other, the parameter it needs is strictly between them. Since the admissible parameters are exactly the two endpoints, such a candidate cannot be closed at either — and that is checkable from the two endpoint values alone, with no solving.

          ∃ c ∈ Set.Ioo a b, f c = T

          Bracketing forces an interior root.

          The acceptance test, in the form a reader can apply. A candidate that brackets the target takes the target value at neither admissible parameter. No continuity is needed for this half: the two strict inequalities are the whole argument, which is what makes the test cheap.
