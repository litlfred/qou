        theorem QOU.QBeta.ECatProbeAssertions.separation_independent_kernel_is_blind_on_the_measured_transposition (J : ℕ → ℕ → ℕ) :
        (∀ (a b : ℕ), J a b = J b a) → pairSum (fun (a b x : ℕ) => J a b) [0, 1, 2] = pairSum (fun (a b x : ℕ) => J a b) [1, 0, 2]

        The converse to pairSum_not_perm_invariant, on the case the probe measured.

        A kernel that ignores the separation and is symmetric in its two letters gives the SAME value on the transposition where a separation-dependent kernel gives different values. So the escape from the letter-sum exclusion is the separation dependence specifically — a pair kernel is not enough on its own.

        Stated as the concrete instance the probe's control measured rather than as a general permutation theorem: the general statement needs an induction over List.Perm that this file does not carry, and claiming it here would be asserting more than is proved. The instance is the one that matters, because [0,1,2] ↦ [1,0,2] is exactly the reordering that separates σ₁σ₀ from σ₀σ₁.

        2. Characters of a letter pair: the linearity identity #

        source
        theorem QOU.QBeta.ECatProbeAssertions.char_letterPair {R : Type u_1} {A : Type u_2} [CommRing R] [Ring A] [Algebra R A] (χ : A →ₗ[R] R) (a b : A) (ca cb : R) :
        χ ((a + ca • 1) * (b + cb • 1)) = χ (a * b) + cb * χ a + ca * χ b + ca * cb * χ 1

        The expansion that makes χ_λ of a letter computable.

        A letter is σ + c·1 — a braid generator only when c = 0. For two letters,

        χ((a + c_a·1)(b + c_b·1)) = χ(ab) + c_b·χ(a) + c_a·χ(b) + c_a·c_b·χ(1)

        so every term is a character of a braid word of length ≤ 2 (and χ(1) = dim). χ is any linear functional; being a trace is not needed, only linearity.

        This is the identity the block-cost probe's [A1] cross-check validated against an independent trace engine, agreeing to 2.6e-50.

        3. Convention-D weights normalise #

        (q ^ 4 + 1) / (q ^ 2 + 1) ^ 2 + 2 * (q ^ 2 / (q ^ 2 + 1) ^ 2) = 1

        y_(3) + 2·y_(2,1) = 1 for the convention-D Markov weights at n = 3.

        tr_M(1) = ∑_λ y_λ·dim_λ with dimensions 1, 2, 1, and y_(1³) = 0 under convention D, so the identity to check is exactly this one. Proved as an algebraic identity in q, valid wherever q² + 1 ≠ 0 — no numerics.

        4. A zero-weight block contributes nothing #

        source
        theorem QOU.QBeta.ECatProbeAssertions.zero_weight_block_contributes_nothing {F : Type u_3} [Field F] (y acc : F) (hy : y = 0) :
        y * acc = 0

        The (1³) column is structurally zero, not numerically small.

        A block whose Markov weight vanishes contributes nothing to t_λ = y_λ·(…) whatever its characters are. Under convention D y_(1³) = 0 — that vanishing IS convention D (the direction used here, D ⟹ vanish, is FibreDimensionForcesTL.threeRow_eq_zero_of_jones_ocneanu, or ocneanuWeight_conventionD_eq_zero_of_three_rows for general n; the converse that makes it an "IS" is markovWeights_eq_jones_of_threeRow_eq_zero, which also needs hfaith : y_(2,1) ≠ 0) — so the alternating block's absence from the cost vector is the convention, and a reader seeing a zero column should not look for a bug.
