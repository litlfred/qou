    QOU.QBeta.MarkovTraceQuotient — the trace radical as an actual ideal #

    QOU.QBeta.TemperleyLiebTower proves the Markov trace radical is closed under multiplication on both sides, and its docstring says this means "the quotient is a ring". QOU.QBeta.MarkovGramDegenerate.pairing_descends then says the pairing is constant on radical cosets.

    Neither builds the quotient. traceRadical is a Set A; the two closure lemmas are about that set; and pairing_descends is a congruence statement (a - a' ∈ rad → τ(a·b) = τ(a'·b)), not a descent to a quotient type. So the sentence "the Frobenius structure lives on H_n / rad τ" has, up to now, had no object in Lean to refer to.

    This file supplies the object, which the refutation of qou-vndn makes load bearing: the Markov pairing is degenerate on H_n at convention D (exactly — conventionD_kills_antisymmetriser plus gram_det_eq_zero_of_radical_combination), so every nondegeneracy claim has to move to the quotient or be abandoned.

    What was missing #

    Mathlib's TwoSidedIdeal.mk' needs six fields. The corpus had two:

    field status before this file
    0 ∈ rad absent
    x, y ∈ rad → x + y ∈ rad absent
    x ∈ rad → -x ∈ rad absent
    y ∈ rad → x * y ∈ rad traceRadical_mem_mul (uses cyclicity)
    x ∈ rad → x * y ∈ rad traceRadical_mul_mem

    The three additive ones are absent because TemperleyLiebTower states the radical for a bare tr : A → R with only [Zero R] — there is no addition on the target to close under. They need τ linear, which the Markov trace is; that is the only strengthening here.

    Note which side needs what: right-closure is associativity alone, left-closure is the only place trace cyclicity is spent, and the additive closures need only linearity. Cyclicity is a real hypothesis and is threaded explicitly rather than assumed.

    Base ring, per AGENTS.md §7c: [Module R A], not [Algebra R A]. Nothing here needs the algebra structure — A →ₗ[R] R types under Module alone — and MarkovGramDegenerate asking for Algebra is not a reason to inherit it.

          theorem QOU.QBeta.MarkovTraceQuotient.quot_pairing_nondegenerate {R : Type u_3} [CommRing R] {A : Type u_4} [Ring A] [Module R A] (tau : A →ₗ[R] R) (hcyc : ∀ (x y : A), tau (x * y) = tau (y * x)) (x : TraceQuot tau hcyc) (hx : x ≠ 0) :
          ∃ (y : TraceQuot tau hcyc), quotTrace tau hcyc (x * y) ≠ 0

          The descended pairing is non-degenerate — in the shape WenzlTowerStep asks for.

          WenzlTowerStep.semisimple_ascend wants its trace to satisfy ∀ y ≠ 0, ∃ z, tr (y * z) ≠ 0. On H_n at convention D that is false (MarkovGramDegenerate.gram_det_eq_zero_of_radical_combination). Here it holds, for the descended trace on the quotient, and the proof is short because the radical was quotiented out by construction: a nonzero class is a non-radical element, and a non-radical element is by definition one the pairing separates.

          The content is not the argument; it is that the statement now has a quotient ring to be about, rather than a congruence on A.

          Non-vacuity #

          quot_pairing_nondegenerate is near-definitional, and it would hold trivially if the quotient were the zero ring — every x ≠ 0 hypothesis would be unsatisfiable. So the statement is worth nothing without a witness that the quotient can be non-trivial. That is exactly the shape of vacuity AGENTS.md §"No trivial trues" is about, and the guard is cheap: if the trace does not kill the unit, the unit's class is nonzero.

          The braided presentation descends #

          Brick 2 of qou-s7z2. Brick 1 built the quotient; this shows the Hecke generators survive the passage to it, which is what any WenzlTowerStep instance over TL_n needs before it can even be stated.

          Two steps, and the first is not bookkeeping: RingCon.mk' is a ring hom, but HeckeBraidedPresentationOfRank.hecke_quadratic reads σ i * σ i = (q - q⁻¹) • σ i + 1, with an R-scalar action. A ring hom does not move •. So the quotient needs an R-algebra structure, which Mathlib does not supply for TwoSidedIdeal (Algebra R I.ringCon.Quotient fails to synthesize), and supplying it needs the image of algebraMap to be central — true here, inherited from Algebra.commutes in A through a surjection.

          A scalar-action diamond to know about. RingCon already puts a bare SMul R on its quotient (instSMulQuotient), and it is not part of a Module, let alone an Algebra — Mathlib supplies neither for this quotient. So the instance below introduces a second SMul that Lean will not identify with the first, and map_smul through the algebra hom fails to synthesize MulActionHomClass in the gap. The descent proof therefore avoids • crossing the hom at all: both sides are rewritten into algebraMap _ * _ form with Algebra.smul_def, so only ring operations and AlgHom.commutes are used. Papering over the diamond with a cast would have been the wrong fix.

          Base ring: this section is over [Field R], not brick 1's [CommRing R], because HeckeBraidedPresentationOfRank is itself stated over a field. That is the presentation class's requirement, not a strengthening chosen here; brick 1 stays at CommRing/Module.
