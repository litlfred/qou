    The Markov–Gram matrix is singular under convention D #

    The excision's mathematical half. Eleven content blocks assert that the Markov pairing ⟨x, y⟩_τ := τ(x·y) on H_n(q) is non-degenerate, that det G ≠ 0, and that the inverse G⁻¹ enters the Frobenius co-Casimir C = Σ_{i,j} (G⁻¹)_{ij} b_i b_j. Under the production convention D every one of those claims is false as stated about H_n: det G = 0 exactly, because the antisymmetric block carries weight y₍₁³₎ = 0 and is therefore in the radical of the trace form.

    Those blocks are not wrong about the mathematics; they are wrong about the object. The Frobenius structure is real — it lives on the quotient H_n / rad τ ≅ TL_n(δ), not on H_n. This file proves both halves of that sentence, so the content can be repaired by citation rather than by deletion.

    The chain, end to end #

    1. TemperleyLiebTower.conventionD_kills_antisymmetriser — the pin z(q²+1) = q³ forces y₍₁³₎ = 0. (already proved)
    2. block_mem_radical — a Wedderburn block whose weight is 0 lies in the trace radical. Three lines, and it is where cyclicity is spent.
    3. gram_det_eq_zero_of_radical_combination — a nonzero radical element in the span of the basis puts a nonzero vector in the kernel of G, so det G = 0.
    4. TemperleyLiebTower.traceRadical_two_sided — the radical is a two-sided ideal, so the quotient is a ring. (already proved)
    5. pairing_descends — the pairing is constant on radical cosets, hence descends to that quotient.
    6. mem_radical_of_pairing_zero — and on the quotient it is non-degenerate.

    Steps 1–3 refute the eleven blocks; steps 4–6 tell them where to move the claim.

    Why det G = 0 is exact, not approximate #

    This is worth being sharp about, because the C-convention numbers made it look like a small perturbation. Under C the antisymmetric weight is y₍₁³₎ = 0.0227449… — small, nonzero, and G is invertible with a large but finite condition number. Under D the weight is 0, full stop: not 10⁻¹⁶, not "numerically singular". The rank drops by exactly the dimension of the discarded blocks (24 − 14 = 3² + 1² at n = 4, TemperleyLiebTower.radical_four), and Σ dim² = Catalan n counts what survives. A G⁻¹ computed under C is not an approximation to a G⁻¹ under D, because the latter does not exist.

      What the rank drop is, exactly #

      The corank of G is the dimension of the radical, and the tower already counts both sides. These are the arithmetic checks that tie the abstract statement to the numbers the content blocks quote; the block dimensions themselves come from TemperleyLiebTower.catalan_four / radical_four.

      The same accounting for general n #

      From "some radical element" to the sharp corank #

      gram_det_eq_zero_of_radical_combination above spends a single radical vector and concludes det G = 0 — i.e. corank ≥ 1. That is all the eleven blocks needed refuting, but it is strictly weaker than what is true, and the gap is exactly where the arithmetic of RankAccounting was left hanging: corank_three and friends are norm_num identities about numbers. Nothing connected them to the rank of any actual matrix, so "corank 10 at n = 4" was, in Lean, an assertion about 24 - 14.

      This section supplies the missing link. A radical subspace of dimension d forces corank ≥ d, by rank–nullity: every such coefficient vector is in ker (G *ᵥ ·), so the kernel is at least d-dimensional and the rank is at most card ι - d. Combined with a matching lower bound on the rank the corank is pinned exactly, which is how the measurement in computations/probes/gram_radical_cellular_revalidation.py is made rigorous rather than merely observed.

      Stated over a Field because rank–nullity is: finrank of a kernel is only well-behaved over a division ring. That is a genuine archimedean-free requirement (§7c) — no ordering, no Real, any field will do, including the rational function field ℚ(q) in which the degeneracy is generic.

      theorem QOU.QBeta.MarkovGramDegenerate.gram_rank_le_catalan {R : Type u_1} [Field R] {A : Type u_2} [Ring A] [Algebra R A] {ι : Type u_3} [Fintype ι] {n : ℕ} (tau : A →ₗ[R] R) (b : ι → A) (W : Submodule R (ι → R)) (hW : ∀ c ∈ W, ∀ (i : ι), tau (b i * ∑ j : ι, c j • b j) = 0) (hcard : Fintype.card ι = n.factorial) (hdim : Module.finrank R ↥W + catalan n = n.factorial) :

      The three hypotheses are the three things that have to be true for the Temperley–Lieb reading of the degeneracy, and the conclusion is derived from them by rank–nullity, not assumed:

      • hW — W is a radical subspace (its combinations pair to zero against everything). For the intended instance this is the image of ker(H_n(q) ↠ TL_n(q)), radical because the radical is a two-sided ideal containing the three-strand q-antisymmetriser.
      • hcard — the basis is the T_w basis, so card ι = n!.
      • hdim — the radical has the predicted dimension. Stated additively, dim W + catalan n = n!, rather than as dim W = n! − catalan n: the subtraction form would be a truncated ℕ subtraction and would silently hold for the wrong reason if catalan n exceeded n!.

      What makes the conclusion worth stating is that catalan n here is Σ_{ℓ(λ) ≤ 2} (dim V_λ)² — see corank_general and QOU.Mathlib.dimHLF_two_row_sq_sum — so this reads: what survives the degenerate trace form is at most the two-row part, for every n, with no per-n computation.

      Blocks versus channels — giving the distinction a name #

      The compute layer enumerates its Wedderburn blocks as all partitions of n and then weights each by y_λ. That is correct as a block list, and it was also correct as a channel list under the excised convention C, where every y_λ was nonzero. Under convention D the two sets come apart — y_λ = 0 for every ℓ(λ) ≥ 3 — and nothing in the pipeline noticed, because nothing in the pipeline could say it: there was no name for "block the trace can actually see".

      The gap is not a missing check, it is a missing word. This section supplies it.

      The whole thing turns on an observation rem:gram-matrix-spectral-connection already contains: in the Wedderburn basis the Gram matrix is diagonal, with the weights themselves on the diagonal. Everything below is then a corollary of Matrix.det_diagonal, and the live set is simply the support of y.
