    The site-weighted (quantum) trace on the R-matrix representation #

    QOU.IwahoriHecke.BraidingTrace joined the braiding to the classical character at q = 1, and said plainly that the q ≠ 1 bridge was open. This file supplies the structure that bridge needs.

    Why the plain trace is the wrong functional #

    QOU.MathlibExt.MarkovTrace defines markovTrace ρ w = ρ.character w — the plain matrix trace of a braid word — and proves it cyclic. That is correct as far as it goes, and it is not the Markov trace of the R-matrix representation: for a quantum-group braiding one must weight the trace site-by-site,

    tr_w(x) = tr(W · ρ(x)),   W = diagonal (fun a => ∏ₘ w (a m)),

    which is the quantum trace. QOU.MassTheory.WeightedPermutationCharacter computes exactly this weighted trace for a permutation, with the physical weight w = (1, q²). This file computes the same shape for the braiding.

    The content #

    braidAt_comm_siteWeight — the braiding commutes with the site weight, for every weight w : Fin 2 → R, with no condition on w at all.

    That is stronger than one might expect and the reason is structural: Ř's only off-diagonal entries connect e_i ⊗ e_j to e_j ⊗ e_i, and those two basis states carry the same site-weight w i · w j. So the weight cannot tell them apart, whatever it is. Concretely, whenever Ř_{ij} a b ≠ 0, either a = b or b = a ∘ (i j) — and a permutation of the sites does not change ∏ₘ w (a m).

    From it:

    • qTrace_sigma_mul_comm — cyclicity tr_w(σ_a · y) = tr_w(y · σ_a) when one factor is a generator;
    • qTrace_one — tr_w(1) = (∑ₖ w k)^n, which is weighted_permutation_character's value at the identity permutation, so the two agree where they overlap;
    • qTrace_smul_one at the physical weight w = (1, q²): tr_w(1) = (1 + q²)^n.

    🛑 What is still missing, and it is the deep half #

    The Markov axiom is not here. A Markov trace must satisfy tr(x σ_n) = z · tr(x) for x in the smaller algebra — the peel — and that is the property the Jones polynomial actually consumes. It needs the tower H_n(q) ⊆ H_{n+1}(q) and a compatibility between the weight and the extra strand. Nothing here supplies it, and QOU.MathlibExt.MarkovTrace's own docstring records the same gap for the weighted block traces ("not the normalisation tr_M(1) = 1 nor the Markov peel axiom").

    Full cyclicity is not here either. qTrace_sigma_mul_comm covers the case where one factor is a generator, which is what the commutation lemma gives directly. Extending it to tr_w(xy) = tr_w(yx) for arbitrary x needs the image of the action to lie in the centralizer of W, i.e. an induction over the algebra rather than over its generators.

    So: the weighted trace exists on the actual R-matrix representation, it is compatible with the weight, and it agrees with the permutation character where they meet. It is not yet a Markov trace, and this file does not call it one.

    -- Ref: [jones1987] Hecke algebra representations of braid groups and link polynomials -- Ref: [jimbo1986]; [manuscript] bean qou-k4oq

    The site weight #

    Matrix (Fin n → Fin 2) (Fin n → Fin 2) R

    The site-wise weight on V^{⊗n}: the diagonal matrix whose entry at a basis state a is the product of the per-site weights ∏ₘ w (a m). For w = (1, q²) this is the K^{⊗n} of the quantum trace.

        Cyclicity against a generator. tr_w(σ_a · y) = tr_w(y · σ_a).

        This is what braidAt_comm_siteWeight gives directly: the weight can be moved past the generator's image, and the ordinary trace is cyclic. Extending it to arbitrary x in place of σ_a would need the whole image to centralise W, which is an induction over the algebra rather than over its generators — see the module docstring.
