    The orbit quotient, and the q = 1 Schur–Weyl trace as a count #

    Bean qou-uinl. Builds on qou-qro1 (OrbitCount.lean) and qou-tjys (AtomWordShadow.lean, for not_sameCycle_of_apply_eq).

    What this is for #

    ClassicalTraceFloor states its step 1 as the two hypotheses hSWfree / hSWatom, namely tr_M(β)|_{q=1} = 2^{c(σ_β) − n}, and says plainly that it is "NOT formal here" because Mathlib has no Schur–Weyl duality. That is correct and still true — bean qou-mpq5 measured it (a grep finds only SchurZassenhaus, Schur's lemma, and Matrix.SchurComplement) and scoped the q-deformed double-centralizer as a multi-week gap it deliberately refused to fake.

    🛑 This file does not close that gap. What it closes is the combinatorial core of the q = 1 case, which is much smaller and self-contained:

    the character of σ permuting the factors of V^{⊗n} is (dim V)^{c(σ)}, because σ fixes exactly the basis vectors constant on each cycle.

    In the monomial basis that character is a count of invariant functions, and this file proves that count: orbitCount_invariant_functions gives

    #{f : α → β // ∀ x, f (σ x) = f x}  =  (card β) ^ orbitCount σ

    which at card β = 2 is the 2^{c(σ)} step 1 needs. What remains between here and hSWfree/hSWatom is the linear-algebra wrapper — identifying this count with a trace over an actual tensor power — and, for q ≠ 1, the whole of quantum Schur–Weyl. Neither is here, and neither is claimed.

    What Mathlib is missing, measured #

    Mathlib has Equiv.Perm.SameCycle.setoid, but nothing relating the resulting orbit quotient to cycleType, no count of invariant functions, and no permutation character. Fintype.card_quotient_le is the only quotient-counting lemma in range, and an inequality is not what is needed. So the bridge

    Fintype.card (Quotient (SameCycle.setoid σ)) = orbitCount σ

    is built here from an explicit equivalence: every orbit is either a fixed point or one of the cycle factors — which is exactly the split orbitCount is defined by, so the bridge is what makes orbitCount a genuine count of orbits rather than a cycleType bookkeeping device.

        theorem QOU.MassTheory.orbitCount_invariant_functions {α : Type u_1} [Fintype α] [DecidableEq α] (σ : Equiv.Perm α) (β : Type u_2) [Fintype β] [DecidableEq β] :
        Fintype.card { f : α → β // ∀ (x : α), f (σ x) = f x } = Fintype.card β ^ orbitCount σ

        The q = 1 Schur–Weyl trace, as a count. A function α → β is invariant under precomposition with σ exactly when it is constant on each orbit, so there are (card β) ^ orbitCount σ of them.

        With card β = 2 this is the 2^{c(σ)} that ClassicalTraceFloor's step 1 assumes: σ permuting the factors of (ℂ²)^{⊗n} fixes exactly the basis vectors constant on each cycle. 🛑 Identifying this count with a trace over an actual tensor power is a further step and is not in this file.

        Smoke tests #

        Two endpoints where the answer is known independently, so a direction or off-by-one error in the count fails the build rather than sitting unnoticed.
