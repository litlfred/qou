        class QOU.MassTheory.CableWidthBraneTower.SubstrateWidthRule (w : ℕ → ℕ) :
        Prop

        Substrate width rule, as a predicate ON a given width function.

        w is a per-nucleon-count cable width; SubstrateWidthRule w asserts that this particular w is the SU(3)_color rule.

        Restated 2026-08-24 (bean qou-2y13). w was a field of the class and is_color its only proposition, so the class pinned its own datum to a constant: SubstrateWidthRule had exactly one model (up to funext), the global instance colorRule supplied it, and [SubstrateWidthRule] was w = fun _ => 3 spelled as a hypothesis — a binder that constrained nothing. Taking the width as a parameter (the remedy worked in QOU/Archimedean/JetOrderIndependence.lean) makes the hypothesis falsifiable: it holds of the colour width (colorRule) and fails of any other (not_widthRule_of_ne, and concretely not_widthRule_width_four).

        Note what this does not touch: whether cableWidthColor = 3 is derived from the SU(3) colour content rather than fitted. Take that at face value — it is a claim about the physics, argued in the header, and the defect here was purely structural.

        • is_color (A : ℕ) : w A = cableWidthColor

                theorem QOU.MassTheory.CableWidthBraneTower.cable_width_wall {E0 h κ₉ : ℝ} (hE : E0 ≠ 0) (hh : h ≠ 0) (h9 : levelMagnitude E0 h κ₉ = derivedWidthMagnitude) :

                WALL (scope-(a)) — the derived cable width / brane-tower level does not close the A=3 residual 0-fit. At the derived (color) width w = 3 (level H₉) the magnitude is strictly positive (sign derived, #4360) but ≠ μ₃ (near-miss, 0.63× μ₃); and any level that does close needs a strictly larger derived h⁴-coefficient (ratio μ₃/0.297 > 1), which no substrate rule supplies — the one candidate (n★ = ℓ·n₀ + k) is refuted, overshooting. Right sign, right order, exact closure open — not a fit, not a hard structural exclusion.
