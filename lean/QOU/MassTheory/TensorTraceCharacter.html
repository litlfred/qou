    The permutation character on a tensor power, as an actual trace #

    Bean qou-uinl, stage 2. OrbitQuotientCount proved the count

    #{f : α → κ // ∀ x, f (σ x) = f x} = (card κ) ^ orbitCount σ

    and said plainly that identifying it with a trace was a further step. This file takes that step, in the concrete free-module model.

    The statement #

    For V free of rank card κ, the tensor power V^{⊗α} has monomial basis indexed by α → κ, and σ permuting the tensor factors acts on that basis by precomposition f ↦ f ∘ σ⁻¹. That is a permutation of the basis, so its matrix is a permutation matrix and its trace is a fixed-point count (trace_permMatrixOf below). Those fixed points are exactly the invariant functions, so

    trace (σ on V^{⊗α}) = (card κ) ^ orbitCount σ

    which at card κ = 2 is 2^{c(σ)} — ClassicalTraceFloor's step 1.

    🛑 Why the model is concrete rather than PiTensorProduct #

    Measured, 2026-09-05: Mathlib/LinearAlgebra/PiTensorProduct.lean contains zero occurrences of Basis. Mathlib has PiTensorProduct.reindex — the action itself — but no basis for ⨂[R] i : ι, M, and no finrank lemma for it either. A literal LinearMap.trace (PiTensorProduct.reindex …) statement therefore cannot be written without first constructing that basis, which is a Mathlib-scale contribution in its own right and is presumably why Mathlib lacks it.

    SUPERSEDED IN PART, same day: QOU.MassTheory.PiTensorMonomialBasis now constructs that basis in the case needed — monoEquiv : (⨂[R] _ : α, (κ → R)) ≃ₗ[R] ((α → κ) → R) — and proves monoEquiv_tensorPerm, that permuting the tensor factors corresponds to the indexPerm below. So the concrete model used here is no longer a substitute for the tensor power; it is the tensor power in coordinates, with the identification proved. And QOU.MassTheory.TensorPowerTrace completes it: trace_tensorPerm states the same character with LinearMap.trace over the tensor power itself. The matrix-trace form below remains the computational core both of those rest on.

    So this file works in the standard concrete model V^{⊗α} = ((α → κ) → R), where the monomial basis is definitionally the index type and the whole argument is a permutation-matrix trace. That is not a workaround for the mathematics — it is the monomial-basis computation — but it is a weaker statement than one phrased over ⨂, and the difference is recorded here rather than papered over.

    Why the permutation matrix is defined here rather than imported #

    Mathlib's Equiv.Perm.permMatrix and Matrix.trace_permutation live in Mathlib.LinearAlgebra.Matrix.Permutation, whose import cone reaches Mathlib.Analysis.CStarAlgebra.Matrix — measured, by trying to build it. Pulling a C*-algebra cone into a statement about counting fixed points of a permutation is disproportionate, so permMatrixOf below is defined directly over Mathlib.LinearAlgebra.Matrix.Trace and trace_permMatrixOf reproves the one fact needed (a five-line Finset.sum computation). If the cone is ever trimmed upstream, this should be replaced by the Mathlib pair.
