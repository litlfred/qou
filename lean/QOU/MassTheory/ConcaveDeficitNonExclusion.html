    "A linear term minus a concave deficit" is convexity restated, not a narrowing #

    QOU.MassTheory.AggregatorConvexityDichotomy narrowed the many-body binding magnitude to convex-through-the-origin aggregators Φ in B(A) = Φ(m_A·g): the measured b₃ = +1.4262225 > 0 excludes every concave-through-the-origin Φ for every bond weight and every bond set, and AME's own Φ is convex on the light-nucleus grid.

    QOU.MassTheory.AggregatorFamilyExclusions then excluded, with nothing fitted, five fixed correction shapes in the two-parameter family Φ = c·x + a·ψ(x) — among them the semi-empirical volume-minus-surface member c·x − a·x^{2/3}.

    A follow-up was proposed off the back of that: excluding the whole linear-minus-concave-deficit class Φ(x) = c·x − a·ψ(x), ψ concave, by showing its local exponent must decrease while the measured one increases.

    This file shows that route is not merely unproved — it cannot succeed, and the obstruction is not analytic but definitional.

    The content #

    On a three-point grid through the origin, write the three secant slopes s₀ = f₁/x₁, s₁ = (f₂−f₁)/(x₂−x₁), s₂ = (f₃−f₂)/(x₃−x₂). Convexity through the origin is s₀ ≤ s₁ ≤ s₂; concavity is the reverse chain.

    Subtracting the data from a linear function negates every slope (deficit_secant₀, deficit_secant₁, deficit_secant₂: the deficit's slopes are c − sⱼ). Hence:

    • deficit_concave_iff_convex — the deficit ψ := c·x − Φ is concave through the origin iff Φ is convex through the origin, for every c;
    • deficit_increasing_of_gt_secant₂ — and ψ is strictly increasing as soon as c exceeds the largest secant slope.

    So exists_concaveDeficit_of_convex: every convex-through-the-origin dataset is exactly c·x − ψ(x) for a strictly increasing concave-through-the- origin ψ, for every c above its top slope — an open ray of witnesses, not a lucky one. concaveDeficit_class_not_excludable states the consequence in the form the follow-up needs: no three-point test can exclude the class, because membership follows from the convexity the same three points establish.

    Why this does not contradict the determinant exclusions #

    AggregatorFamilyExclusions.not_realizable_of_det3_ne_zero excludes a two-parameter family with ψ fixed in advance: three points, two parameters, one residual. Here ψ is a free shape — chosen after the data — so the family has as many parameters as the grid has points and there is no residual left to fail. The five shape exclusions are about parameter counting; they say nothing about the concave-deficit structure, and this file says the structure is vacuous as a constraint.

    ame_grid_is_convex pins the antecedent on the corpus's own numbers, and ame_grid_has_concave_deficit exhibits a concrete witness at c = 7, so the statement is not vacuously true here.

    What this does NOT establish #

    • It says nothing about whether any particular ψ is right — only that "concave deficit" is not a filter. A fixed shape is still testable by det3.
    • It does not refute the proposed monotone-exponent claim as a statement about ψ(x) = x^s, where it is true. It shows that no such claim can generalise to the class, since the class contains the data itself.
    • Three points are three points: this is a statement about what a three-point grid can decide, and the standing recommendation to extend the grid past A = 4 is what would change it.

    Base ring: generic [Field R] [LinearOrder R] [IsStrictOrderedRing R] (§7c) — no archimedean construct is used.

                    The consequence for the proposed exclusion. Stated as: the class-membership predicate is implied by the antecedent, so it cannot be false on a convex dataset.

                      The same statement on an arbitrary grid #

                      The three-point version above matches the corpus's grid. Nothing in it depends on there being three points, and that matters for what to do next: the natural reading of the result is "get a fourth data point and the class becomes testable", and that reading is wrong. The equivalence below is uniform in the number of grid points, so no amount of extra data can exclude the class.

                      Index a grid by Fin (n+1) with x 0 = 0, f 0 = 0 if the origin is wanted — the statements do not need that hypothesis, since the origin is just index 0.
