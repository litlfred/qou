    QOU.Eightfold.OcneanuTwoThreeNotProportional — the N=2 and N=3 weight ratios differ #

    Bean qou-bhfg. Companion to docs/audits/2026-08-25-n3-exclusion-provenance-audit.md (route 3).

    What this closes #

    One of the seven N = 3 exclusions is "re-tune the Ocneanu parameter to N = 3", excluded because the N=2 and N=3 traces are not proportional. Its source (docs/audits/2026-08-07-two-row-projection-is-the-pairwise-cap.md) supplies the closed form

    y_{(2,1)} / y_{(3)}  =  q [2]_q [N−1]_q / [N+2]_q

    and then concludes non-proportionality because the ratio "differs at every q tested". The formula is symbolic; that last step was sampling. A provenance audit that reports the row as resting on exact algebra should not leave the inference resting on a finite sample, so it is proved here instead.

    The identity #

    At N = 2 the ratio is q [2]_q [1]_q / [4]_q; at N = 3 it is q [2]_q [2]_q / [5]_q. Cancelling the common nonzero q [2]_q, they agree iff [1]_q [5]_q = [2]_q [4]_q. And there is an exact identity:

    [2]_q [4]_q  −  [1]_q [5]_q  =  [3]_q

    (an instance of [a][b] − [a−1][b+1] = [b−a+1]). So the two ratios agree iff [3]_q = 0 — a single, checkable condition, rather than a sample.

    qb_three_eq gives [3]_q = q² + 1 + q⁻², so over an ordered field the condition fails outright; that discharge is QOU.Archimedean.OcneanuTwoThreeSubstrate, kept separate per §7c. Nothing in this file mentions ℝ or an ordering.

    Scope #

    This is an identity about q-brackets and the quoted ratio formula. It does not re-derive the ratio formula itself from the Hecke weights — that is the source audit's, consumed here as the definition of what is being compared. It therefore strengthens the exclusion's stated reason from sampled to proved, and claims nothing further about N = 3.

      theorem QOU.Eightfold.OcneanuTwoThreeNotProportional.qb_shift_identity {R : Type u_1} [Field R] (q : R) (hq : q ≠ 0) (hq2 : q ^ 2 ≠ 1) (n : ℕ) :
      qb q (n + 1) * qb q (n + 3) - qb q n * qb q (n + 4) = qb q 3

      The general shift identity. [n+1]_q [n+3]_q − [n]_q [n+4]_q = [3]_q for every n — the right-hand side does not depend on n.

      This is the statement the exclusion actually wants. Comparing the Ocneanu weight ratio at N and at N+1 reduces to this cross-product difference, and it is [3]_q at every N. So re-tuning does not fail to reproduce the N = 2 weighting only at N = 3: every adjacent pair of N re-weights, and always by the same amount.

      theorem QOU.Eightfold.OcneanuTwoThreeNotProportional.ratio_eq_iff_qb_three_eq_zero {R : Type u_1} [Field R] (q : R) (hq : q ≠ 0) (hq2 : q ^ 2 ≠ 1) (h2 : qb q 2 ≠ 0) (h4 : qb q 4 ≠ 0) (h5 : qb q 5 ≠ 0) :
      q * qb q 2 * qb q 1 / qb q 4 = q * qb q 2 * qb q 2 / qb q 5 ↔ qb q 3 = 0

      The gate. The N=2 and N=3 Ocneanu weight ratios are equal iff [3]_q = 0.

      Stated as an iff deliberately: it says exactly what would have to happen for the two traces to be proportional, rather than asserting they are not. The archimedean file rules the right-hand side out.
