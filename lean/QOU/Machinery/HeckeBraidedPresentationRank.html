    A rank-bounded braided presentation — and the corpus's first content-bearing instance #

    HeckeBraidedCategory.HeckeBraidedPresentation quantifies its three relations over all i : ℕ, i.e. it describes H_∞. Two facts about that, both proved in HeckeTowerBasicConstruction:

    • it is satisfiable degenerately — a single element meeting the quadratic gives an instance via the constant family, with braid and far-commutation rfl (constant_generator_presentation);
    • and no finite H_n satisfies it with its true generators (far_commute_zero; the same obstruction, covering both padding routes, is recorded in prose in HeckeH3AlgebraLaws's honesty note, which predates this file — the Lean version machine-checks half of what was already known there).

    Together those say the class cannot be given a useful instance: the reachable ones carry no Hecke content, and the contentful ones do not exist.

    HeckeBraidedPresentationOfRank fixes that by bounding the relations to a rank n, which is what a finite Hecke algebra actually satisfies. It is a NEW class rather than a change to the old one: twelve files bind HeckeBraidedPresentation, and mutating its signature is a refactor whose blast radius is unrelated to the point being made here.

    What this buys #

    heckePresentationOfRank_H3A is an instance with real content: the genuine H₃(q) on the six-element normal-form basis, its two true generators σ₀ and σ₁, the Hecke quadratic for both, and the braid relation σ₀σ₁σ₀ = σ₁σ₀σ₁. Nothing is padded and nothing is constant — σ₀ and σ₁ are distinct and do not commute.

    It is, as far as the corpus goes, the first presentation instance of any kind. The concrete layer it is built from (H3A, mulNF, the proved laws) is pre-existing; what is new is that a presentation class now has somewhere to land.

    What it does NOT do #

    It does not give HeckeCosetSpanning an instance. That class binds the unbounded presentation, so re-pointing it at this one is a further change, deliberately not made here — and the spanning statement itself would still need proving for H₂ ⊂ H₃ afterwards.

          H₂ ⊂ H₃: the spanning decomposition, concretely #

          product basis index
          σ₁ 2
          σ₁ · σ₀ 3
          σ₀ · σ₁ 4
          σ₀ · σ₁ · σ₀ 5

              The conditional expectation for H₂ ⊂ H₃ #

              ε is FORCED on the basis once the Markov property is imposed, given the coset table above:

              ε γ = γ, ε σ₀ = σ₀ (retraction on the image) ε σ₁ = z•γ (Markov) ε (σ₁σ₀) = z•σ₀, ε (σ₀σ₁) = z•σ₀ (bimodule, one side trivial) ε (σ₀σ₁σ₀) = z•σ₀² = z•(h•σ₀ + 1) (bimodule, both sides)

              so in coordinates

              ε v = ⟨v₀ + z·v₂ + z·v₅ , v₁ + z·v₃ + z·v₄ + z·h·v₅⟩.

              Nothing is chosen here: every entry is read off the table.

                  WenzlTowerStep at this rung is a TRIVIAL discharge — read this before citing it #

                  WenzlTowerStep's field is an implication whose conclusion is IsSemisimpleRing Hn1. At H₂ → H₃ that conclusion is already a theorem — isSemisimpleRing_H3A, via the explicit Wedderburn decomposition — so the field can be discharged by ignoring both hypotheses and citing it.

                  That is what wenzlTowerStep_H2_H3_trivial below does, and it is why the name says so. It is a true statement and it is not Wenzl's ascent: the induction step (semisimplicity of Hₙ plus trace nondegeneracy implying semisimplicity of H_{n+1}) is never exercised. Anything downstream that cites this as evidence the ascent is formalized would be wrong.

                  The same shape as constant_generator_presentation: an instance can exist while carrying none of the content its class is named for. Recorded for the same reason — so the next reader does not mistake inhabitation for content.

                  The general-n ascent remains open. It is the actual target, and no part of this file touches it.

                  WenzlTowerStep at GENERAL rank, for the regular trace #

                  wenzlTowerStep_H2_H3_trivial above discharges the field by discarding both hypotheses — it proves nothing about the ascent. This does the opposite, and the difference is the point.

                  Read the field again:

                  semisimple_ascend :
  IsSemisimpleRing Hn →
  (∀ y : Hn1, y ≠ 0 → ∃ z, trn1 (y * z) ≠ 0) →
  IsSemisimpleRing Hn1

                  The second hypothesis is exactly left-nondegeneracy of trn1. So when trn1 is the algebra trace, QOU.MathlibExt.isSemisimpleRing_of_trace_nondegenerate discharges the field from that hypothesis alone — at every rank, with no appeal to any particular H_n.

                  And the first hypothesis is then redundant. IsSemisimpleRing Hn is never used. That is a fact about the class worth stating plainly: for the algebra trace the ascent does not need semisimplicity at the level below, only nondegeneracy at the level above.

                  Scope — the one thing this does NOT settle #

                  It holds for trn1 = algTrace. Whether QOU's Markov trace is the algebra trace, or a nonzero multiple of it, is a separate question and is not settled here. If the Markov trace is some other functional, this instance does not apply to it and the general-n ascent for that trace remains open. Do not cite this as "the Wenzl ascent is formalized" without first pinning down which trace is meant.

                  The semisimplicity engine is NOT proved here — it is QOU.MathlibExt.isSemisimpleRing_of_regTraceForm_nondegenerate, which the corpus has carried since brick B3d (epic qou-hnhg).
