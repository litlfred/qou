    Hecke algebra H_n(q) — abstract scaffold #

    The Iwahori-Hecke algebra is presented as a quotient of the braid group algebra of B_n by the relation (σ_i - q)(σ_i + q⁻¹) = 0 (AGENTS.md §7a Hecke-Skein convention). Mathlib has only a basic stub; here we axiomatise the structure for downstream consumers.

    Removed: the QOU.Machinery.HeckeAlgebra marker class #

    There used to be a second class of that name here:

    class HeckeAlgebra (R) [CommRing R] (q : R) (n : ℕ) (H) [Ring H] [Algebra R H] : Prop where
  hecke_structure : True

    described as an "opaque marker … instance gates the categorical promotion". It gated nothing: the sole field is True, so ⟨trivial⟩ instantiates it and any [HeckeAlgebra …] hypothesis drawn from it carries no content — the skill's : True-carrier pattern (lean-proof-vacuity-audit.md §7).

    It also collided by name with the real QOU.Hecke.HeckeAlgebra (embed / quadratic / braid / farCommute / spans), which is what every actual consumer in the tree uses.

    Removed rather than fixed, because it had zero consumers: all five importers of this module referenced it zero times, and no file reached it via open QOU.Machinery. The real class now also has a real instance at n = 2 (QOU.Hecke.InstanceH2), so a contentless marker has nothing left to mark.

    Markov trace as a linear functional #

    source
    class QOU.Machinery.MarkovTrace (R : Type u_1) (H : Type u_2) [CommRing R] [Ring H] [Algebra R H] (tr : H → R) :
    Prop

    A Markov trace on H_n(q) is a linear functional satisfying the Markov reduction property.

    Two of the three Markov laws are now enforced as Lean propositions over the (tr : H → R) parameter (H is a Ring, R-algebra): (M1) R-linearity of tr and (M2) conjugation invariance tr (x·y) = tr (y·x). The third law, (M3) Markov reduction tr (x·σ_{n-1}) = z·tr (x), still requires the generator σ_{n-1} — not a parameter of this class — so it remains documentation for the eventual instance, not an enforced field.

    • cyclic (x y : H) : tr (x * y) = tr (y * x)

      (M2) Conjugation invariance / cyclicity: tr (x·y) = tr (y·x).

    • map_add (x y : H) : tr (x + y) = tr x + tr y

      (M1a) Additivity — part of R-linearity of tr.

    • map_smul (r : R) (x : H) : tr (r • x) = r * tr x

      (M1b) R-scalar compatibility — the rest of R-linearity.

                    Extending past H₃ (open keystone infra) #

                    The H3 realization above is n = 3-specific (the Fin 6 NF basis [γ, σ₀, σ₁, L₊, L₋, e⁻]). The markov_trace_origin marker (QOU.BraidKnot.MmuR9V9Closure.UniversalHabiroStructure) needs the trace for general n — the fun n r => ℏ_rⁿ family — which requires two ingredients this file does not yet carry:

                    1. The H₄(q) NF basis + mulNF table — DONE (verified 2026-08-22). This item is no longer open, and the paragraph that followed it described the work as still to do for roughly a month after it landed. What exists now:

                      • computations/markov/hecke-regular-nf-h4.witness.json — "H_n(q) regular-rep GB-NF generator actions + Ocneanu/Markov trace; H3 validation + H4 emission for the Lean H4 Markov-trace formalization" (bean qou-1jrr). Generated from the confluent Gröbner normal forms, as this block required — not hand-written, not a local-rewriting Python reimplementation.
                      • QOU.Machinery.H4Cyclicity — the Fin 24 subscript basis (24 = 4! GB normal forms, exactly the count this block predicts) with the e₄_eq_mul_* factorizations. Sorry-free, as are H4GeneratorAction, HeckeH4RepDecomp, BilinearTraceRepBasis and BilinearTraceCyclicity: zero real sorry across the whole cluster.
                      • QOU.Machinery.MarkovTraceH4 — trM_cyclic for n = 4, off gram_symm's 576 computed entries, reduced through BilinearTraceCyclicity.cyclic_of_gram_symm.

                      The reducer caveat this block recorded was correct and was respected: the H₄ table does come from the GB route, not from Hecke + commute + adjacent-braid local rewriting (which is non-confluent and yields 60+ irreducibles rather than 24). Reducer caveat, retained for anyone extending to H₅ (verified 2026-07-13). gram.py's _reduce_nf is H₃-specific: it applies only the Hecke-square and adjacent braid moves, which suffice for H₃ (whose two generators σ₀,σ₁ are adjacent). H₄ also needs the non-adjacent commuting relation σ₀σ₂ = σ₂σ₀, and even Hecke + commute + adjacent-braid is not confluent — a BFS over that rule set yields 60+ irreducible words, not the 24 = 4! GB normal forms. Use the confluent reducer (hecke-engine's gb_nf_reducer.rs, Rust, permutation/Coxeter-canonical and general-n), not a naive local-rewriting Python reimplementation.

                    2. The Ind_{H₃}^{H₄} Markov stabilization. The general-n trace is built from the H₃ trace by the Markov induction/stabilization the (M3) law encodes; the trM_markov_σ₁ reduction here is the n = 3 base case. The n = 4 case is numerically confirmed — tr_M⁴(x·σ₂) = z·tr_M³(x) and tr_M⁴(x) = tr_M³(x) hold for H₃ words beyond the weight-pinning constraints (over-determination test, float64) by computations/probes/markov_reduction_h3_to_h4_verify.py, via the same seminormal machinery as alpha_k_jones_markov_h4.py. That is evidence for ingredient (2); the Lean-grade proof still awaits a symbolic-exact cyclicity argument over ℚ(z,h) (ingredient (1)'s table is now in hand — see item 1 above).

                      Read that citation with three caveats (measured 2026-08-22, bean qou-ze9n). The cited probe (a) is written in convention C, z = 1/(√q + 1/√q) = 0.4993…, which the 2026-08-15 ruling excised in favour of D's q³/(q²+1) = 0.6127…, a 23 % difference; (b) computes in float64 throughout, which was never necessary — the seminormal machinery accepts and returns mpf; and (c) did not run as committed, its bootstrap omitting qou-substrate and pointing at the pyhecke package directory rather than its parent.                       The conclusion survives all three, which is why item 2 still stands. computations/probes/markov_reduction_h3_to_h4_conventions.py re-runs the same over-determination test at 50 dps under both conventions and finds the reduction holds either way, worst residuals ~1e-51 against a 1e-30 tolerance — agreement to the limit of the arithmetic used, not an exactness claim. The reason is structural: z is an input to the weight solve, not an output, so the Ocneanu trace is a one-parameter family and the Markov law is insensitive to which member is chosen. Prefer the companion probe for new work.
