    QOU.Machinery.H4AsciiPresentation — the Hecke presentation on the ASCII basis #

    The tree carries two 24-word normal-form bases for H₄(q). The subscript basis (HeckeH4StabilizationRung) has the full presentation proved on it: mulσ₀_hecke, mulσ₁_hecke, mulσ₂_hecke, braid_σ₀σ₁, braid_σ₁σ₂, far_commute_σ₀σ₂. The ASCII basis (MarkovTraceH4, the one carrying trM and the sorry-free trM_cyclic) is a different table, so none of those transfer for free; until H4BasisBridge closes phi_mulNF they have to be checked on each side separately.

    This file is that check, on the ASCII generator actions mulσ0/1/2:

    lemma depth relation subscript counterpart
    mulσ_sq0/1/2 2 σₖ² = 1 + h·σₖ HeckeH4StabilizationRung.mulσₖ_hecke
    mulσ_farcomm02 2 σ₀σ₂ = σ₂σ₀ …far_commute_σ₀σ₂
    mulσ_braid01/12 3 σᵢσⱼσᵢ = σⱼσᵢσⱼ …braid_σ₀σ₁, …braid_σ₁σ₂

    All six by fin_cases + simp + ring, on a free vector at depth ≤ 3 — about thirteen seconds for the lot. Base ring is generic [CommRing R]: none of them uses inversion, so none needs a field.

    n = 4 is where far-commutativity first has content at all: Generator n carries idx : Fin (n - 1), and Generator.farCommuting needs two indices differing by ≥ 2, so it is unsatisfiable until n - 1 ≥ 3.

    Provenance #

    These were proved in QOU/Hecke/InstanceH4.lean, which wrapped them as the relation fields of a HeckeAlgebra R 4 q instance on Algebra.adjoin R {L0,L1,L2} ⊆ Module.End R (Fin 24 → R) — the right regular representation, so that associativity was function composition. That carrier has been retired (bean qou-ti7p): QOU.Hecke.InstanceOnH4A.instHeckeAlgebraH4A now puts the class on H4A, the tree's actual H₄ ring, where IsHeckeOfFullRank K 4 holds of the same carrier (FullRankFromWedderburn.isHeckeOfFullRank_H4A) — which the operator algebra never delivered. The relations themselves were not duplicated anywhere, because they are on the ASCII table; they are what survives, and they live here.

    mulσ_farcomm02 was also proved a second time in H4BasisBridge, which needs it to normalise the six words where the two bases differ. That copy is gone; the bridge imports this module.

      The right basis action #

      mulNF is a 24-term sum ∑ⱼ vⱼ · (u · bⱼ), with the composites written out inline. Packaging them as a function of the index — exactly what HeckeH4AlgebraLaws.wordAction does for the subscript basis — turns that inline sum into a Finset.sum, which is the only form in which the 24 terms can be reindexed rather than expanded. H4BasisBridge needs precisely that: the two bases differ by the permutation piIdx, so the products correspond by reindexing the sum, not by unfolding it (three simp-based unfolding attempts failed, one producing 70 terms where 24 were expected).

      wordActionA is transcribed from mulNF's own term list and cross-checked against it, and against the 24 H4BasisBridge.phi_word_* statements — all 24 agree — so it cannot silently drift from the table it describes.
