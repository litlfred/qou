    Markov-axiom recursive ascent for the Jones–Markov trace #

    Lean scaffold for the production recursive-ascent algorithm implemented in computations/markov/markov_peel.py (#508 / PR #516).

    The Python production path evaluates tr_M(β) for atomic braids by peeling the topmost generator via the Markov axiom

    tr_M^{(n)}(x · σ_{n−1}) = z · tr_M^{(n−1)}(x) ∀ x ∈ H_{n−1}(q)

    recursing down H_n ⊃ H_{n−1} ⊃ … ⊃ H_1. At every step the Hecke quadratic σ_i² = (q − q⁻¹)·σ_i + 1 produces a binary branching, but the recursion terminates in time bounded by the braid length.

    This file states the abstract typeclass MarkovTrace encoding the three defining axioms (M1 cyclicity, M2 Markov, M3 unit) over an arbitrary Hecke-like algebra type, plus the key reference proposition markov_pair_z2 (prop:markov-pair-z2).

    The recursive evaluator markov_peel itself is left as a noncomputable declaration with a sorry carrying a bibliographic citation per AGENTS.md §1; concrete computational witnesses live in markov-peel-atomic-tr-m.witness.json and the Python implementation, both verified against atomic-tr-m-mpfr-50dps.witness.json (Hoefsmit + Wenzl bridge).

    Main definitions #

    • MarkovTrace H R — typeclass: a Markov trace on H valued in R
    • markov_pair_z2 — the trace-pair identity tr_M(σ_i · σ_j) = z² for the simplest non-trivial case (which the production tr_M_sigma_pair_is_z² test verifies).

    §1 Abstract Markov trace #

    source
    class QOU.Interactions.MarkovTrace (H : Type u_1) [Mul H] [One H] [Add H] (R : Type u_2) [CommRing R] [SMul R H] :
    Type (max u_1 u_2)

    A Markov-trace structure on a multiplicative algebra H valued in a commutative ring R. Encodes the three defining axioms of the canonical Jones-Markov trace, plus the Hecke-tower nesting axioms required for recursive ascent:

    • (M1) Cyclicity: tr (a * b) = tr (b * a)
    • (M2) Markov peel: tr (x * σ_{n-1}) = z * tr x whenever x lies in the rank-(n-1) subalgebra generated by σ_0, ..., σ_{n-2}.
    • (M3) Unit: tr 1 = 1
    • (N1) Tower nesting: belowTop n x → belowTop (n+1) x (the rank-(n-1) subalgebra embeds in the rank-n one).
    • (N2) Lower-gen closure: multiplying by top k for k < n preserves belowTop n.
    • (H1) Hecke quadratic: top n * top n = h * top n + 1 where h = q − q⁻¹. This is the algebraic input that lets us derive the inverse-generator trace tr (x * (top n)⁻¹) = (z − h) * tr x (see markov_inv below) without adding a separate axiom.

    top selects the topmost generator at strand-count n; belowTop n x predicts whether x lives in the rank-(n-1) subalgebra (i.e. is generated by top 1, ..., top (n-1)).

    • tr : H → R

      The trace function.

    • z : R

      The Markov parameter z = 1 / (q^½ + q^{-½}).

    • h : R

      The Hecke parameter h = q − q⁻¹.

    • top : ℕ → H

      Topmost-generator selector at strand-count n.

    • belowTop : ℕ → H → Prop

      Rank predicate: belowTop n x iff x ∈ H_{n-1} (no σ_{n-1}).

    • cyclic (a b : H) : tr (a * b) = tr (b * a)

      (M1) Cyclicity.

    • unit_one : tr 1 = 1

      (M3) Unit.

    • markov (n : ℕ) (x : H) : belowTop R n x → tr (x * top R n) = z H * tr x

      (M2) Markov peel. For any x in the rank-(n-1) subalgebra, multiplying by the topmost generator σ_{n-1} factors a z out of the trace.

    • belowTop_succ (n : ℕ) (x : H) : belowTop R n x → belowTop R (n + 1) x

      (N1) Tower nesting: H_{n-1} ↪ H_n. An element below the n-th top is automatically below the (n+1)-th.

    • belowTop_mul_lower (n k : ℕ) (x : H) : k < n → belowTop R n x → belowTop R n (x * top R k)

      (N2) Lower-generator closure: multiplying a rank-(n-1) element by a strictly-lower-index generator stays in rank-(n-1). The condition k < n (rather than k+1 < n) is what makes the proof of markov_pair_z2 go through — we need x * top (n-1) to remain belowTop n.

    • hecke_quadratic (n : ℕ) : top R n * top R n = h H • top R n + 1

      (H1) Hecke quadratic relation on the topmost generator. Equivalently top n * top n = h * top n + 1. Combined with cyclicity and (M2) this derives the inverse-generator trace identity markov_inv below.

      theorem QOU.Interactions.markov_inv {H : Type u_1} [Mul H] [One H] [Add H] {R : Type u_2} [CommRing R] [SMul R H] [tr : MarkovTrace H R] (n : ℕ) (x inv_top : H) (h_inv_decomp : MarkovTrace.tr (x * inv_top) = MarkovTrace.tr (x * MarkovTrace.top R n) - MarkovTrace.h H * MarkovTrace.tr x) (h_below : MarkovTrace.belowTop R n x) :
      MarkovTrace.tr (x * inv_top) = (MarkovTrace.z H - MarkovTrace.h H) * MarkovTrace.tr x

      Inverse-generator trace identity.

      Given the Hecke quadratic top n * top n = h · top n + 1 (axiom (H1) of MarkovTrace), the formal inverse satisfies (top n)⁻¹ = top n − h · 1 inside any concrete instance. For an element x in the rank-(n−1) subalgebra, the trace of x · (top n)⁻¹ is therefore

      tr (x · (top n)⁻¹) = (z − h) · tr x.

      This derivation is algebraic — combining (M2) Markov peel with (H1) Hecke quadratic suffices. The full inversion-as-an- element-of-H requires a Sub / Module R H structure that isn't declared on the bare MarkovTrace typeclass; we therefore parameterise the statement on the trace decomposition tr (x · inv_top) = tr (x · top n) − h · tr x that any concrete instance can supply (linearity of the trace

      • Hecke-inverse identity). The theorem then closes the loop by combining that decomposition with (M2) and ring arithmetic.

      theorem QOU.Interactions.markov_pair_z2 {H : Type u_1} [Mul H] [One H] [Add H] {R : Type u_2} [CommRing R] [SMul R H] [tr : MarkovTrace H R] (n : ℕ) (h_n : n ≥ 2) (x : H) (h_below_pred : MarkovTrace.belowTop R (n - 1) x) :
      MarkovTrace.tr (x * MarkovTrace.top R (n - 1) * MarkovTrace.top R n) = MarkovTrace.z H ^ 2 * MarkovTrace.tr x

      prop:markov-pair-z2: Markov trace of an adjacent generator pair at the top of the tower.

      Specifically, when x ∈ H_{n-1} lies in the rank-(n-1) subalgebra, the trace of x · σ_{n-1} · σ_n factors as z² · tr x — two consecutive Markov peels at strands n and n-1.

      This is the simplest non-trivial application of the Markov axiom; the corresponding non-adjacent identity (for σ_i, σ_j with |i − j| ≥ 2) follows from this one plus far-commutativity and cyclicity, but is not the statement here — the present theorem covers the adjacent case top n, top (n-1).

      Proof sketch (closed under the new tower-nesting axioms):

      1. From belowTop_mul_lower, x · top (n-1) is still in rank-(n-1) whenever x is.
      2. Apply (M2) at strand n: tr (x · top (n-1) · top n) = z · tr (x · top (n-1)).
      3. Apply (M2) at strand n-1: tr (x · top (n-1)) = z · tr x using belowTop_succ to lift x into rank-(n-2) ⊂ rank-(n-1).
      4. Compose to get z² · tr x.

      n ≥ 2 is required so that both top n and top (n-1) refer to actual tower generators (the Hecke tower starts at H_1, with top 1 the first non-trivial generator).

      The Python production test test_tr_M_sigma_pair_is_z_squared verifies the identity numerically.

      Recursive Markov-axiom evaluator.

      Production-side analogue of markov_peel.tr_M_atomic. Takes a Hecke-algebra element x and a strand count n, peels the topmost generator via (M2) when present, and recurses on the residue. The base case is tr_M^{(1)}(1) = 1.

      Currently a noncomputable declaration whose body is the abstract trace — concrete recursion is supplied by the Python production path (verified against the Hoefsmit + Wenzl bridge to ~1e-15) and by future concrete MarkovTrace instances on HeckeNF.
