    v_[2] is not a descent measure on D∞ (bean qou-4atn, settled negative) #

    reaches_cycle_of_descent_domainStable reduces q-Collatz convergence on the domain-stable cone to the existence of a measure μ : Skein → ℕ with

    ∀ P, domainStable P → P ≠ attractor → μ (C P) < μ P.

    The natural candidate is the [2]_q-adic valuation v_[2]. Two landed results bracketed it without settling it:

    • collatz_vtwo_obstruction.qcollatz_vTwo_increases_on_odd_branch — v_[2] increases on the witness -X-2;
    • collatz_vtwo_domain_rescope.qcollatz_vTwo_witness_escapes_domain — but that witness escapes the domain, so it says nothing about D∞.

    The positive datum was collatz_vtwo_cycle_descent: v_[2] does drop 1 → 0 on the even step of the fundamental cycle. Bean qou-4atn recorded the question as re-opened.

    This file settles it: v_[2] does not descend on D∞. The reason is structural rather than a lucky witness, and that is what makes it useful.

    The obstruction #

    μ takes values in ℕ. So μ (C P) < μ P is impossible wherever μ P = 0 — nothing in ℕ lies below 0. Hence any working descent measure must be strictly positive at every non-attractor point of the cone (descent_measure_pos_off_target).

    But v_[2] vanishes on every q-odd element: q-odd means [2]_q ∣ P + 1, and if [2]_q also divided P it would divide 1 and be a unit, which it is not (T1_add_one_not_isUnit). So v_[2] P = 0 for every q-odd P (laurentTwoVal_qOdd).

    D∞ contains q-odd elements other than the attractor. Therefore v_[2] fails.

    The witness, and how it was found #

    witnessP = q⁻¹·(q⁶+7q⁵+20q⁴+29q³+21q²+6q+1) is q-odd, lies in D∞, and its Collatz image is witnessCP = q⁻¹·(q+1)⁷ — so v_[2] goes 0 → 7 in one step.

    It was produced by construction, not search (computations/qcollatz_vtwo_domain_stable_probe.py): every backward orbit of the attractor cycle lies in D∞ by definition, because if C^[n](P) is the cycle then every forward iterate of P is defined. The probe generates that backward tree exactly — even-preimage [2]_q·P, odd-preimage ([2]_q P − 1)/[3]_q when exact — in exact ℤ[q^{±1}] arithmetic, and also verifies each node forward by iterating to the cycle, so D∞ membership is established twice. witnessP reaches the cycle in 7 steps. The probe finds the same failure at every odd-branch node it generates (3 of 3, at v_[2] jumps 0 → 7, 0 → 13, 0 → 19) — as the structural argument predicts, since every q-odd point sits at valuation 0.

    Scope — (a), and what it does not say #

    This is a scope-(a) negative: it refutes v_[2] as the descent measure, and says nothing about whether some other measure descends on D∞. It is not a structural exclusion of the descent route.

    What it does buy going forward is a genuine necessary condition on any candidate μ: by descent_measure_pos_off_target, μ must be strictly positive at every non-attractor point of D∞. Since D∞ contains q-odd points, any valuation-like candidate that vanishes on the q-odd part is excluded for the same reason — so the next candidate must not be one.

    Base ring: the obstruction is over an arbitrary type; the witness identity is over a generic [CommRing R] with q a unit (§7c); only the valuation statement needs the Laurent ring.

        Part 4 — the refutation #

        source
        theorem QOU.AppendixSurreals.CollatzVTwoDinfRefutation.vTwo_not_descent_measure (f : LaurentPolynomial ℤ → LaurentPolynomial ℤ) (target : LaurentPolynomial ℤ) (S : LaurentPolynomial ℤ → Prop) (hS : S witnessP) (hne : witnessP ≠ target) :
        ¬∀ (x : LaurentPolynomial ℤ), S x → x ≠ target → (MathlibExt.LaurentTwoValuation.laurentTwoVal (f x)).toNat < (MathlibExt.LaurentTwoValuation.laurentTwoVal x).toNat

        v_[2] is not a descent measure on any cone containing witnessP.

        In particular it is not one on D∞, which does contain witnessP (verified both by construction as a backward orbit of the attractor and forward by iteration). Instantiating f at the Skein-Collatz map, target at the attractor and S at domainStable refutes exactly the hdesc hypothesis of reaches_cycle_of_descent_domainStable for μ = v_[2].

        Scope (a). This excludes v_[2], not the descent route: some other μ may still work. What survives as forward guidance is descent_measure_pos_off_target — any candidate must be strictly positive at every non-attractor point of the cone.
