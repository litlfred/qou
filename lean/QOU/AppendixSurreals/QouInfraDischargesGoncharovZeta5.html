    QOU.AppendixSurreals.QouInfraDischargesGoncharovZeta5 — conjecture carrier #

    §3b-cond class axiomatisation for content block conj:qou-infra-discharges-goncharov-zeta5: QOU's Hecke-NF + Bring-S₅ infrastructure discharges Goncharov's depth-3 conjecture at F = ℚ(ζ₅).

    Primary conjecture carrier with no instance — the honest open state per AGENTS.md §3b-tax.

    What changed (bean qou-ffwk) #

    The previous field schema was a scalar plus a field asserting that it vanishes, inhabited by ⟨0, rfl⟩. The class chose its own witness, so it asserted nothing and a downstream hypothesis on it was not a meaningful conditional.

    Its docstring's "Content statement (from manuscript)" was also the conjecture's own title, repeated — it recorded no content at all, so the block was the only source. Fixed here.

    What is encoded: the block's own reduced target #

    The full statement quantifies over motivic cohomology — K₅^ind(F) ⊗ ℚ ≅ 𝔅₃(F) ⊗ ℚ, the weight-3 Bloch group, the Goncharov 22-term relation, the regulator into 𝒫₃/𝒫₂. None of that exists in this library, and neither do polylogarithms; inventing any of it would assert constructions the corpus does not have.

    The block does not require that, because it states its own reduced form:

    The reduced target for QOU is to prove that {Li₃(ζ₅ᵏ) : k = 1,2,3,4} modulo the multiplication-formula identity span exactly this rank-2 image.

    with the rank supplied by Borel: dim_ℚ K₅^ind(ℚ(ζ₅)) ⊗ ℚ = 2. That is a statement of linear algebra over ℚ about four named elements, and it is encodable exactly as written.

    So the class takes the ambient ℚ-space and the four values as caller data, and asserts the rank. V stands for 𝒫₃/𝒫₂ over ℚ(ζ₅) and li3 k for Li₃(ζ₅^{k+1}); both are parameters because this library builds neither.

    What is deliberately not encoded #

    • The two routes. Jones-coincident pair generation and the direct construction of G₂₂(ζ₅) are strategies — the block says "if either route succeeds". A carrier that encoded a route would assert a proof method as part of the claim.
    • "the only further relation being the 22-term one." This constrains the relation module beyond its dimension. Its dimension is already forced — relations_finrank_eq_two below derives it — but which relations they are needs G₂₂ written down, and that needs polylogarithm identities the library does not have. Encoding a placeholder for it would be the defect this bean exists to remove.
    • Borel's theorem. The rank 2 enters as the content of the conjecture at this level, not as a cited input; the block uses Borel to say what the target rank is, and the open question is whether the four Li₃ values realise it.

    Base ring (§7c) #

    ℚ-linear throughout, with no real-field type anywhere: the target is a ℚ-vector space and the rank is an integer. Nothing is ordered, normed, or compared against a numerical substrate value. ζ₅ appears only in prose naming the arguments, never as a computed quantity.

    class QOU.AppendixSurreals.QouInfraDischargesGoncharovZeta5 (V : Type v) [AddCommGroup V] [Module ℚ V] (li3 : Fin 4 → V) :
    Prop

    Goncharov's depth-3 conjecture at ℚ(ζ₅), in the block's reduced form.

    See conj:qou-infra-discharges-goncharov-zeta5.

    Parameters are the caller's data:

    • V — the target ℚ-space, standing for 𝒫₃/𝒫₂ over ℚ(ζ₅);
    • li3 k — the value Li₃(ζ₅^{k+1}) for k : Fin 4.

    Neither is constructed in this library, so both are supplied rather than built.

    An instance is the conjecture, for that data. None is provided.

    • span_finrank_eq_two : Module.finrank ℚ ↥(Submodule.span ℚ (Set.range li3)) = 2

      The reduced target. The four Li₃(ζ₅ᵏ) span a space of rank exactly 2 — Borel's dim_ℚ K₅^ind(ℚ(ζ₅)) ⊗ ℚ.

      Rank 2 from four generators is the whole content: it says the multiplication-formula identities cut the four values down to Borel's rank and no further.

      Exactly two independent relations — the multiplication-formula count, derived rather than assumed.

      Four generators spanning rank 2 leave a relation space of rank 2, by rank-nullity applied to Fintype.linearCombination. The block attributes those relations to the multiplication formula; the count follows from the rank alone and needs nothing about which relations they are.

      This is what makes the single field say something structural rather than merely numerical.
