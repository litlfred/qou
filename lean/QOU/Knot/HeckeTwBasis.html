            Is this rule actually the Hecke algebra's? #

            genTerm is a definition, so nothing so far rules out its being the wrong rule written down confidently. The falsifiable check is the Hecke relation itself: T_s^2 = A * T_s + 1, i.e. applying mulGen twice must equal A * (once) + (identity). That is proved below, and it is not automatic -- see the hypothesis hne, which is where the rule would genuinely fail.

            The Hecke relation. Applying the rule twice gives A ·(once) + (id), which is T_s² = A·T_s + 1 read on the basis element T_w.

            The hypothesis hne is the real content and is not decoration. If the length were allowed to stay put under s, the descending branch would be taken twice and the relation would fail outright -- so this theorem is a genuine constraint on s, satisfied by a simple reflection (where the length parity flips) and not by an arbitrary permutation. Stating it for arbitrary s without hne would be false, which is precisely why it is worth proving rather than assuming.

            The bond factor, on the element itself #

            Everything above states the generating function over an explicitly-supplied Finset. gfOf reads it straight off the element instead, which is what makes the two operations of a bridge -- promote, then add a multiple of the original -- composable in one expression.

            The result is the interface factor (X + C d) of GradedGeneratingFunction, now with both halves derived: the X from Hecke multiplication by the fresh generator, and the C d from the interface scalar.

              GradedGeneratingFunction.gf_bonds then multiplies these across a list of bonds. What that composition still does NOT supply is the per-nucleon factorisation G_1(x)^A of the measured composition law; that is the block factorisation, a separate fact, not proved anywhere here.
