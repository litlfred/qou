    QOU.Knot.BraidClosure — the closure permutation and its component count #

    Bean qou-e6db, step 1. QOU.Knot.MFWSkeinInduction states the MFW window in terms of three integers: the strand count n, the writhe e, and the number of closure components c. Of those, n and e already existed (QOU.BraidKnot.BraidWord.writhe); c did not exist anywhere in the tree, so nothing could connect a braid word to the window it is supposed to satisfy.

    This file supplies it. A braid word induces a permutation of the strand endpoints — each crossing swaps two adjacent positions, regardless of its sign — and the closure's components are exactly that permutation's orbits.

    Built on the existing type, deliberately. BraidWord is defined nine times across this Lean tree (PhotonThreading, four separate StandardModel files, two Archimedean files, BraidKnot.BraidGroupNStrand, BraidKnot.BraidWordBasisGram, and KnotTheory), with writhe defined at least five times — four of them character-identical. A tenth definition would make that worse. BraidKnot.BraidGroupNStrand.BraidWord is used here because it is the only one indexed by the strand count n and carrying the crossing sign, which is precisely what MFW needs. The fragmentation is recorded in qou-e6db; it is an obstacle to HOMFLY-in-Lean, not something this file fixes.

              The skein moves, on actual braid words #

              MFWSkeinInduction.mfw_step takes the window shifts as arithmetic hypotheses: switching moves e ↦ e - 2, smoothing moves e ↦ e - 1, and both keep n. Nothing so far proved that a braid word realises those shifts, nor that c behaves as the induction needs. These lemmas supply exactly that.

                Parity — why |e| ≤ n - c is a same-parity statement #

                The exhaustive measurement behind MFWSkeinInduction's base case found |e| and n - c always sharing a parity, with the bound tight whenever they agree. That is not a coincidence of small cases: it follows from the sign homomorphism, because each crossing contributes exactly one transposition.

                c depends only on the generator sequence #

                components_switch handles one crossing change. The reduction to a descending word changes many, so what is actually needed is that c is a function of the generator sequence alone, blind to every sign at once. That is this section.

                It is also the precise reason the ±1 orbit-count lemma is not needed for the MFW induction, contrary to what an earlier note in qou-e6db claimed: mfw_step is stated purely in n, e, d — c never appears in the propagation — and c enters only in the base case, applied to the descending word itself. Since the descending word is reached by sign changes alone, it has the same n and c as the original and differs only in e.

                  Orientation, against the reference engine #

                  computations/homfly_skein_braid.py::traverse counts closure components by walking each strand around the closure, and its comps is the number of orbits of the strand map — the same quantity components defines here. But it composes crossings in the opposite order: it applies word[0], word[1], … in turn, whereas Lean's f * g means f ∘ g, so closurePerm applies the last letter first.

                  The two therefore differ by an inversion, not by an error, and inversion preserves both the cycle type and the support — so the component counts agree. Proved rather than asserted, because this is exactly the kind of convention mismatch that silently produces a mirror (cf. qou-7ue5, where two places in computations/ disagreed about a HOMFLY by a v ↦ v⁻¹ mirror). It will matter concretely when the traversal itself is formalised, where the order — not just the orbit count — is load-bearing.

                  Over/under at a crossing — the atom of the traversal #

                  The descending predicate is about which strand is met over and which under. closurePerm already carries where a strand goes; this carries which of the two passes over. Together they are the Lean analogue of the reference engine's _step, whose convention is fixed here: for σ_i (positive) the strand entering at the lower position i passes OVER.

                  Sign conventions in this area are not free — qou-7ue5 records two places in computations/ disagreeing about a HOMFLY by a mirror — so the convention is stated, and the two defining properties below are proved rather than left implicit.

                    One lap — a single strand's pass through the whole word #

                    The traversal walks a strand around the closure; one lap is one pass through the word. lapStep is where the strand ends up, lapVerdicts is what it met.

                    lapVerdicts returns List (Option Bool) indexed by crossing position rather than a list of (index, verdict) pairs: the crossing index is then the list index, and no index arithmetic is needed anywhere. none means this strand was not one of the two at that crossing.

                    Note the direction: a lap applies w[0] first, matching the reference engine, so it runs opposite to closurePerm — which is why the lemma below identifies it with the inverse. This is the orientation already pinned by closurePerm_reverse; it is restated here as an equation rather than left for the reader to re-derive.

                        Walking a component #

                        A lap is one trip through the word; a component is walked by taking laps until the strand returns to where it started. Rather than a loop-until-return — which would need its own termination argument — the lap count is supplied explicitly as the cycle length, and the fact that the walk closes up is then a theorem rather than a side condition.

                        orderOf (f.cycleOf p) is the right count: orderOf f would also close up, but it is the lcm over all cycles and so would walk short components round and round instead of once.
