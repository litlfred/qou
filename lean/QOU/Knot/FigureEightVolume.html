          noncomputable def QOU.Knot.FigureEightVolume.VOL_4_1_decimal :
          ℝ

          The 30-digit decimal approximation of Vol(4_1). An APPROXIMATION carrier only — VOL_4_1 = 2·Cl₂(π/3) is transcendental; no formal identity between the two is claimed (that would need certified interval arithmetic on Cl₂).

          ⚠ **CORRECTED 2026-08-30 (bean `qou-f8lit`) — this literal was WRONG.**

          It read 2.029883212819307250011597804990, which is wrong from the 21st significant figure (error 3.08e-20) against the canonical 2·Cl₂(π/3) = 2.0298832128193072500424051085490…. Verified by three independent routes: 2·Cl₂(π/3), 6·Λ(π/3), and 2·Im Li₂(e^{iπ/3}).

          This is worse in kind than a truncation. A truncated literal is correct but short; this one presented 30 digits of which only 20 were right, and the extra digits invite the trust that a short value would not get. MassDerivation.vol_figure_eight carries the correct value at 24 digits, so the corpus disagreed with itself.

          Nothing in Lean was unsound: abs_VOL_4_1_sub_decimal_lt bounds the gap by 1/10 and 3.08e-20 < 1/10 comfortably, so the theorem held either way — which is exactly why a coarse certified bound does not protect a decimal's digits.

          Known family, partially drained: bean qou-jgew found seven wrong hand-typed Vol(4₁) values in one session, and docs/audits/2026-06-21-q0-clusterD-and-vol41-fixes.md fixed one .py probe. Those drains never reached this Lean carrier. Still live: six computations/ sites carry the sibling variant 2.0298832128193072500115970029, one of them a committed witness that needs a producer re-run.
