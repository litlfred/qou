    QOU.GroundRingCore — the one ground ring, and nothing else #

    R_q = ℤ[q, q⁻¹] and its indeterminate, in a module light enough that any other module can import it.

    Why this module exists (bean qou-kfcl) #

    Seven library modules declared their own R_q, in five namespaces, because each wanted the ground ring without taking a dependency. Two of those are outright FQN collisions, and collisions make modules mutually un-importable — Lean's environment is flat, so

        import QOU.BraidKnot.CasimirShared
    import QOU.CategoricalDqSquared

    (indented on purpose — scripts/lean_cone_build.py reads ^import anywhere in the file, so an example written flush-left becomes a phantom dependency)

    fails with environment already contains 'QOU.q_param'. The worse of the two was QOU.R_q itself, which denoted RatFunc ℚ in one module and LaurentPolynomial ℤ in the other: the same name for two different rings.

    QOU.Archimedean.GroundRing was the natural home and could not serve, because it pulls Mathlib.Tactic and QOU.MathlibExt.QIntegerCanonical. Pointing a module with three Mathlib imports at that, to fix a three-line duplication, is a build-cost regression rather than a cleanup — so the ring moved down here instead, and GroundRing keeps its tactic-heavy material on top.

    One import, three declarations, one theorem. Keep it that way. The value of this module is entirely in being cheap enough that nobody has a reason to re-declare the ring locally again. Anything needing tactics, order, or the archimedean specialisation belongs in QOU.Archimedean.GroundRing or further out.

    Not the archimedean side #

    R_q is the algebraic ground ring: an un-ordered commutative ring with no canonical topology. The archimedean specialisation ι : R_q → ℝ, q ↦ q₀ lives on the far side of the §7c wall and is deliberately absent here.

          instance QOU.GroundRing.instNontrivialR_q :
          Nontrivial R_q

          R_q is not the zero ring.

          Free by instance search — LaurentPolynomial ℤ is nontrivial — but named here so it can be cited rather than re-derived, and so the fact is greppable.

          Why it is worth a name. A statement proved over an arbitrary CommRing often needs [Nontrivial R] to have content: in the zero ring 1 = 0, so x ≠ 0 is unsatisfiable, every module is zero, and every short exact sequence splits vacuously. The zero ring is the ring-level analogue of the trivial instances the vacuity audit exists to catch, and a theorem that holds only there holds for the same reason PUnit satisfies a class with a propositional field.

          Downstream, that hypothesis does not need adding to the substrate classes. Anything stated over R_q gets it from here, which is why QOU/Mathlib/HeckeExtOne.lean can carry [Nontrivial R] in its general form and drop it entirely in groundRing_not_splits_at_neg_one.
