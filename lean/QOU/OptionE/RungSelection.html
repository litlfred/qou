    QOU.OptionE.RungSelection — Canonical rung-selection at k ≥ 3 #

    Option E infrastructure file 2/4 — canonical (non-fitted) rung-selection function from crystal-graph data.

    The k=2 truncation of the τ_M Kashiwara derivation drops k ≥ 3 rungs as "non-canonical" — meaning no derivation rule from substrate gives them. Option E's substantive content is to derive the k ≥ 3 rungs canonically from crystal-graph structure.

    Candidate rule (this file) #

    Given a crystal graph Γ for partition λ ⊢ n, the canonical rung-selection function kCan : CrystalVertex → ℕ is determined by the depth of the vertex in the crystal's directed-graph structure (= max distance from a source vertex along directed edges).

    The substrate-derivation property requires:

    1. kCan depends ONLY on the crystal-graph topology, NOT on AME measurements. (Not checkable in Lean — see the RungRule docstring: this is a claim about how kCan is defined, and Lean sees only its extension.)
    2. kCan(v) ≥ 3 for vertices below the k=2 horizon in the crystal's longitudinal grading.
    3. The induced Δ_λ derived from kCan-weighted sums closes the AME light-isotope binding-energies at the 10% threshold.

    This file provides the framework + a candidate rule. Verification that the candidate rule actually closes deuteron lives in DeuteronVerification.lean.

    substrate_derived : Prop removed 2026-09-14, and NOT replaced by a parameter. It was typed with the universe Prop, so the constructor chose the proposition — depthBasedRule supplied True — and it was measured dead: written once, read by nothing inside this file or outside it.

    The property it named is not expressible in this type at all, which is why parameterising would not have helped. It read: "the rule does not directly reference any real-valued AME constant." That is a statement about how k is defined, not about k as a function — two extensionally equal functions can differ entirely in provenance, and Lean sees only the extension. No field, and no caller-supplied predicate on k, can carry it.

    Its honest home is a provenance audit over the source, which this corpus already does elsewhere: scripts/precision-gates.sh runs a no-free-parameter certificate of exactly that shape. The Option-E anti-fit discipline for this rule belongs there, not here.

    Nothing else changes: the field's removal keeps RungRule n's arity, so DeltaLambda, DeuteronVerification and CrystalDeltaLambdaScaffold are untouched.
