            Hypothesis dropped and section moved, 2026-09-05. This was stated in section Ordered as {h : K} (hh : 0 < h), and hh was never used: the proof is rfl, because toCrossingCoords h c₁ cσ is defined as (cσ + c₁/h, -(c₁/h)), so the second component at c₁ = 1 is -(1/h) syntactically, for every h — including h = 0, where both sides are Lean's junk -(1/0). Carrying 0 < h made the theorem strictly weaker than what was proved and made it look as though positivity were doing work somewhere. It also forced the whole statement into the ordered section, requiring [LinearOrder K] [IsStrictOrderedRing K] for an identity that needs only [Field K] — the §7c defect of inheriting archimedean structure a statement does not use.

            Contrast crossingCoord_snd_neg_of_two_le immediately below in Ordered, which genuinely needs 0 < h: its conclusion is an inequality, and the positivity is what drives the pow_coords induction. The two sat adjacent with the same binder, which is presumably how the decorative one arrived.

            3. A central multiplier is exactly a reweighting #

            Schur's lemma makes a central element a scalar on each Wedderburn block; the step that carries the claim is what a scalar does to the character.

            source
            theorem QOU.Hecke.CrossingConvexity.trace_mul_scalar {n : Type u_1} [Fintype n] [DecidableEq n] {R : Type u_2} [CommRing R] (M : Matrix n n R) (c : R) :
            (M * c • 1).trace = c * M.trace

            Central multiplication rescales the character. This is the whole content of "the ell-1 ceiling bounds precisely the centre": the ceiling already ranges over per-block coefficients, and a central Z = c • 1 only supplies one more.
