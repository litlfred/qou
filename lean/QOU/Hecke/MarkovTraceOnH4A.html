    QOU.Hecke.MarkovTraceOnH4A — the Markov trace at n = 4, the top of the ladder #

    QOU.Hecke.MarkovTraceH2 gave the first QOU.Hecke.MarkovTrace, at n = 2, and said plainly that two of its five fields were free there. MarkovTraceOnH3A gave n = 3, where cyclic and trace_prod_gen both carry content. This file gives n = 4, which is where the ladder stops mattering: Generator n carries idx : Fin (n - 1), so n = 4 is the last level at which a class field (HeckeAlgebra.farCommute) becomes satisfiable for the first time. Every field of both classes now has content on one and the same carrier.

    What had to be proved first #

    cyclic was the whole obstruction, and it is not free at n = 4: H₄(q) is noncommutative, and trM4 had no cyclicity theorem on the subscript basis — which is exactly the basis H4A, and hence QOU.Hecke.InstanceOnH4A.instHeckeAlgebraH4A, is built on. The ASCII basis had one (QOU.Machinery.H4.trM_cyclic, sorry-free via the 576-entry gram_symm closure) but the two are different tables.

    QOU.Machinery.H4Bridge.trM4_cyclic closes it, by transport rather than by a second Gram closure: the two bases are one basis relabelled, the relabelling carries products to products (phi_mulNF) and trM to trM4 (trM4_phi), so cyclicity comes across. Bean qou-x64l.

    Where the trace values come from #

    H4A's basis vectors are e₄ j, so trM4 z h (b j).v is the single weight TRM4 z h j — no sum to evaluate. The generators are basis vectors (s0 = b 1, s1 = b 2, s2 = b 6, all weight z), and each of the three ordered generator products is again a basis vector, reached by one step of the word tree InstanceOnH4A.b_tree_*:

    product basis vector why weight
    σ₀σ₁ b 4 b_tree_4 z²
    σ₁σ₂ b 7 b_tree_7 z²
    σ₀σ₂ b 8 farcomm02 then b_tree_8 z²

    The third is the one n = 3 cannot ask: it is the far-commuting pair, and reaching its basis vector needs the relation, not just the tree.

    z is still a parameter #

    As at n = 2 and n = 3, markovTraceH4A is a def taking z, not an instance: QOU.Hecke.MarkovTrace does not index on z and constrains it only through trace_gen, so every z gives a Markov trace here too. Excluding the wrong convention needs the bar law bar(z) = z − h, which this class has no field for — see PR #4834.

      The Markov trace #

      source
      def QOU.Hecke.MarkovTraceOnH4A.markovTraceH4A (K : Type u) [Field K] (q z : K) :
      MarkovTrace 4 q (Machinery.H4.H4A K (q - q⁻¹))

      A Markov trace on H₄(q), for any Markov parameter z.

      Every field carries content. cyclic is QOU.Machinery.H4.trM4_cyclic — a theorem, not a consequence of commutativity, since H₄(q) is noncommutative — and trace_prod_gen must deliver all three ordered pairs, including the far-commuting one.

      Previously this was H4Bridge.trM4_cyclic, which transported the ASCII trM_cyclic across the basis relabelling and so depended on gram_symm's 576 computed entries. H4.trM4_cyclic proves the same statement directly from the three generators, so that dependency — and the Gram chain behind it — is gone. Note the argument order differs: (z, h, …) here, against the bridge's (h, z, …).
