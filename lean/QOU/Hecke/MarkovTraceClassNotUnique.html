    QOU.Hecke.MarkovTraceClassNotUnique — the MarkovTrace class does not determine the trace #

    QOU.Hecke.MarkovTrace records normalisation, cyclicity, tr(σᵢ) = z and tr(σᵢσⱼ) = z² (i < j), but not the cross-level Markov property. This file shows that those fields do not determine the trace, refuting the former axiom QOU.Hecke.markov_trace_unique_axiom (which, being an axiom and false, made the environment inconsistent).

    The counterexample #

    Carrier: the tree's own four-strand Hecke algebra H4A K (q − q⁻¹) with instHeckeAlgebraH4A, over any field K, any q. For every w : K, markovTraceH4A K q w is the Ocneanu trace at parameter w. All of them are cyclic, so any K-linear combination is cyclic too. Take

    t_Z = 4·tr_Z − 3·tr_{Z+1} − tr_{Z−1} + tr_{Z+2}.

    The weights (4, −3, −1, 1) at offsets (0, 1, −1, 2) have moments Σ a = 1, Σ a·d = 0, Σ a·d² = 0, Σ a·d³ = 6. Hence

    • t_Z(1) = 1, t_Z(σᵢ) = Z, t_Z(σᵢσⱼ) = Z² — every MarkovTrace field holds with z_param = Z;
    • t_Z(σ₀σ₁σ₂) = Z³ + 6, while tr_Z(σ₀σ₁σ₂) = Z³.

    So t_Z ≠ tr_Z whenever 6 ≠ 0 in K. Structurally: the cyclic traces on H₄(q) form a 5-dimensional space (one coordinate per partition of 4, i.e. per conjugacy class of S₄, via the minimal-length class representatives 1, σ₀, σ₀σ₂, σ₀σ₁, σ₀σ₁σ₂), and the class fields fix only the first four coordinates; the 4-cycle class σ₀σ₁σ₂ is free.

    t_Z is not a Markov trace in the sense of (M3); QOU.Hecke.markov_trace_unique proves uniqueness once (M3) is assumed.
