    QOU.Torsion.skein_generation — Skein generation, DERIVED from a terminating resolution #

    Proposition (prop:skein-generation).

    The Skein module 𝓢_q = 𝓢_q(𝐂) is generated as an algebra by:

    (1) The fundamental (mass-zero) knot types {K_i}_{i ∈ 𝓕} (torus knots), and

    (2) The Hopf link 𝓛_Hopf (the binding operation).

    Every hadron admits a terminal Skein resolution into a finite polynomial in these generators with coefficients in ℤ[q^±1].

    What changed, and why (bean qou-skgn) #

    This file previously carried generation_top : Algebra.adjoin R G = ⊤ as a class field and proved the proposition by rw [ctx.generation_top]; exact Algebra.mem_top. That is the vacuous self-assuming projection AGENTS.md §3b-cond item 5 defines: the class carried the block's own conclusion and the "theorem" projected it, so the Lean derived nothing.

    The remedy taken here is §3b-cond item 5's own: the class now carries the inputs — a terminating resolution — and generation is derived from them.

    The mathematical content of "the skein relations generate" is exactly that: a skein move rewrites an element in terms of strictly simpler ones, and the rewriting terminates. So the honest hypotheses are

    • complexity — a ℕ-valued measure (crossing number, in the intended model);
    • base — an element of complexity 0 is already in the generated subalgebra;
    • resolve — an element of positive complexity lies in the subalgebra generated by the generators together with finitely many strictly simpler elements.

    skein_generation is then a genuine strong induction on complexity, and it would be false for a context whose resolution did not terminate. That is what distinguishes it from the projection it replaces: the conclusion now depends on the hypotheses.

    The Finset in resolve is deliberate — it encodes the narrative's "finite polynomial", which the previous encoding dropped.

    What is still NOT formalised #

    Stated so the formalisation is not read as stronger than it is. The narrative sentence has four content words and this file carries two of them:

    • no hadron restriction — the conclusion is for every h : Skein, whereas the prose says "every hadron". QOU/scratch_skein.lean carries a Hadron : Skein → Prop restriction and is closer on this point.
    • no ℤ[q^{±1}] coefficient ring — R is an arbitrary CommRing.

    Both are recorded in bean qou-skgn as route (3), a strictly harder formalisation than either copy in the corpus has.

    class QOU.Torsion.SkeinGenerationContext (R : Type u_1) (Skein : Type u_2) (FundamentalKnotIndex : Type u_3) [CommRing R] [Ring Skein] [Algebra R Skein] :
    Type (max u_2 u_3)

    Abstract context for the Skein-module generation claim.

    The fields are the inputs to generation, not generation itself: a complexity measure, a base case, and a resolution step that strictly decreases it. See the module docstring for why (bean qou-skgn).

    • fundamentalKnot : FundamentalKnotIndex → Skein

      The fundamental knot embeddings K_i ∈ 𝓢_q.

    • hopfLink : Skein

      The Hopf-link generator 𝓛_Hopf.

    • complexity : Skein → ℕ

      Complexity of a Skein element — crossing number, in the intended model. Well-foundedness of ℕ is what makes the resolution terminate.

    • base (s : Skein) : complexity R FundamentalKnotIndex s = 0 → s ∈ Algebra.adjoin R (Set.range (fundamentalKnot R) ∪ {hopfLink R FundamentalKnotIndex})

      Base case. An element of complexity 0 is irreducible: it already lies in the subalgebra generated by the fundamentals and the Hopf link.

    • resolve (s : Skein) : 0 < complexity R FundamentalKnotIndex s → ∃ (t : Finset Skein), (∀ x ∈ t, complexity R FundamentalKnotIndex x < complexity R FundamentalKnotIndex s) ∧ s ∈ Algebra.adjoin R (↑t ∪ (Set.range (fundamentalKnot R) ∪ {hopfLink R FundamentalKnotIndex}))

      Resolution step. An element of positive complexity is expressible using the generators together with finitely many strictly simpler elements — one application of the skein relations.

      The Finset carries the narrative's "finite polynomial"; the strict decrease is what makes the induction terminate.

        The generation statement in = ⊤ form — the shape the previous encoding took as a hypothesis. It is now a consequence.

        Non-vacuity #

        skein_generation is conditional on SkeinGenerationContext. A conditional theorem is worthless if its hypotheses cannot be jointly met, so the interface is exhibited inhabited below.

        This is deliberately NOT an instance. Declared as one it would apply to every Skein by instance resolution, silently discharging the hypothesis everywhere and making skein_generation trivially available for all — which is precisely the defect this file was restructured to remove. It is a def, used only to witness satisfiability.

          Route (3), hadron half — the narrative's actual quantifier #

          skein_generation above concludes for every h : Skein, while the narrative says "every hadron admits a terminal Skein resolution". Those are different claims, and the unrestricted one is not automatically the more useful: it demands a resolution for elements the physics never asks about.

          The class below is the honest restriction. Its hypotheses are strictly weaker — only hadrons need resolve, and a resolution must stay within hadrons — and its conclusion is correspondingly restricted. It is not a specialisation of the above; neither implies the other.

          This supersedes QOU/scratch_skein.lean, which carried the Hadron restriction but did so as a projection: its hadron_is_polynomial field was the conclusion. The restriction was the only thing in that file worth keeping, and here it is derived rather than assumed (beans qou-skgn, qou-scrx).
