    QOU.Archimedean.lepton_continuant_positivity — the invariant that closes the node escape #

    Ordered-field companion to lepton_continuant_binet. Split out per the §7c base-ring wall: the Binet / linear-readout algebra there holds over a bare [Field K], while everything here needs an order on K.

    Nothing in this file is archimedean — no Real.sqrt, Real.log, Real.exp or CODATA constant appears — so it stays generic over an ordered field and is instantiated at ℝ only where measured masses enter, i.e. in the Python twin lepton_linear_readout_rigidity.py.

    What this closes #

    linFunctionalK_two_step bounds the increment of a readout, not its ratio. If a readout φ had a zero — a node — just below the generation window (windings 3, 5, 7, i.e. n = 2, 4, 6), then φ(2) ≈ 0 and φ(4)/φ(2) would be arbitrarily large, which can reproduce the observed m_μ/m_e = 206.8. So "no linear readout works" is false as a bare claim, and the exclusion is incomplete without the results below.

    Solving that escape exactly (a quadratic in A/B, in the Python twin) gives two roots, and both require φ(1) and φ(σ₀) to have opposite signs.

    That is what positivity forbids. For q > 1 the Hecke parameter h = q − q⁻¹ is positive, so the Morgan–Voyce continuant — starting 0, 1 and built by b_{n+2} = h·b_{n+1} + b_n — is positive from b₁ on. Hence any readout with φ(1) ≥ 0 and φ(σ₀) > 0 is strictly positive at every index: its node does not lie outside the window, it does not exist.

    The canonical Markov trace is such a readout (tr_M(1) = 1, tr_M(σ₀) = z = 1/(q^{1/2} + q^{-1/2}) > 0), so the escape is unavailable to the only readout the framework actually derives. That is what makes the exclusion scope-(b) — resting on a proved invariant — rather than a failed search.
