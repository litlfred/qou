    QOU.ParticleInteractions.frobenius_positivity_filter #

    Lean statement for content block prop:frobenius-positivity-filter.

    Statement (manuscript). For even mass number A, a channel configuration c ∈ {triv, conf, unconf, sign}^A is Frobenius-positive iff both the parent product m_par = ∏ₘ G_{nₘ}(cₘ) and the daughter product m_dau = ∏ₘ G_{n'ₘ}(cₘ) are non-negative. Exactly half of the configurations — 2^{A-1} out of 4^A — are excluded (non-positive).

    Disposition (honest sorry). The two parts have different status:

    • The characterisation FrobeniusPositive c ↔ (0 ≤ parentProd c ∧ 0 ≤ daughterProd c) is the definition of Frobenius-positivity in terms of the parent/daughter products and holds by rfl/Iff.rfl against the predicate as defined below — it is recorded as a def.

    • The count (excludedConfigs).card = 2^(A-1) is the genuine combinatorial claim. Establishing it requires the spectator-factor sign structure of the products G_{nₘ}(cₘ) (which fixes, per added cell, the sign of each factor and hence the parity of the product), i.e. the Hoefsmit/Markov-trace G-function machinery and the confinement-LP feasibility argument Gx ≥ 0 — none of which is present in this file. The proposition is therefore stated faithfully over real types (a Fintype configuration space, a real non-negativity predicate, a real cardinality conclusion) and closed with sorry.

    This replaces the previous self-assuming class … Context whose fields were the manuscript conclusions (claim_i_positivity_condition, claim_ii_exclusion_count) with a theorem … := ⟨ctx.…, ctx.…⟩ projection (forbidden by AGENTS.md §1a / §3b-cond rule 5).

    Base ring (§7c) #

    The proved core (parity_odd_card, frobenius_positivity_filter) lives entirely in ZMod 2 and Finset and mentions no scalars at all. The only scalars are the parent/daughter Hoefsmit G-function products, and the sole thing asked of them is 0 ≤ ·; so they take values in a generic ordered commutative ring and the substrate evaluation is R := ℝ.

              §2 The exclusion count over the sign-pattern space #

              The manuscript claims 2^{A-1} excluded configurations. The honest carrier of that count is not the full 4^A configuration space (over which the count is P-dependent and false for generic P — an all-positive product excludes nothing; see docs/audits/2026-07-05-frobenius-positivity-filter-lean-overgeneralization.md), but the 2^A per-factor sign-pattern space Fin A → ZMod 2, on which the exclusion is governed by the odd total parity of the per-factor signs (product ∏ₘ G(cₘ) is negative ⟺ an odd number of factors are negative). On that space the count is a clean, unconditional combinatorial fact — exactly half the parity-vectors are odd — proved here sorry-free.

              theorem QOU.ParticleInteractions.parity_odd_card (A : ℕ) (hA : 1 ≤ A) :
              {s : Fin A → ZMod 2 | ∑ i : Fin A, s i = 1}.card = 2 ^ (A - 1)

              Parity count (provable core). Exactly half — 2^{A-1} — of the 2^A per-factor sign-patterns Fin A → ZMod 2 have odd total parity ∑ᵢ sᵢ = 1.

              Proof: drop the last coordinate. Any tail t : Fin (A-1) → ZMod 2 extends to a unique odd-parity vector (the head is forced to 1 − ∑ t), so the odd-parity set is in bijection with Fin (A-1) → ZMod 2, which has cardinality 2^{A-1}.

              theorem QOU.ParticleInteractions.frobenius_positivity_filter {A : ℕ} (hA : 1 ≤ A) (excludedSign : (Fin A → ZMod 2) → Prop) [DecidablePred excludedSign] (hchar : ∀ (s : Fin A → ZMod 2), excludedSign s ↔ ∑ i : Fin A, s i = 1) :
              (Finset.filter excludedSign Finset.univ).card = 2 ^ (A - 1)

              Frobenius positivity filter — corrected, proved (manuscript part (ii)).

              Conditional on the sign-mechanism characterisation hchar (a configuration is excluded ⟺ its per-factor sign-pattern signOf c has odd total parity — the Hoefsmit spectator-factor structure), exactly 2^{A-1} of the 2^A sign-patterns are excluded, for A ≥ 1.

              The hypothesis hchar carries the mechanism (the physical input); the 2^{A-1} count is then derived from parity_odd_card (no sorry). This replaces the previous unconditional statement over the 4^A configuration space, which was false for generic ProductData (see the audit doc referenced above).
