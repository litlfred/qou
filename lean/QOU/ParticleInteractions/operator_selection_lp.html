    QOU.ParticleInteractions.operator_selection_lp #

    Proposition (prop:operator-selection-lp): Knot operator selection as a linear program with LP duality.

    The knot operator Φ = Σᵢ xᵢ bᵢ ∈ Hₙ(q) for a target interaction with net value n_target is the optimum of

    minimise Σᵢ tᵢ xᵢ subject to Σᵢ xᵢ = n_target (net constraint) Σⱼ G_{ij} xⱼ ≥ 0 ∀ i (Frobenius positivity) xᵢ ≥ -M ∀ i (boundedness),

    and the dual certificate (y₀*, y*) satisfies strong duality Σᵢ tᵢ xᵢ* = n_target · y₀* and complementary slackness.

    Disposition (integrity) #

    The class below carries only the LP data — the cost vector t, the Frobenius Gram matrix G, a candidate x*, the target n_target, and the dual variable y₀*. It does not carry the optimality / strong-duality conclusions as fields (the previous version did, then projected them — a self-assuming projection forbidden by AGENTS.md §3b-cond item 5).

    operator_selection_lp states the genuine conclusion — x* is primal-feasible AND optimal among all feasible points AND strong duality holds — and is now proved, sorry-free. The feasible-set definition IsFeasible is genuine (no opaque Prop field projected).

    2026-08-16. The previous version ended in sorry, citing the LP strong-duality theorem as missing infrastructure. That was the wrong diagnosis twice over.

    First, the statement was false: stripping the conclusions out of the class (rightly, per §3b-cond item 5) left the class carrying only data and no hypotheses, so the theorem asserted IsFeasible x_star for an arbitrary x_star. With d = 1, n_target = 1, x_star = 0 the first conjunct reads 0 = 1, and False was derivable. See bean qou/k4ul.

    Second, no strong-duality theorem is needed. x* is a given candidate and y₀* a given dual variable, so this is certificate verification, not optimisation: the class now carries the dual slack s ≥ 0, the dual equality tⱼ = y₀ + Σᵢ sᵢGᵢⱼ, primal feasibility of x*, and the zero-gap identity — all hypotheses about the data, never the block's own conclusion. Optimality then follows by the weak-duality computation inlined below: for any feasible x,

    Σⱼ tⱼxⱼ = y₀·n_target + Σᵢ sᵢ(Gx)ᵢ ≥ y₀·n_target = Σⱼ tⱼx*ⱼ ,

    since sᵢ ≥ 0 and (Gx)ᵢ ≥ 0. Farkas' lemma is irrelevant here (it is still the open input for general strong duality — see bean qou/kl8z).

    If the substrate's concrete x*/y₀* do not satisfy these hypotheses, that is a content finding about the claimed optimum, not a Lean one.

    Checking a certificate index by index #

    The zero-gap hypothesis is a single equation over the whole data, which a symbolic evaluation cannot discharge without summing d products. zero_gap_iff_complementary_slackness replaces it, for feasible points, with the equivalent per-index condition

    ∀ i,  sᵢ · (Gx)ᵢ = 0

    — each Frobenius constraint is inactive (sᵢ = 0) or tight ((Gx)ᵢ = 0). Both directions matter and are used differently:

    • .mp (complementary_slackness_x_star) extracts the per-index facts from a context that has already been built, so an evaluation can check them one at a time.
    • zero_gap_of_complementary_slackness runs the other way and is stated over raw data, not over the class: zero_gap is a field, so a lemma assuming OperatorSelectionLpContext could never supply it. This is what an instantiation for concrete t, G, x* uses.

    The algebra common to all of it is sum_cost_mul_eq, which needs no order on R at all and no sign hypotheses — the ordering enters only where non-negativity is genuinely required.

    What the substrate actually is (2026-08-16, bean qou/k4f8) #

    Computed exactly in ℚ(q) by computations/operator_selection_lp_symbolic_qq.py — 18/18 checks, no floating point, because the question is whether det G is zero, not whether it is small. For H₃(q) (d = 6):

    • t is row 0 of G. Not a coincidence: tⱼ = tr_M(bⱼ) = tr_M(b₀·bⱼ) = G₀ⱼ whenever the basis contains the identity. So a certificate always exists — y₀ = 0, s = e₀ — and certificate existence is not, and never was, the obstruction. What it certifies is Σⱼtⱼxⱼ ≥ 0 from the constraint (Gx)₀ ≥ 0, which is the same inequality. See dualCertificateExists_of_cost_eq_gram_row.
    • det G = 0 identically, rank 5, radical spanned by v = (−q³, q², q², −q, −q, 1) ∼ (−1/q)^len(wᵢ), the q-antisymmetriser. G has no inverse, so dualCertificateExists_of_left_inverse does not apply here.
    • y₀ = 0 is forced for every dual-feasible pair, at every q ≠ 1, since ⟨𝟙,v⟩ = −(q−1)(q²−q+1). See y_0_eq_zero_of_radical. The optimum is attained on the radical itself with objective 0 and every Frobenius constraint tight — see OperatorSelectionLpContext.ofRadical.
    • H₂(q) is not degenerate (det G = (q⁴+q²+1)/(q²+1)²), so this is a fact about H₃, not about how the LP was written down.

    The consequence is a content question, not a Lean one: the dual objective is n_target · y₀, so the optimal value is 0 for every n_target, and y₀ cannot be the shadow price of the net constraint. Anything dividing by it is 0/0. Nothing in this file asserts otherwise; the theorems below are exactly as strong as their hypotheses.

    Rebuilding G does not help (bean qou/ndsa) #

    ndsa proposes breaking the confinement LP's homogeneity by getting the braid into the objective t or the Gram G rather than only into n_target. Two of its candidates are ruled out here.

    y_0_eq_zero_of_cost_perp_radical is the reason, and it is stated so that nothing in its hypotheses mentions where G came from: a right radical direction, a cost vector orthogonal to it, and Σⱼvⱼ ≠ 0. For a Gram of the form G^w_{ij} = tr_M(bᵢ w bⱼ) — any fixed algebra element w, so any braid — both survive: V = Σⱼvⱼbⱼ spans a two-sided ideal (the sign block), so G^w v = 0; and ⟨t,v⟩ = tr_M(V) = 0 is a fact about the cost vector and the radical, independent of the Gram. Verified exactly in ℚ(q) for nine braid words on both sides by computations/confinement_lp_braid_gram_probe.py, rank 5/6 throughout.

    The equality-constrained variant fares worse: by objective_eq_demand_coord, t·x = u_{i₀} for every feasible x, so the program has nothing to optimise and a knot-dependent u buys a knot-dependent answer only by reading a coordinate of its own input back out. demand_perp_radical adds that u is not even free — it must be orthogonal to the radical for a feasible point to exist.

    So the degeneracy is not a property of G. It is the conjunction of "the cost vector is the Markov trace vector" and "the Gram annihilates the trace form's radical", and the second is automatic for anything built from tr_M. A formulation that survives has to change the objective.

    Base ring (§7c) #

    Nothing in the program is archimedean: feasibility, optimality and strong duality are statements about Finset.sum, * and ≤, and a linear program makes sense over any ordered commutative ring. The scalars are therefore a generic R, and the substrate evaluation is the instantiation R := ℝ.

    Prop

    A dual certificate for cost vector t and Gram matrix G: a scalar y₀ together with non-negative slacks s satisfying t = y₀·𝟙 + sᵀG.

    Existence is not automatic. It asks whether t lies in the cone {y₀·𝟙 + sᵀG : y₀ ∈ R, s ≥ 0} — d equations in d+1 unknowns with a sign constraint, a genuine Farkas-type question about the substrate data. Bean qou/k4f8.

      theorem QOU.ParticleInteractions.y_0_eq_zero_of_contribution_perp_radical {R : Type u_1} [CommRing R] {d : ℕ} [NoZeroDivisors R] {t v c : Fin d → R} {y_0 : R} (htv : ∑ j : Fin d, t j * v j = 0) (hcv : ∑ j : Fin d, c j * v j = 0) (hone : ∑ j : Fin d, v j ≠ 0) (dual : ∀ (j : Fin d), t j = y_0 + c j) :
      y_0 = 0

      The degeneracy criterion, in the only form that is really needed.

      Strip everything away and dual feasibility for the x-block of any conic program has the shape

      tⱼ = y₀ + cⱼ

      where c is whatever the constraints contribute. For a linear program cⱼ = Σᵢ sᵢGᵢⱼ; for an SDP with lift M₀ + Σₖ xₖMₖ ⪰ 0 and dual Z ⪰ 0 it is cⱼ = ⟨Z, Mⱼ⟩; for a moment relaxation it picks up the moment block as well.

      Whatever it is, y₀ = 0 follows as soon as the contribution is orthogonal to v. So the question to ask of any proposed reformulation is exactly one thing:

      does the constraint map annihilate the radical?

      If it does, the reformulation is degenerate before it is solved. For the LP that is Gv = 0; for a dense PSD lift it is Σⱼ vⱼMⱼ = 0. Bean qou/ndsa.

      The radical of the form forces the dual variable to vanish.

      • hv — v is a right radical direction, ∀ i, Σⱼ Gᵢⱼvⱼ = 0;

                  Tighter x_star ∧ ∀ (x : Fin (d R) → R), Tighter x → objective x_star ≤ objective x

                  A tightening buys nothing if the optimum survives it.

                  Tighter is an arbitrary refinement of IsFeasible — a PSD lift, a Lasserre moment relaxation, extra cuts, anything at all. The only hypotheses are that it is a refinement (hsub) and that x* still satisfies it (hstar). Then x* is optimal for the tightened program too, at the same value.

                  This is what settles the third candidate in bean qou/ndsa. The moment lift in computations/sdp_moment_lift.py keeps Gx ≥ 0 and adds M ⪰ 0, X ⪰ 0, tr(GX) ≥ 0, so hsub holds by inspection. And x* lifts: take the rank-one moment matrix X = x*x*ᵀ, which is PSD by construction and satisfies tr(GX) = x*ᵀ(Gx*) = 0 because Gx* = 0 — every Frobenius constraint is tight at the radical optimum. So hstar holds too, and the SDP's optimal value is the LP's.

                  The lesson is not about semidefinite programming. A tightening can only help when it cuts off the incumbent optimum, and this one cannot: x* is the point where all the constraints already hold with equality.
