    Finitely generated cones are closed #

    Bean qou/kl8z. QOU.Optimization.LPStrongDuality derives lp_strong_duality, lp_dual_feasible_of_lower_bound and lp_zero_duality_gap sorry-free from the conditional class MatrixFarkas, whose single field is the Farkas/Gale alternative. The whole LP layer therefore rests on one analytic input, and that input rests in turn on one topological fact:

    the cone `{Σᵢ xᵢ vᵢ : x ≥ 0}` generated by finitely many vectors
is closed.

    Mathlib has the separation engine (ProperCone.innerDual_innerDual, ProperCone.hyperplane_separation) but not this. That is the Mathlib-shaped hole, and this file is where it gets filled.

    Two corrections to the scoping in qou/kl8z #

    • The bean records ProperCone as absent from the olean cache, "a separate, purely practical obstacle". It is present: the names moved, and ConvexCone.innerDualCone_of_innerDualCone_eq_self, Set.innerDualCone, isClosed_innerDualCone are now deprecated aliases for ProperCone.innerDual_innerDual, ProperCone.innerDual and ProperCone.isClosed. Measured 2026-08-21 against the pinned rev by compiling a probe. There is no practical obstacle here.
    • Mathlib/Analysis/Convex/Caratheodory.lean is about convex hulls (convexHull_eq_union over affinely independent subsets), not cones. It is a template for the argument, not a source of it: the conic statement has to be proved separately.

    What this file proves #

    isClosed_coneSpan — the lemma qou/kl8z names, proved, sorry-free. The proof splits in two along the line of what Mathlib already supports:

    1. isClosed_coneSpan_of_linearIndependent. When the generators are linearly independent the coefficient map is an injective linear map out of a finite-dimensional space, hence a closed embedding, and the cone is the image of the closed non-negative orthant. This is the half LinearMap.isClosedEmbedding_of_injective was made for.

    2. exists_linearIndependent_support — conic Carathéodory. Every point of the cone is a non-negative combination of a linearly independent subfamily. Purely combinatorial, and proved here by induction on the support: if the active generators are dependent, move along the dependency until a coefficient hits zero. No topology is involved, which is why it belongs in the algebraic half.

    coneSpan_eq_iUnion then exhibits the cone as a finite union of the sub-cones on independent subfamilies, and a finite union of closed sets is closed.

    The whole file is stated over an arbitrary [Fintype ι] rather than Fin n. That is not decoration: it is what lets the subfamily indexed by s : Finset ι reuse (1) directly, instead of needing a Fin reindexing detour.

    What is still open above this file #

    MatrixFarkas does not follow from this file alone, and the bean's claim that it does "by the standard route" is still unverified. Its farkas_alternative field is strong-duality shaped — if the primal is feasible and no feasible point beats γ, the dual has a point with objective ≥ γ — not the classic alternative. Deriving it from ProperCone.innerDual_innerDual plus closedness is a real argument that nobody has checked. Until someone does, "the LP layer is one lemma from done" remains a claim about work not yet inspected.

              ∃ (f : E →L[ℝ] ℝ), (∀ (i : ι), 0 ≤ f (v i)) ∧ f b < 0

              Farkas' lemma, in separating-functional form.

              If b is not a non-negative combination of v, then some continuous linear functional is non-negative on every generator and strictly negative at b. Exactly one of the two alternatives holds — the converse direction is immediate, since a functional non-negative on the generators is non-negative on the whole cone.

              This is what isClosed_coneSpan was for: ProperCone.hyperplane_separation needs a closed cone, and closedness of a finitely generated cone is precisely the fact Mathlib was missing.

                Farkas' lemma for a system of linear inequalities.

                If Bl ≤ d has no solution, there are non-negative multipliers z with Bᵀz = 0 and dᵀz < 0 — a certificate of infeasibility.

                This is the form the LP duality argument consumes. It follows from farkas_vector applied to ineqGens B: non-negativity on the basis generators gives z ≥ 0, non-negativity on both a column and its negation forces the column pairing to vanish, and the strict inequality at d is dᵀz < 0.

                theorem QOU.Mathlib.farkas_alternative_real {m n : ℕ} (A : Fin m → Fin n → ℝ) (a : Fin m → ℝ) (c : Fin n → ℝ) (γ : ℝ) (hpf : ∃ (x₀ : Fin n → ℝ), (∀ (i : Fin m), ∑ j : Fin n, A i j * x₀ j = a i) ∧ ∀ (j : Fin n), 0 ≤ x₀ j) (hlb : ¬∃ (x' : Fin n → ℝ), ((∀ (i : Fin m), ∑ j : Fin n, A i j * x' j = a i) ∧ ∀ (j : Fin n), 0 ≤ x' j) ∧ ∑ j : Fin n, c j * x' j < γ) :
                ∃ (l : Fin m → ℝ), (∀ (j : Fin n), ∑ i : Fin m, l i * A i j ≤ c j) ∧ γ ≤ ∑ i : Fin m, a i * l i

                The affine Farkas alternative — the duality-shaped statement.

                If the primal {Ax = a, x ≥ 0} is feasible and no feasible point has objective below γ, then the dual {lᵀA ≤ c} has a point with aᵀl ≥ γ.

                This is the statement QOU.Optimization.MatrixFarkas carries as its single field, unfolded. It is stated here without importing that module so this file stays Mathlib-shaped; the instance at R = ℝ is a one-liner in a file that imports both.

                No attainment is used. The naive route — separating (a, γ−ε) from the epigraph cone — yields aᵀl > γ − ε for every ε and never ≥ γ. This argues by contradiction on the conclusion instead: if the dual system is infeasible, farkas_inequality produces multipliers (x, μ) with Ax = μa and cᵀx < μγ, and both branches of μ contradict the hypothesis directly. μ > 0 rescales to a feasible point beating γ; μ = 0 gives a recession direction along which the objective is unbounded below, so x₀ + tx beats γ for large t.

                The primal-feasibility hypothesis is what makes the μ = 0 branch contradictory rather than merely uninformative — it supplies the x₀ to move from.
