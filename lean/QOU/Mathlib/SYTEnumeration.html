    QOU.Mathlib.SYTEnumeration — brute-force #SYT over the list model, validating the hook formula #

    The Frame–Robinson–Thrall hook-length dimension dimHLF l = (∑l)!/∏h_c is the repo's combinatorial #SYT(λ) (QOU.BraidKnot.IdentityI). It is decide-validated only in aggregate (dim_validated_le12 : Σ_λ dimHLF(λ)² = n!, the RSK sum-of-squares) — never per shape against an independent count of actual standard tableaux.

    This file supplies the missing direct check: a computable brute-force enumeration of standard Young tableaux of a shape l : List ℕ (weakly-decreasing row lengths), and decide-proves numSYTenum l = dimHLF l for every shape with n = ∑l ≤ 4 — confirming the hook formula gives the genuine #SYT shape by shape, not merely on the sum. (Bounded at n ≤ 4 because the count enumerates all n! fillings in the kernel; the aggregate dim_validated_le12 already covers n ≤ 12 via the cheaper hook product.)

    A standard filling is a bijection of the n cells onto {1,…,n} that is strictly increasing along rows and down columns. We represent a candidate as a permutation of [1,…,n] laid out in row-major order, reshape it into rows by l, and check strict rows + strict columns — all Bool, hence Decidable. Pure combinatorics on ℕ; nothing archimedean; no fit.

    Why a hand-rolled allPerms, not List.permutations. Mathlib's List.permutations is defined by well-founded recursion, which the kernel does not reduce — decide gets stuck on it. The generator here (allPerms/insertEverywhere) is structurally recursive on the list, so it reduces definitionally in the kernel; this keeps numSYTenum_eq_dimHLF_le4 a genuine, fully kernel-checked decide proof rather than a native_decide (which would offload to compiled code — avoidable here, and contentious per AGENTS.md §1a).

                      theorem QOU.Mathlib.SYTEnum.rsk_sumSq_eq_factorial_le4 (nps : ℕ × List (List ℕ)) :
                      nps ∈ partitionsByN → (List.map (fun (l : List ℕ) => numSYTenum l ^ 2) nps.2).sum = nps.1.factorial

                      Identity I axiom (i), validated against genuine standard-tableau counts (sorry-free). For every n ≤ 4, the RSK / Burnside sum of squares of the brute-force #SYT(λ) counts equals n!:

                      Σ_{λ ⊢ n} (numSYTenum λ)² = n!.

                      dim_validated_le12 proves the same sum-of-squares for the hook dimension dimHLF; this proves it for the independently-enumerated standard-tableau count — so the RSK identity holds at the level of actual tableaux, not merely of the hook closed form. Together with numSYTenum_eq_dimHLF_le4 (per-shape numSYTenum = dimHLF), this re-grounds dim_validated_le12 itself in genuine #SYT for n ≤ 4.

                      Extension to n = 5 and n = 6 #

                      The n ≤ 4 checks above enumerate n! fillings in the kernel. n = 5 (120 fillings/shape) still decides at the default maxRecDepth; n = 6 (720 fillings/shape) needs the recursion-depth limit raised (the structural allPerms/insertEverywhere recursion goes 720 deep per shape). n = 7 (5040 fillings/shape) is left to the aggregate dim_validated_le12: the per-shape kernel enumeration becomes the build-time bottleneck, not a soundness limit — recorded here, not silently dropped.
