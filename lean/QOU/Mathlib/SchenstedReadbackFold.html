    QOU.Mathlib.SchenstedReadbackFold — the whole index list, read back off Q (RSK inverse, brick 6) #

    Brick 5 read one append back. This file threads it along the fold, under the invariant that makes the read-back well defined: every timestamp already in Q is below the next one to be written. Timestamps count up, so the invariant is self-propagating, and each append is fresh for everything before it.

    • AllLt Q s — every entry of Q is < s.
    • mem_qAppend / allLt_qAppend — an append adds only s, so the invariant survives with s+1.
    • qRowOf_qAppendSteps_of_lt — later appends never move an earlier timestamp.
    • qRowOf_qAppendSteps — qRowOf (qAppendSteps Q is s) (s + k) = some (is.getD k 0): timestamp s+k sits in the row the k-th step wrote to.

    Combined with brick 4 (Q(w) is qAppendSteps [] (rowIndices [] w) 0), the index list is a function of Q(w) — which is what brick 3's word_eq_of_insertWord_eq needs to become injectivity of the RSK map.

    Scope #

    The read-back. Assembling it into rskPair injectivity, then surjectivity, then RSKBurnsideHolds, is the remainder of epic qou-nrex. Nothing here claims them.

    Pure combinatorics on ℕ; nothing archimedean.
