    theorem MvPolynomial.coeff_sumElim_rename_mul {σ : Type u_1} {τ : Type u_2} {R : Type u_3} [CommRing R] (u : MvPolynomial σ R) (v : MvPolynomial τ R) (i : σ →₀ ℕ) (j : τ →₀ ℕ) :
    coeff (i.sumElim j) ((rename Sum.inl) u * (rename Sum.inr) v) = coeff i u * coeff j v

    The identity this module rests on. For disjoint variable groups the coefficients of a product are exactly the products of the coefficients:

    coeff (i ⊞ j) (U · V) = coeff i U * coeff j V

    coeff_mul sums over the antidiagonal of i ⊞ j, but a summand can be non-zero only if its first component is supported on σ and its second on τ — and there is exactly one such splitting. Every other term dies, so no estimate is involved and the result is an equality.

    Stated over any CommRing; no domain hypothesis, because the vanishing of the other terms is established factor-by-factor rather than through mul_ne_zero_iff.

    theorem MvPolynomial.abs_coeff_le_of_mul_separated {σ : Type u_1} {τ : Type u_2} {u : MvPolynomial σ ℤ} {v : MvPolynomial τ ℤ} (hv : v ≠ 0) {B : ℤ} (hB : ∀ (n : σ ⊕ τ →₀ ℕ), |coeff n ((rename Sum.inl) u * (rename Sum.inr) v)| ≤ B) (i : σ →₀ ℕ) :
    |coeff i u| ≤ B

    H(U) ≤ H(U · V) for a non-zero integer V in disjoint variables — the direction the induction step of Roth's lemma needs, and the one bean qou-4lbh predicted would require Gelfond's inequality.

    It requires nothing of the kind. Choose any j in the support of V; then coeff j V is a non-zero integer, so 1 ≤ |coeff j V|, and

    |coeff i U|  ≤  |coeff i U| · |coeff j V|  =  |coeff (i ⊞ j) (U · V)|  ≤  B.

    The middle step is the identity, not an estimate. Gelfond bounds the heights of factors of a product in shared variables, where the coefficients genuinely mix; in disjoint variables they do not mix, and the bound is free.

    An earlier version of this module deferred this one, on the grounds that nothing called for it. The induction step of Roth's lemma calls for it: it bounds both factors of the separated Wronskian, not just the first.

    Non-vacuity guards #

    The identity above would still typecheck with a wrong index convention — it would simply be a true statement about a different coefficient. These two examples pin it down against a case computed by hand: (3x²)·(5y) has coefficient 15 at x²y and 0 at x¹y.

    Next #

    The symmetric statement H(V) ≤ H(U · V) is now abs_coeff_le_of_mul_separated_right above. An earlier version of this note deferred it as speculative; the induction step of Roth's lemma turned out to need both factors bounded, so it was written.

    The next real step is the height of a generalized Wronskian, and it is now assembled rather than open. mvGenWronskian D f is a determinant whose entries are iterated pderivs of P, and the three pieces line up:

    • MvPolynomial.abs_coeff_pderiv_le and card_support_pderiv_le (QOU/Mathlib/MvGenWronskian.lean) bound an entry's height and support size;
    • MvPolynomial.abs_coeff_det_le (QOU/Mathlib/MvPolynomialHeight.lean) turns per-entry bounds into m!·(S·B)^m for the determinant;
    • abs_coeff_le_of_mul_separated above then carries that down to each separated factor.

    The composite is now written too — abs_coeff_mvGenWronskian_le in QOU/Mathlib/WronskianHeight.lean gives H(mvGenWronskian D f) ≤ m!·(S·(d^L·B))^m, with the pderivList iteration actually performed. An earlier version of this note said the chain had not been walked; it has.

    ⚠ What remains is structural: assembling the induction on the number of variables. No further height machinery is known to be needed, but that is a prediction, not a measurement — see bean qou-4lbh for why predictions from this arc deserve suspicion.
