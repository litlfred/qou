    QOU.Mathlib.SchenstedRecordingTrunc — rebuilding a recording tableau from its positions #

    Bricks 30 and 31 of epic qou-nrex (RSK inverse).

    Brick 4 showed a recording tableau is built by qAppendSteps: timestamp t written at the end of row p t. Brick 24 read the positions back off a finished Q as qPositions. This file closes the loop — the appends replay Q exactly:

    qAppendSteps_qPositions — qAppendSteps [] (qPositions Q n) 0 = qTrunc Q n, and hence qAppendSteps_qPositions_self — = Q once the horizon n clears every entry.

    The intermediate object is the horizon truncation qTrunc Q n: the timestamps of Q below n, with the rows that have emptied dropped. It is what the partial replay has built, and stating the induction at it is what makes the step provable — the replay after n steps is not Q, and the naive statement has nothing to induct on.

    The step qAppend_qTrunc is where the tableau structure enters. Two facts do the work, and both are consequences of column strictness rather than of the appends:

    • the truncation's non-empty rows are an initial segment, so a row index means the same thing in qTrunc Q t as in Q (exists_le_head — an entry anywhere has a strictly smaller entry in the top row);
    • a timestamp is written at the end of its row, because the row is strictly increasing and every smaller entry of that row is already present (filter_lt_succ_mem).

    Scope #

    The Q half of the correspondence's forward direction only: positions replay to the tableau. It does not say the recovered word has these positions — that is brick 29 — and assembling both into insertWordRec w = (P, Q) is the next brick. rskPair bijectivity and RSKBurnsideHolds for general n are past that and are not claimed here.

    Pure combinatorics on ℕ; nothing archimedean; no fit.

    def QOU.Mathlib.Schensted.qTrunc :
    List (List ℕ) → ℕ → List (List ℕ)

    The horizon truncation. qTrunc Q n keeps the timestamps of Q below n, stopping at the first row that has emptied. On a standard tableau the emptied rows are exactly the bottom ones, so stopping at the first is the same as dropping them all — and it keeps the recursion structural.

      theorem QOU.Mathlib.Schensted.qAppend_qTrunc (Q : List (List ℕ)) (r t : ℕ) :
      ColStrict Q → (∀ row ∈ Q, List.Sorted (fun (x1 x2 : ℕ) => x1 < x2) row) → Q.flatten.Nodup → t ∈ Q.getD r [] → qAppend (qTrunc Q t) r t = qTrunc Q (t + 1)

      One step of the replay. Writing timestamp t at the end of its row in qTrunc Q t produces qTrunc Q (t + 1).

      The two cases at the top row are the whole content. When the top row holds nothing below t the truncation is empty and t starts the tableau — and then no row below can hold anything below t + 1 either, because column strictness would put a smaller entry in the top row. Otherwise the top row survives and t is appended to it, the rows below being untouched because t occurs once. Below the top row the argument recurses, with exists_le_head supplying the fact that the top row is still non-empty so the index has not shifted.
