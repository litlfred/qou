          source
          theorem MvPolynomial.index_mul_ge {σ : Type u_1} {R : Type u_2} [CommRing R] (d : σ → ℕ) (α : σ → R) (P Q : MvPolynomial σ R) :
          index d α P + index d α Q ≤ index d α (P * Q)

          The index of a product is at least the sum of the indices.

          The load-bearing algebraic property, and the reason index must return ⊤ at 0 rather than a junk 0: with a junk value this is false, since index 0 + index Q = index Q would have to bound index 0 = 0.

          Every monomial of P·Q is a sum of one from P and one from Q, and the weight is additive — so the weight of any monomial of the product is a sum of two weights, each bounded below by its factor's index.

          ⚠ The definition computes the right number #

          index_nonneg and index_add_ge would both hold of a definition that returned 0 everywhere, and index_eq_top_iff of one that returned ⊤ off the zero polynomial. None of the lemmas above pins the value, so a wrong definition would satisfy all of them.

          This does pin it: X² vanishes to order two at the origin, and the index says 2.

          theorem MvPolynomial.translate_pderiv {σ : Type u_1} {R : Type u_2} [CommRing R] [DecidableEq σ] (α : σ → R) (i : σ) (P : MvPolynomial σ R) :

          Translation commutes with partial differentiation: (∂ⱼP)(x + α) = ∂ⱼ(P(x + α)).

          This is the chain rule for a translation, whose Jacobian is the identity. Mathlib has no chain rule for aeval, so it goes by induction on P; the multiplicative step is the only one with content, and it splits on whether the differentiated variable is the multiplied one.

          ⚠ Why this is the gateway lemma. index is a minimum over the support of the translate, so any statement about the index of a derivative has to move pderiv across translate before the support is visible at all. Without this, no index-under-differentiation estimate can even be stated in terms of the definition used here.

          Rescaling the degree vector #

          ⚠ These exist because of a gap identified in QOU/Mathlib/RothInductionStep.lean: the classical proof of Roth's lemma measures a Wronskian's index against the Wronskian's own degree vector, while every other statement in this arc uses one degree vector throughout.

          degreeOf_mvGenWronskian_le says a generalized Wronskian of r functions of degree ≤ d has degree ≤ r · d, so the scale factor is exactly r. These three lemmas are what let that rescaling be expressed and moved across.

          ⚠ They make the rescaling expressible. They do not by themselves establish that the error term in the induction step becomes small — that is the recursion's arithmetic, and it is not done.

          Upper bounds transport across a rescaling: index_{c·d} P ≤ θ ↔ index_d P ≤ c·θ.

          This is the direction the induction hypothesis is used in — it supplies upper bounds on the factors' indices, which have to be converted out of the rescaled weights.

          The proof goes through Finset.inf_le_iff, which needs the bound to be below ⊤; a coerced rational always is.

          Sums, products and determinants #

          The index counterparts of the height bounds in QOU/Mathlib/MvPolynomialHeight.lean, and what the generalized-Wronskian estimate needs. Note the direction: heights are bounded from above by their parts, indices from below — vanishing to high order is preserved by sums and added by products, so every statement here is a lower bound.

          source
          theorem MvPolynomial.index_sum_ge {σ : Type u_1} {R : Type u_2} [CommRing R] {ι : Type u_3} (d : σ → ℕ) (α : σ → R) (s : Finset ι) (F : ι → MvPolynomial σ R) :
          (s.inf fun (i : ι) => index d α (F i)) ≤ index d α (∑ i ∈ s, F i)

          The index of a finite sum is at least the least index of a summand. The Finset form of index_add_ge; the empty sum is 0, whose index is ⊤, matching Finset.inf_empty with no side condition.

          source
          theorem MvPolynomial.index_prod_ge {σ : Type u_1} {R : Type u_2} [CommRing R] {ι : Type u_3} (d : σ → ℕ) (α : σ → R) (s : Finset ι) (F : ι → MvPolynomial σ R) :
          ∑ i ∈ s, index d α (F i) ≤ index d α (∏ i ∈ s, F i)

          The index of a finite product is at least the sum of the indices. The Finset form of index_mul_ge; the empty product is 1, and 0 ≤ index d α 1 is index_nonneg.

          source
          theorem MvPolynomial.index_smul_units {σ : Type u_1} {R : Type u_2} [CommRing R] (d : σ → ℕ) (α : σ → R) (u : ℤˣ) (P : MvPolynomial σ R) :
          index d α (u • P) = index d α P

          Scaling by a unit of ℤ — the only scalars the Leibniz expansion produces — leaves the index alone.

          source
          theorem MvPolynomial.support_C_mul {σ : Type u_1} {R : Type u_2} [CommRing R] [NoZeroDivisors R] {c : R} (hc : c ≠ 0) (P : MvPolynomial σ R) :
          (C c * P).support = P.support

          Multiplying by a non-zero constant does not change the support.

          source
          theorem MvPolynomial.index_C_mul {σ : Type u_1} {R : Type u_2} [CommRing R] [NoZeroDivisors R] (d : σ → ℕ) (α : σ → R) {c : R} (hc : c ≠ 0) (P : MvPolynomial σ R) :
          index d α (C c * P) = index d α P

          Rescaling the polynomial does not move its index.

          index_smul_units says this for ℤˣ; this says it for any non-zero constant over a domain, which is what a determinant of derivatives needs — a generalized Wronskian of powers is always a scalar multiple of a monomial, and the scalar is an accident of the differentiation rather than part of the vanishing behaviour.

          source
          theorem MvPolynomial.index_det_ge {σ : Type u_1} {R : Type u_2} [CommRing R] {ι : Type u_3} [Fintype ι] [DecidableEq ι] (d : σ → ℕ) (α : σ → R) (M : Matrix ι ι (MvPolynomial σ R)) :
          (Finset.univ.inf fun (p : Equiv.Perm ι) => ∑ i : ι, index d α (M (p i) i)) ≤ index d α M.det

          The index of a determinant is at least the least permutation-sum of entry indices.

          Leibniz plus the two lemmas above: the determinant is a sum over permutations, so index_sum_ge takes the least term; each term is a unit times a product, so index_smul_units discards the sign and index_prod_ge adds the entries' indices.

          This is what bounds the index of a generalized Wronskian from below in terms of the indices of the differentiated entries — the estimate Roth's lemma runs on. ⚠ It says nothing about the entries themselves; relating index (pderivList D (f j)) back to index (f j) is index_le_index_iterate_pderiv_add above, and that is where the differentiation cost enters.
