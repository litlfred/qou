    QOU.Mathlib.SchenstedCascadeColStrict — the reverse cascade keeps columns strict (brick 13) #

    Brick 11 proved that RowsSorted and NoEmptyRows survive the reverse cascade unconditionally, and located the corner condition that ColStrict needs. Brick 12 built the index theory of rowUninsert. This file finishes the job.

    It does not go through brick 12's strictBelow_reverse_bump_step, and that is worth saying plainly because brick 12 was written expecting it would. That lemma relates upper and lower when both rows are rowUninsert images. In the cascade the row below the one being written is not always such an image: at the target row it is a dropLast, or the row is deleted outright. So the pair-of-rows step does not compose along the cascade, and the induction below does the four column cases directly against the returned top row. What brick 12 actually supplies here is rowUninsert_spec, le_index_of_lt and reverse_bump_index_mono — the index theory, not the packaged step.

    The corner predicate #

    IsCorner T i says the row below row i is strictly shorter, so removing the last cell of row i leaves a Young shape. Two conveniences fall out of reading out-of-range rows as []:

    • the last row of a tableau is automatically a corner (the row below reads [], length 0);
    • an out-of-range index is automatically not one, so IsCorner T i already carries i < T.length and no separate range hypothesis is needed.

    Scope #

    The cascade-level ColStrict preservation. Word-level surjectivity and RSKBurnsideHolds for general n are the remainder of epic qou-nrex. Nothing here claims them.

    Pure combinatorics on ℕ; nothing archimedean.

      def QOU.Mathlib.Schensted.CascadeStep (T T' : List (List ℕ)) (z : ℕ) :
      Prop

      What the reverse cascade guarantees about the tableau it returns, relative to the one it was handed. Three facts about the top row, each needed one level up:

      • the ejected value z came from some index k of the old top row;
      • the new top row is no longer, and none of its entries is smaller;
      • z is strictly below every surviving entry from column k rightwards.

      That last clause is what lets the row above write z into its own column without breaking the comparison, and it is what unifies the cascade's three shapes at the target row — row deleted, row shortened by dropLast, row written by rowUninsert.

        theorem QOU.Mathlib.Schensted.uninsert_colStrict_step (T : List (List ℕ)) (i : ℕ) :
        ColStrict T → NoEmptyRows T → IsCorner T i → ColStrict (uninsert T i).1 ∧ ∃ (z : ℕ), (uninsert T i).2 = some z ∧ CascadeStep T (uninsert T i).1 z

        The reverse cascade keeps columns strict, at a corner.

        The statement carries CascadeStep alongside because the induction needs it: at row i + 1 the row above has to write the value that came up from below into its own column, and the only way to know that write is safe is to know where the value came from and what became of the row it came from. CascadeStep is exactly that bookkeeping.

        Three shapes occur at the target row and the invariant absorbs all three:

        • row deleted — and the corner condition forces this to be the last row, since a length-one row with anything below it is not a corner. So the tableau below is empty and every clause is vacuous. This is the one case that surprised me: IsCorner does not merely make the deletion safe, it makes it rare.
        • row shortened by dropLast — the ejected cell sat at the far right, so its column index is at or past the end of the shortened row and the last clause is vacuous again.
        • row written by rowUninsert — the substantive case, and the one brick 12 was built for.

        Relation to the shape-level corner predicate #

        QOU.Mathlib.SYTEnum.IsCorner (SYTListCorner.lean) is the same notion one level down, on the shape list rather than the tableau. The two agree, and the bridge is recorded so this is not read as a fourth duplication of corpus machinery.

        The tableau-level form is the one the induction wants: isCorner_cons_succ is a one-line simp, whereas the shape-level form would push tableauShape through every step. It also needs no explicit i < T.length conjunct — out-of-range rows read as [], so 0 < 0 fails and the range condition is already implied (isCorner_lt_length).
