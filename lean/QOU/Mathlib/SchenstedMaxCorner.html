    QOU.Mathlib.SchenstedMaxCorner — a row holding a maximum entry is a corner (brick 16) #

    Brick 15 discharged brick 14's CornersAlong hypothesis for runs built by insertion, which showed the hypothesis is inhabited. Surjectivity of rskPair needs something strictly stronger: CornersAlong P is for an arbitrary standard pair (P, Q), with the positions read off Q rather than off an insertion history. This file proves the keystone that argument turns on.

    isCorner_of_max_in_row — if the last cell of row i holds an entry no smaller than every entry of the tableau, then row i is a corner.

    The proof is the one-line contradiction the classical argument uses, and it needs less than standardness. Suppose row i were not a corner. ColStrict's length half already forces len(row i+1) ≤ len(row i), so "not a corner" pins them equal — and then row i + 1 has a cell directly below the maximum, carrying a strictly larger entry. That contradicts maximality.

    No hypothesis that rows increase strictly is needed, and no standardness predicate is needed — ColStrict plus knowing where the maximum sits is enough. That is worth recording, because the corpus has no list-level standardness predicate and I was about to write one.

    The two pieces #

    • le_getD_last_of_sorted — in a weakly-increasing row, the last entry is the largest. This is what lets a caller who only knows "the maximum is somewhere in row i" reach the hypothesis of the keystone, which is stated about the last cell.
    • isCorner_of_max_in_row — the keystone.

    Scope #

    One step. Wiring this along a whole run — reading the positions off Q, showing each step's removed cell carries the largest remaining entry, and assembling CornersAlong — is the next brick of epic qou-nrex. Nothing here claims it, nothing here claims rskPair is bijective, and RSKBurnsideHolds for general n stays open (proved for n ≤ 12 by an unrelated route, PartitionsOfBridge.rskBurnsideHolds_le12, with no RSK correspondence in it).

    Pure combinatorics on ℕ; nothing archimedean.

    theorem QOU.Mathlib.Schensted.isCorner_of_max_in_row {T : List (List ℕ)} (hc : ColStrict T) (hne : NoEmptyRows T) {i : ℕ} (hi : i < T.length) (hmax : ∀ row ∈ T, ∀ v ∈ row, v ≤ (T.getD i []).getD ((T.getD i []).length - 1) 0) :
    IsCorner T i

    A row whose last cell holds a maximum entry is a corner.

    If row i were not a corner, ColStrict's length half — which already gives len(row i+1) ≤ len(row i) — would pin the two rows equal in length, putting a cell of row i + 1 directly below the maximum. Column-strictness makes that cell strictly larger, contradicting maximality.

    Note what is not assumed: rows need not increase strictly, and no standardness predicate appears. ColStrict and the position of the maximum are the whole input.

    theorem QOU.Mathlib.Schensted.tableauShape_uninsert (T : List (List ℕ)) (i : ℕ) :
    ColStrict T → NoEmptyRows T → IsCorner T i → tableauShape (uninsert T i).1 = SYTEnum.removeCorner (tableauShape T) i

    The reverse cascade is shape-level corner removal.

    uninsert T i changes exactly one row length — every row it passes through above the target is rewritten by rowUninsert, which preserves length — so on shapes it decrements entry i and drops the row if that empties it. That is removeCorner.

    This is the step a run needs: IsCorner is determined by the shape (isCorner_iff_shape), so once the shape is tracked, a corner of Q's shape is a corner of P's.
