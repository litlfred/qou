    QOU.Mathlib.SkewBranchingSum — the classical branching sum ∑_λ f^λ f^{λ/μ} #

    With the skew branching rule in hand (SkewSYTBranchingBijection) and the up-operator identity already proved (QOU.Mathlib.upSum_eq), the classical identity

    ∑_{λ ⊢ k}  f^λ · f^{λ/μ}  =  (k! / |μ|!) · f^μ        (k ≥ |μ|)

    falls out by a one-step induction on k. Stated divisor-free as

    |μ|! · G(μ, k)  =  k! · f^μ.

    The argument #

    Write G(μ, k) = ∑_{λ of size k} f^λ · f^{λ/μ}. Then

    • Base G(μ, |μ|) = f^μ: the only diagram of size |μ| containing μ is μ itself, and f^{μ/μ} = 1 (fDimSkew_self — the skew region is empty, so the tableau is the empty filling and nothing else).
    • Step G(μ, k+1) = (k+1) · G(μ, k) for k ≥ |μ|: expand f^{λ/μ} by skew branching, reindex the resulting (λ, corner) pairs as (ν, addable cell) pairs by rankExchange, and collapse the inner sum with upSum_eq.

    Two places where the bookkeeping would go wrong if done naively #

    • The corner sum must run over ALL corners of λ, not only those outside μ. A corner c ∈ μ contributes f^{(λ∖c)/μ} = 0, since λ ∖ c no longer contains μ — so widening the index is free, and it is what lets rankExchange apply unchanged. That is fDimSkew_branching_corners.
    • Dually, the addable sum must run over ALL addable cells of ν. It looks like it should be restricted to cells outside μ, but the restriction is vacuous: if μ ≤ ν then no cell addable to ν can lie in μ (it would already be in ν), and if μ ⊄ ν the whole term carries the factor f^{ν/μ} = 0. So the inner sum is exactly upSum ν, with nothing to strip.

    Pure combinatorics; nothing archimedean (§7c); no fit.

    References #

    • [stanley1999ec2] Enumerative Combinatorics I, §7.10
    • [manuscript] bean qou-b21r
