    QOU.Mathlib.SchenstedShapeOfPositions — the positions build the recording tableau's shape #

    Brick 37 of epic qou-nrex (RSK inverse).

    Brick 32 takes the two tableaux of a pair as related by hshape : tableauShape P = addCellSteps [] (qPositions Q n) — the shape Q's positions build. For a pair of standard tableaux the hypothesis one actually has is that P and Q share a shape. This file identifies the two:

    addCellSteps_qPositions — addCellSteps [] (qPositions Q n) = tableauShape Q.

    Row i of the built shape has one cell per position equal to i (brick 22's getD_addCellSteps), which is the number of Q's row-i entries below the horizon (brick 26's count_qPositions) — and once the horizon clears every entry, that is the row's length. Off the end both sides vanish: every position is a genuine row index, so it contributes no count there.

    The two lists are then equal by eq_of_getD_eq: lists of positive naturals agreeing at every index are equal. Positivity is what supplies the lengths — a longer list would read positive where the shorter reads the default 0 — and both sides have it, tableauShape Q because Q has no empty rows and the built shape because addCell only ever adds.
