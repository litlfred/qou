    Validation — the bound is attained #

    RothIndex.lean sets the standard that a validation should pin a value, since a wrong constant would satisfy every structural lemma. Here the risk is the cost factor: a bound with 2·m·C, or with the cost dropped entirely, would still be a true theorem in many instances and would still typecheck.

    This instance is tight, so it pins the constant. Take m = 1, f = X, D = ![[0]] — one derivative — with unit weight at the origin, so C = 1. Then index X = 1 on the left, the Wronskian is ∂₀X = 1 with index 0, and the right side is 0 + 1·1 = 1. Both sides are 1: a smaller cost factor would make the theorem false at this very instance.

    The truncated-sum shape Mahler §13 actually needs #

    The three theorems below take the last step of the index side from "index_det_ge gives a lower bound in terms of the entries" to the concrete ∑_{ν<r} max(0, θ − t − ν/rr) that QOU/Mathlib/RothRecursionArith.lean consumes.

    ⚠ This is the shape that the arc's sixth correction identified as missing. The error was not in any lemma; it was the assumption that once the per-column cost is t + ν/rr, the conclusion follows by dividing through linearly. It does not — the columns whose cost already exceeds θ contribute nothing, so the sum is truncated, and truncation is what turns the bound from linear into the square root of RothArith.

    theorem MvPolynomial.sum_max_le_index_det {σ : Type u_1} {R : Type u_2} [CommRing R] [DecidableEq σ] {r : ℕ} (d : σ → ℕ) (α : σ → R) (D : Fin r → Fin r → List σ) (P : MvPolynomial σ R) (θ t rr : ℚ) (hθ : ↑θ ≤ index d α P) (hc : ∀ (i j : Fin r), (List.map (fun (k : σ) => 1 / ↑(d k)) (D i j)).sum ≤ t + ↑↑j / rr) :
    ↑(∑ j : Fin r, max 0 (θ - t - ↑↑j / rr)) ≤ index d α (Matrix.of fun (i j : Fin r) => (pderivList (D i j)) P).det

    The bridge. A lower bound θ on index P, plus a per-column cost bound t + j/rr on the operator lists D i j, gives the truncated-sum lower bound on the determinant's index.

    The max 0 is the whole point: index_le_index_pderivList_add gives index P ≤ index (∂_{D i j} P) + cost, so column j contributes at least θ − t − j/rr only while that is positive; past the cut-off all it contributes is index ≥ 0. A formulation without the max would be false for every column past (θ−t)·rr.

    Note the permutation p₀: index_det_ge bounds index (det M) below by the Finset.inf over permutations, so we pick the minimising one and bound its diagonal. The cost hypothesis is uniform in i, so the choice of p₀ costs nothing.

    Next #

    Both halves of what the induction needs from a Wronskian are now composites rather than fragments: abs_coeff_mvGenWronskian_le bounds its height, sum_index_le_index_mvGenWronskian_add bounds its index, and index_separated / abs_coeff_le_of_mul_separated carry both across the separated factorization to the two factors.

    sum_max_le_index_det above adds the piece those composites were missing: when the per-column cost is allowed to grow with the column (t + ν/rr, which is what a bounded-order operator family actually gives), the resulting lower bound on the determinant's index is a truncated sum, not a linear one. Feeding it to RothArith.sq_mul_le_two_mul_of_sum_le is done in QOU/Mathlib/RothInductionStep.lean as sq_index_le_of_det_bound.

    ⚠ What remains is the recursion — Roth's lemma's statement with its parameter conditions (dⱼ/dⱼ₊₁ growth, ε, the qⱼ hypotheses) and the step feeding RothBaseCase and the m−1 case back into the m case. What sq_index_le_of_det_bound supplies is the shape of that recursion's conclusion ((θ−t)² · rr ≤ 2S); choosing ω(m, ε) still has to be done.

    ⚠ And a standing caution, earned: this module exists because a prose claim about what was "bounded" turned out false. The next such claim should be checked by writing Roth's lemma's statement in Lean and matching each hypothesis to a named theorem — not to a module docstring or a bean entry.
