    QOU.Mathlib.SkewSYTBranchingBijection — the skew branching rule #

    QOU/Mathlib/SkewSYTMaxCorner.lean built both directions of the erase-max step and stopped there, recording explicitly that "both directions built" is not "bijection proved". This file closes that gap and draws the count:

    f^{outer/inner} = ∑_{c a corner of outer, c ∉ inner}  f^{(outer ∖ c)/inner}.

    The shape of the argument is the straight case's (QOU/Mathlib/SYTBranchingRule.lean): a map ⨆_c SkewSYT(outer ∖ c, inner) → SkewSYT(outer, inner) given by re-inserting the maximum, shown bijective, then Equiv.ofBijective + Nat.card_sigma.

    What is genuinely different from the straight case #

    Three things, and each cost a lemma here rather than a rewrite:

    • The index type carries a second condition. The corner must also lie outside inner, since a corner of outer that sits inside inner is not a skew cell at all and deleting it would break inner ≤ outer ∖ c. So the fibre is indexed by {c // IsCornerCell outer c ∧ c ∉ inner}, not by corners alone.
    • content must be re-derived rather than cited. StandardYoungTableau hands over bijOn; SkewStandardYoungTableau certifies its filling with a Finset image equality, so the erase step has to recover image = range n from image = range (n+1) by erasing the top value from both sides. That is what skewEraseMax's content field does.
    • Entries are 0-based. The maximum of a skew tableau on n + 1 cells is n, not n + 1; the straight case's μ.cells.card reads as card - 1 here. Index arithmetic does not port, which is why every statement below carries the size explicitly.

    Pure combinatorics; nothing archimedean (§7c); no fit.

    fDimSkew is defined as a Nat.card, and nothing in the corpus had yet established that this count is finite — so every Nat.card fact about it was, strictly, a fact about a possibly-junk 0. The restriction map T ↦ (entry on the skew cells, valued in Fin |skew|) is injective by skew_entry_ext and lands in a finite type, which settles it.

    exists_max_corner produces the corner; this turns the deletion into an actual SkewStandardYoungTableau on the smaller shape.

    SkewStandardYoungTableau (Mathlib.eraseCorner outer (p, q) hc) inner

    Delete the maximal entry at a corner outside inner. The mirror of skewInsertMax: zero out the corner and keep T elsewhere.

    content is the only field that does real work. Splitting skew outer inner as insert c (skew (outer ∖ c) inner) turns T.content : image = range (n + 1) into insert n (image over the smaller region) = insert n (range n); since n is missing from both inner sets (from skew_injOn, the only cell carrying n is the deleted corner), erasing n from both sides gives exactly the smaller content.
