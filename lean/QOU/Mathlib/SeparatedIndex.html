    The weight is additive across the split #

    theorem MvPolynomial.idxWeight_sumElim {σ : Type u_1} {τ : Type u_2} (d₁ : σ → ℕ) (d₂ : τ → ℕ) (i : σ →₀ ℕ) (j : τ →₀ ℕ) :
    idxWeight (Sum.elim d₁ d₂) (i.sumElim j) = idxWeight d₁ i + idxWeight d₂ j

    idxWeight is additive on Finsupp.sumElim. The support of sumElim i j is the disjoint sum of the two supports, so the defining sum splits with no overlap — this is the combinatorial reason the index is exactly additive rather than merely superadditive.

    The index is exactly additive across a disjoint-variable product #

    source
    theorem MvPolynomial.index_separated {σ : Type u_1} {τ : Type u_2} {R : Type u_3} [CommRing R] [IsDomain R] (d₁ : σ → ℕ) (d₂ : τ → ℕ) (α : σ → R) (β : τ → R) (U : MvPolynomial σ R) (V : MvPolynomial τ R) :
    index (Sum.elim d₁ d₂) (Sum.elim α β) ((rename Sum.inl) U * (rename Sum.inr) V) = index d₁ α U + index d₂ β V

    index (U(x)·V(y)) = index U + index V for disjoint variable groups, over a domain.

    The ≥ half is index_mul_ge plus the rename-invariance above, and holds over any CommRing. The ≤ half is the new content and is where IsDomain is used: it picks multi-indices realising each index and needs their combination to occur in the product, whose coefficient there is a product of two non-zero elements. See the module header — over a ring with zero divisors that monomial can cancel and the inequality can be strict.

    ⊤ is handled by the same argument rather than by a special case: if translate α U = 0 then the left side is ⊤ and so is the right, since ⊤ + x = ⊤.

    Validation #

    RothIndex.lean pins the value of index on X and X² rather than trusting its properties, on the grounds that a wrong definition would satisfy all the structural lemmas. The same applies here: index_separated is symmetric-looking, and with σ = τ a version that attached d₁ to the wrong factor would still typecheck.

    The example below distinguishes them. It uses different weights on the two sides — 1 on the left, 2 on the right — with X on the left and X² on the right, giving 1 + 1 = 2. Had the weights been attached to the wrong factors the value would be 1/2 + 2 = 5/2.

    source
    theorem MvPolynomial.index_X_sq_weight_two :
    index (fun (x : Fin 1) => 2) (fun (x : Fin 1) => 0) (X 0 ^ 2) = ↑1
