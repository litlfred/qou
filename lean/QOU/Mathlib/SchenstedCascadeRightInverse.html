    QOU.Mathlib.SchenstedCascadeRightInverse — the cascade right inverse (brick 10) #

    Brick 9 gave rowInsert ∘ rowUninsert = id on one row. This lifts it to the cascade:

    insert (uninsert T i).1 z = T when the reverse cascade at row i displaced z.

    Brick 2 proved the other composite (uninsert ∘ insert = id). That one supports injectivity; this one is what surjectivity needs — running the inverse on a tableau and re-inserting must return the tableau you started from.

    The hypothesis, and why it is not the corner condition I predicted #

    I expected to need a corner condition (row i + 1 strictly shorter than row i). It is not that, and it is not a weakening of it. uninsert has two branches at the target row and they want different things:

    • row kept (length > 1) — the row loses its last cell, and re-inserting the displaced value appends it straight back: rowInsert finds no entry above it, so there is no bump and no cascade. This needs nothing but row-sortedness. The corner condition was doing no work here.
    • row deleted (length ≤ 1) — the whole row goes, and the displaced value has to come back as a new top row. But insert only ever appends rows at the bottom, so insert T z = [z] :: T can hold only when T is a single column whose entries increase strictly downward: each step rowInsert [b] a must bump, which needs a < b, and that has to hold all the way down.

    So the deleting branch needs column strictness plus the shape condition — and ColStrict, already in SchenstedInsertion, is exactly that: StrictBelow upper lower asserts both lower.length ≤ upper.length (the Young-shape half) and upper[j] < lower[j] (the strictness half). The bumping lemma insert_colStrict proving insert preserves it is already there too.

    A first pass here stated the theorem under 2 ≤ (T.getD i []).length, dodging the deleting branch and calling the shape condition a later brick. That was under-read: the corpus already carried the invariant. The general statement below needs no length side condition at all.

    For the record, the deleting branch really does fail without the hypothesis — #eval-checked, not asserted: uninsert [[1],[2,4]] 0 = ([[2,4]], some 1) while insert [[2,4]] 1 = [[1,4],[2]]. Row lengths there are (1,2), so StrictBelow fails on its length half; a genuine tableau excludes it.

    One insertion step of the cascade, undone and redone. Word-level surjectivity (iterating this the way brick 3 iterates brick 2) and RSKBurnsideHolds for general n are the remainder of epic qou-nrex. Nothing here claims them.

    theorem QOU.Mathlib.Schensted.insert_eq_cons_of_colStrict (T : List (List ℕ)) :
    ColStrict T → NoEmptyRows T → ∀ (a : ℕ), (∀ row ∈ T.head?, row.length ≤ 1 ∧ a < row.getD 0 0) → insert T a = [a] :: T

    Re-inserting a deleted top cell rebuilds a single column. insert only ever appends rows at the bottom, so insert T a = [a] :: T needs every row of T to be a single cell strictly above the next — which is what ColStrict gives once the top row has length one.

    theorem QOU.Mathlib.Schensted.insert_uninsert (T : List (List ℕ)) (i : ℕ) :
    RowsSorted T → ColStrict T → NoEmptyRows T → ∀ (z : ℕ), (uninsert T i).2 = some z → insert (uninsert T i).1 z = T

    The cascade right inverse. If the reverse cascade at row i displaces z, re-inserting z rebuilds T.

    Together with brick 2's uninsert_insert this makes insert and uninsert mutually inverse on a column-strict tableau: brick 2 gives uninsert ∘ insert = id, which supports injectivity, and this gives insert ∘ uninsert = id, which is what surjectivity needs.

    The induction mirrors brick 2's. Above the target row each step is undone by brick 9's rowInsert_rowUninsert. At the target row there are two cases: a row that keeps a cell is rebuilt by insert_dropLast with no bump, and a row that is deleted is rebuilt by insert_eq_cons_of_colStrict, which is where column strictness is spent.

    The obtain ⟨_, _, h⟩ : ∃ …, … = (…, …) := ⟨_, _, rfl⟩ idiom names the intermediate results without touching the goal; rcases h : e with ⟨…⟩ would substitute e in the goal but not in the hypotheses, which leaves the two out of step under the nested match.
