    QOU.Mathlib.VandermondeUpdateRatio — scaling one node of a Vandermonde pair product #

    ∏_{i<j}(x_i − x_j), with one node replaced. Adding a box to row a of a partition sends the shifted part x_a = Q^{β_a} to Q·x_a and fixes every other node, so the effect of a box on the level-r principal specialisation is the effect of a single-node update on this product.
    vandPairProd n x ∏_{i<j<n} (x_i − x_j)
    inner_prod_update one row of the double product under Function.update
    vandPairProd_update V(x[a↦y]) · ∏_{j≠a}(x_a − x_j) = ∏_{j≠a}(y − x_j) · V(x)
    vandPairProd_update_div the same as a ratio, when the denominator is invertible
    sum_vandPairProd_scale branching: ∑_a V(x[a ↦ Q·x_a]) = [n]_Q · V(x)

    The signs cancel, and that is the only subtle point. For j > a the pair is (a,j) and the factor x_a − x_j becomes y − x_j. For j < a the pair is (j,a) and x_j − x_a becomes x_j − y — the opposite orientation. But (x_j − y)/(x_j − x_a) = (y − x_j)/(x_a − x_j), so both halves contribute the same shape and the (−1)^a from the lower rows cancels between the two sides. Hence the update ratio is the unordered ∏_{j ≠ a}, which is exactly the shape QOU.Mathlib.sum_prod_qratio sums over.

    The statement is division-free so that it holds over any commutative ring and needs no non-vanishing hypothesis; vandPairProd_update_div is the field-valued corollary.

      A collided node kills the product.

      If the updated value equals the node just above it, the pair (a−1, a) contributes a zero factor. Applied to a partition: adding a box to row a is illegal exactly when μ_a = μ_{a−1}, and then the shifted parts satisfy β_{a−1} = β_a + 1, i.e. x_{a−1} = Q·x_a. So the illegal rows contribute nothing to the sum in sum_vandPairProd_scale and need no separate case.

      Branching, unconditionally, for the Vandermonde pair product.

      ∑_{a<n} V(x[a ↦ Q·x_a]) = (1 + Q + ⋯ + Q^{n−1}) · V(x).

      Scaling node a by Q is what adding a box to row a does to the shifted parts x_i = Q^{μ_i + r − i}; vandPairProd_update_div turns each summand into the a-th q-ratio and QOU.Mathlib.sum_prod_qratio sums those to [n]_Q.

      Rows to which a box cannot be added need no separate treatment: there Q·x_a = x_{a−1}, so the updated node collides with its neighbour and V vanishes — vandPairProd_update_eq_zero below. Summing over all rows and summing over addable rows are therefore the same sum, which is what the r = 2 chain needed rowLen_two_addCell_row2 for.
