    QOU.Mathlib.HomotopyGroupFunctor — π_n of a map #

    Bean qou-de7r. Mathlib defines HomotopyGroup N X x but not the induced map: a survey of Mathlib.Topology.Homotopy.HomotopyGroup by enumerating its declarations turns up GenLoop.transAt, symmAt, toLoop, fromLoop, copy, the group instances and the π₀/π₁ comparison equivalences — and no map, on either GenLoop or HomotopyGroup. Without it π_n is a family of groups with no morphisms between them, which is not enough to state any exact sequence.

    This file supplies the missing arrow and its functoriality.

    What is proved #

    • genLoopMap f hf g = f ∘ g — a based map pushes a based cube forward. The boundary condition survives because f sends the old basepoint to the new one, which is the entire content of hf.
    • homotopyGroupMap f hf : π_N(X, x) → π_N(Y, y), well defined on classes. Mathlib's ContinuousMap.HomotopicRel.comp_continuousMap does the work; the only thing added is the observation that it applies verbatim, since GenLoop.Homotopic is HomotopicRel relative to Cube.boundary N.
    • Functoriality: homotopyGroupMap_id, homotopyGroupMap_comp.
    • homotopyGroupMap_const — a constant map induces the trivial map. This is the half of exactness at the middle spot that needs no fibration, and it is the reason p ∘ ι being constant on the fibre is worth writing down.
    • homotopyGroupHom — the same map as a MonoidHom, for N nonempty with decidable equality (Mathlib's hypotheses for the group structure). map_mul reduces to f (if P then u else v) = if P then f u else f v, because GenLoop.transAt carries an explicit pointwise formula through GenLoop.copy.

    What is assumed #

    Nothing. There is no fibration hypothesis anywhere in this file — an induced map exists for any based continuous map, and saying so separately from the lifting theory is what keeps the fibration hypothesis in FibrationExactness.lean honest about where it is actually used.

    Index type #

    N is an arbitrary type throughout, matching Mathlib, rather than Fin n. HomotopyGroup.Pi n X x (π_ n X x) is HomotopyGroup (Fin n) X x, so every result here specialises to it; stating them for Fin n only would have been a gratuitous restriction, and Cube.boundary never needed the finiteness.

        A constant map kills every class. The induced map factors through π_N(point), which is trivial — but no such factorisation is needed: the pushforward of any cube along a constant map is the constant cube, on the nose.

        This is the easy half of exactness at the middle spot of the fibration sequence. p ∘ ι is constant on the fibre for the reason the fibre exists, so p_* ∘ ι_* = 1 with no lifting property in sight.
