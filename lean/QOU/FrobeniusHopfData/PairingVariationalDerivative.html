    A rank-2 field space for a variational derivative #

    The gap this file addresses #

    QOU/MathlibExt/MonoidalCalcVar.lean declares

    class HasAction (R : Type*) (C : Type u) … where
  action : ((𝟙_ C) ⟶ (𝟙_ C)) → R

    whose domain is the scalars End(𝟙_C). A variational derivative is an object on the field space — the thing being varied — so an action whose field space is the scalars has a scalar derivative, and nothing in the type of HasAction mentions the objects being paired at all. Downstream, ExternalCurrents.einsteinTensor (MonoidalCalcVar.lean:89) and CategoricalVariationalData.einsteinTensor (QOU/QuantumObservableUniverse/GaugeTheory.lean:127) are both typed (𝟙_ C) ⟶ (𝟙_ C): they are scalars carrying a tensor's name.

    What this file supplies #

    The field space that was missing. A FrobeniusPairingData carries eval : dual ⊗ obj ⟶ 𝟙_ C — a pairing, which is the categorical shape of a rank-2 object — and in a Preadditive, R-linear category the set of such pairings, dual ⊗ obj ⟶ 𝟙_ C, is an R-module. That module is a genuine field space, and §1 develops the variational calculus on it.

    • §1 is generic linear algebra over {R} [CommRing R]: a quadratic action on a module, its variational derivative, the exact Taylor identity that defines that derivative, degree-2 homogeneity, the Euler contraction, and polarization. No limits are needed — for a quadratic functional the Gateaux derivative is algebraic, so the categorical calculus of variations is available in this case without any axiom. (MonoidalCalcVar states that a categorical calculus of variations "does not yet exist in Lean/Mathlib" and axiomatises the equations of motion on that ground; for a quadratic action that is not so.)
    • §2 instantiates §1 at the pairing field space and contracts back to the scalars, which is where the corpus's einsteinTensor slot lives.

    The relation between the rank-2 object and the corpus's scalar #

    contract η T = η ≫ T composes a rank-2 field T : dual ⊗ obj ⟶ 𝟙_ C with a co-pairing η : 𝟙_ C ⟶ dual ⊗ obj (index raising) and lands in 𝟙_ C ⟶ 𝟙_ C. So the corpus's scalar is the trace of a rank-2 object, and contract is R-linear (contract is built as a LinearMap, whose map_add'/map_smul' fields are the content).

    subsingleton_of_contract_reflects is the structural statement of the defect: if a scalar equation of contractions implied the corresponding rank-2 equation, uniformly in the co-pairing, then the pairing field space would have at most one element. The witness is the degenerate co-pairing η = 0, for which every rank-2 field contracts to the same scalar. So a scalar-only Einstein-shaped equation is strictly weaker than the rank-2 identity it is named after, in any Preadditive monoidal category with more than one pairing.

    What is NOT claimed #

    • No gravitational content. No metric, no curvature, no stress-energy, no Newton constant, no 8π, no numerical constant of any kind. This file is about whether the categorical setting supports a rank-2 variational calculus — which is a question about types and modules, not about gravity.
    • No general Euler-Lagrange machinery. §1 covers quadratic actions. A higher-degree or non-polynomial action needs a genuine limit and is not addressed.
    • contract uses a co-pairing η : 𝟙_ C ⟶ dual ⊗ obj, whose handedness is the opposite of the coev : 𝟙_ C ⟶ obj ⊗ dual in FrobeniusPairingData.Nondegenerate. In a braided or rigid setting the two are transported into each other; that transport is not asserted here, and η is taken as a datum.
    • Nothing here is wired into MonoidalCalcVar or GaugeTheory; those two files are untouched. Retyping HasAction.action is a separate change.

    Base ring (§7c) #

    Generic {R : Type*} [CommRing R] throughout. The single ℤ occurrence is the separating witness value_does_not_determine_variation, which needs a concrete module to exhibit two fields with equal action and different derivative; no ℝ and no archimedean tactic appears in this file.
