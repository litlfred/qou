    The categorical half of the Frobenius-pairing claim #

    QOU/FrobeniusHopfData/frobeniusForm.lean states only that the Frobenius pairing is bijective, because FrobeniusFormContext models A and A^∨ as plain Type — no category is in scope there, so the manuscript's categorical side (the pairing induces an iso A ≅ A^∨, via the snake identities with a coevaluation η̃ : 𝟏 → A ⊗ A) cannot be written against it.

    That was recorded on 2026-09-07 as needing "the rigid-monoidal apparatus", which was wrong: Mathlib carries CategoryTheory.Monoidal.Rigid at the pin. This file is the correction made constructive.

    And the manuscript's non-degeneracy condition IS Mathlib's ExactPairing. That class asks for exactly what the manuscript asks for — a coevaluation and an evaluation satisfying two triangle (snake) identities (Rigid/Basic.lean:73-87). So the categorical half needs no new infrastructure at all; it needed the right model.

    What is and is not claimed #

    Nondegenerate is stated over the pairing the data actually carries, so it is not satisfiable by choosing a proposition — the failure mode that made the is_iso : Prop field of FrobeniusFormContext assert nothing. exactPairing_of_nondegenerate turns it into Mathlib's class, which is where the downstream rigid-monoidal API lives.

    This says nothing about the manuscript's equivalence with bijectivity: that needs a faithful fibre functor τ reflecting isomorphisms, which is a further step and is deliberately not asserted here.
