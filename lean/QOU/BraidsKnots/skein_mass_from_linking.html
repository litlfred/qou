    QOU.BraidsKnots.skein_mass_from_linking #

    Canonical declaration for content block lem:skein-mass-from-linking: Mass functional on a Skein resolution: linking-energy plus constituent volume. The lean.ref URI qou:QOU.BraidsKnots.skein_mass_from_linking resolves here.

    Lemma statement (from manuscript): evaluating the mass functional $\mathfrak{m}$ on the terminal Skein resolution of a hadron $H$ gives

    $$ \mathfrak{m}(H) #

    Q(q) \cdot \mathfrak{m}(\mathcal{L}{\mathrm{Hopf}}) + \sum{i=1}^{n} \frac{\mathrm{Vol}(K_i)}{\hbar_q^{2}}, $$

    where the first term is the binding energy from linking and the second is the constituent mass (zero for torus-knot constituents), $Q(q) \in \mathbb{Z}[q^{\pm 1}]$ is the Skein polynomial of the linking configuration, and $\hbar_q = 1 - q^{-1}$.

    2026-09-03 — the previous docstring described a repair that was never made #

    This module's header used to say:

    "It does not carry the Skein mass identity as a projected field (the previous version carried claim_skein_mass_from_linking and a def handing it back — the self-assuming projection forbidden by AGENTS.md §3b-cond item 5)."

    "skein_mass_from_linking states the real manuscript identity as a theorem over the class's data fields; it is unproved (sorry + manuscript citation per AGENTS.md §1a disposition 2)."

    Neither sentence described the code beneath it. SkeinMassFromLinkingContext did carry the identity, as a field mass_identity, and skein_mass_from_linking ended not in sorry but in ctx.mass_identity — the projection, under prose naming the rule it violates. Only the rename claim_skein_mass_from_linking → mass_identity had happened; the class docstring recorded that honestly ("carried as an upstream class field"), and the module docstring above it went on asserting the opposite. This is the second file in this drain with that exact shape (cf. QOU.Archimedean.knot_operator_selection), and in both the prose was the only place the repair existed.

    Why sorry (disposition 2) would not have been sound either #

    With mass, Q, mass_Hopf, n and Vol_K chosen by the instance, the identity is refutable — not_skeinMassDecomposition_of_free_data below takes mass = 1 against Q = mass_Hopf = 0, n = 0, and gets 1 = 0. A sorry there would read as "true, not yet proved" over a statement that is false at freely-chosen data, which is worse than the projection it would replace.

    The lemma is about the mass functional evaluated on the terminal Skein resolution of a hadron, not about arbitrary reals, and this development constructs none of those objects.

    Disposition: name it, assert nothing (AGENTS.md §1a, disposition 3) #

    skein_mass_from_linking is now a Prop-valued definition over caller-supplied data. A caller who has an actual Skein resolution supplies its data and takes this as an ordinary hypothesis, and it constrains them because the data are theirs.

    Two things make this a better fit for disposition 3 than QOU.BraidKnot.six_term_mass_formula_complete, where naming the claim recovered nothing:

    • hbar_q is no longer free. hbarQ q = 1 - q⁻¹ is a definition here, so the manuscript's ℏ_q = 1 − q⁻¹ is encoded structurally rather than carried as an assumption an instance could satisfy vacuously.
    • The torus-knot specialisation is a genuine consequence and is derived from the named Prop as a hypothesis (skein_mass_torus_constituents), so the file contains a real implication rather than only a schema.

    What is still unencoded, stated rather than implied #

    The mass functional 𝔪, the Skein resolution and its terminality, and Q being the Skein polynomial of the linking configuration are not constructed anywhere in this file — Q is a real number, not a Laurent polynomial evaluated at q. So the decomposition names which quantities are added, not why they are the ones that appear.

    Note also what the manuscript's own proof (skein-mass-from-linking-proof.md) establishes: it restates the decomposition and then derives the torus-knot case from it. The decomposition itself is asserted there too, so the Lean is faithful to the manuscript in leaving it unproved — the gap is the manuscript's, not this file's.

        Torus-knot specialisation — derived from the decomposition rather than projected.

        When every constituent is a torus knot (Vol(Kᵢ) = 0 for all i, the hyperbolic volume of a torus knot vanishing), the constituent sum drops and the hadron mass is pure linking energy, 𝔪(H) = Q(q) · 𝔪(L_Hopf).

        This is the one step the manuscript's proof actually derives, and it is the reason the decomposition is worth naming: it is a hypothesis something is proved from.
