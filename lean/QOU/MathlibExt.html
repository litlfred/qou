    QOU.MathlibExt — Mathlib-extension lemmas for the QOU formalisation #

    Standard / mechanical lemmas not yet in Mathlib but needed by the QOU formalisation. Each is a candidate for upstream contribution; until they land, callers in QOU.* use the local versions.

    Sections #

    • §1 List sort identities (sum / product preserved by insertionSort)
    • §2 Foldl-as-product for commutative monoids
    • §3 Permutation-invariance of foldl/foldr over commutative ops
    • §3b Reversal-invariance of products under Pairwise Commute
    • §4 Real.rpow numerical helpers (sqrt bridge for half-powers)

    §2 Foldl as initial · product (commutative monoids) #

    source
    theorem QOU.MathlibExt.List.foldl_mul_eq_mul_prod {α : Type u_1} [Monoid α] (xs : List α) (init : α) :
    List.foldl (fun (x1 x2 : α) => x1 * x2) init xs = init * xs.prod

    For any monoid, List.foldl (· * ·) init xs equals init * xs.prod. Holds for arbitrary Monoid — no commutativity needed; the proof uses associativity only.

    §3 Foldl/foldr commutativity #

    source
    theorem QOU.MathlibExt.foldl_eq_foldr_comm {α : Type u_1} [CommMonoid α] (xs : List α) (init : α) :
    List.foldl (fun (x1 x2 : α) => x1 * x2) init xs = List.foldr (fun (x1 x2 : α) => x1 * x2) init xs

    For a commutative monoid, foldl and foldr agree: both produce init * xs.prod = xs.prod * init.

    §3a Pairwise Commute foldl/foldr theorem #

    This is the form needed for MatrixChainEqBuildChains: matrices are not a CommMonoid, but the specific transfer matrices in the chain pairwise commute (witnessed by transferMatrix_comm), and the chain initialiser commutes with each matrix in the chain. Under those hypotheses, foldl and foldr agree.

    source
    theorem QOU.MathlibExt.List.commute_init_prod {α : Type u_1} [Monoid α] (init : α) (xs : List α) (h : ∀ x ∈ xs, Commute init x) :
    Commute init xs.prod

    Commute init xs.prod follows from init commuting with every element of xs.

    source
    theorem QOU.MathlibExt.foldl_eq_foldr_of_commute_init {α : Type u_1} [Monoid α] (xs : List α) (init : α) (h : ∀ x ∈ xs, Commute init x) :
    List.foldl (fun (x1 x2 : α) => x1 * x2) init xs = List.foldr (fun (x1 x2 : α) => x1 * x2) init xs

    Foldl/foldr equality from a Commute hypothesis on the initial accumulator: foldl and foldr produce the same result over an arbitrary Monoid whenever the initial accumulator commutes with every list element.

    Note: pairwise commutativity among the list elements is not needed for this form — the result is init * xs.prod either way (foldl) or xs.prod * init (foldr), and these are equal iff init commutes with xs.prod, which is exactly the Commute init x for all x hypothesis (via commute_init_prod).

    CORRECTION 2026-09-05: this does NOT discharge MatrixChainEqBuildChains. The sentence removed here claimed it did "after some rearrangement". It does not, and the reason is structural rather than a missing rearrangement: this lemma moves the initial accumulator from one end of the product to the other and leaves the list order alone (both sides are init * xs.prod / xs.prod * init). matrixChain does not have an accumulator problem — it reverses the list (matrixChain (x :: l) = matrixChain l * f x, so matrixChain seq = (seq.map f).reverse.prod). The lemma that applies is prod_reverse_eq_of_pairwise_commute in §3b. (That call site is now fully closed — QOU.TMCorrespondence.matrixChain_eq_buildChains is proved unconditionally as of 2026-09-05, and the class has an instance.)

    The lemma itself is correct and is kept; only its claimed consequence was wrong.

    theorem QOU.MathlibExt.prod_eq_of_perm {α : Type u_1} [CommMonoid α] {xs ys : List α} (h : xs.Perm ys) :
    xs.prod = ys.prod

    Permutation-invariance of products in a commutative monoid (specialisation of List.Perm.prod_eq for use as a lookup target by automation).

    For a CommMonoid, the underlying Mathlib lemma List.Perm.prod_eq already gives us order-invariance of products — folding from any direction over any permutation of the list produces the same answer. The two corollaries below package this for use at common call sites.

    source
    theorem QOU.MathlibExt.prod_reverse_eq {α : Type u_1} [CommMonoid α] (xs : List α) :
    xs.reverse.prod = xs.prod

    xs.reverse.prod = xs.prod in a CommMonoid.

    §3b Reversal-invariance WITHOUT commutativity of the operation #

    `prod_reverse_eq` above needs a `CommMonoid`.  The matrices this
formalisation actually reverses (`QOU.TMCorrespondence.matrixChain`)
live in `Matrix (Fin 2) (Fin 2) R_t`, which is **not** commutative —
only the *specific* transfer matrices in play commute pairwise
(`QOU.Archimedean.transferMatrix_comm`).  The lemmas below are the
`Pairwise Commute` strengthening that case needs.
    source
    theorem QOU.MathlibExt.pairwise_of_forall {α : Type u_1} {R : α → α → Prop} (xs : List α) (h : ∀ (a b : α), R a b) :
    List.Pairwise R xs

    A Pairwise relation that holds for every pair holds along any list.

    source
    theorem QOU.MathlibExt.prod_reverse_eq_of_pairwise_commute {α : Type u_1} [Monoid α] (xs : List α) (h : List.Pairwise Commute xs) :
    xs.reverse.prod = xs.prod

    Reversing a list does not change its product when the list's own elements commute pairwise — the non-commutative-monoid form of prod_reverse_eq.

    Note this needs nothing new from Mathlib: List.Perm.prod_eq' (Mathlib/Algebra/BigOperators/Group/List/Lemmas.lean:56) already takes exactly a Pairwise Commute hypothesis, and List.reverse_perm supplies the permutation. Recorded here because the QOU call site had been looking for a foldl/foldr bridge lemma instead, which is a different (and, for that call site, unnecessary) statement — see the correction on §3a below and on QOU.TMCorrespondence.MatrixChainEqBuildChains.

    theorem QOU.MathlibExt.prod_map_reverse_eq_of_forall_commute {α : Type u_1} {β : Type u_2} [Monoid β] (f : α → β) (xs : List α) (h : ∀ (x y : α), Commute (f x) (f y)) :

    §4 Real.rpow numerical helpers #

    The Real.rpow function is central to several QOU bounds (skein mass relation, pair-skein decomposition, q-Planck constant), but norm_num does not yet evaluate it on non-integer exponents. The lemmas below convert the most common QOU pattern q^(1/2 : ℝ) + q^(-(1/2) : ℝ) to Real.sqrt q + 1 / Real.sqrt q, where Mathlib's existing Real.sqrt-based numerics apply.

    source
    theorem QOU.MathlibExt.Real.rpow_half_eq_sqrt (x : ℝ) :
    x ^ (1 / 2) = √x

    x^(1/2 : ℝ) = Real.sqrt x (for any real x; both sides are zero on the negative reals via the rpow / sqrt conventions). Symmetric form of Mathlib's Real.sqrt_eq_rpow.

    Upstream status: this is the .symm of Mathlib's Real.sqrt_eq_rpow (present in the pinned v4.24). A named Real.rpow_one_div_two is not in the pinned Mathlib (probed 2026-06-26 — unknown constant), so this local convenience wrapper stays until/unless one lands upstream.

    source
    theorem QOU.MathlibExt.Real.rpow_neg_half_eq (x : ℝ) (hx : 0 < x) :
    x ^ (-(1 / 2)) = 1 / √x

    For x > 0, x^(-(1/2) : ℝ) = 1 / Real.sqrt x.

    source
    theorem QOU.MathlibExt.q_half_denom (q : ℝ) (hq : 0 < q) :
    q ^ (1 / 2) + q ^ (-(1 / 2)) = √q + 1 / √q

    The QOU "denominator" q^(1/2) + q^(-1/2) equals sqrt q + 1 / sqrt q.

    source
    theorem QOU.MathlibExt.sqrt_mul_half_denom (x : ℝ) (hx : 0 < x) :
    √x * (√x + 1 / √x) = x + 1

    For x > 0, the function t ↦ t + 1/t evaluated at t = Real.sqrt x is non-negative and admits a clean cross-multiplication identity: (Real.sqrt x) · ((Real.sqrt x) + 1 / (Real.sqrt x)) = x + 1, i.e. multiplying the QOU half-denominator by sqrt x clears the inverse, yielding a closed-form polynomial in x.

    source
    theorem QOU.MathlibExt.Real.lt_sqrt_of_sq_lt (a x : ℝ) (ha : 0 ≤ a) (hsq : a ^ 2 < x) :
    a < √x

    Bracketing helper: if a > 0 and a^2 < x, then a < Real.sqrt x. Lifted from Real.sqrt_lt_sqrt with the Real.sqrt_sq simplification baked in.

    source
    theorem QOU.MathlibExt.Real.sqrt_lt_of_lt_sq (a x : ℝ) (ha : 0 ≤ a) (hx : 0 ≤ x) (hsq : x < a ^ 2) :
    √x < a

    Bracketing helper: if 0 ≤ x and x < a^2, then Real.sqrt x < a (assuming 0 ≤ a).

    theorem QOU.MathlibExt.add_inv_ge_two (t : ℝ) (ht : 0 < t) :
    t + 1 / t ≥ 2

    AM-GM for t + 1/t: for t > 0, t + 1/t ≥ 2.

    Proof: (t - 1)² ≥ 0 expands to t² - 2t + 1 ≥ 0, dividing by t gives t - 2 + 1/t ≥ 0, i.e. t + 1/t ≥ 2.
