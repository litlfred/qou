    The q-dimensions the selection rule runs on, derived rather than substituted #

    prop:selection-rule-anchors-c1-c3 and prop:selection-rule-c2-prediction state the per-component selection rule

    lw(c)(q) := (1/(c+1)) · Σ_{λ ⊢ c+1} dim_q V_λ

    and give closed forms at c = 1, 2, 3. Their .md calls those "derivation-tight (not a fit; both follow from the q-deformed hook-length formula)".

    Their Lean did not follow from the hook-length formula, because it never mentioned it. What those files prove is, in full:

    selection_rule_c1_eq_one          ((1 : R) + 1) / 2 = 1
selection_rule_c2_prediction      (1 + (q + q⁻¹) + 1) / 3 = (q+1)^2 / (3*q)
selection_rule_c3_eq_family_a     (1 + (q²+1+q⁻²) + (q²+q⁻²) + (q²+1+q⁻²) + 1) / 4
                                    = 5/2 + (3/4)(q - q⁻¹)^2

    Every one is an arithmetic identity over literals typed in by hand. No partition, no Young diagram, no hook length and no dim_q occurs in any statement; the hook-length computation was done in a docstring and only its output reached the Lean. The c=1 case is the clearest: (1+1)/2 = 1 is true of the numeral 1, and its own docstring concedes the q argument "is genuinely unused". That is the sorry-free ≠ derived failure AGENTS.md legislates against, and Strict Lean Discipline §8's test catches it — could this be wrong? No: not because the mathematics is sound, but because the statement does not mention the objects it claims to be about.

    This file supplies the missing half. dimQ is built from the shape:

    shape (a `List ℕ`)  →  conjugate  →  hook lengths  →  q-hook-length formula

    so dimQ_two_one and friends are computed, and the selection-rule sums below are consequences of the hook-length formula rather than restatements of a docstring. The originals are not wrong and are not deleted — they remain true arithmetic, and selection_rule_c2_from_hooks closes the gap by deriving their left-hand sides.

    Conventions #

    qInt is the balanced q-integer [n]_q = (qⁿ − q⁻ⁿ)/(q − q⁻¹), matching mass_at_3A_proper.qint in computations/, so [2]_q = q + q⁻¹ and [3]_q = q² + 1 + q⁻². It is written as an explicit zpow sum rather than as that quotient so it is defined at q = 1 too and needs no q ≠ ±1 side condition; qInt_two and qInt_three below check it against the closed forms.

    source

    Balanced q-integer [n]_q = q^{-(n-1)} + q^{-(n-3)} + ⋯ + q^{n-1}.

                The q-dimensions, derived #

                Each is now [n]_q! over the product of the computed hooks.

                The non-vanishing hypotheses are not decoration. dimQ divides by the product of the hooks' q-integers, and Lean's division sends a zero denominator to 0, so at [2]_q = 0 (that is, q² = −1) the claim dimQ q [2] = 1 is genuinely FALSE rather than merely unproved. Carrying qInt q 2 ≠ 0 explicitly is what makes each statement true as written; qInt_pos below discharges it for every real q > 0, which is the regime the selection rule is stated in.
