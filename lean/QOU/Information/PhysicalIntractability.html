    QOU.Information.PhysicalIntractability — the honest, derived lower bound #

    The one route by which Option B yields a derived (non-fiat) separation — though of something strictly weaker than abstract P ≠ NP.

    The corpus's Bekenstein / bandwidth bound says a substrate computation processes at most 𝔅(q) q-bits per Planck step, so in t steps it can access at most t · 𝔅 bits. If deciding an instance of size n genuinely requires info(n) bits of the degree-0 obstruction, then a correct bandwidth-limited device needs at least info(n) / 𝔅 steps. When info(n) is super-polynomial, no bandwidth-limited device decides the problem in polynomial time.

    This is a genuine information-theoretic lower bound — a pigeonhole argument, proved sorry-free below — not a fiat identification. Its honest scope:

    • the physical input is info(n) super-polynomial (the degree-0 answer needs more than poly bits — the horizon/3^c-tree content, to be derived, not assumed);
    • the conclusion bounds only bandwidth-limited (physical) computation. A general Turing machine is not Bekenstein-limited, so this is strictly weaker than abstract P ≠ NP — a physical Church–Turing statement, not the Clay problem.

    That is the ceiling of the non-fiat route, and it is the theorem the QOU is actually positioned to prove.

    Relation to the query-model lower bound (integration) #

    This file is the bandwidth / physical-device derivation of the 3^c lower bound. Its query-model sibling lives in QOU.Information.SkeinHorizonLowerBound (treeSearch, treeSearch_hcost: the observer must visit every one of the 3^d leaves) and QOU.Information.SkeinInfoLowerBound (info_depth_lower_bound, numLeaves_eq_three_pow_info: the entropy floor info = 3^c, exact). The two are the same phenomenon proved in two models — a Bekenstein-bandwidth pigeonhole here, a ternary decision-tree entropy floor there.

    Algebrization caveat (shared, do not over-claim). The correct hypothesis below — the device must access the full 3^{3n}-tree worth of bits — is exactly the no-shortcut / black-box assumption. SkeinHorizonLowerBound.no_horizon_cost_of_polyObservable makes the flip side precise: an efficiently-evaluable algebraic observation (a poly shortcut) refutes correct, so neither this bandwidth bound nor the query-model bound crosses to abstract P ≠ NP — that crossing needs a genuinely non-algebraic separating invariant (the χ(A) residue), which is the algebrization barrier (Aaronson–Wigderson). Both derivations are honestly weaker than the Clay problem, and for the same structural reason.

    def QOU.Information.SuperPolynomial (f : ℕ → ℕ) :
    Prop

    A function f : ℕ → ℕ is super-polynomial if it exceeds every polynomial c · n^k at some argument n ≥ 1.

    The 1 ≤ n guard is essential: without it the n = 0 term c · 0^k = 0 (for k ≥ 1) is < f 0 for any f with f 0 ≥ 1, so a mere polynomial like n ↦ (n+1)^2 would spuriously satisfy the predicate (confirmed in Lean, bean qou-qgyw). Guarding the witness away from 0 makes the predicate mean genuine polynomial domination and makes PolyGrowth ⟹ ¬SuperPolynomial (PolyGrowthAlgebra.not_superPolynomial_of_polyGrowth) provable.

      The QOU resolution-tree information requirement #

      The corpus derives the physical input info(n) — the information the degree-0 answer requires — from the skein resolution tree. A c-crossing link has a 3^c-leaf resolution tree (three skein channels per crossing). At a non-torsion substrate q₀ the Hecke algebra is semisimple, so no paths cancel: the full 3^c tree survives (corpus nontorsion_full_tree). The NP-complete boundary family uses c_N = 3N crossings (prop:p-vs-np-boundary), so extracting the degree-0 answer for instance size n requires the whole surviving tree, info(n) = 3^{3n}.
