    QOU.Information.SkeinInfoLowerBound — the rigorous info(n) entropy floor #

    SkeinHorizonLowerBound discharged the sequential-walk cost: treeSearch must visit all 3^c leaves (treeSearch_hcost), an honest but naive O(3^c)-step bound. This file supplies its information-theoretic complement — the entropy floor: the optimal-query decision depth to distinguish the horizon's 3^c leaves is exactly

    info(H) = log₃(numLeaves) = c trits,

    and no ternary decision process can do better. Each step reveals at most one trit, so d steps separate at most 3^d outcomes; distinguishing N outcomes therefore needs depth ≥ log₃ N. Pure counting — no P-vs-NP content, no conjecture: this is the rigorous lower bound the horizon's 3^c leaf count forces, unconditionally.

    Contents (all sorry-free):

    • horizonInfo — info(H) := log₃(numLeaves).

    • horizon_depth_ge_info — its horizon instantiation: covering the horizon's leaves needs depth ≥ info(H) = c.
    • treeSearch_info — the two ends of the query spectrum: treeSearch d carries exactly d trits (log₃ 3^d = d), the filtration level, while its sequential cost is 3^d steps.

    def QOU.Information.horizonInfo (H : ComputationalHorizon) :
    ℕ

    Information content of the computational horizon, in trits — the base-3 logarithm of the leaf count. Since the ternary resolution tree has numLeaves = 3^c, this is exactly the crossing count c: the number of independent ternary resolutions the observer must fix.
