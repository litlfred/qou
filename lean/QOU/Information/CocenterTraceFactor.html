    QOU.Information.CocenterTraceFactor — the trace factors through HH₀ = A/[A,A] #

    Sharpens the [Q,M] operator lemma (MagnitudeTraceCommutator) to the exact homological home of the magnitude/decision split. The magnitude functional M = tr_M is a trace, so it not only kills the commutator subspace [A,A] — it factors through the cocenter

    HH₀(A) = A / [A,A]

    (the zeroth Hochschild homology). This file formalizes that, sorry-free, for any R-algebra A, and instantiates it for the Markov-trace model A = End V, M = LinearMap.trace.

    Shared trace abstraction (unification with Machinery.BilinearTraceCyclicity). The cyclicity hypothesis is the single predicate QOU.Machinery.BilinearTrace.IsCyclic τ := ∀ x y, τ (x·y) = τ (y·x) — the same "a functional is a trace" abstraction the Gram-symmetry / character-decomposition machinery uses. That file supplies the constructors of cyclic functionals — a matrix character χ_λ = trace ∘ ρ_λ is cyclic (isCyclic_trace_comp), and a finite weighted sum tr_M = ∑_λ w_λ · χ_λ of cyclic functionals is cyclic (isCyclic_weighted_sum), which is exactly the shape of the QOU Markov trace. This file supplies the consequence: every such cyclic functional factors through the cocenter HH₀. So the two independently-developed frameworks meet here — the character side builds the Markov trace, the cocenter side localizes what it discards (the decision axis [A,A]).

    Why this is the P-vs-NP-relevant sharpening. HH₀(A) is the space of trace functionals — the magnitude axis. Every such functional is a function of the cocenter class alone, so it is blind to the complementary [A,A] — the decision/quantifier axis (MagnitudeAxisBoundary). A decision-separating invariant would therefore have to be a non-trace functional: not a class in HH₀, but a cocycle in HH₁ (outer derivations). For the Iwahori–Hecke algebra H_n(q) the cocenter HH₀(H_n(q)) and the commutator subspace [H,H] have an explicit basis of minimal-length conjugacy-class representatives (Xuhua He's cocenter / density theorems); the search for a decision functional is the search for a HH₁ class, which (at generic q, where H_n(q) is semisimple) vanishes — it can live only at the root-of-unity / fibre level. This file supplies the HH₀ half rigorously; the HH₁ search stays open.

          The wrong-axis corollary: a trace cannot separate the [A,A] axis #

          An Euler characteristic (χ(Σ₄) = −6 for the QOU's Bring fibre) is an additive-on-triangles / K₀ invariant — the Hattori–Stallings/dimension trace. So it factors through HH₀ and inherits the blindness below: it cannot distinguish elements differing by a commutator, i.e. it is blind to the [A,A] (decision/quantifier) axis. Therefore a nonzero χ — however axiom-fixed — is never the P-vs-NP decision residue: that residue must live in [A,A] = ker(every trace), i.e. be a non-trace (HH₁) object.
