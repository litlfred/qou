    The arm/leg decomposition of a hook, as reusable lemmas #

    YoungDiagramKernelPincer.hookShape_of_hookLen_eq_sum (the v = n carrier lemma) proved its arm/leg machinery inline as local haves: the hook of (i,j) is the disjoint union of its arm {(i,j') : j ≤ j' < λᵢ} and its strict leg {(i',j) : i < i' < λ'ⱼ}, both inside the cell set, with total cardinality hookLen.

    Depth-1 (ν_{n−1}, epic qou-ec5z, bean D1) needs the same decomposition but with a different equality analysis: hookLen = n − 1 means the union misses exactly one cell, so the classification splits on which cell is missed rather than collapsing to the corner. That requires the pieces as named lemmas rather than as haves inside someone else's proof. This file extracts them; the v = n proof is left as-is (it is merged and green).

    Nothing here is new mathematics — it is the merged argument, factored.

        Depth-1: the hook misses exactly one cell #

        The equality analysis (TAIL) depth-1 needs (bean qou-ckyw). At hookLen = n − 1 the arm/leg union sits inside the n-cell set with n − 1 elements, so its complement is a singleton — and the depth-1 carrier classification is then a case split on which cell that is.

        theorem QOU.BraidsAndKnots.HookArmLeg.origin_not_mem_hookUnion (l : List ℕ) (p : ℕ × ℕ) (hp : p ≠ (0, 0)) :
        (0, 0) ∉ armF l p ∪ legF l p

        The corner is outside every hook but its own. The hook of p meets row p.1 only from column p.2 rightward and column p.2 only strictly below row p.1, so it contains (0,0) exactly when p = (0,0). This is the pivot of the depth-1 case analysis: for any other carrier the corner is the missed cell, which then forces every other cell into the hook.

        The carrier lies on the first row or the first column. If both coordinates were positive the hook would miss two distinct cells — the corner (0,0) and (0, p.2) — contradicting card_sdiff_hookUnion_eq_one. Combined with the corner lemma this is the case split that pins the depth-1 carriers.

        carrier_fst_or_snd_eq_zero puts it on row 0 or column 0; pushing further out along either axis produces a second missed cell — (0,1) in the row case, (1,0) in the column case — contradicting the singleton. These are exactly the carriers of the second-instance audit's three shapes: two-corner (a,2,1^c) at (0,0), row (n) at (0,1), column (1^n) at (1,0).
