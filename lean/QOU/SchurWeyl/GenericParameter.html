    QOU.SchurWeyl.GenericParameter — what "generic q" has to mean over a general field #

    Beans qou-kwoa (the general-field item) and qou-j377 (SW-6).

    QOU/SchurWeyl/HeckeWedderburnGeneral.lean proves the Wedderburn decomposition at every rank, but over ℝ. qou-kwoa recorded that as "blocked upstream — heckeWedderburn is ℝ-only", which is true and says nothing about why, so it reads as an accident of statement. It is not. Measured on the theorem's 103-module in-repo import cone:

    • Real.sqrt does not occur anywhere in it — the seminormal form as built here needs no square roots, so the usual reason a Hoefsmit construction wants ℝ does not apply;
    • exactly two modules use anything Real.* in code, SeminormalRep and SeminormalInequivalence, and both use only the Real.log family, in one idiom.

    That idiom is zpow_ne_one : q ≠ 0 → q ^ 2 ≠ 1 → ∀ m ≠ 0, q ^ m ≠ 1, whose own docstring already says it is sharp over ℝ: q ^ m = 1 forces |q| = 1, hence q = ±1, hence q ^ 2 = 1. So over ℝ the two-line hypothesis q ≠ 0 ∧ q ^ 2 ≠ 1 is "q is not a root of unity". Over a general field it is not — a primitive cube root of unity in ℂ satisfies both and has q ^ 3 = 1.

    So the ℝ is load-bearing, but only as a cheap proof of one hypothesis. The classical criterion is the one the literature states — q not a root of unity — and this file carries it as a hypothesis over an arbitrary field, together with the two consequences the two Real.log proofs actually extract from it. Nothing here is about ℝ; the last theorem is the bridge showing the ℝ statement is the specialisation.

    Why this and not the whole refactor #

    Generalising the cone means moving 13 files and 248 occurrences of ℝ, which is a tranche rather than a step. These three lemmas are the part that must exist whichever way that tranche is done, and they are what makes it mechanical: once q not a root of unity is a hypothesis, every remaining ℝ in those files is a base ring that never gets ordered.

      q ≠ 0 is not needed: if q = 0 then NotRootOfUnity q holds vacuously-ish (0 ^ m = 0 ≠ 1 for m > 0) and 0 ^ (-k) = (0 ^ k)⁻¹ = 0 ≠ 1, so the conclusion is still true. The ℝ original carries hq0 because its Real.log route needs it.

      The order-free replacements for the cone's positivity steps #

      The Wedderburn cone's remaining archimedean uses are not Real.* — they are order tactics, and the recurring one is (q ^ 2 + 1) ≠ 0, proved over ℝ by positivity (HoefsmitRep.sq_add_one_ne) and used again inside SeminormalParam's (q ^ 2 - 1) * (q ^ 2 + 1) = 0 argument. That statement is false over a general field — a primitive fourth root of unity has q ^ 2 + 1 = 0 — so it looks like a second, independent obstruction to leaving ℝ.

      It is not. q ^ 2 + 1 = 0 forces q ^ 4 = 1, which NotRootOfUnity already forbids. So the single hypothesis introduced above covers the order steps too, and the migration does not need [LinearOrderedField K].

      theorem QOU.SchurWeyl.GenericParameter.sq_add_one_ne_zero {K : Type u_1} [Field K] {q : K} (hq : NotRootOfUnity q) :

      q ^ 2 + 1 ≠ 0 over any field, given only that q is not a root of unity.

      This is the lemma that keeps the general-field migration from needing an order. Over ℝ it is positivity; over a general field positivity is unavailable and the statement can fail — but only at a fourth root of unity, which the hypothesis excludes: q ^ 2 = -1 gives q ^ 4 = (-1) ^ 2 = 1.
