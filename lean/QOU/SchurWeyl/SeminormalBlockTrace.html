    QOU.SchurWeyl.SeminormalBlockTrace — the structural half of the Markov reduction #

    OcneanuWeightMarkovCorner proves the arithmetic core of the general-n Markov condition and records that the reduction to it was derived on paper and not formalised. This file formalises the structural part of that reduction.

    What the reduction needs #

    Restricting V_λ to the subalgebra generated by σ_1, …, σ_{k-1} decomposes it by the cell holding the largest entry. The reduction needs exactly two facts about that decomposition:

    1. σ_k's off-diagonal entries cross blocks — genMat_eq_zero_of_cellOf_succ_eq.
    2. Earlier generators preserve blocks — cellOf_eq_of_genMat_ne_zero.

    Fact 2 is stated for a single generator; adjoin_earlyGens_le_blockSubalgebra lifts it to the whole algebra those generators build, which is what H_{N-1} ⊂ H_N actually contributes.

    Together they give trace_mul_genMat (and its usable form trace_mul_genMat_of_adjoin): for any block-preserving X,

    tr(X · σ_k) = ∑_T X_{TT} · seminormalParam q (axialDist T k),

    which is the identity the corner reduction runs on — the step that turns χ^λ(x·σ_n) into a sum of diagonal entries weighted by Hoefsmit parameters.

    Correction to how this was justified #

    OcneanuWeightMarkovCorner's docstring, and bean qou-uer7, justify fact 1 by "branching is multiplicity-free, so the commutant of H_{n-1} in End(V_μ) is the Gelfand–Tsetlin algebra" — the Okounkov–Vershik route. That argument is correct but far heavier than necessary, and it is not the one used here. genMat is defined with exactly two nonzero entries per column — the diagonal, and the swap partner swapTableau T k — so fact 1 is immediate: the swap partner moves k+1 to the cell that held k (cellOf_swapTableau_succ), which is a different cell (cellOf_ne). Twelve lines, no representation theory. Fact 2 is the same argument against cellOf_swapTableau_of_ne.

    I record this rather than quietly using the shorter route: the heavier justification is what the earlier docstring and bean claim, and a reader comparing them should see which one the Lean actually takes.

    What is still NOT proved #

    trace_mul_genMat_of_adjoin is about one V_λ. The Markov condition is a statement about the weighted sum over all λ ⊢ n+1, and assembling it needs the λ-indexed decomposition of H_{n+1} and the weights — i.e. heckeWedderburn plus ocneanuWeight, together with the corner identities of OcneanuWeightMarkovCorner. A further step is also missing on this side: identifying Algebra.adjoin ℝ (earlyGens q N) with the image of the Hecke inclusion H_{N-1} → H_N under seminormalRep. That identification is what would let a statement about x ∈ H_{N-1} be fed to trace_mul_genMat_of_adjoin at all. Neither is done here. So the Markov condition remains open; what has changed is that its structural half is now Lean, not paper. Bean qou-uer7.

    An earlier generator never moves the cell of N: if σ_l's matrix entry between T' and T is nonzero and l + 1 < N, then T' and T agree on the cell of N. This is the statement that H_{N-1} ⊂ H_N preserves the block decomposition by cellOf · N.

    theorem QOU.SchurWeyl.SeminormalRep.trace_mul_genMat {μ : YoungDiagram} {K : Type u_1} [Field K] (q : K) {k : ℕ} (hk : 1 ≤ k) (hkn : k + 1 ≤ μ.cells.card) (X : Matrix (Mathlib.StandardYoungTableau μ) (Mathlib.StandardYoungTableau μ) K) (hX : ∀ (T S : Mathlib.StandardYoungTableau μ), TableauCells.cellOf T (k + 1) ≠ TableauCells.cellOf S (k + 1) → X T S = 0) :
    (X * genMat q k hk hkn).trace = ∑ T : Mathlib.StandardYoungTableau μ, X T T * Seminormal.seminormalParam q (TableauCells.axialDist T k)

    The trace identity the Markov reduction runs on. For any matrix X that preserves the block decomposition by cellOf · (k+1) — in particular the image of any element of the subalgebra generated by σ_1, …, σ_{k-1}, by cellOf_eq_of_genMat_ne_zero — the trace of X · σ_k picks up only the diagonal:

    tr(X · σ_k) = ∑_T X_{TT} · seminormalParam q (axialDist T k).

    Both cross terms die: off-diagonal entries of σ_k cross blocks, and X is zero across blocks.

    From generators to the subalgebra #

    cellOf_eq_of_genMat_ne_zero is about a single generator. What the reduction actually needs is that everything H_{N-1} can build preserves the blocks — sums, products, scalars. The block- preserving matrices form a subalgebra, so that follows from generator membership.

          Connecting to actual Hecke elements #

          The subalgebra results above are about matrices. What the reduction needs is a statement about y ∈ H_m(q). heckeIncl is an AlgHom and adjoin_range_σ_eq_top says the σ generate, so the image of the composite lands in the block subalgebra — and trace_heckeIncl_mul_lastGen is then the reduction's identity for a single V_λ, with its hypothesis discharged rather than assumed.

          The reduction, for a single V_λ, stated about an actual Hecke element.
