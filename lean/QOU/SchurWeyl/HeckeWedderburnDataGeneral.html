    QOU.SchurWeyl.HeckeWedderburnDataGeneral — HeckeWedderburnData at every n #

    HeckeWedderburnData (QSchurWeyl.lean) is the structure the R2 results consume: a partition-indexed Wedderburn isomorphism together with a Markov trace realised as the weighted character sum tr_M = Σ_λ w_λ χ_λ. Only HeckeWedderburnData3 existed, at n = 3.

    heckeWedderburn (SW-7) supplies the isomorphism at every n, so the structure can now be built at every n — after reindexing each block from SYT λ to Fin d_λ, which is what the structure's Matrix (Fin (dim l)) field asks for.

    What is honestly delivered, and what is not #

    The weights are a parameter of this construction, not a result of it. Given any family w : λ ↦ ℝ, the functional Σ_λ w_λ χ_λ is well defined and markov_eq holds by rfl — it is a definition, not a theorem. So this file delivers the structural half of SW-8 at general n: the partition-indexed block decomposition, in the packaging downstream results consume.

    It does not deliver a Markov trace. What makes a weight family the Ocneanu one is the pair of properties tr(xy) = tr(yx) and the Markov condition tr(x·σ_n) = z·tr(x), and those single out a specific w_λ(q, z). At n = 3 those are proved (HeckeMarkov3.markovWeights_markov_σ1); at general n they are open, and nothing here should be read as closing them. Instantiating the structure with an arbitrary w would let a downstream consumer call the result a Markov trace without it being one — so the naming below keeps weight visibly a parameter.

    Base ring (§7c) #

    Same inherited-ℝ case as HeckeProductSurjective: every ℝ here comes from heckeWedderburn, hence from seminormalRep. check-sidecars.sh flags it as "likely gratuitous" because the archimedean construct is one import away rather than in this file. Checker gap tracked as qou-9e7p.

The real lemma is OffDiagNonvanishing.offDiag_axialDist_ne_zero, and it is order-free: its file's whole variable block is {K : Type*} [Field K] (q : K), its conclusion is an inequation offDiag q (axialDist T k) ≠ 0, and its hypotheses are q ≠ 0 and NotRootOfUnity q. Nor is seminormalRep ℝ-only: SeminormalRep.lean:73 declares variable {μ : YoungDiagram} {K : Type*} [Field K] (q : K), genMat returns Matrix _ _ K, and Real.sqrt appears nowhere in that file or in HoefsmitRep.lean.

    What is NOT established: that the ℝ here can actually be removed. That needs an attempted generalisation and a compile, and has not been done. The claim being retracted is only the stated justification — "an inequality in an ordered field" — not the conclusion that ℝ is needed. It may well be, for some other reason; nothing in the corpus currently names one.

    This site also carried "the suggested generalisation to [Field R] is impossible, not merely unnecessary". That is withdrawn: it was inferred from the non-existent lemma, and nothing measured supports impossible.
