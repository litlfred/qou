    QOU.SchurWeyl.BranchingGenericity — the four side conditions, from one hypothesis #

    schurPrincipal_addCell_eq carries four non-vanishing hypotheses, and the headline sum needs a fifth (injectivity of the nodes) plus a row-count bound. They are all the same hypothesis: Q is not a root of unity, in the exact form QBeta.WenzlWeight.schurPrincipal_eq_zero_iff already states it,

    hgen : ∀ k : ℤ, k ≠ 0 → Q ^ k ≠ 1.

    Deriving them here, once, keeps that condition from appearing five times over in every downstream signature.
    one_sub_pow_ne_zero 1 − Qⁿ ≠ 0 for n ≠ 0 — the primitive all four rest on
    descFactF_ne_zero, levelConst_ne_zero the μ-independent constant is invertible
    rowColProd_ne_zero the row-a and column-a factors are invertible
    hookProd_ne_zero the hook product is invertible (hooks are ≥ 1)
    betaR_pow_injOn i ↦ Q^{β_i} is injective on the r rows
    colLen_zero_addCell_le adding a box at row a keeps the row count ≤ max(colLen, a+1)
    sum_schurPrincipal_addCellOrSelf ∑_a s_{μ+□ at a} = [r]_Q · s_μ — general-r branching
    sum_wenzlWeight_addCellOrSelf the same for the normalised weight: ∑_a w_{μ+□ at a} = w_μ
    wenzlWeight_addCell_beyond_eq_zero the addable cell the range r sum omits has weight 0
    betaR_ne_succ_of_addable no other β is β_i + 1 when row i admits a box

    The last is not a genericity fact at all — it is the shape bound that keeps μ + □ inside the ≤ r-row hypothesis — but it belongs with the others because it is the remaining side condition.

    Base ring (§7c) #

    Generic [Field F]; colLen_zero_addCell_le is pure combinatorics. No ordering, no ℝ.

    theorem QOU.SchurWeyl.betaR_ne_succ_of_addable {r : ℕ} {μ : YoungDiagram} {i b : ℕ} (hs : Mathlib.IsAddableCell μ (i, μ.rowLen i)) (hi : i < r) (hb : b < r) (hbi : b ≠ i) :
    betaR r μ b ≠ betaR r μ i + 1

    An addable row leaves a gap of two below it.

    If row i admits a box then μ_i < μ_{i−1}, so β_{i−1} ≥ β_i + 2 — the row-length inequality and the shift each contribute one. Hence no other β equals β_i + 1: rows above are at least β_i + 2, rows below are strictly less than β_i.

    betaR_lt alone does not give this. It says the β are strictly decreasing, which allows β_{i−1} = β_i + 1; ruling that out is exactly what addability buys, and it is what discharges the hne hypothesis of QOU.Mathlib.sum_prod_qratio_weighted — the hypothesis whose failure would make a summand 0/0.

    General-r branching for schurPrincipal #

    source
    theorem QOU.SchurWeyl.sum_schurPrincipal_addCellOrSelf {F : Type u_1} [Field F] (Q : F) (hQ0 : Q ≠ 0) (hQ1 : Q ≠ 1) (hgen : ∀ (k : ℤ), k ≠ 0 → Q ^ k ≠ 1) {r : ℕ} {μ : YoungDiagram} (hrμ : μ.colLen 0 ≤ r) :
    (∑ a ∈ Finset.range r, if Mathlib.IsAddableCell μ (a, μ.rowLen a) then QBeta.WenzlWeight.schurPrincipal r Q (Mathlib.addCellOrSelf μ (a, μ.rowLen a)) else 0) = (∑ k ∈ Finset.range r, Q ^ k) * QBeta.WenzlWeight.schurPrincipal r Q μ

    General-r branching for the corpus weight.

    ∑_{a < r} s_{μ + □ at row a}(1, Q, …, Q^{r−1}) = (1 + Q + ⋯ + Q^{r−1}) · s_μ(1, Q, …, Q^{r−1}),

    the sum running over all r rows with the non-addable ones contributing 0.

    This is what #5575 proves at r = 2 by way of schurPrincipal_twoRow's telescoping closed form — now at every level, for QBeta.WenzlWeight.schurPrincipal itself. The single hypothesis hgen is the same root-of-unity genericity schurPrincipal_eq_zero_iff carries; everything else is derived above.

    The summand is total (addCellOrSelf guarded by the decidable IsAddableCell) rather than indexed by addability proofs, which is what qratio_prod_eq_zero_of_not_addable buys: on a row that cannot take a box the q-ratio is already zero, so the guarded sum and a sum over addable rows agree.

    theorem QOU.SchurWeyl.sum_wenzlWeight_addCellOrSelf {F : Type u_1} [Field F] (Q : F) (hQ0 : Q ≠ 0) (hQ1 : Q ≠ 1) (hgen : ∀ (k : ℤ), k ≠ 0 → Q ^ k ≠ 1) {r : ℕ} {μ : YoungDiagram} (hrμ : μ.colLen 0 ≤ r) (hbr : levelBracket r Q ≠ 0) :
    (∑ a ∈ Finset.range r, if Mathlib.IsAddableCell μ (a, μ.rowLen a) then wenzlWeight r Q (Mathlib.addCellOrSelf μ (a, μ.rowLen a)) else 0) = wenzlWeight r Q μ

    Branching for the normalised weight: ∑_{a<r} w_{μ + □ at row a} = w_μ.

    The normalisation w_μ = s_μ / [r]_Q^{|μ|} is chosen so that the [r]_Q produced by sum_schurPrincipal_addCellOrSelf is exactly absorbed by the one extra cell each summand carries. This is the "weights are consistent under restriction" half of "these are the Ocneanu weights" — MarkovNormalisation.ocneanuWeight_addable_sum at r = 2, now at every level.

    theorem QOU.SchurWeyl.wenzlWeight_addCell_beyond_eq_zero {F : Type u_1} [Field F] {Q : F} {r a : ℕ} {μ : YoungDiagram} (hQ0 : Q ≠ 0) (hgen : ∀ (k : ℤ), k ≠ 0 → Q ^ k ≠ 1) (hbr : levelBracket r Q ≠ 0) (hra : r ≤ a) (hs : Mathlib.IsAddableCell μ (a, μ.rowLen a)) :
    wenzlWeight r Q (Mathlib.addCell μ (a, μ.rowLen a) hs) = 0

    The one addable cell the range r sum omits carries weight zero.

    A diagram with exactly r rows has an addable cell at row r — start a new row — and sum_wenzlWeight_addCellOrSelf sums only over rows < r, so that cell is missing from it. It contributes nothing: the resulting diagram has r + 1 rows, and wenzlWeight_eq_zero_iff kills it.

    This is what makes the guarded range r sum agree with a sum over the addable cells of μ, which is the indexing MarkovNormalisation's (λ, corner) ↔ (ν, addable) reindexing uses. Stated for any row a ≥ r, since none of them can appear in the sum either.
