    QOU.SchurWeyl.WenzlNormalisation — ∑_{|μ|=n} f^μ w_μ = 1, at every level #

    MarkovNormalisation proves the normalisation at r = 2, over ℝ, at convention D. This is the same argument at every level r for the normalised Wenzl weight, over any field.
    colLen_zero_le_addCell adding a box never lowers the row count
    sum_addable_wenzlWeight_all branching with no row-count hypothesis
    sum_dim_wenzlWeight_succ the weighted dimension sum does not depend on n
    sum_dim_wenzlWeight_eq_one ∑_{|μ|=n} f^μ w_μ = 1
    wenzlWeight_addCell_eq the termwise box-addition ratio for the normalised weight

    The row-count hypothesis has to go first, and that is not bookkeeping. The induction sums over every diagram of size n, including those with more than r rows, where sum_addable_wenzlWeight does not apply. There the identity still holds, but for the opposite reason: both sides are 0 — the diagram's weight vanishes, and so does every diagram obtained from it, since adding a box cannot reduce the row count. Missing this would leave the induction stuck on exactly the diagrams the level-r cap is about.

    Together with wenzlWeight_eq_zero_iff and sum_wenzlWeight_addCellOrSelf, both defining properties of the level-r weight system are now proved at every level: the weights vanish above r rows, they are consistent under restriction, and they sum to 1.

    theorem QOU.SchurWeyl.wenzlWeight_addCell_eq {F : Type u_1} [Field F] (Q : F) (hQ0 : Q ≠ 0) (hgen : ∀ (k : ℤ), k ≠ 0 → Q ^ k ≠ 1) {r : ℕ} {μ : YoungDiagram} {s : ℕ × ℕ} (hs : Mathlib.IsAddableCell μ s) (ha : s.1 < r) (hrμ : μ.colLen 0 ≤ r) (hbr : levelBracket r Q ≠ 0) :
    wenzlWeight r Q (Mathlib.addCell μ s hs) = (∏ j ∈ (Finset.range r).erase s.1, (Q * Q ^ betaR r μ s.1 - Q ^ betaR r μ j) / (Q ^ betaR r μ s.1 - Q ^ betaR r μ j)) / levelBracket r Q * wenzlWeight r Q μ

    The termwise box-addition ratio for the normalised weight.

    w_{μ+□ at row a} = (q-ratio_a / [r]_Q) · w_μ.

    sum_wenzlWeight_addCellOrSelf sums these; the corner identity needs them one at a time, because it weights each by the seminormal entry before summing. The [r]_Q is the one extra cell's worth of normalisation, exactly as in card_addCell.
