    QOU.SchurWeyl.MarkovTraceUnique — a Markov trace is determined by its parameter #

    MarkovConventionD and MarkovNormalisation prove that ocneanuWeight at convention D satisfies the two defining properties of a Markov trace weight. That licenses "a Markov trace"; the definite article needs uniqueness, which is what this file proves:

    any two Markov traces on the Hecke tower with the same z agree, on every H_n(q).

    How #

    HeckeCoset.span_cosetFam_eq_top already supplies the spanning family — cosetFam (m+1) (b, j) = ι(cosetFam m b) · r_j with r_j = σ_m σ_{m-1} ⋯ — so the whole proof is an induction over it:

    • r_0 = 1, so the element is ι(w) and consistency gives tr_{m+1}(ι w) = tr_m w.
    • r_j for 1 ≤ j ≤ m+1 factors as the top generator times something from the subalgebra (descProd_eq_last_mul_incl). Cyclicity moves that tail across, and the Markov property collapses what is left: tr(ι w · σ_m · ι t) = tr(ι(t·w) · σ_m) = z · tr_m(t·w).

    Then Submodule.span_induction extends off the family. The j ≤ m+1 bound matters: the factorisation is false past it — descProd 0 2 = σ_0 · σ_0, and σ_0 ∉ ι(H_0) = K·1 — but cosetIndex only ever supplies j : Fin (m+2), so the family stays inside the range.

    What this does and does not give #

    It is a real theorem: the induction uses all four axioms, and dropping any one breaks it. But it is a statement about MarkovTraceFamily, and no instance is built here — so it does not, by itself, identify the weighted seminormal trace with anything. Doing that needs the seminormal trace packaged as a MarkovTraceFamily, which in turn needs two properties not yet proved for it:

    • cyclicity tr(xy) = tr(yx) — should follow blockwise from Matrix.trace_mul_comm;
    • consistency tr_{n+1}(ι x) = tr_n x — the corner decomposition again, this time without the σ factor, closed by ocneanuWeight_addable_sum.

    Until that packaging exists, read this as "uniqueness holds, and the identification is one step away", not as "the Ocneanu weight is the Markov trace". Index conventions will need care in that step: this file's tr (n+1) is the trace on Hecke K q qi (n+1) = H_{n+2}(q), while markov_conventionD is indexed by the diagram size.

    Base ring (§7c) #

    Generic [CommRing K] throughout — no ordering, nothing archimedean, and no ℝ.

    Type u_2

    A Markov trace on the Hecke tower, with parameter z.

    • tr (n : ℕ) : Hecke K q qi n →ₗ[K] K
    • tr_one (n : ℕ) : (self.tr n) 1 = 1
    • tr_cyclic (n : ℕ) (x y : Hecke K q qi n) : (self.tr n) (x * y) = (self.tr n) (y * x)
    • tr_incl (n : ℕ) (x : Hecke K q qi n) : (self.tr (n + 1)) ((HeckeInclusion.heckeIncl K q qi n) x) = (self.tr n) x
    • tr_markov (n : ℕ) (x : Hecke K q qi n) : (self.tr (n + 1)) ((HeckeInclusion.heckeIncl K q qi n) x * Hecke.σ K q qi (n + 1) (Fin.last n)) = z * (self.tr n) x

      The Markov parameter is a value of the trace, namely z = tr₁(σ₀).

      Take x = 1 in the Markov axiom: tr₁(ι(1)·σ₀) = z · tr₀(1) = z. Two Markov trace families whose underlying tr agree therefore carry the same parameter — which is what lets markovTrace_unique (one z, one trace) be used in the other direction, to read a parameter off a trace.
