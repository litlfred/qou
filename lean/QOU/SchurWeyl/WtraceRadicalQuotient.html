    H_n(q)/rad(wtrace) ≅ ∏_{ℓ(λ) ≤ 2} M_{f^λ} #

    WtraceRadicalIdeal supplies the two halves of the first isomorphism theorem (traceRadicalIdeal_eq_ker and twoRowProduct_surjective); this file turns them into an ≃ₐ, which the pinned Mathlib cannot do for a RingCon quotient.

    The generic lift that gap calls for now lives in QOU.MathlibExt.RingConLiftAlgHom, split out under §7c because it mentions no ℝ. 🛑 traceQuotEquiv below does not use it — see twoRowQuotHom's docstring for the instance collision that forces an inlined construction. Do not read the split as a dependency.

      The two-row projection, descended to the quotient.

      Not built from RingConLiftAlgHom.liftAlgHom, and the reason is a live instance collision rather than a stylistic choice: there are two Algebra ℝ instances on this type — Mathlib's RingCon.instAlgebraQuotient and the corpus's own QBeta.MarkovTraceQuotient.instAlgebraTraceQuot — so liftAlgHom's output (which picks Mathlib's) and a signature written against TraceQuot (which picks the corpus's) are different AlgHom types and do not unify. Spelling the type as .ringCon.Quotient does not help: instAlgebraTraceQuot matches whenever the ideal is a traceRadicalIdeal. TwoRowBlocks adds a second, smaller mismatch of the same kind (Pi.semiring against Pi.ring.toSemiring). So this is inlined against the corpus's instances; liftAlgHom stays as the general-purpose piece in QOU.MathlibExt.RingConLiftAlgHom, which is what would go upstream.

      That duplication is a defect in its own right and is not fixed here — changing which instance the corpus uses is a behavioural change across every quotMk consumer, so it is recorded rather than touched.

          ↑1 ≠ 0

          The isomorphism is not between one-point algebras.

          AlgEquiv.ofBijective would accept a bijection of trivial algebras just as happily, so this forecloses the vacuous reading structurally rather than by inspection: wtrace 1 = 1 ≠ 0, so 1 is not in the radical, so the class of 1 is not the class of 0. Its image twoRowProduct 1 = 1 is therefore nonzero in TwoRowBlocks n, which also says the target is not the one-point ring.
