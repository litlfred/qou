    QOU.MathlibExt.ExponentialGrowthRate — asymptotics that survive (1/N)·log‖·‖ #

    Bean qou-mlgp Gap 5.

    Why this is the right first brick #

    Every volume-conjecture instance has the same shape. Some hard analysis — steepest descent, Poisson summation — produces an asymptotic expansion

    `⟨K⟩_N = e^{Nζ} · N^{p} · ω · (1 + o(1))`,

    and the conjecture is then read off its exponential growth rate,

    `(2π/N) · log‖⟨K⟩_N‖ → 2π · Re ζ = Vol(K)`.

    The second step is not the hard analysis, and it should not be re-done per knot. It is one fact — a sub-exponential factor cannot change an exponential growth rate — and Mathlib does not have it in usable form.

    That separation is what makes the "shrink the axiom" strategy pay: it moves everything except the expansion itself out of the assumed input. See QOU.Archimedean.FiveTwoOhtsukiBridge, where the entire content of part (C) is tendsto_log_norm_div_of_tendsto_one below.

    What is here, and what is deliberately not #

    • tendsto_log_norm_sub_div_atTop — asymptotic equivalence preserves the growth rate.
    • tendsto_log_norm_model — the growth rate of e^{Nζ}·N^p·ω is Re ζ, for any p and any ω ≠ 0. This is where N^p is shown not to matter, via Real.isLittleO_log_id_atTop.
    • tendsto_log_norm_div_of_tendsto_one — the two composed, which is the statement a volume-conjecture bridge actually consumes.

    Not here: anything that would produce such an expansion. Steepest descent and stationary phase are absent from Mathlib entirely (measured: grep -ril "steepest descent\|stationary phase\|Laplace" over the pinned rev f897ebcf returns nothing), and building them is the expensive part of Gap 5. This file is the part that does not need them, isolated so the cost of the part that does is visible.

    theorem QOU.MathlibExt.tendsto_log_norm_sub_div_atTop {f g : ℕ → ℂ} (hf : ∀ᶠ (N : ℕ) in Filter.atTop, f N ≠ 0) (hg : ∀ᶠ (N : ℕ) in Filter.atTop, g N ≠ 0) (h : Filter.Tendsto (fun (N : ℕ) => f N / g N) Filter.atTop (nhds 1)) :
    Filter.Tendsto (fun (N : ℕ) => (Real.log ‖f N‖ - Real.log ‖g N‖) / ↑N) Filter.atTop (nhds 0)

    Asymptotic equivalence preserves the exponential growth rate.

    If f N / g N → 1 then (log‖f N‖ − log‖g N‖)/N → 0. The (1 + o(1)) factor of an asymptotic expansion is invisible at this resolution — which is the entire reason a volume conjecture can be read off an expansion whose subleading terms nobody has computed.

    theorem QOU.MathlibExt.tendsto_log_norm_model (ζ ω : ℂ) (hω : ω ≠ 0) (p : ℝ) :
    Filter.Tendsto (fun (N : ℕ) => Real.log ‖Complex.exp (↑N * ζ) * ↑(↑N ^ p) * ω‖ / ↑N) Filter.atTop (nhds ζ.re)

    The model's growth rate is Re ζ.

    ‖e^{Nζ}·N^p·ω‖ = e^{N·Re ζ}·N^p·‖ω‖, so its log over N is Re ζ + p·(log N)/N + log‖ω‖/N, and both correction terms vanish. The exponent p is arbitrary — 3/2 for Ohtsuki's 5₂, 1/2 for the deformed torus-knot expansions — and never enters the limit.

    The statement a volume-conjecture bridge consumes.

    This is part (C) of QOU.Archimedean.FiveTwoOhtsukiBridge, stated once, for any knot whose Kashaev invariant has such an expansion.

    The squeeze skeleton #

    Every positive-sum volume-conjecture proof in the corpus has the same skeleton: bound the sum between its largest term and card × that term, take logs, divide by N, and observe that log(card)/N → 0 closes the gap. The corpus has this argument written out for 4₁ (the E5d Riemann-sum squeeze in FigureEightVolumeSqueeze) and again in outline for the Borromean rings. It is the same argument both times.

    Stated once here, and stated so that the "card" is any sub-exponential factor rather than literally a cardinality — which is what lets it also absorb the phase cost of an oscillatory sum. That is the point of contact with QOU.MathlibExt.HalfPlaneNonCancellation: a half-plane bound supplies exactly a constant c, and a constant is sub-exponential.

    theorem QOU.MathlibExt.tendsto_log_div_of_sandwich {S m c : ℕ → ℝ} {L : ℝ} (hm : ∀ᶠ (N : ℕ) in Filter.atTop, 0 < m N) (hc : ∀ᶠ (N : ℕ) in Filter.atTop, 0 < c N) (hlo : ∀ᶠ (N : ℕ) in Filter.atTop, m N ≤ S N) (hhi : ∀ᶠ (N : ℕ) in Filter.atTop, S N ≤ c N * m N) (hclog : Filter.Tendsto (fun (N : ℕ) => Real.log (c N) / ↑N) Filter.atTop (nhds 0)) (hmlog : Filter.Tendsto (fun (N : ℕ) => Real.log (m N) / ↑N) Filter.atTop (nhds L)) :
    Filter.Tendsto (fun (N : ℕ) => Real.log (S N) / ↑N) Filter.atTop (nhds L)

    A sub-exponential sandwich does not move the growth rate.

    If m N ≤ S N ≤ c N · m N with m positive and log (c N)/N → 0, then S and m have the same exponential growth rate.

    The hypotheses are stated ∀ᶠ rather than ∀ because the interesting instances only sandwich for large N — a Kashaev sum has no useful bound at N = 2.
