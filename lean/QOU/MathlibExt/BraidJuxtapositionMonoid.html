    Juxtaposition of braids as a monoid #

    Mathlib has no braid groups and no knot theory. Measured against the vendored tree (commit f897ebcf72cd16f89ab4577d0c826cd14afaafc7, 6996 modules): find -iname '*braid*' returns only CategoryTheory files about the monoidal braiding; find -iname '*Hecke*' and -iname '*knot*' return nothing; word-boundary greps for Markov trace, Ocneanu, Temperley, Kauffman, skein, Jones polynomial and braid closure return zero. Two near-misses a bare grep reports: Mathlib.CategoryTheory.MarkovCategory is categorical probability and Mathlib.MeasureTheory…Markov is Markov's inequality; neither is relevant here.

    This file supplies the structural layer under trace multiplicativity: putting two braids side by side on disjoint strand blocks, as an algebraic operation, and the monoid it generates.

    The setting #

    Juxtaposition (disjoint side-by-side union, "distant union") takes a braid on m strands and a braid on n strands to a braid on m + n strands. Because the index changes, no fixed-n algebraic structure can express it: the operation lives on a family F : ℕ → Type* and has the heterogeneous shape

    jux : F m → F n → F (m + n).

    Juxtaposable F is exactly that data plus an empty braid empty : F 0 and the three laws below. Nothing here assumes F n is the Artin braid group, which is why the results apply verbatim to it, to its abelianisation (the writhe), to a Hecke-type quotient, and to the word model.

    What is proved here (all theorems, no sorry, no axiom beyond Mathlib's) #

    • instMonoidSigma — the disjoint union Σ n, F n is a monoid under juxtaposition, with the empty braid as unit. This is the "juxtaposition monoid" of the title.
    • strandCount — Σ n, F n →* Multiplicative ℕ, i.e. juxtaposition adds strand counts.
    • juxHom, juxLeft, juxRight — the interchange law in MonoidHom form: juxtaposition is a monoid homomorphism F m × F n →* F (m + n), and each block includes as a submonoid.
    • juxLeft_commute_juxRight — the two blocks do not interact: their images commute inside F (m + n). This is the algebraic content of far commutation σᵢσⱼ = σⱼσᵢ for distant i, j, and it is derived from the interchange law, not assumed. It is checked against a model whose ambient monoid is not commutative (see Non-vacuity below), so it is not true merely because every witness happens to commute.
    • const_interchange_iff_commutative — the interchange law has real content: on the constant family it holds iff the fibre monoid is commutative. So JuxtaposableMonoid is a genuine restriction, not a bookkeeping tautology.
    • ofMultiplicative / ofMultiplicative_comp — a functional f with f (jux a b) = f a * f b is exactly a monoid hom out of the juxtaposition monoid, and every monoid hom arises this way. This is the abstract home of QOU.MathlibExt.MarkovTraceMultiplicative.markovTrace_juxtapose (tr (K₁ # K₂) = tr K₁ * tr K₂): that file proves the hypothesis f (jux a b) = f a * f b for the matrix trace under the Kronecker model; this file says what such an f is. MonoidHom.map_pow then gives k disjoint copies for free.

    The index arithmetic, handled honestly #

    (m + n) + k and m + (n + k) are not definitionally equal in ℕ (Nat.add recurses on its second argument), so jux (jux a b) c and jux a (jux b c) do not even have the same type. The associativity axiom is therefore stated as an equality in the sigma type Σ i, F i, which carries the index equality and the value equality together. Likewise 0 + n does not reduce, so the left-unit law empty_jux is stated in the sigma type as well.

    n + 0 does reduce to n, so the right-unit law jux_empty is stated directly in F n with no cast. The asymmetry between empty_jux and jux_empty is not an oversight: it records exactly where a cast is needed and where it is not.

    Non-vacuity #

    Three concrete models, all verified:

    • Const M (constant family, jux = (*)) for a commutative monoid M. At M = Multiplicative ℤ this is the writhe model — the exponent sum of a juxtaposed braid is the sum of the exponent sums — and it satisfies the interchange law. writheTotal_surjective shows the resulting monoid is not degenerate.
    • WordFamily α (words of length n, jux = concatenation) — a genuinely dependent family, so it exercises the cast the constant model does not. wordEquiv identifies its juxtaposition monoid with FreeMonoid α, on the nose. It witnesses Juxtaposable only: WordFamily α n carries no monoid structure of its own, so JuxtaposableMonoid cannot even be stated for it.
    • TupleFamily M (tuples Fin n → M, jux = concatenation, pointwise multiplication) — dependent and with noncommutative fibres whenever M is noncommutative, while still satisfying the interchange law for any monoid M.

    The third model exists because the first two leave juxLeft_commute_juxRight weaker than it looks. Const M is a JuxtaposableMonoid only for commutative M, so in that model every pair of elements of F (m + n) commutes and the theorem asserts nothing specific about the two blocks. With TupleFamily the ambient monoid genuinely fails to commute — tuple_free_noncommutative exhibits a non-commuting pair over FreeMonoid Bool — while tuple_free_blocks_commute still holds. That pair of facts is what makes the commutation theorem content-bearing rather than an artefact of a commutative witness.

    It also shows that commutativity of the fibre is not what the interchange law demands in general: const_interchange_iff_commutative forces it only for the constant family, where jux is the multiplication, and does not generalise to models whose jux moves the two arguments onto disjoint coordinates.

    Scope — read this before citing it #

    Everything below is algebra. That a given pair of link diagrams' connected sum is realised by juxtaposition on disjoint strand blocks is a modelling statement about diagrams, not proved here and not provable in Mathlib as it stands (there is no Link, no diagram, no Reidemeister move). This file makes no topological claim.

    Ground ring / typeclass: nothing stronger than Monoid is used; there is no ordering, no ℝ, and no archimedean content.

    The juxtaposition structure #

    source
    class QOU.MathlibExt.BraidJuxtaposition.Juxtaposable (F : ℕ → Type u) :
    Type u

    A juxtaposable family: a family of "braid-like" objects indexed by strand count, with a side-by-side union jux : F m → F n → F (m + n) and an empty object on 0 strands.

    The three laws are associativity, and the two unit laws. Associativity and the left unit law are stated as equalities in Σ i, F i, because their two sides live in types indexed by propositionally- but not definitionally-equal naturals ((m + n) + k vs m + (n + k), and 0 + n vs n). The right unit law needs no such packaging, since n + 0 reduces to n.

    • jux {m n : ℕ} : F m → F n → F (m + n)

      Side-by-side union of a braid on m strands with one on n strands.

    • empty : F 0

      The empty braid, on zero strands.

    • jux_assoc {m n k : ℕ} (a : F m) (b : F n) (c : F k) : ⟨m + n + k, jux (jux a b) c⟩ = ⟨m + (n + k), jux a (jux b c)⟩

      Juxtaposition is associative, as an equality in Σ i, F i (the index equality (m + n) + k = m + (n + k) is part of the statement).

    • empty_jux {n : ℕ} (a : F n) : ⟨0 + n, jux empty a⟩ = ⟨n, a⟩

      The empty braid is a left unit, as an equality in Σ i, F i (0 + n = n is part of the statement, since 0 + n does not reduce).

    • jux_empty {n : ℕ} (a : F n) : jux a empty = a

      The empty braid is a right unit. No cast is needed: n + 0 reduces to n.

        The interchange (bifunctoriality) law #

        source
        class QOU.MathlibExt.BraidJuxtaposition.JuxtaposableMonoid (F : ℕ → Type u) [(n : ℕ) → Monoid (F n)] [Juxtaposable F] :
        Prop

        A juxtaposable family whose fibres are monoids, satisfying the interchange law

        jux (a * a') (b * b') = jux a b * jux a' b'.

        This is the algebraic statement that the two strand blocks do not interact: composing inside each block and then juxtaposing is the same as juxtaposing and then composing. For the Artin braid groups it is the assertion that Bₘ × Bₙ → Bₘ₊ₙ is a group homomorphism, i.e. that the image is the parabolic subgroup on the two blocks.

        Both fields are quantified equations in the shape of the claim; see const_interchange_iff_commutative for a proof that they are a genuine restriction.

        • jux_one {m n : ℕ} : jux 1 1 = 1

          Juxtaposing the two units gives the unit.

        • jux_mul {m n : ℕ} (a a' : F m) (b b' : F n) : jux (a * a') (b * b') = jux a b * jux a' b'

          The interchange law: the two blocks compose independently.

                              Non-vacuity, model 3: tuples — a dependent family with noncommutative fibres #

                              The two models above leave juxLeft_commute_juxRight weaker than it looks. Const M is the only JuxtaposableMonoid witness so far, and there M is commutative, so every pair in F (m + n) commutes and the theorem says nothing specific about the two blocks; WordFamily cannot help, since its fibres carry no multiplication at all. This section removes that weakness with a model that is dependent, satisfies the interchange law over an arbitrary monoid, and has genuinely noncommutative fibres.
