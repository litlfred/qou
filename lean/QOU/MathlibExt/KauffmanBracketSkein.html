    The Kauffman bracket, algebraically #

    Mathlib has no Kauffman bracket. A case-insensitive search over the vendored tree (leanprover/lean4:v4.24.0, Mathlib commit f897ebcf72cd16f89ab4577d0c826cd14afaafc7, 6996 modules) returns 0 files for each of Kauffman, skein, Temperley and bracket polynomial; there is also no link type, no knot diagram, no Reidemeister move and no writhe. The only knot-motivated file in Mathlib is Mathlib/Algebra/Quandle.lean, in which knots appear only in prose.

    This file supplies the algebraic skeleton of the bracket: the three defining rules, packaged as a structure, together with the consequences that follow from them by ring arithmetic alone.

    The setting #

    R is any commutative ring and D any type, thought of as a type of link diagrams. A KauffmanBracketSpec R D carries

    • a variable A : R together with a stand-in Ainv : R for A⁻¹ and the hypothesis A * Ainv = 1 — this is what keeps the base ring a bare CommRing, with no Field, no Inv, no ordering and no archimedean structure anywhere in the file (AGENTS.md §7c);
    • a function bracket : D → R;
    • a distinguished unknot : D and an operation addCircle : D → D;
    • a relation Smoothing : D → D → D → Prop, where Smoothing d d₀ d₁ is read "d carries a distinguished crossing whose A-smoothing is d₀ and whose B-smoothing is d₁";

    subject to the three Kauffman rules

    • K1 (skein) Smoothing d d₀ d₁ → ⟨d⟩ = A⟨d₀⟩ + A⁻¹⟨d₁⟩;
    • K2 (loop) ⟨addCircle d⟩ = δ⟨d⟩ with δ = -(A² + A⁻²);
    • K3 (normalisation) ⟨unknot⟩ = 1.

    What is a THEOREM here #

    Everything below is proved from K1–K3; there is no sorry and no new axiom.

    • loopValue_sq, A_sq_mul_loopValue, Ainv_sq_mul_loopValue — the defining quadratic of the loop value. A² δ + A⁴ + 1 = 0 (and its mirror), so δ is the root of an explicit monic-in-δ linear relation over A, and δ² = A⁴ + 2 + A⁻⁴. All three genuinely use A * Ainv = 1.
    • bracket_iterate_addCircle, bracket_unlink — the k-circle scaling: adding n disjoint trivial circles multiplies the bracket by δⁿ, so the (n+1)-component unlink has bracket δⁿ. Proved by induction on n.
    • bracket_kink_left, bracket_kink_right — the writhe-normalisation factors. A crossing whose two smoothings are d and d ⊔ (circle) has bracket -A⁻³⟨d⟩; with the roles exchanged, -A³⟨d⟩. These are the framing factors that force the writhe correction in the Jones normalisation, and they are the sharpest consequence of K1–K3 in this file.
    • kinkFactor_mul_kinkFactor_inv, bracket_kink_pair — the two factors are mutually inverse, so a positive kink followed by a negative kink returns the original bracket.
    • bracket_eq_of_smoothing — the bracket of a crossing is determined by the brackets of its two smoothings.
    • bracket_add_mirror, bracket_sub_mirror — a crossing and its mirror satisfy ⟨d⟩ + ⟨d'⟩ = (A + A⁻¹)(⟨d₀⟩ + ⟨d₁⟩) and ⟨d⟩ - ⟨d'⟩ = (A - A⁻¹)(⟨d₀⟩ - ⟨d₁⟩).
    • unreduced_skein, unreduced_loop, unreduced_unknot, unreduced_unlink — the reduced-versus-unreduced relationship. δ · ⟨-⟩ satisfies K1 and K2 unchanged and sends the unknot to δ rather than to 1; the (n+1)-component unlink then has unreduced bracket δⁿ⁺¹, i.e. one factor of δ per component rather than per added component.
    • smul_skein, smul_loop, scale_eq_one_of_normalised — K1 and K2 are homogeneous (invariant under rescaling the bracket by any c : R), and K3 is exactly what pins the scale: c · ⟨unknot⟩ = 1 forces c = 1. This is the precise sense in which the normalisation is a normalisation.

    What is a HYPOTHESIS or a DEFINITION here #

    • KauffmanBracketSpec is a specification, not a construction. Nothing here builds a bracket from a diagram; the state sum over smoothings is not formalised, and no existence theorem over any diagram type is claimed.
    • D is an opaque type and Smoothing is an abstract relation. There is no planar diagram, no crossing, no smoothing operation and no combinatorics of any kind in this file. Smoothing d d₀ d₁ asserts only that the triple stands in some relation; that the relation is realised by resolving a crossing in a planar diagram is a reading imposed from outside, exactly as in QOU.MathlibExt.SkeinRelation.
    • No orientation, and therefore no writhe. bracket_kink_left and bracket_kink_right are distinguished only by which of the two smoothings carries the extra circle. Neither is labelled the positive or the negative curl, because signing a curl needs an orientation and D has none; the writhe correction (-A³)^{-w} that would convert these factors into an invariant is correspondingly absent.
    • Homogeneity is not a uniqueness statement. smul_skein and smul_loop say rescaling carries solutions of K1–K2 to solutions. They do not say that any two solutions differ by a scalar — that is false, and scale_eq_one_of_normalised records the counterexample.
    • No topological invariance is proved, and none is true as stated. The bracket specified here is deliberately not a link invariant: bracket_kink_* shows R1 fails by the factor -A^{∓3}, and exists_kink_bracket_ne exhibits a model in which that failure is visible (-1/8 ≠ 1 over ℚ). Recovering an invariant needs the writhe correction, which needs a writhe, which needs a diagram — none of which exists here. R2 and R3 invariance are not consequences of K1–K3 alone over an abstract Smoothing relation and are not claimed.

    Non-vacuity #

    A spec with an opaque carrier is worthless unless satisfiable, so:

    • tautological — a model for every R and every A with A * Ainv = 1, on the diagram type D := R itself, with bracket = id. All three rules hold, two of them by rfl.
    • tautological_smoothing — its Smoothing relation is richly inhabited: every pair (y, z) is the smoothing pair of some diagram. So K1 is not satisfied vacuously by an empty relation, which is the one cheap way this structure could have been made trivially consistent.
    • exists_bracket_addCircle_ne — over ℚ at A = 2 the bracket is not constant: ⟨unknot ⊔ circle⟩ = -17/4 ≠ 1 = ⟨unknot⟩. The theorems above are therefore not statements about a degenerate model.
    • exists_kink_bracket_ne — the same model contains a genuine kink, whose bracket is -A⁻³ = -1/8, confirming bracket_kink_left on a witness.

    Relation to the rest of this repository #

    QOU.Knots.KauffmanTL3 computes a bracket, but only for the fixed 5-dimensional Temperley–Lieb algebra TL₃ with loop counts hard-coded into the closure, over a bespoke Laurent-polynomial type, by decide. It is a computation at n = 3, not a specification, and nothing in it is stated for general diagrams or a general ring. QOU.MathlibExt.SkeinFromHecke treats the Hecke skein relation L₊ - L₋ = (q - q⁻¹)L₀ at the level of one ring element; that is the other of the two standard skein calculi and is not the bracket relation. QOU.MathlibExt.TemperleyLiebAlgebra supplies the algebra whose loop parameter δ this file's loopValue would specialise to. Imports are Mathlib-only.

      structure QOU.MathlibExt.KauffmanBracket.KauffmanBracketSpec (R : Type u_2) [CommRing R] (D : Type u_3) :
      Type (max u_2 u_3)

      A Kauffman bracket specification on a type D of diagrams, valued in a commutative ring R.

      The three fields skein, loop and normalisation are Kauffman's rules K1, K2 and K3. D is opaque and Smoothing is an abstract ternary relation: this structure encodes the algebra of the bracket and contains no diagram combinatorics whatsoever. See the module docstring on what is and is not claimed.

      • A : R

        The bracket variable A.

      • Ainv : R

        A stand-in for A⁻¹, kept as a separate scalar so that R need only be a CommRing.

      • A_mul_Ainv : self.A * self.Ainv = 1

        Ainv really is a two-sided inverse of A.

      • bracket : D → R

        The bracket itself.

      • unknot : D

        The distinguished one-component trivial diagram.

      • addCircle : D → D

        Adjoin a disjoint trivial circle.

      • Smoothing : D → D → D → Prop

        Smoothing d d₀ d₁: d carries a distinguished crossing whose A-smoothing is d₀ and whose B-smoothing is d₁.

      • skein {d d₀ d₁ : D} : self.Smoothing d d₀ d₁ → self.bracket d = self.A * self.bracket d₀ + self.Ainv * self.bracket d₁

        K1, the bracket skein rule.

      • loop (d : D) : self.bracket (self.addCircle d) = loopValue self.A self.Ainv * self.bracket d

        K2, the loop rule, with loop value δ = -(A² + A⁻²).

      • normalisation : self.bracket self.unknot = 1

        K3, the normalisation.

          The writhe-normalisation factors #

          A curl (a Reidemeister-I kink) is a crossing one of whose smoothings is the original diagram and the other of which is that diagram with a trivial circle adjoined. K1 and K2 then force the bracket to change by -A^{∓3}.

          source
          theorem QOU.MathlibExt.KauffmanBracket.KauffmanBracketSpec.bracket_kink_left {R : Type u_1} [CommRing R] {D : Type u_2} {S : KauffmanBracketSpec R D} {k d : D} (h : S.Smoothing k d (S.addCircle d)) :
          S.bracket k = -S.Ainv ^ 3 * S.bracket d

          Kink with the circle on the B-smoothing. If k is a crossing whose A-smoothing is d and whose B-smoothing is d with a trivial circle adjoined, then ⟨k⟩ = -A⁻³ ⟨d⟩.

          Deliberately not called the positive curl: signing a curl requires an orientation and a writhe, and D carries neither. On the usual convention it is the other case, bracket_kink_right, that is the positive one.

            Non-vacuity #

            The rules K1–K3 constrain each other — K1 relates three values, K2 forces a specific multiplier and K3 fixes an absolute value — so their joint satisfiability is not automatic and must be exhibited.

            def QOU.MathlibExt.KauffmanBracket.tautological {R : Type u_1} [CommRing R] (A Ainv : R) (h : A * Ainv = 1) :
            KauffmanBracketSpec R R

            The tautological model: take the diagram type to be R itself, with the bracket the identity. Every one of K1, K2, K3 holds, the last two by rfl.

            This model exists for every commutative ring R and every pair A, Ainv with A * Ainv = 1, so the specification is consistent in complete generality.
