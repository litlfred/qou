    QOU.MathlibExt.QPartitionCombinatorics #

    — q-deformed partition combinatorics infrastructure

    This module provides the partition combinatorial infrastructure needed by the QOU mass-formula chain:

    • qBracket q n — [n]_q = (q^n − q^{-n}) / (q − q⁻¹)
    • qFactorial q n — [n]_q! = ∏_{k=1}^n [k]_q
    • Partition.hookLength — hook length at cell (i, j)
    • Partition.contentSum — sum of contents Σ (j − i)
    • qDim — q-deformed dimension

    with basic positivity / nonvanishing lemmas for q > 1.

    These constructions are the concrete substrate behind the abstract Wedderburn-weight \tilde w_lam = dim_q²(lam) / [n]_q! and the Wenzl Schur element s_{lam,X}(Q) used in the canonical Markov-trace decomposition (per prop:wedderburn-weight-canonical and prop:macdonald-hook-telescope).

    Refs:

    • [macdonald1995] Symmetric Functions and Hall Polynomials, I.3
    • [wenzl1988] Hecke algebras of type A_n and subfactors, Invent. Math. 92
    • [stanley1999] Enumerative Combinatorics II, Cor. 7.12.5

    Base ring for the algebraic q-integer core (§7c): a generic [Field R]. The q-bracket / q-factorial / q-dimension / q-binomial and their algebraic identities hold over any field (the balanced [n]_q needs q⁻¹ and division, hence a field, but no ordering). The 1 < q positivity / nonvanishing lemmas below stay over ℝ — they are genuinely archimedean — and reference the generic qBracket etc. with R := ℝ inferred.

    The q-bracket [n]_q = (q^n − q^{-n}) / (q − q⁻¹) for n : ℕ. At n = 0 we set [0]_q := 0; for n ≥ 1 the formula reduces to 1 + q² + q⁴ + … + q^{2(n−1)} (up to a q^{-(n-1)} factor).

                          n(λ), the row-weighted size #

                          Not the same quantity as contentSum, and the two are easy to confuse — contentSum is Σ_x (j − i) over cells, whereas n(λ) is Σ_i i·λ_i. They coincide only for a single row of length ≤ 1. In terms of the conjugate, contentSum λ = n(λ') − n(λ).

                          The distinction is load-bearing: the Wenzl Schur element's prefactor is Q^{n(λ)}, and substituting contentSum there breaks the Macdonald hook telescope from n = 2 upward (measured; see WenzlSchurElement.schurElement).

                            Adding a box, and how hook lengths respond #

                            Infrastructure for the Pieri step of the Macdonald hook telescope (MathlibExt.MacdonaldTelescope). Adding one box to row r of λ changes hookLength by exactly +1 on two sets and not at all elsewhere:

                            • the cells of row r strictly left of the new box — their arm grows;
                            • the cells of column λ_r strictly above row r — their leg grows.

                            Verified against this very definition over 111 cells across the addable corners of twelve shapes before being formalised. Both halves are proved below, and hookLength_addBoxRow_of_ne_corner assembles them into the rule for every cell but the new box itself.

                            The two halves need genuinely different arguments. The arm half is a drop argument: the entry that moved is dropped before the leg count sees it. The leg half cannot use that, because the modified entry survives into the tail — it is a countP-over-set argument instead, and j = λ_r is exactly the threshold at which the predicate (· > j) flips.

                              The corner addBoxRow cannot reach #

                              addBoxRow is List.set, and List.set is a no-op out of range — so addBoxRow lam lam.length is lam, not lam ++ [1]. The new-bottom-row corner is therefore not expressible by it, and every partition has exactly one such corner (measured in computations/y_lambda_pieri_step_probe.py, where each of the eight shapes checked contributes one). It is a second operation, not a defect in addBoxRow — a set genuinely cannot lengthen a list.

                              The new row is last, which makes this case easier than the interior one in two places: nothing lies below it, so the new cell's hook length is unconditionally 1 (the interior corner needs the weakly-decreasing property, which the carrier does not have), and only column 0 sees any change at all.

                                Addable corners #
