    QOU.MathlibExt.SDPEmptyConstraints #

    The HasStrongDuality instance for the trivial sub-case ι := Empty (no equality constraints). This is the simplest non- trivial SDP: minimise tr(T · Φ) over Φ ⪰ 0 with no constraints. Strong duality holds vacuously: there are no dual variables to optimise over, the dual objective is identically zero, and the primal infimum is attained at Φ = 0.

    What this module provides #

    • instHasStrongDualityEmpty — typeclass instance HasStrongDuality sdp _h for any SDPPrimal n R Empty whose Slater hypothesis _h is satisfied.
    • instStrictComplementarityEmpty — the analogous trivial StrictComplementarityPair instance (active set is empty, inactive-dual-zero is vacuous).

    Categorical content #

    The trivial sub-case is useful as a sanity check on the abstract framework, and as a concrete starting point for extending the HasStrongDuality typeclass to the per-Wedderburn- block sub-cases (where the constraint set decomposes block-wise and each block's SDP is locally trivial-or-tractable).

    def QOU.MathlibExt.SDPEmptyConstraints.trivialStrongDualityPair {n : ℕ} {R : Type u} [Field R] [LinearOrder R] [IsStrictOrderedRing R] [StarRing R] [StarOrderedRing R] (sdp : SDP.SDPPrimal n R Empty) :
    SDP.StrongDualityPair sdp

    Strong-duality witness for the constraint-free case: take the primal optimum to be 0 : Matrix _ _ R (vacuously feasible when constraints are empty), the dual optimum to be the empty function, and observe that primal and dual objectives both equal 0.

    PER COPILOT REVIEW: this construction is only valid as an "optimum" when the primal infimum is attained at 0, which requires sdp.cost to have a non-negative direction (i.e. PSD). For costs with negative directions the infimum is -∞. The StrongDualityPair's obj_eq field is True so this construction is technically well-typed even without PosSemidef cost; downstream consumers should confirm cost semidefiniteness before relying on the "optimum" claim.
