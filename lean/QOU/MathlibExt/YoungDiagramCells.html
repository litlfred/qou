    Cell statistics of a Young diagram — one definition each #

    content, arm, leg, hook over ℤ, with the basic lemmas.

    Why this module exists #

    Each of these was defined independently in several places (bean qou-cdup). The one-liner (c.2 : ℤ) - (c.1 : ℤ) — and its curried twin (j : ℤ) - (i : ℤ) — appear nine times under four spellings, across two argument conventions:

    tuple (c : ℕ × ℕ) curried (i j : _)
    QOU.BraidKnot.IdentityAArmLeg.content QOU.MathlibExt.QPartitionCombinatorics.cellContent
    QOU.BraidKnot.TableauContent.content QOU.MathlibExt.WenzlSchurElement.cellContent
    QOU.BraidKnot.JucysMurphy.cellContent QOU.BraidsAndKnots.cellContent (y-lambda-recipe-from-partition)
    QOU.BraidKnot.PieceA.contentZ QOU.BraidKnot.cellContent (jucys-murphy-central-elements-qou)
    QOU.BraidKnot.cellContent (TwoFiltrationBridge)

    Arm/leg/hook are defined twice over ℤ (IdentityAArmLeg, PieceAGeneral) and once more over ℕ (TwoFiltrationBridge.hookLength).

    One of those pairs is a genuine clash, not merely a duplicate. The last row of each column is the same fully-qualified name — QOU.BraidKnot.cellContent — declared twice, once in the library file BraidKnot/TwoFiltrationBridge.lean and once in the standalone content-block sibling mass-theory/jucys-murphy-central-elements-qou.lean, with incompatible signatures (ℕ × ℕ → ℤ vs ℤ → ℤ → ℤ). They compile today only because the sibling is standalone and is never imported alongside the library module; the moment anything imports both, it is a hard duplicate-declaration error. Removing the library-side copy in favour of this module is what clears it.

    The rest cost no errors — each sits in its own namespace — but the copies cannot share lemmas: PieceAGeneral proves hookZ_eq / armZ_nonneg / legZ_nonneg against its copy, HoefsmitRep builds axialDistance on another, TwoFiltrationBridge proves the content-spread results on a third, and none of those is reachable from the others without a rfl bridge nobody wrote.

    This module is the single home. TwoFiltrationBridge is migrated onto it; the rest are the drain half of qou-cdup.

    The counts in the table above are understated, and "every bridge is rfl" is false. Re-measured 2026-08-24: ten reachable content copies, four of them never recorded anywhere (one of which an earlier note claimed does not exist); and the hookLength bridge is conditional, not rfl, because it is ℕ-valued with truncated subtraction. The measured list, the bridges, and the axialDistance escalation are in QOU.MathlibExt.YoungDiagramCellsBridges.

    Namespace note. This lives under QOU.MathlibExt — the corpus's established home for Mathlib extensions — rather than the more obvious QOU.YoungDiagram. The obvious name is a trap: a QOU.YoungDiagram namespace captures open YoungDiagram inside any QOU.* namespace, silently redirecting it away from Mathlib's YoungDiagram and breaking rowLen_anti, mem_iff_lt_rowLen and the rest at every existing call site.

    Content (diagonal index) of a cell: j - i.

    Contents are what the Jucys–Murphy elements measure — L_k acts on the seminormal basis by a function of the content of the cell added at step k — so this is the coordinate in which diagram statistics become algebra statements.

            Axial distance #

            The content difference between two cells. This is the parameter Young's seminormal / orthogonal form is built from: axialDistance (cell of k) (cell of k+1) determines the 2×2 block by which the generator σ_k acts.

            It is included here for the same reason content is: it was defined twice independently (QOU.SchurWeyl.axialDistance on one copy of content, QOU.BraidKnot.TableauContent.axialDistance on another), and the duplication bites harder one level up than it does on content itself — see the bridges module for why.
