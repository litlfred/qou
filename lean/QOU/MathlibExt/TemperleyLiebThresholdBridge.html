    Threshold domination gives pointwise domination — the bridge NormalIdx needed #

    Bean qou-cds1. TemperleyLiebWordBlocks recorded a gap that was a cost of a choice made two tranches earlier: NormalIdx states domination as a threshold count

    ∀ x,  |I ∩ [0,x]|  ≤  |J ∩ [0,x]|

    because that form needs no sorting and is decidable — which is what made Fintype.card fall to decide for m ≤ 6. But descRun_eq_cons, and with it the whole word construction, needs the pointwise form j_r ≤ i_r. The two were verified equivalent for every pair at m ≤ 7 before the encoding was adopted; the equivalence was not proved.

    This file proves the direction that was blocking: threshold ⟹ pointwise.

    The mechanism, in one lemma #

    Everything reduces to a single statement about a strictly sorted list:

    l[r] ≤ x   ↔   r + 1 ≤ (l.filter (· ≤ x)).length

    Read left to right at x = i_r it says I has at least r+1 elements ≤ i_r; the threshold hypothesis transports that to J; read right to left for J it gives j_r ≤ i_r. So one iff, applied once in each direction, is the whole bridge — no counting argument beyond it.

    Two things worth noting #

    The equal-cardinality hypothesis is not needed. NormalIdx carries J.card = I.card, and the bridge does not use it. The threshold condition alone forces pointwise domination wherever both lists have an r-th entry. Stated without it, since a hypothesis that is not used should not be required.

    elems pays off again. elems_nodup, elems_length and elems_filter all come out of elems being a filter over List.finRange — nodup and sortedness are inherited by Sublist, and elems (s.filter p) = (elems s).filter p is a List.filter_filter away. None of this would be available from Finset.sort, which is also the reason decide works on this type at all.

    🛑 What this does NOT do #

    • The converse is not proved. Only threshold ⟹ pointwise is here, which is the direction the word construction needs. The other direction is true (both were checked at m ≤ 7) and is not required by anything yet.
    • The instantiation is still not finished. This unblocks descRun_eq_cons at a normal-form index, but assembling word (I,J) = pre ++ k :: post with pre far from k — and hence discharging e_mul_prod_eq_smul's hypothesis — is the next step and is not taken here.
    • Nothing here bears on the loops = 0 branch of the closure rule, which remains open.

    theorem QOU.MathlibExt.TemperleyLiebThresholdBridge.sorted_getElem_le_iff {m : ℕ} (l : List (Fin m)) :
    List.Sorted (fun (x1 x2 : Fin m) => x1 < x2) l → ∀ (x : Fin m) (r : ℕ) (hr : r < l.length), l[r] ≤ x ↔ r + 1 ≤ (List.filter (fun (y : Fin m) => decide (y ≤ x)) l).length

    The one lemma the bridge rests on. For a strictly sorted list, "the r-th entry is ≤ x" is exactly "at least r+1 entries are ≤ x".

    The ¬ (a ≤ x) branch is where sortedness is used: if the head already exceeds x then so does everything after it, so the filter is empty and both sides are false.
