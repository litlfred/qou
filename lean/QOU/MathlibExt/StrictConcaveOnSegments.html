    QOU.MathlibExt.StrictConcaveOnSegments — strict concavity, tested one segment at a time #

    Bean qou-mlgp Gap 3.

    The gap, stated precisely #

    Mathlib can prove strict concavity in one variable — strictConcaveOn_of_deriv2_neg turns f'' < 0 on an interval into StrictConcaveOn ℝ D f. It has nothing that promotes that to a set in a higher-dimensional space. Measured against the pinned revision (f897ebcf):

    • grep -rn "StrictConvexOn.*fderiv\|ConvexOn_of_hasFDeriv" over all of Mathlib — no hits. There is no multi-dimensional convexity-from-second-derivative test.
    • ConvexOn.comp_affineMap and ConcaveOn.comp_affineMap exist; the strict versions do not.

    Why this is the piece the corpus is actually missing #

    QOU.Knot.RivinConcavity proves strictConcaveOn_tetVolLine: the tetrahedron volume Λ(α)+Λ(β)+Λ(γ) is strictly concave along a line in the angle simplex. Its own docstring then says

    strict concavity on a convex set is strict concavity along every segment

    which is true, and was asserted in prose rather than proved. strictConcaveOn_of_segments below is that sentence as a theorem. Without it the line result cannot be promoted, and Rivin concavity — hence the variational characterisation of the hyperbolic structure, hence everything the volume conjecture work stands on — stops at one dimension.

    Why the affine-slice phrasing is not needed #

    Gap 3 was recorded as wanting "negative-definite Hessian on the tangent space of an affine constraint ⟹ strictly concave on that slice", and that framing suggests machinery for affine subspaces, tangent spaces and restricted Hessians. It turns out none of that is required, because the constraint set is already carried by S:

    every segment between two points of S has its direction in the directions of S.

    So a hypothesis quantified over pairs x, y ∈ S is automatically a hypothesis about tangent directions only. For an S inside the affine slice {Σθ = π}, the direction y − x automatically satisfies Σ(y−x) = 0 — which is exactly the tangency condition u + v + w = 0 that RivinConcavity.cot_quadratic_pos consumes. The affine structure never has to be mentioned.

    This is worth recording because the survey's framing overstated the cost: the general lemma is nine lines and needs no geometry.

    Scope #

    These are statements about StrictConcaveOn and nothing else — no knots, no volume, no Λ. They belong upstream, and are written so they could be moved there unchanged.

    Archimedean (ℝ), but strictConcaveOn_of_segments is stated over an arbitrary real module.

    theorem QOU.MathlibExt.strictConcaveOn_of_segments {E : Type u_1} [AddCommGroup E] [Module ℝ E] {S : Set E} (hS : Convex ℝ S) {f : E → ℝ} (h : ∀ x ∈ S, ∀ y ∈ S, x ≠ y → StrictConcaveOn ℝ (Set.Icc 0 1) fun (t : ℝ) => f (x + t • (y - x))) :
    StrictConcaveOn ℝ S f

    Strict concavity is a segment-wise property.

    If for every pair of distinct points x, y ∈ S the one-variable restriction t ↦ f (x + t • (y − x)) is strictly concave on [0,1], then f is strictly concave on S.

    This is the promotion Mathlib lacks: it turns any number of one-dimensional strict concavity facts — each provable by strictConcaveOn_of_deriv2_neg — into a single statement about a set in a space of any dimension.

    The proof is the two-point evaluation. The segment hypothesis at (x, y), applied at the endpoints 0 and 1 of [0,1], gives exactly the defining inequality of StrictConcaveOn after identifying x + 0•(y−x) = x, x + 1•(y−x) = y, and x + b•(y−x) = a•x + b•y when a + b = 1.

    theorem QOU.MathlibExt.strictConcaveOn_of_deriv2_neg_along_segments {E : Type u_1} [AddCommGroup E] [Module ℝ E] {S : Set E} (hS : Convex ℝ S) {f : E → ℝ} (hcont : ∀ x ∈ S, ∀ y ∈ S, ContinuousOn (fun (t : ℝ) => f (x + t • (y - x))) (Set.Icc 0 1)) (hneg : ∀ x ∈ S, ∀ y ∈ S, x ≠ y → ∀ t ∈ Set.Ioo 0 1, deriv^[2] (fun (s : ℝ) => f (x + s • (y - x))) t < 0) :
    StrictConcaveOn ℝ S f

    The second-derivative test, in any dimension.

    f is strictly concave on the convex set S as soon as, along every segment of S, it is continuous and its second derivative is negative on the open segment.

    This is strictConcaveOn_of_deriv2_neg lifted out of ℝ by strictConcaveOn_of_segments. Note what the hypotheses do not mention: no Fréchet derivative, no Hessian as a bilinear form, no affine subspace. The direction of the segment is y − x with both endpoints in S, so the second-derivative hypothesis is only ever asked about directions tangent to S — which is what makes this usable on a constraint set where the ambient Hessian is not negative definite.

    That last point is the whole reason the corpus needs it. Λ″ = −cot is negative on (0, π/2) and positive on (π/2, π), so Λ(α)+Λ(β)+Λ(γ) is not concave on the open cube. It is concave on the slice α+β+γ = π, and only there.

    theorem QOU.MathlibExt.StrictConcaveOn.comp_affineMap {𝕜 : Type u_1} {E : Type u_2} {F : Type u_3} {β : Type u_4} [Field 𝕜] [LinearOrder 𝕜] [AddCommGroup E] [AddCommGroup F] [AddCommMonoid β] [PartialOrder β] [Module 𝕜 E] [Module 𝕜 F] [SMul 𝕜 β] {f : F → β} (g : E →ᵃ[𝕜] F) (hg : Function.Injective ⇑g) {s : Set F} (hf : StrictConcaveOn 𝕜 s f) :
    StrictConcaveOn 𝕜 (⇑g ⁻¹' s) (f ∘ ⇑g)

    Strict concavity survives precomposition by an injective affine map.

    Mathlib has ConvexOn.comp_affineMap and ConcaveOn.comp_affineMap but not the strict versions, and injectivity is exactly what the strict versions need: the defining inequality is quantified over x ≠ y, and without injectivity g x = g y is possible, where the strict inequality is false.

    Useful for reading a concavity statement off a parametrisation of a constraint set — give the slice {Σθ = π} a linear coordinate system and this transports concavity between the two descriptions.

    theorem QOU.MathlibExt.StrictConcaveOn.restrict_segment {E : Type u_1} [AddCommGroup E] [Module ℝ E] [NoZeroSMulDivisors ℝ E] {S : Set E} {f : E → ℝ} (hf : StrictConcaveOn ℝ S f) {x y : E} (hx : x ∈ S) (hy : y ∈ S) (hxy : x ≠ y) :
    StrictConcaveOn ℝ (Set.Icc 0 1) fun (t : ℝ) => f (x + t • (y - x))

    The converse of strictConcaveOn_of_segments: a strictly concave function restricts to a strictly concave function on each of its segments.

    Together the two say strict concavity on a convex set is segment-wise strict concavity — which is the sentence QOU.Knot.RivinConcavity asserts in prose.

    The proof is StrictConcaveOn.comp_affineMap above applied to AffineMap.lineMap x y, which is injective exactly because x ≠ y (NoZeroSMulDivisors is what turns that into injectivity of t ↦ t • (y − x)). This is the direction that needs the strict comp_affineMap, and hence the reason it is worth having.
