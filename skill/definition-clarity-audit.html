titledefinition-clarity-audit
descriptionDefinition / statement clarity + concision audit. A content block can validate (schema-clean, refs resolve, Lean sibling present) and still read badly: the defined term is never emphasised, the definition is buried under paragraphs of motivation, or one definition block silently bundles three or four distinct definienda. No existing QA axis (voice / wall / q-usage / canonical / detangler / bib / proof / compute) measures clarity of the statement itself. Use when asked to "bold defined terms", "tighten definitions", "no rambling definitions", "one definition per block", "tight theorem/proposition/lemma statements", or to set up / run a clarity audit. Also runs the inverse audit — a non-definition block that secretly carries a definition (clarity-defn-misplaced) — plus a statement-purity check (clarity-stmt-pure: a theorem/prop/lemma/conjecture carries only its claim; embedded remark / interpretation moves to a follow-on remark) and a register check (clarity-grad-style: graduate-level formal-math prose — no contractions, second-person, hype, colloquialism, or emoji). Emits per-block QA sidecar params under the clarity-* criteria via folio/pipeline/definition-clarity-audit.ts.
