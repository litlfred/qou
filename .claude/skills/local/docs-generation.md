# Documentation Generation Skill

## Role

Coordinate all documentation generation pipelines. This covers the
full set of rendered artifacts published to GitHub Pages, from the
content-object schemas through to per-paper PDF/HTML viewers.

## Paper document generation

### Pipeline: content objects → PDF

```
content/<paper>/<paper>.ts          paper manifest (metadata, chapters)
     ↓
content/pipeline/build.ts           validates + renders chapters → .tex
     ↓
latex/preamble.tex + manifest       generate-main-tex.ts → main.tex
     ↓
latexmk (pdflatex)                  main.tex → main.pdf
     ↓
latexpand + pandoc                  → .md → paper-raw.html
     ↓
generate-html.py                    → paper.html (enhanced)
     ↓
generate-index.py                   → per-paper index.html (viewer)
```

### Running locally

```bash
# Build chapters + generate main.tex from manifest
cd content && bun run pipeline/build.ts \
  quantum-observable-universe/quantum-observable-universe.ts \
  --out-dir ../chapters/ \
  --generate-main \
  --main-out ../main.tex \
  --preamble ../latex/preamble.tex

# Compile PDF (requires TeX Live). No engine in the sandbox? Run
# scripts/install-tex.sh first (installs texlive-full + latexmk).
cd .. && latexmk -pdf main.tex
```

### Key files

| File | Purpose |
|------|---------|
| `latex/preamble.tex` | Shared LaTeX preamble template (paper-agnostic) |
| `content/pipeline/build.ts` | Content → LaTeX chapter build |
| `content/pipeline/generate-main-tex.ts` | Manifest + preamble → `main.tex` |
| `content/pipeline/render-latex.ts` | Block-level markdown → LaTeX conversion |
| `.github/scripts/generate-html.py` | Pandoc HTML → enhanced paper.html |
| `.github/scripts/generate-index.py` | Per-paper viewer (paper/visualizer toggle) |
| `.github/scripts/generate-folio-index.py` | Root folio landing page |

## Schema documentation (TypeDoc)

Pretty-printed HTML reference for the content-object type system.

### Configuration

| File | Purpose |
|------|---------|
| `typedoc.json` | TypeDoc config (entry points, output dir, theme) |
| `folio-assistant/schemas/types.ts` | Core types: `Block`, `Chapter`, `Paper`, `Section` |
| `folio-assistant/schemas/constraints.ts` | Zod runtime validation schemas |
| `folio-assistant/schemas/builders.ts` | Constructor functions (`definition()`, `theorem()`, etc.) |
| `folio-assistant/schemas/qou-types.ts` | CI/output types (proof objects, glossary, coverage) |
| `folio-assistant/schemas/README.md` | TypeDoc landing page content |
| `package.json` | `build:docs` script |

### Running locally

```bash
# Install TypeDoc (if not already)
npm install

# Generate schema docs
npm run build:docs
# Output: build/schema-docs/
```

### Schema manifest (lightweight JSON)

For programmatic access (viewer, MCP server):

```bash
bun run scripts/generate-schema-manifest.ts
# Output: build/schema-manifest.json
```

## Folio landing page

The root `index.html` on gh-pages is a folio page listing all papers
with viewer links. Generated from `content/folio.ts`.

### Adding a new paper to the folio

1. Create `content/<paper-dir>/<paper-dir>.ts` (paper manifest with
   title, authors, abstract, macros, chapters)
2. Create chapter directories with content objects
3. Add `paperRef({ dir: "<paper-dir>", title: "...", ... })` to
   `content/folio.ts`
4. The pipeline discovers it automatically via `extract-folio.py`

### Key scripts

| Script | Purpose |
|--------|---------|
| `.github/scripts/extract-folio.py` | Parse `folio.ts` → JSON paper list |
| `.github/scripts/generate-folio-index.py` | Generate root `index.html` |

## Unified Docker image

All CI/CD workflows use the same **paper-assistant** Docker image
(`scripts/mcp-server/Dockerfile`), which is also the folio MCP server.
This eliminates per-workflow tool installation and ensures consistent
build environments.

### Image contents

| Tool | Purpose |
|------|---------|
| TeX Live (full) | PDF compilation, SVG rendering |
| Lean 4 + elan | Formal verification, doc-gen4 |
| Bun | Content pipeline, MCP server |
| pandoc | LaTeX → HTML/Markdown conversion |
| latexdiff | Feature-branch diff PDFs |
| graphviz | Dependency graph SVGs |
| gh CLI | PR preview comments |
| Python 3 + requests | CI scripts |
| ripgrep | Lean symbol search |

### Image lifecycle

| Trigger | When |
|---------|------|
| Push to main | Content, Lean, MCP server, or CI script changes |
| Weekly (Sunday) | Picks up Mathlib cache + TeX Live updates |
| Manual dispatch | `build-lean-mcp.yml` workflow |

Image: `ghcr.io/litlfred/qou/paper-assistant:latest`

### Using locally (Docker fallback)

When pdflatex isn't installed locally, the render hooks automatically
fall back to the Docker image:

```bash
# Pull once
docker pull ghcr.io/litlfred/qou/paper-assistant:latest

# Use as CI toolbox (override entrypoint)
docker run --rm --entrypoint "" \
  -v $(pwd):/work -w /work \
  ghcr.io/litlfred/qou/paper-assistant:latest \
  latexmk -pdf main.tex
```

The `scripts/lib/docker-tex.sh` helper automates this fallback for
`render-on-change.sh` and `render-pre-commit.sh`.
