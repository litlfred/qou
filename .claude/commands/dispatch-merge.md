`/dispatch-merge` is `/prepare-merge` executed **by a background agent**
instead of inline. Use it when you want the (long, blocking) prepare-merge
pipeline to run without tying up the main session — e.g. while you keep
working other beans. The dispatched agent does everything `/prepare-merge`
does through **Step 6** (rebase, witness-drift resolution, lean-ref
migration, content integration, reuse-and-simplify, one-voice, 100% Lean,
final rebase, request the Copilot review), then **stops before the
merge** and reports the PR's readiness. It does **NOT** merge — merging still
requires explicit human permission (AGENTS.md §Branch + PR workflow rules 7 &
10), and a background agent cannot take interactive confirmation. After the
agent reports "ready", the user says "merge it" and the main session performs
the merge (or invoke `/prepare-merge-auto` if autonomous merge-on-review is
wanted).

## What the main session does when this command is invoked

1. **Resolve the target branch + PR.**
   - If `$ARGUMENTS` names a PR number or branch, use that.
   - Otherwise use the **current branch** and its open PR
     (`mcp__github__list_pull_requests` filtered by head). If the current
     branch is `main`, has no open PR, or has uncommitted work, STOP and tell
     the user to create the branch + PR first (same precondition as
     `/prepare-merge`).

2. **Launch ONE background agent** with `isolation: "worktree"` and
   `run_in_background: true` (via the Agent tool), passing the prompt below
   with `<branch>` / `<PR#>` filled in. Do **not** run the pipeline inline.

3. **Report** that the dispatch happened (agent + target PR), then continue
   other work. Relay the agent's findings when its completion notification
   arrives; prune its worktree afterward.

## Agent prompt (fill in `<branch>` and `<PR#>`)

> You are running the `/prepare-merge` workflow for litlfred/qou PR **#<PR#>**
> (branch `<branch>`) as a background agent. Read AGENTS.md first (Branch + PR
> workflow, witness-drift rules, Strict Lean Discipline, §q₀ anchor
> convention). Then read `.claude/commands/prepare-merge.md` in your worktree
> and **execute its Steps 1 through 6 exactly**, on the feature branch:
>
> - In your isolated worktree, operate on the REAL feature branch, not the
>   auto-created temp branch: `git fetch origin <branch> main` then
>   `git checkout -B <branch> origin/<branch>`.
> - **Step 1** rebase onto `origin/main`; use the witness-drift auto-resolution
>   loop verbatim from `prepare-merge.md §1·a` (it self-halts on any non-witness
>   conflict — if it halts, resolve real conflicts by hand, never discard work,
>   and bean anything genuinely ambiguous rather than guessing).
> - **Step 1a** run the lean-ref migration (idempotent) and verify the three
>   counts are 0.
> - **Step 2 / 2a** integrate upstream content; run the reuse-and-simplify pass.
> - **Step 3** one-voice sweep on touched `.md`.
> - **Step 4** Lean: prefer `lean`-direct against the restored
>   `lake-cache/qou-<toolchain-slug>` oleans per AGENTS.md (a full root
>   `lake build` is usually infeasible in-sandbox — if it is, say so and fall
>   back to lean-direct on the changed modules + `lean-completeness-audit`).
>   The build/verify must be clean before you continue.
> - **Step 5** final rebase onto current `origin/main`; push with
>   `git push --force-with-lease -u origin <branch>`.
> - **Step 6** request the review: `mcp__github__request_copilot_review`,
>   then `subscribe_pr_activity`. Do **NOT** post `/gemini review` — Gemini
>   Code Assist is sunset and answers only with a sunset notice; record
>   "Gemini: sunset" and proceed. Copilot is the only live external reviewer. If GitHub's REST API is rate-limited, retry
>   with backoff; git push goes through the git proxy and is not REST-limited.
>
> **STOP after Step 6 — do NOT merge.** Merging is human-gated. On any Step 1–5
> failure that you cannot resolve, stop and report the blocker (per
> `prepare-merge.md §Failure handling`); if you already requested reviews, warn
> that reviewers may be looking at a broken branch.
>
> **Report:** the PR URL, a readiness verdict (green / blocked-on-X), what the
> rebase pulled in and any conflicts resolved, the Lean verification result
> (lean-direct exit code or build status), the review requests posted, and any
> beans filed. End with the exact line: **"Ready for merge — say the word."**
> (or the blocker if not ready). Append the attribution footer to any GitHub
> comment you post: a blank line, `---`, then
> `_Generated by [Claude Code](https://claude.ai/code)_`.

## Notes

- **One PR per dispatch.** To prepare several PRs, invoke `/dispatch-merge`
  once per PR (each gets its own background agent + worktree).
- **Merge default stays rebase-merge** (AGENTS.md rule 8) when the human later
  authorizes it — the agent does not choose the merge method.
- **Difference from `/prepare-merge-auto`:** `prepare-merge-auto` runs inline
  and merges after resolving reviews; `/dispatch-merge` runs in the background
  and stops at readiness, leaving the merge to the human.
