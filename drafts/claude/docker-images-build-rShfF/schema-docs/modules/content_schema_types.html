    Module content/schema/types

    Content-Object AST — Authoritative document model for QOU.

    Directory convention

    Content is organized by document structure:

    content/ / .ts — Paper manifest (references chapter URIs) / .ts — Chapter manifest (sections + block refs) .ts — Typed block manifest (kind, label, lean, etc.) .md — Narrative content (markdown + TeX snippets) .lean — Lean formalization (when required by kind)

    The paper .ts is authoritative for where chapter .ts files live, via URI (defaults to relative local path). Chapter .ts references blocks within its directory.

    File naming convention

    Each content object has sibling files sharing the same root name: rigid-monoidal-category.ts — manifest rigid-monoidal-category.md — narrative rigid-monoidal-category.lean — Lean (when required)

    Markdown content grammar (in .md files)

    Each .md file uses a constrained markdown dialect that embeds TeX. The content is parsed by remark + remark-math (AST-based, not regex), and the extracted TeX is validated by unified-latex (LaTeX AST parser).

    AST node mapping

    Markdown syntax remark AST node LaTeX output
    $...$ inlineMath passthrough
    $$...$$ math (display) \[...\]
    ```tex ... ``` code (lang=tex) raw LaTeX passthrough
    **bold** strong \textbf{}
    *italic* emphasis \emph{}
    [text](#label) link \hyperref[label]{text}
    - item listItem \begin{itemize} \item
    1. item listItem \begin{enumerate} \item
    blank line paragraph break \par / blank line

    TeX embedding rules

    Inline math ($...$):

    • Single-line only. Content is raw TeX in math mode.
    • Escape literal $ with \$ in surrounding prose.
    • Example: The connection $\nabla_q$ satisfies $d_q^2 = 0$.

    Display math ($$...$$):

    • Multi-line allowed. Content is raw TeX in display math mode.
    • Do NOT nest \begin{equation} inside $$...$$ — the pipeline wraps display math in \[...\] automatically.
    • Example:
      $$
      F_{\mu\nu} = \partial_\mu A_\nu - \partial_\nu A_\mu
      $$

    Fenced TeX (```tex ... ```):

    • Raw LaTeX passthrough — inserted verbatim into the output.
    • Use for environments that cannot appear in math mode: tikzcd, align, gather, figure, tabular, etc.
    • The pipeline does NOT wrap this in math mode.
    • Example:
      \begin{tikzcd}
  A \arrow[r, "f"] & B \arrow[d, "g"] \\
  C \arrow[u, "h"] & D
\end{tikzcd}

    Block-kind–specific content rules

    Block kind .md content contains
    prose Full markdown (lists, bold, math, fenced TeX)
    definition Full markdown (body of the definition env)
    theorem etc. Full markdown (statement body)
    proof Full markdown (proof body)
    equation TeX math ONLY — no lists, no bold, no prose
    diagram Fenced TeX (```tex) + optional prose / inline math

    Critical: For equation blocks, the pipeline uses extractMathContent() (not markdownToLatex()) to prevent list environments from appearing inside math mode. Authors should put pure TeX in equation .md files, not markdown prose.

    diagram blocks use markdownToLatex() so that surrounding prose and inline math (e.g. $\mathrm{SU}(2)$) render correctly. All TeX environments (tikzcd, etc.) must be in fenced ```tex blocks.

    Validation pipeline

    Three-level validation runs on every .md file:

    1. Markdown AST (remark + remark-math):

      • Parses markdown into typed AST nodes
      • Extracts inlineMath, math, and code[lang=tex] nodes
      • Provides source positions (line:column) for error reporting

    2. LaTeX AST (unified-latex):

      • Parses each extracted TeX snippet into a LaTeX AST
      • Detects: unbalanced braces, malformed environments, invalid nesting
      • Catches: non-math environments in math context (e.g. itemize in $$)

    3. Compilation (optional, pdflatex):

      • Compiles each snippet with the project's preamble
      • Catches: undefined commands, missing packages, font issues
      • Enabled via --compile flag on validate-tex.ts

    Tools:

    • bun run pipeline/validate-tex.ts — AST validation of all .md files
    • bun run pipeline/validate.ts — full content validation (schema + constraints + AST)

    Constraint enforcement

    TypeScript types enforce structure at compile time. Zod schemas (constraints.ts) validate at runtime + CI. Pipeline validates sibling files exist where required.
